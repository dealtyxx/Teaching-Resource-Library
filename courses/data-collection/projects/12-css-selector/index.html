思政会客厅

🔬科研诚信· 性能结论必须来自实测

  • 「lxml 更快」是社区共识，但写进你的选型报告之前，要有自己机器上的计时数据——引用结论和验证结论是两种职业习惯。
  • 基准测试要控制变量：同一文档、同一选择器、足够轮次，否则数据本身就是造假。
  • 把 perf_counter 用成肌肉记忆：可复现的数字，是工程师之间最硬的通货。

💡创新思维· 表达力就是生产力

  • CSS 选择器把「三层 find_all 嵌套」压缩成一行声明——学会站在更高的抽象层写代码。
  • 选择器语法与前端通用：一次学习，浏览器 DevTools、爬虫、自动化测试三处受益。
  • 工具在演进（html.parser → lxml → 更快的解析器），但「先量化再选择」的方法论不过时。
