场景导入

社团想在活动室挂一块「今日校园天气」小屏幕，你去调了一个开放天气接口。请求发出去，返回的不是排好队的表格，而是一长串带大括号的文本——这就是 JSON。它是几乎所有 Web 接口的「通用语」：键值成对、层层嵌套，机器好解析、人也读得懂。今天的任务很实在：把这串文本变成 Python 能操作的数据，再从里面精准挑出「今日概况」和「高温预警」两样东西。

动手实验

接口返回的 JSON 就存在 resp 这个字符串里。核心其实只有一步——json.loads() 把文本解析成字典，之后就像查字典一样用「键」逐层取值。注意最后 json.dumps() 里的 ensure_ascii=False，它是让中文正常显示、而不是变成一堆转义码的关键：

思政会客厅

🧭职业伦理· 调用别人的接口，先守别人的规矩

  • 开放接口不是「免费自助餐」：多数平台要求先注册申请 API Key、标注数据来源，并限制调用频次（QPS 与每日上限）。守约调用，是数据工程师的职业底线。
  • 高德开放平台、和风天气等真实服务都设有配额，恶意高频请求会触发风控限流甚至封禁——尊重规则，也是尊重对方的服务器与其他使用者。
  • 《数据安全法》第三十二条要求：收集数据应采取合法、正当的方式。按约定用接口，就是「合法正当」最日常的体现。

🌐开源共享· 站在开放能力的肩膀上

  • 气象、地图、翻译这些能力被封装成开放 API 共享出来，小团队也能几行代码就用上——这正是「共享」精神的技术形态。
  • 享受开放资源的同时，也应回馈约定：注明出处、遵守协议、发现问题反馈给维护方，让这份共享生态可持续。

🔑契约精神藏在 API Key 里

一把 Key、一个配额、一份服务协议，构成了 API 世界的「契约」。写脚本前先读文档、算清调用量、做好本地缓存降频——这不是束缚，而是把「用好开放接口」变成一种专业素养。
