文本脏数据清洗替换器

进阶选做 数据清洗 ★★★ 约 40 分钟

学习目标：掌握正则替换与优化

思政目标：清洗不改语义——效率与真实并重

🔬科研诚信💡创新思维 sub()替换compile预编译反向引用

场景导入

你接手一批从网页复制来的商品评论，打开一看：全角数字混着半角、HTML 标签没删干净、句尾一连串「！！！」、还夹着大片多余空格。模型可读不了这样的「脏数据」。这一课，我们用 re.sub 给文本「洗个澡」——但记住一条铁律：只做规范化，绝不改动原意。

动手实验

re.sub(pattern, repl, s) 把匹配到的片段替换成新内容；repl 既可以是字符串，也可以是一个函数。清洗规则往往要反复施用，这时 re.compile 预编译就派上用场——同一个模式只解析一次，又快又清晰：

# 写法一：每次都重新解析同一个模式，能跑，但重复
re.sub(r'\s+', ' ', a)
re.sub(r'\s+', ' ', b)

# 写法二：预编译一次，反复复用——更快，也让「这是一条固定规则」一目了然
WS = re.compile(r'\s+')
WS.sub(' ', a)
WS.sub(' ', b)

下面这个清洗器把「去标签、全角转半角、去重复标点、规整空白」串成一条流水线，而且每一步都往审计清单里记一笔「改了什么」。运行看看清洗前后的对照：

思政会客厅

🔬科研诚信· 清洗不改语义

  • 清洗是为了让真相更清楚，不是把数据改成你想要的样子。删空格、转半角属于「规范化」；改数值、悄悄删掉「碍事」的样本，就滑向了「造假」。
  • 每一步都记进审计清单，别人才能复现你的结果。可复现，是诚信最硬的技术证据。
  • 遇到可疑数据，先标注、再讨论，而不是直接抹掉——异常里可能正藏着真问题。

💡创新思维· 从「能跑」到「工程」

  • re.compile 把模式变成可复用的对象，既快，又让「这是一条固定规则」显性化。
  • 把零散的替换整理成有序流水线，每一步单一职责、可插拔——这就是工程化思维。
  • 好的清洗器像流水线：换一种脏数据，只需增删一节，而不必推倒重来。

🔬审计意识：留一份「改动清单」

清洗后的数据固然干净，可若没人知道你到底动了哪里，这份数据就失去了可信度。养成习惯：每一步替换都记一笔「改了什么、改了多少」。可追溯的清洗，才敢拿去做科研。
