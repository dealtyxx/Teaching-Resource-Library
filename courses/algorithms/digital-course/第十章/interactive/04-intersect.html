一、教材标准算法：两步走

快速排斥试验 + 跨立试验
本页演示只做了第二步。教材给出的线段相交判定是两个试验的合取：先用快速排斥试验（rapid exclusion test）以极低代价筛掉绝大多数明显不相交的情形，再用跨立试验（straddle test）作严格判定。演示为了突出叉积的作用，只实现了跨立试验；下面把缺失的第一步补齐。
1
快速排斥试验：为两条线段各作一个轴对齐包围盒（AABB）。若两个矩形不重叠，则线段一定不相交，立即返回 false。这一步只需 4 次比较，比叉积还便宜。
2
跨立试验：若包围盒重叠，再判断「C、D 分列直线 AB 两侧」且「A、B 分列直线 CD 两侧」。两者同时成立即为相交。

二、快速排斥试验

rapid exclusion · 包围盒预判
定义

线段 AB 的轴对齐包围盒是能包住它的最小矩形，即 [min(xA,xB), max(xA,xB)] × [min(yA,yB), max(yA,yB)]。两条线段的包围盒重叠，当且仅当它们在 x 方向与 y 方向的投影区间都重叠。

min(xA,xB) ≤ max(xC,xD)　∧　min(xC,xD) ≤ max(xA,xB)
min(yA,yB) ≤ max(yC,yD)　∧　min(yC,yD) ≤ max(yA,yB)
性质

快速排斥试验是相交的必要条件而非充分条件：包围盒不重叠 ⇒ 一定不相交（这一步的结论是可靠的）；但包围盒重叠 ⇏ 相交（两条互不相交的对角线也可能共用一个包围盒）。因此它只能否定，不能肯定，必须与跨立试验联用。

为什么值得多写这一步？两个理由。其一是效率：包围盒判定只有加载与比较，没有乘法，在大规模求交（例如判断上万条边两两是否相交）时能剔除掉绝大多数候选。其二是正确性：当两条线段共线时，四个叉积全为 0，跨立试验完全失效——此时正是包围盒重叠与否给出了「共线但不重叠」与「共线且重叠」的区分。所以这一步不只是优化，它还是共线情形的判据。

三、跨立试验

straddle test · 四次方向判定
定义

称线段 CD 跨立于直线 AB，是指 C 与 D 分别位于直线 AB 的两侧。用第 2 节的方向判定表述：d1 = (B−A)×(C−A)，d2 = (B−A)×(D−A)，若 d1 与 d2 异号则 CD 跨立 AB。

d1=Cross(A,B,C)　d2=Cross(A,B,D)　d3=Cross(C,D,A)　d4=Cross(C,D,B)
规范相交 ⇔ d1·d2 < 0 且 d3·d4 < 0
为什么必须互相跨立？只判「CD 跨立 AB」是不够的——一条很短的线段 CD 可能确实横跨了直线 AB，却落在线段 AB 之外的延长线区域。反过来也一样。只有两个方向的跨立同时成立，交点才被同时约束在两条线段的内部。

四、规范相交 vs 非规范相交

本页演示的边界行为
定义

规范相交（proper intersection）：两线段恰有一个公共点，且该点位于两条线段的内部（不是任何一方的端点）。
非规范相交（improper / degenerate intersection）：仍有公共点，但至少满足下列之一——公共点是某条线段的端点；或两线段共线且部分重叠（此时公共点有无穷多个）。

演示代码的严格性说明：本页 JS 写的是 return d1*d2 < 0 && d3*d4 < 0;。这里用的是严格小于，意味着只要有任何一个 di 等于 0（即某个端点恰好落在另一条线段所在直线上），乘积就是 0 而非负数，判定结果为 false。因此在演示里：T 形接触（端点顶在另一条线段中间）、V 形共端点（两线段共用一个端点）、共线重叠（两条线段叠在一起）——这三种「肉眼看着明明相交」的情形，全都会显示「不相交」。这不是 bug，而是规范相交的定义使然。请务必在演示中亲手把端点拖到另一条线段上验证这一行为。
几何情形d1d2, d3d4规范相交判定是否真的有公共点
标准「×」形交叉均 < 0true是（唯一交点）
T 形：C 落在 AB 内部d3d4 = 0false是（端点接触）
V 形：A 与 C 重合含 0false是（共端点）
共线且重叠四个 d 全为 0false是（无穷多公共点）
共线但分离四个 d 全为 0false否
完全错开至少一组 > 0false否
该用哪一种？看题意。如果题目问的是「两条道路是否交叉通行」，端点相接通常算相交，要用完整版判定；如果问的是「多边形是否自交」，共享端点的相邻边不该算相交，正需要规范相交这种严格定义。写代码前先问清楚边界该归哪一边——这是几何题最常见的 WA 来源。

五、C++ 实现

规范版 + 完整版 + 求交点
// ---------- 线段相交判定 ---------- const double EPS = 1e-8; int sgn(double x) { return fabs(x) < EPS ? 0 : (x < 0 ? -1 : 1); } double Cross(Point a, Point b, Point c) { return (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x - a.x); } // 【第一步】快速排斥试验：包围盒不重叠则必不相交 bool RapidExclusion(Point a, Point b, Point c, Point d) { return min(a.x, b.x) <= max(c.x, d.x) + EPS && min(c.x, d.x) <= max(a.x, b.x) + EPS && min(a.y, b.y) <= max(c.y, d.y) + EPS && min(c.y, d.y) <= max(a.y, b.y) + EPS; } // 【第二步·规范相交】严格异号：端点接触与共线重叠都返回 false // —— 这正是本页 canvas 演示所实现的版本 bool ProperIntersect(Point a, Point b, Point c, Point d) { int d1 = sgn(Cross(a, b, c)), d2 = sgn(Cross(a, b, d)); int d3 = sgn(Cross(c, d, a)), d4 = sgn(Cross(c, d, b)); return d1 * d2 < 0 && d3 * d4 < 0; } // 判点 p 是否在线段 ab 上（共线 + 落在区间内），用于处理非规范情形 bool OnSegment(Point p, Point a, Point b) { return sgn(Cross(a, b, p)) == 0 && sgn(Dot(a - p, b - p)) <= 0; } // 【完整版】教材标准：快速排斥 + 跨立，端点接触与共线重叠均算相交 bool SegmentIntersect(Point a, Point b, Point c, Point d) { if (!RapidExclusion(a, b, c, d)) return false; // 便宜的否定，顺带处理共线分离 int d1 = sgn(Cross(a, b, c)), d2 = sgn(Cross(a, b, d)); int d3 = sgn(Cross(c, d, a)), d4 = sgn(Cross(c, d, b)); if (d1 * d2 < 0 && d3 * d4 < 0) return true; // 规范相交 // 以下为非规范情形：某端点落在另一线段上 if (d1 == 0 && OnSegment(c, a, b)) return true; if (d2 == 0 && OnSegment(d, a, b)) return true; if (d3 == 0 && OnSegment(a, c, d)) return true; if (d4 == 0 && OnSegment(b, c, d)) return true; return false; } // 【求交点】仅在两直线不平行时有效，调用前须先判 sgn(den) != 0 Point LineIntersection(Point a, Point b, Point c, Point d) { Vector u = b - a, v = d - c, w = a - c; double den = Cross(u, v); // den == 0 ⇔ 两直线平行或重合 double t = Cross(v, w) / den; // 此处唯一的除法 return a + u * t; }
注意判定与求交点的分工：「是否相交」的判定只有乘法与减法，整数坐标下可用 long long 做到零误差；而「交点在哪里」必然含除法，结果一般不是整数。所以工程上的铁律是：能只判不求就别求交点。凡是只关心相交与否的场合（自交检测、可见性判断、多边形裁剪的预筛），都不要去算那个除法。

七、退化情形与浮点精度

d = 0 的每一种解读
退化情形征兆正确处理
某端点落在另一线段内部（T 形）恰有一个 di = 0用 OnSegment 补判；先想清题意要不要算相交
两线段共用端点（V 形）两个 di = 0同上；多边形自交检测中通常需排除相邻边
两线段共线四个 di 全为 0跨立试验完全失效，只能靠包围盒区分重叠与分离
线段退化为点（A=B）Cross(a,b,·) 恒为 0转化为「点是否在另一线段上」，用 OnSegment
两线段几乎平行求交点时 den 极小交点坐标被放大，误差爆炸；先 sgn(den)==0 拦截

一个特别隐蔽的坑：如果直接写 if (Cross(a,b,c) * Cross(a,b,d) < 0)，两个 double 相乘会把误差也乘起来；当两个叉积都是 1e-160 量级时乘积会下溢为 0，当它们都很大时又可能上溢为 inf。正确做法是先用 sgn() 把每个叉积规约成 −1/0/+1 这三个整数，再判断乘积的符号——这样既避免了溢出，也让容差只在一个地方生效。
易错点
  • 只做跨立、不做快速排斥：共线情形下四个叉积全为 0，跨立无法区分「重叠」与「分离」，必然出错。
  • 只判单向跨立就下结论，忘了必须互相跨立。
  • 没想清题目要的是规范相交还是含端点接触，边界数据一到就 WA。
  • 把两个 double 叉积直接相乘再比较符号（应先 sgn）。
  • 不判平行就去算交点，除以近似为 0 的 den 得到坐标为 ±1e18 的「交点」。
  • 共线重叠时试图返回「一个交点」——此时公共部分是一条线段，应返回区间而非点。
  • 多边形自交检测时忘了排除相邻边，它们必然共享端点，会被全部误报。

本节小结
  • 教材标准算法是两步：先快速排斥（包围盒），后跨立试验（四次叉积）。
  • 快速排斥是必要非充分条件，只能否定不能肯定；但它同时是共线情形唯一的判据。
  • 跨立必须双向：d1d2 < 0 且 d3d4 < 0，否则交点可能落在延长线上。
  • 规范相交要求唯一交点且不在端点；本页演示的 d1*d2<0 正是这一严格版本，端点接触会判为不相交。
  • 非规范情形（T 形、V 形、共线重叠）需用 OnSegment 单独补判。
  • 判定无除法，整数坐标下完全精确；求交点必然有除法，能不求就不求。
  • n 条线段两两判交为 O(n2)，扫描线可降到 O(n log n)。
1关于快速排斥试验，下列说法正确的是？
A包围盒重叠 ⇒ 两线段一定相交
B包围盒不重叠 ⇒ 两线段一定不相交；反之不成立
C它可以完全替代跨立试验，因此跨立试验是多余的
D它只是性能优化，去掉后算法在任何情况下仍然正确
解析：选 B。快速排斥是必要非充分条件——只能可靠地做出「不相交」的否定结论。A 反了：一个正方形的两条不相邻的边可以共用同一个包围盒却互不相交。C 更离谱：包围盒完全无法分辨盒内两条线段的真实位置关系。D 是最有迷惑性的一项，也是本节的关键点：当两线段共线时四个叉积全为 0，跨立试验彻底失效，此时恰恰只有快速排斥能区分「共线重叠」与「共线分离」，所以它不仅是优化，还承担着正确性职责。
2线段 AB 与 CD 呈 T 形：C 恰好落在 AB 的中点上。用本页演示的 d1*d2 < 0 && d3*d4 < 0 判定，结果是？
A相交，因为它们确实有公共点
B不相交，因为 d1 = 0 使乘积为 0，不满足严格小于
C结果不确定，取决于点的输入顺序
D程序会因除零而崩溃
解析：选 B。C 落在直线 AB 上，故 d1 = Cross(A,B,C) = 0，于是 d1·d2 = 0，不满足严格小于 0，判定返回 false。这不是缺陷而是规范相交的定义——它要求交点位于两线段内部且不是端点。C 错在跨立试验对输入顺序是对称的（交换 A、B 只让 d1、d2 同时变号，乘积不变）。D 错在整个判定不含任何除法，无从崩溃。若题意要求端点接触也算相交，就得再补 OnSegment 的四次检查。
3用 double 坐标做跨立试验，下列写法中最稳妥的是？
Aif (Cross(a,b,c) * Cross(a,b,d) < 0)
B先 int d1 = sgn(Cross(a,b,c)), d2 = sgn(Cross(a,b,d)); 再判 d1*d2 < 0
Cif (Cross(a,b,c) < 0 != Cross(a,b,d) < 0)
D把坐标乘以 10000 取整后再用 A 的写法
解析：选 B。先用 sgn 把每个叉积规约成 −1/0/+1，容差只在一处生效，之后是整数相乘，既不会下溢也不会上溢。A 有双重隐患：两个各带误差的浮点数相乘会放大误差，而且极小值相乘会下溢为 0、极大值相乘会上溢为 inf。C 虽避开了乘法，但它把「叉积等于 0」当成了「不小于 0」，即把共线归入了正侧，共线情形的处理就此错乱，而且完全没有容差。D 的缩放取整思路在特定题目里可行，但乘 10000 后坐标量级放大，反而更容易溢出，且四舍五入本身就可能改变几何关系（原本共线的三点取整后不再共线）。
