一、点到直线：投影与距离

point-to-line · 不截断
定义

设直线由点 A 与方向向量 ab = B − A 确定（|ab| ≠ 0）。点 P 在该直线上的垂足（投影点）记为 C，则存在唯一实数 t 使 C = A + t·ab。这个 t 称为投影参数。

第一步：令 ap = P − A，垂足条件是 (P − C) ⊥ ab，即 (ap − t·ab) · ab = 0 垂直 ⇔ 点积为零 第二步：展开得 ap·ab − t(ab·ab) = 0 点积的线性 第三步：解出 t = (ap · ab) / |ab|2 这里出现了唯一的除法——除零风险由此而来 第四步：垂足 C = A + t·ab，点到直线距离 = |P − C| 先求垂足再求距离 第五步：也可绕开垂足，直接用叉积的面积意义：|ab × ap| 是平行四边形面积，除以底 |ab| 即得高 一步到位，更稳
t = (ap · ab) / |ab|2　　　d直线 = |ab × ap| / |ab|
性质

投影参数 t 是一个无量纲的比例：t = 0 对应 A，t = 1 对应 B，t = 0.5 对应中点。t < 0 表示垂足落在 A 的反向延长线上，t > 1 表示落在 B 的正向延长线上。因此 t 本身就是「垂足是否落在线段内」的判据。

二、点到线段：为什么必须截断

point-to-segment · clamp t 到 [0,1]
直线是无限的，线段不是。点到直线的最近点永远是垂足；但线段只是直线上 t ∈ [0, 1] 的那一段。当垂足落在线段之外时，它根本不属于线段，此时线段上真正离 P 最近的点必然是离垂足更近的那个端点。这就是把 t 截断（clamp）到 [0, 1] 的全部理由。
定理

设 f(t) = |A + t·ab − P|2，它是关于 t 的开口向上的二次函数，对称轴恰为 t0 = (ap·ab)/|ab|2。在闭区间 [0, 1] 上二次函数的最小值只可能出现在对称轴处或区间端点处，故取 t* = clamp(t0, 0, 1) 一定给出线段上的最近点。这正是 clamp 做法的严格依据。

t* = clamp( (ap·ab) / |ab|2 , 0, 1 )　　最近点 C = A + t*·ab　　d = |P − C|
t0 的范围截断后 t*最近点位置几何图景
t0 < 00端点 AP 位于 A 一侧的「外侧扇区」，垂足在反向延长线上
0 ≤ t0 ≤ 1t0线段内部（真正的垂足）P 位于线段的「带状区域」正对面
t0 > 11端点 BP 位于 B 一侧的外侧扇区
对比项点到直线点到线段
最近点永远是垂足垂足或某个端点
是否截断 t不截断必须截断到 [0,1]
可用叉积一步求距离可以：|ab×ap|/|ab|不可以——外侧扇区时该式给出的是到直线的距离，会偏小
距离随 P 移动的变化处处光滑在两条端点法线上不可导（分段拼接）
最常见的错误：把点到直线的公式 |ab×ap|/|ab| 直接当成点到线段的距离。当 P 远远处在线段延长线的外侧时，它算出的距离几乎是 0，而真实的线段距离可能很大——碰撞检测、地图匹配里的诡异 bug 十有八九源于此。

三、C++ 实现

含退化保护
// ---------- 点到直线 / 点到线段 ---------- const double EPS = 1e-8; int sgn(double x) { return fabs(x) < EPS ? 0 : (x < 0 ? -1 : 1); } // 点 p 到「直线 AB」的距离：用叉积的面积意义，一步到位 // 前提：A != B，否则底为 0，除零！ double DistanceToLine(Point p, Point a, Point b) { Vector ab = b - a, ap = p - a; return fabs(Cross(ab, ap)) / Length(ab); // 平行四边形面积 / 底 = 高 } // 点 p 在线段 AB 上的最近点（投影后截断） Point ProjectOnSegment(Point p, Point a, Point b) { Vector ab = b - a, ap = p - a; double d2 = Dot(ab, ab); // = |ab|^2 if (sgn(d2) == 0) return a; // ★ 退化：A==B，线段其实是一个点 double t = Dot(ap, ab) / d2; if (t < 0.0) t = 0.0; // 截断到 [0,1]： if (t > 1.0) t = 1.0; // 垂足在段外时退回端点 return a + ab * t; } // 点 p 到「线段 AB」的距离 double DistanceToSegment(Point p, Point a, Point b) { return Length(p - ProjectOnSegment(p, a, b)); } // 只比较远近时的高效版本：返回距离的平方，全程不开方 double DistanceToSegment2(Point p, Point a, Point b) { Point c = ProjectOnSegment(p, a, b); return Dot(p - c, p - c); } // 判定点 p 是否落在线段 AB 上（含端点） // 条件一：三点共线（叉积为 0）；条件二：p 位于 A、B 之间（点积非正） bool OnSegment(Point p, Point a, Point b) { return sgn(Cross(a, b, p)) == 0 && sgn(Dot(a - p, b - p)) <= 0; }
OnSegment 为什么用 Dot(a−p, b−p) ≤ 0？若 p 落在 A、B 之间，则从 p 看向 A 与看向 B 的两个向量方向相反，夹角为 180°，点积必为负；p 恰在端点时其中一个向量为零向量，点积为 0；p 在段外时两向量同向，点积为正。一次叉积管共线、一次点积管区间，两行搞定，且不含任何除法。

五、退化情形与浮点精度

A = B 时的除零陷阱
本页演示代码里的 ||1 是一个「兜底」：它写的是 t = Dot(ap,ab) / (Dot(ab,ab) || 1)。当 A 与 B 被拖到重合时 Dot(ab,ab) 为 0，JavaScript 的 || 会把分母悄悄换成 1，程序不会崩溃——但这只是让它别炸，并不是正确处理。在 C++ 里没有这层保护：0.0 / 0.0 得到 NaN，x / 0.0 得到 inf，随后的 clamp（t < 0 与 t > 1 对 NaN 都为 false）会把 NaN 原样传下去，最终整个距离变成 NaN，而且任何与 NaN 的比较都是 false，最小值更新永远不触发——这类 bug 极难定位。
退化情形问题所在正确处理
A = B（线段退化成点）|ab|2 = 0，t 的除法分母为零 → NaN / inf先 if (sgn(Dot(ab,ab)) == 0) return a;，退化为点到点距离
A、B 极其接近但不相等分母是很小的数，t 被放大，误差剧增同样按重合处理，或先用 EPS 合并近重合点
P 恰好落在线段上距离为 0，但浮点可能算出 1e-17用 sgn(d) == 0 判「在线段上」，或直接用 OnSegment
t 恰为 0 或 1浮点比较 t == 0 不可靠判断落在端点用 t < EPS / t > 1 - EPS
坐标量级悬殊|ab|2 可能溢出或损失精度必要时先做坐标平移（整体减去重心），把数量级压下来
易错点
  • 忘记 clamp：直接用垂足当最近点，导致 P 在延长线外侧时距离严重偏小。
  • 不判 A = B：这是本节唯一带除法的公式，退化时必然除零，产生 NaN 并静默污染后续所有比较。
  • 把 t 当作「距离」使用——t 是无量纲比例，不是长度，长度是 t·|ab|。
  • 用 fabs(Cross(ab,ap))/Length(ab) 当作点到线段的距离（那是点到直线）。
  • 逐边求最短距离时每次都开方——应先比较平方距离，最后再 sqrt 一次。
  • 判断「点在线段上」时只查了共线而没查区间，把延长线上的点也算了进去。

六、应用场景

这段十行代码用途极广
1
碰撞检测：圆与线段是否相交，只需判断「圆心到线段的距离 ≤ 半径」。游戏里的子弹擦墙、角色贴墙判定都走这条路径。
2
轨迹 / 曲线简化：Douglas-Peucker 算法反复寻找「离首尾连线最远的点」，用它决定是否保留该点，是 GIS 与地图渲染的标准做法。
3
地图匹配（map matching）：把 GPS 采样点吸附到最近的道路段上，投影参数 t 顺带给出「在这条路上走了百分之多少」。
4
鼠标拾取：判断点击位置是否落在某条折线附近（距离小于若干像素即命中）。
5
点到多边形距离：对所有边取最小值；配合第 5 节的内外判定，还能得到有符号距离场（内为负、外为正）。

本节小结
  • 投影参数 t = (ap·ab)/|ab|2 把「点到线」问题化归为一维求最值。
  • 点到直线不截断，最近点恒为垂足，距离可用 |ab×ap|/|ab| 一步求出。
  • 点到线段必须把 t 截断到 [0, 1]；依据是二次函数在闭区间上的最小值只出现在对称轴或端点。
  • t < 0 取 A，t > 1 取 B，否则取真实垂足——三种情形对应三块几何区域。
  • 本节公式含唯一一次除法，分母 |ab|2 在 A = B 时为零，必须显式判退化，否则得到 NaN 并静默传播。
  • 只作大小比较时用平方距离；判「点在线段上」用「叉积判共线 + 点积判区间」两步。
1A(0,0)、B(10,0)、P(−5, 3)。点 P 到线段 AB 的距离是？
A3
B√34 ≈ 5.83
C5
D8
解析：选 B。t0 = (ap·ab)/|ab|2 = ((−5)×10 + 3×0)/100 = −0.5 < 0，垂足落在 A 的反向延长线上，故截断 t* = 0，最近点就是端点 A(0,0)，距离 = √((−5)2+32) = √34 ≈ 5.83。A 选项 3 是最典型的陷阱：它是点到直线（x 轴）的距离，正是「忘记 clamp」得到的错误答案。C 只算了水平方向的 5，D 则是 5+3 的臆测。
2在 C++ 中计算点到线段距离，若线段两端点 A 与 B 恰好重合而代码未做任何判断，会发生什么？
A程序抛出除零异常并终止
Bt 被自动置为 0，恰好得到正确答案
Ct 变为 NaN 或 inf，clamp 无法拦住 NaN，最终距离为 NaN 且所有比较均为 false
D没有影响，因为分子同时也是 0
解析：选 C。C++ 的浮点除零不产生异常（那是整数除零才有的行为），而是按 IEEE 754 给出 inf 或 NaN，所以 A 错。关键在于 t < 0.0 与 t > 1.0 在 t 为 NaN 时都返回 false，clamp 形同虚设，NaN 会一路传到最终结果；而 NaN 参与的任何比较（包括 d < best）也都是 false，于是「求最小距离」的循环永远不更新，表现为答案离奇错误却不报错。B 属于一厢情愿；D 忽略了 0/0 在 IEEE 754 中定义为 NaN 而非 0。正解是显式写 if (sgn(Dot(ab,ab)) == 0) return a;，退化为点到点距离。
3要判断点 P 是否落在线段 AB 上（含端点），下列条件组合正确的是？
A仅 sgn(Cross(a,b,p)) == 0
B仅 sgn(Dot(a-p, b-p)) <= 0
Csgn(Cross(a,b,p)) == 0 且 sgn(Dot(a-p, b-p)) <= 0
Dfabs(Length(p-a) + Length(p-b) - Length(a-b)) == 0
解析：选 C，两个条件缺一不可。A 只保证 P 在直线上，延长线上的点也会通过——这是最常见的漏判。B 只保证 P 落在以 AB 为直径的圆内（从 P 看 A、B 的张角不小于 90°），圆内偏离直线的点同样会通过。D 的数学思路是对的（三角不等式取等当且仅当共线且居中），但写法致命：它用 == 0 比较浮点，且经过三次 sqrt 误差累积，几乎永远不成立；即便改成带 EPS 的版本，也比 C 慢（三次开方 vs 零次开方）。
