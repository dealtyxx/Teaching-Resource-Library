0/1 背包 · 限界剪支

物品按 v/w 降序；bound = 当前价值 + 剩余用分数背包上界。bound≤best 则剪。

学习目标

  1. 能够形式化描述 0/1 背包问题，并说明它与分数背包（可分割背包）在约束上的唯一差别。
  2. 能够构造限界函数 bound(i, cw, cv)：当前价值 + 用分数背包松弛填满剩余容量所得的价值。
  3. 能够完整证明限界函数的正确性——bound 一定 ≥ 该结点子树内任何 0/1 可行解的价值，因此按 bound ≤ bestV 剪支不会丢失最优解。
  4. 能够说明为什么"必须先按价值密度 v/w 降序排序"是 bound 成为合法上界的前提，并指出不排序会导致什么后果。
  5. 能够写出带 bound 的完整 C++ 代码，并分析其时间复杂度 O(n·2n)。

问题定义与限界函数

用分数背包松弛构造上界
定义 1 · 0/1 背包问题

给定 n 个物品，物品 i 的重量为 wi > 0、价值为 vi > 0，背包容量为 W。求 x = (x0,…,xn−1) ∈ {0,1}n，使 ∑ wixi ≤ W 的前提下 ∑ vixi 最大。"0/1"指物品不可分割，要么整件装入、要么完全不装。该问题是 NP 难的。

定义 2 · 分数背包（松弛问题）

把上述约束中的 xi ∈ {0,1} 放宽为 xi ∈ [0,1]（允许切下一部分装入），所得问题称为分数背包（fractional knapsack），也称 0/1 背包的线性松弛。它可用贪心法在 O(n log n) 内精确求解：按价值密度 vi/wi 从大到小依次整件装入，装不下的最后一件按比例切分填满剩余容量。

定义 3 · 限界函数 bound

设搜索到第 i 层，已装入物品的总重为 cw、总价值为 cv。定义
bound(i, cw, cv) = cv + F(i, W−cw)
其中 F(i, c) 表示"用物品 i, i+1, …, n−1 以分数背包方式装满容量 c 所能获得的最大价值"。由于物品已按密度降序排好，F 可由一趟贪心扫描在 O(n) 内算出。

bound = cv + ∑整件装入的 j vj + vk · (剩余容量 / wk)

限界函数的正确性证明

本节最核心的内容
定理 · bound 是合法上界

若物品已按价值密度 v/w 降序排列，则对解空间树中任一结点 u（对应状态 i, cw, cv），以 u 为根的子树内任何 0/1 可行解的总价值 V 都满足
V ≤ bound(i, cw, cv)。
因此，当 bound(i, cw, cv) ≤ bestV 时剪去该子树，不会丢失最优解。

设 S 是 u 子树内任一可行 0/1 解，其取值为 (yi, …, yn−1) ∈ {0,1}n−i 前 i 项已被 u 固定，贡献恰为 cv V = cv + ∑j≥i vjyj，且 ∑j≥i wjyj ≤ W − cw S 可行 ⇒ 满足容量约束 因 {0,1} ⊂ [0,1]，(yi,…,yn−1) 也是分数背包 F(i, W−cw) 的一个可行解 松弛问题的可行域包含原问题的可行域 ⇒ ∑j≥i vjyj ≤ F(i, W−cw) F 是松弛问题的最优值，不小于任一可行解的值 ⇒ V = cv + ∑j≥i vjyj ≤ cv + F(i, W−cw) = bound   （上界性得证） 两边同加 cv 若 bound ≤ bestV，则 u 子树内任意解 V ≤ bound ≤ bestV 传递性 ⇒ 该子树内不存在严格优于 bestV 的解，剪去它不影响最优值 证毕
引理 · 为什么必须先排序

上述证明的第 4 步用到了"F(i, c) 是松弛问题的最优值"。而代码中的 F 是用贪心一趟扫描算出来的——只有当物品按 v/w 降序排列时，这趟贪心才等于分数背包的最优值；否则它只是某个可行分数解的值，可能严格小于真正的最优值。

不排序的后果（务必记住）：若不排序，算出的 F 偏小 ⇒ bound 偏小 ⇒ 可能出现 bound < V真实最优 的情形。此时 bound ≤ bestV 会把含最优解的子树剪掉，算法照常终止、照常输出一个答案，但答案是错的。这种错误既不崩溃也不报警，是最难排查的一类 bug。第 6 章分支限界法的背包实现正是在此处出过错，请对照记忆：限界函数的合法性依赖于它的计算方式，而计算方式依赖于排序。
性质 · 上界的紧度

bound 与真实最优值之间的差距称为松弛间隙（integrality gap）。分数背包松弛的间隙很小——最多只比 0/1 最优值大"一件物品的价值"。间隙越小，bound 越紧，bound ≤ bestV 越容易成立，剪支越强。这解释了为什么背包问题的回溯法在实际数据上效率极高，往往只需访问几十个结点。

算法实现

C++ · 含 bound 函数
// ── 0/1 背包 · 限界函数回溯（子集树）───────────────── struct Item { int w, v; char name; }; Item it[MAXN]; int n, W; int bestV = 0; // 当前已求得的最优价值 int x[MAXN], bestX[MAXN]; // 当前解 / 最优解 bool cmp(const Item &p, const Item &q) { return (double)p.v / p.w > (double)q.v / q.w; // ★ 价值密度降序 } // 限界函数：cv + 用分数背包填满剩余容量所得的最大价值 double bound(int i, int cw, int cv) { double b = cv; int left = W - cw; // 剩余容量 for (int j = i; j < n && left > 0; j++) { if (it[j].w <= left) { // 整件装得下 ⇒ 全装 left -= it[j].w; b += it[j].v; } else { // 装不下 ⇒ 切一部分填满 b += 1.0 * it[j].v * left / it[j].w; left = 0; // 填满即止，循环结束 } } return b; } void dfs(int i, int cw, int cv) { if (i >= n) { // 叶子：更新最优解 if (cv > bestV) { bestV = cv; memcpy(bestX, x, sizeof(x)); } return; } if (bound(i, cw, cv) <= bestV) return; // ① 限界剪支（最优性） if (cw + it[i].w <= W) { // ② 约束剪支（可行性）：装得下才装 x[i] = 1; dfs(i + 1, cw + it[i].w, cv + it[i].v); x[i] = 0; // 回溯还原 } dfs(i + 1, cw, cv); // 右支：不装 it[i] } int main() { sort(it, it + n, cmp); // ★★ 必须先排序，否则 bound 不是合法上界 ★★ dfs(0, 0, 0); printf("最优价值 = %d\n", bestV); }
两处剪支各司其职：第 ① 处是限界函数（最优性剪支），砍掉"可行但不可能更优"的子树；第 ② 处 cw + wi ≤ W 是约束函数（可行性剪支），只作用于左支——因为不装物品永远不会超重，右支无需检查容量。两者缺一不可：只有 ② 就退化成纯枚举，只有 ① 会输出超重的非法解。

复杂度分析

最坏仍是指数级
排序预处理：Θ(n log n) 一次性开销 解空间是高度 n 的子集树，结点总数 2n+1−1 每件物品装 / 不装 每个结点调用一次 bound，代价 O(n) 最坏要扫完剩余全部物品 ⇒ T(n) = O(n log n) + O(n · 2n) = O(n · 2n) 指数项占主导 构造最坏实例：所有物品密度相同（如 wi = vi = 1）且 ∑wi ≤ W 全部装得下 此时 bound 恒大于 bestV，一次也剪不掉 ⇒ Ω(2n) 剪支完全失效
T最坏(n) = O(n · 2n)  S(n) = Θ(n)  预处理 Θ(n log n)
为什么实际这么快？本页演示中 n = 5，纯枚举需检查 25 = 32 个子集，而带限界的回溯只访问 13 个结点。原因有二：(1) 按密度降序搜索使得"先装密度高的"这条路径很快找到一个接近最优的 bestV，后续剪支立刻变强（这也是排序的第二重好处）；(2) 分数背包松弛的间隙极小，bound 很紧。但请牢记：这只是平均情况的加速，最坏情况的渐进阶不变。
方法时间复杂度空间是否最优适用规模
纯枚举全部子集Θ(n·2n)O(n)是n ≤ 25
回溯 + 限界函数（本节）O(n·2n) 最坏O(n)是n ≤ 40∼50
动态规划（第 7 章）Θ(n·W)O(W)是W 不大时
贪心（分数背包）Θ(n log n)O(1)仅对分数背包最优任意
注意 DP 的 Θ(n·W) 不是多项式复杂度：W 的输入长度是 log W 位，所以 n·W 关于输入规模是指数的，称为伪多项式。0/1 背包仍是 NP 难问题，回溯法与 DP 各有适用区间：n 小而 W 巨大时用回溯，n 大而 W 适中时用 DP。

例题 1

物品数据为 A(w=2,v=6)、B(w=2,v=3)、C(w=6,v=5)、D(w=5,v=4)、E(w=4,v=6)，容量 W = 10。请(1) 按密度排序；(2) 计算根结点的 bound；(3) 求最优解。

排序后序号物品重量 w价值 v密度 v/w是否入选最优解
0A263.00是
1B231.50是
2E461.50是
3C650.83否
4D540.80否
1
根结点的 bound：依次整件装入 A(w2,v6) → B(w2,v3) → E(w4,v6)，已用容量 2+2+4 = 8，累计价值 15，剩余容量 2。下一件 C 的 w = 6 > 2 装不下，切下 2/6 装入，贡献 5 × 2/6 ≈ 1.67。故 bound(0,0,0) = 15 + 1.67 = 16.67。
2
最优解：选 {A, B, E}，总重 8 ≤ 10，总价值 = 6 + 3 + 6 = 15。可以验证 bound = 16.67 ≥ 15，上界性成立；两者之差 1.67 就是本例的松弛间隙。
3
效率对比：限界回溯只访问 13 个结点即可确定最优；纯枚举需检查 32 个子集。请点击上方"▶ 限界回溯"与"纯枚举对比"两个按钮亲自验证这两个数字。
例题 2 · 反面教材

若不排序、直接按输入顺序 A, B, C, D, E 计算 bound，会发生什么？

1
在根结点，贪心扫描顺序变为 A(w2,v6) → B(w2,v3) → C(w6,v5)，容量恰好用满 2+2+6 = 10，得 bound = 6+3+5 = 14。
2
但真实最优值是 15 > 14 —— 所谓的"上界"竟然小于最优值！一旦算法先在别处找到 bestV = 14，根结点就会被 bound ≤ bestV 剪掉，最终输出 14 而不是 15。算法不报错，只是安静地给出错误答案。
3
结论：sort(it, it+n, cmp) 这一行不是"优化"，而是 bound 函数正确性的前提。删掉它，整个算法就从"精确算法"退化成"启发式算法"。
易错点
  • 忘记按 v/w 降序排序。本节头号错误。不排序时贪心扫描算出的不是分数背包最优值，bound 不再是合法上界，会剪掉含最优解的子树，输出错误答案且不报错。
  • 把 bound 的返回类型写成 int。切分那一步 v*left/w 是小数，用 int 会向下取整，把上界压小 —— 同样可能剪掉最优解。必须用 double（或统一乘以分母做整数比较）。
  • 把限界条件写成 bound < bestV 还是 ≤ 分不清。若只需一个最优解，用 ≤ 剪得更狠、更快；若需要列出所有价值同为最优的方案，必须用 <，否则等值的其它最优解会被剪掉。
  • 在右支（不装）也检查容量。不装物品不会增加重量，右支永远可行，多写一次判断无害但说明没理解可行性剪支的作用位置。
  • 剪支方向搞反：写成 bound ≥ bestV 就剪。本题求最大值，bound 是上界，上界大说明还有希望，应当继续搜；只有上界不超过已知最优才剪。最小化问题（如 §09）才是"下界 ≥ best 则剪"。
  • 误以为限界函数把复杂度降到多项式。最坏仍是 O(n·2n)：令所有物品密度相同且总重不超 W，bound 恒大于 bestV，一次也剪不掉。
  • 把回溯法的 bound 当成解本身。bound = 16.67 只是估计值，真实答案是 15；分数背包的解（切开 C）在 0/1 背包中是非法的。
本节小结
  • 限界函数 bound(i, cw, cv) = cv + 用分数背包松弛填满剩余容量所得价值，是子树内 0/1 最优值的上界。
  • 正确性证明：任一 0/1 可行完成方案都是松弛问题的可行解（{0,1} ⊂ [0,1]），故其价值不超过松弛问题的最优值 F，两边加 cv 即得 V ≤ bound。于是 bound ≤ bestV 时子树内不含更优解，剪之无害。
  • 必须先按 v/w 降序排序：只有排序后，贪心一趟扫描算出的 F 才等于分数背包的最优值；否则 F 偏小、bound 不合法，会剪掉最优解且不报错。
  • 算法同时使用两类剪支：左支用约束函数 cw + wi ≤ W（可行性），入口用限界函数 bound ≤ bestV（最优性）。
  • 复杂度：最坏 O(n·2n)（bound 每次 O(n)），空间 Θ(n)，排序 Θ(n log n)。实际数据上剪支极强（本例 13 结点 vs 32 子集），但渐进阶不变。
1某同学实现 0/1 背包的限界回溯时，忘记了按 v/w 降序排序，其余代码完全正确。运行结果最可能是？
A结果仍然正确，只是运行变慢
B程序数组越界或死循环
C可能输出一个偏小的价值，且程序不报任何错误
D输出的价值可能大于真实最优值
解析：选 C。不排序时，bound 里的贪心扫描算出的只是某个可行分数解的值，可能小于分数背包的真正最优值，于是 bound 可能小于子树内真实的 0/1 最优价值——它不再是合法上界。此时 bound ≤ bestV 会把含最优解的子树剪掉，程序正常结束却输出偏小的答案。A 是最常见的误解：排序在这里不是性能优化而是正确性前提（当然它同时也能提升性能，因为能更早找到好的 bestV）。B 错，剪支只会让搜索提前结束。D 方向错了：bestV 始终来自一个真实可行的叶子，绝不可能超过真实最优值；错误只会表现为偏小。
2限界函数正确性证明中，"任一 0/1 可行解的价值 ≤ 分数背包最优值"这一步依据的是？
A贪心算法对 0/1 背包也是最优的
B{0,1} ⊂ [0,1]，故原问题的可行解也是松弛问题的可行解，而最优值不小于任一可行解的值
C分数背包与 0/1 背包的最优值总是相等
D物品按密度降序后，前几件一定都属于最优解
解析：选 B。这是松弛（relaxation）技术的通用逻辑：放宽约束会扩大可行域，因此松弛问题的最优值一定不劣于原问题的最优值，从而可以充当界。A 明确错误——贪心对 0/1 背包不最优，这正是 0/1 背包 NP 难而分数背包多项式可解的分野。C 错，两者一般不相等，其差额正是松弛间隙（本页例子中 16.67 vs 15）；若相等就不需要回溯了。D 是对贪心的过度推广，密度最高的物品完全可能因为太重而不在 0/1 最优解中。
3若题目要求输出所有达到最优价值的装法（而不只是一种），代码需要怎么改？
A无需修改，回溯法天然会遍历所有解
B把剪支条件由 bound ≤ bestV 改成 bound < bestV，并在叶子处用 cv ≥ bestV 收集方案
C去掉限界函数，只保留容量约束
D把 bound 改成返回 int 以便精确比较
解析：选 B。bound ≤ bestV 会把"上界恰好等于当前最优"的子树也剪掉，而这类子树里可能藏着价值同样最优的其它装法。改成严格小于即可保留它们，同时叶子处的更新条件也要从 cv > bestV 放宽为 cv ≥ bestV（并在 cv > bestV 时清空已收集的方案列表）。A 错，正是限界剪支主动丢弃了等值解。C 虽然能得到全部解，但退化为纯枚举 Θ(n·2n)，是"用正确性换效率"的下策，且题目问的是"怎么改"而非"怎么退化"。D 与本题无关，且把 bound 改成 int 会因向下取整而破坏上界性，反而引入新错误。
