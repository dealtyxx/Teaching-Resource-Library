学习目标

  1. 能够陈述回溯法的定义，并说明它与第 3 章穷举法在"何时检验"上的本质差别。
  2. 能够准确定义并区分活结点、扩展结点、死结点，给定一张搜索快照能指出每个结点当前属于哪一类。
  3. 能够默写回溯法的通用递归框架，指出框架中"做选择—剪支—深入—撤销"四个位置。
  4. 能够辨析约束函数与限界函数：前者做可行性剪支，后者做最优性剪支，并说明何种问题需要哪一种。
  5. 能够解释为什么剪支不能降低回溯法最坏情况的指数级复杂度，却能在实际问题上带来数量级的加速。

基本概念

解空间树与三类结点
定义 1 · 解空间树

把问题的解表示成一个 n 元组 (x1, x2, …, xn)，其中 xi 取自有限集合 Si。所有这样的元组构成解空间（solution space）。若用一棵树来组织解空间——根结点表示"尚未做任何选择"，第 i 层的每条向下的边表示为 xi 选定一个具体取值，从根到某个叶子的一条路径就对应一个完整的 n 元组——这棵树称为解空间树（state space tree），也叫状态空间树。

定义 2 · 活结点

活结点（live node）：已经生成、但其子结点尚未全部生成的结点。换言之，这个结点身上还留有"没走完的路"，将来还可能回到它继续往下试。在递归实现中，活结点恰好就是当前递归调用栈上的那些结点。

定义 3 · 扩展结点（E-结点）

扩展结点（expansion node，简称 E-结点）：当前正在生成其子结点的那个活结点。任一时刻有且仅有一个扩展结点，它就是 DFS 递归中最深的那一层，即演示图里被高亮为红色的结点。扩展结点一定是活结点，反之不然。

定义 4 · 死结点

死结点（dead node）：不再进一步扩展的结点。它有三种成因：(1) 其子结点已全部生成完毕，无路可走；(2) 它是叶子结点，已经得到一个完整的候选解；(3) 它被剪支掉了——约束函数或限界函数判定以它为根的整棵子树内不可能出现（更优的）解。死结点一旦产生，搜索立即回溯到它的父结点。

三者的关系：结点的生命周期是「被生成 → 成为活结点 → 被选中成为扩展结点 → 子结点生成完毕（或被剪支）→ 变成死结点」。回溯法之所以叫"回溯"，正是因为一个结点变成死结点后，搜索要沿着来路退回上一层，把上一层重新变成扩展结点。请对照上方演示：红色 = 扩展结点，紫色/绿色 = 还在栈上的活结点，灰色 = 已经变成死结点。

通用算法框架

递归形式 · 教材标配模板
定义 5 · 回溯法

回溯法是一种"能进则进、进不了则换、换不了则退"的系统搜索方法：从根结点出发按深度优先的方式搜索解空间树，每到一个结点先用约束函数和限界函数判断该结点所代表的子树是否可能包含（更优的）解；若不可能，就不再深入而直接回退（剪支），否则继续向下扩展。一句话概括：

回溯法 = 深度优先搜索 + 剪支
// ── 回溯法通用递归框架 ───────────────────────────── // n ：解向量的维数（解空间树的深度） // x[i] ：第 i 层所做的选择，即解向量的第 i 个分量 int n, x[MAXN]; void backtrack(int i) { // i：当前扩展结点所在的层次 if (i >= n) { // ① 到达叶子 → 得到一个完整解 record(x); // 记录/输出，本结点成为死结点 return; // 回溯到父结点 } for (int c = first(i); c <= last(i); c++) { // ② 枚举第 i 层的所有分支 x[i] = c; // ③ 做出选择（置位） if (constraint(i) && bound(i)) // ④ 双重剪支：可行 + 有希望 backtrack(i + 1); // ⑤ 深入下一层 undo(i, c); // ⑥ 撤销选择（回溯还原现场） } // for 循环结束 ⇒ 子结点已全部生成 ⇒ 本结点由活结点变为死结点 } backtrack(0); // 从根结点（第 0 层）启动
1
做选择（第 ③ 步）：把 x[i] 置为本次尝试的分支值，相当于在解空间树上沿一条边向下走一步，新结点成为扩展结点。
2
剪支（第 ④ 步）：这是回溯法区别于纯穷举法的唯一要害。穷举法要走到叶子才检验，回溯法在内部结点就检验，一旦判定无望立即砍掉整棵子树。
3
深入（第 ⑤ 步）：递归调用即"深度优先"。调用栈上的所有结点就是当前的全部活结点。
4
撤销（第 ⑥ 步）：把在第 ③ 步修改过的全局状态恢复原样（如取消标记、减去累计和、swap 换回）。若只用 x[i]=c 这种"覆盖式赋值"而没有共享的全局状态，撤销可以省略，称为隐式回溯；只要动了全局变量就必须显式撤销，否则兄弟分支会读到被污染的现场。
与穷举法对照：把第 ④ 行的剪支条件改成恒为 true，上面的框架就退化成第 3 章的递归穷举——这说明回溯法的解空间与穷举法完全相同，差别只在"提前判死"。

两类剪支函数

约束函数 vs 限界函数 · 全章的钥匙
定义 6 · 约束函数

约束函数（constraint function）用于可行性剪支。它检查当前部分解 (x0, …, xi) 是否违反了问题本身的约束条件。一旦违反，由于后续再怎么选也无法把已经违反的约束"修回来"，该结点子树内不含任何可行解，可以整体剪掉。约束函数针对的是"能不能"。

定义 7 · 限界函数

限界函数（bounding function）用于最优性剪支，只在最优化问题中出现。它计算以当前结点为根的子树内、目标函数所能达到的最好值的界：求最大值问题算上界 bound，求最小值问题算下界 bound。若这个界已经不优于当前已求得的最优值 best，则该子树中不可能出现更优解，可以整体剪掉。限界函数针对的是"值不值"。

求最大值：bound(i) ≤ best ⇒ 剪支  求最小值：bound(i) ≥ best ⇒ 剪支
对比项约束函数 constraint限界函数 bound
剪支类型可行性剪支最优性剪支
判断依据是否违反问题约束目标函数的界是否已不优于 best
剪掉的是不可行的分支可行但不可能更优的分支
适用问题判定问题、求所有解、最优化问题仅最优化问题
是否依赖 best否（静态判定）是（随 best 变优而愈发有效）
本章实例§04 sum>t、§06 邻点同色、§08 对角线冲突§05 分数背包上界、§09 行最小值下界
用错的后果漏解或输出非法解界不合法则丢失最优解
记忆口诀：约束函数管"合法不合法"，限界函数管"值得不值得"。只求可行解的问题（幂集、着色、n 皇后）只需要约束函数；求最优解的问题（背包、任务分配）两者都要，且限界函数才是效率的主要来源。

复杂度分析

为什么剪支救不了最坏情况
设解空间树的深度为 n，每个内部结点的分支数（度）为 d d 由 |Si| 决定 第 k 层的结点数至多为 dk 每层分支数相乘 结点总数 N ≤ 1 + d + d2 + … + dn = (dn+1−1)/(d−1) = Θ(dn) 等比数列求和，d > 1 在每个结点上计算约束函数与限界函数的代价记为 O(p(n)) 通常为 O(1) 或 O(n) ⇒ 总时间 T(n) = O(p(n) · dn) 结点数 × 单结点代价
T(n) = O( p(n) · dn ) —— 子集树 d=2 ⇒ O(p(n)·2n)，排列树 ⇒ O(p(n)·n!)
性质 · 剪支的作用范围

剪支不改变回溯法在最坏情况下的渐进复杂度。因为总存在这样的输入实例，使得所有剪支条件全部失效（例如 0/1 背包中所有物品都装得下、n 皇后中 n 很小时冲突很少），此时算法退化为完全枚举，仍需访问 Θ(dn) 个结点。剪支改善的是平均情况与实际运行时间：它把"实际访问的结点数"从理论上界压下来，这个压缩幅度在真实数据上常常达到几个数量级，但渐进阶不变。

因此：回溯法是求解 NP 难问题的精确算法，它保证找到最优解，代价是最坏情况的指数时间。工程上它适用的规模通常在 n ≤ 30∼50 之间（视剪支强度而定）。若需要处理更大规模，只能转向近似算法或启发式算法。
空间复杂度：回溯法只保存从根到当前扩展结点的这一条路径（即递归栈 + 解向量 x），因此空间为 O(n)（若解向量分量本身是 O(1) 的话）。这正是回溯法相对于第 6 章分支限界法（需要维护整个活结点表，空间可能达到 O(dn)）的最大优势。

例题

用通用框架套一个具体问题
例题 1

给定正整数集合 a = {3, 5, 2, 8, 1, 6} 与目标值 t = 9，用回溯法求出所有和恰为 t 的子集。请指出：(1) 解空间树的类型与规模；(2) 解向量的含义；(3) 约束函数是什么；(4) 是否需要限界函数。

1
解空间树：每个元素只有"选"与"不选"两种可能，d = 2，深度 n = 6，是一棵子集树，叶子数 26 = 64，结点总数 27−1 = 127。
2
解向量：x = (x0, …, x5)，xi ∈ {0, 1}，xi=1 表示选入 a[i]。
3
约束函数：设 sum 为当前已选元素之和、rest 为尚未考虑的元素之和，则 sum > t（已经超了，再加只会更大）或 sum + rest < t（全加上也不够）时剪支。二者都是可行性剪支。
4
限界函数：不需要。本题要求"所有解"而非"最优解"，没有目标函数可言，因此只有约束函数、没有限界函数。这道题的完整代码与动画见 §04 剪支与子集和，答案是 4 个解：{3,6}、{8,1}、{3,5,1}、{2,1,6}。
建模三问：拿到一个新问题，按顺序问自己——① 解能不能写成定长元组？（决定树深）② 每个分量的取值集合有多大？（决定树型：2 → 子集树，m → m 叉树，"剩余未用元素" → 排列树）③ 要求所有解还是最优解？（决定是否需要限界函数）。三问答完，套用上面的框架即可。
易错点
  • 把"活结点"当成"扩展结点"。活结点可以有很多个（整条递归栈），扩展结点任一时刻只有一个。考试中常问"某时刻活结点有几个"，答案是当前路径长度，而不是 1。
  • 以为叶子结点才是死结点。被剪支掉的内部结点同样是死结点——这正是剪支的收益所在，一次剪支可以让整棵子树的结点根本没被生成。
  • 忘记撤销现场。凡是在做选择时修改了共享状态（used[] 标记、累加和、swap 交换），回溯时必须逐一还原。漏掉撤销的典型症状是"只找到第一个解，后面全错"。
  • 混淆约束函数与限界函数。求所有可行解的问题（幂集、着色、n 皇后）没有限界函数；只有带目标函数的最优化问题才谈得上限界。
  • 误以为剪支能把指数级降为多项式级。剪支只压低常数因子与实际结点数，最坏情况仍是 Θ(dn)。若哪道题声称"加了剪支后复杂度变成 O(n2)"，一定是错的。
  • 限界函数取界的方向搞反。最大化问题必须取上界、最小化问题必须取下界；方向反了会剪掉含最优解的分支，得到错误答案却不报错，极难排查。
本节小结
  • 回溯法 = 解空间树上的深度优先搜索 + 剪支，其本质是"边生成边检验、无望就回退"的系统搜索。
  • 活结点是已生成而子结点未全部生成的结点；扩展结点（E-结点）是当前正在生成子结点的那个活结点，任一时刻唯一；死结点是不再扩展的结点，成因为"子结点已生成完"、"是叶子"或"被剪支"。
  • 通用框架四步：做选择 → 剪支判定 → 递归深入 → 撤销选择。改动了全局状态就必须显式撤销。
  • 约束函数做可行性剪支（管合法性），限界函数做最优性剪支（管优劣，仅用于最优化问题）。这是理解后续 §04、§05、§09 的前提。
  • 时间复杂度 T(n) = O(p(n)·dn)，剪支不改变最坏情况的指数阶，只改善实际结点数；空间复杂度仅 O(n)。
1在回溯法的某一时刻，从根结点到当前正在处理的结点的路径长度为 5（含根共 6 个结点）。此时活结点与扩展结点的个数分别是？
A活结点 1 个，扩展结点 6 个
B活结点 6 个，扩展结点 1 个
C活结点 5 个，扩展结点 5 个
D活结点与扩展结点都是 6 个
解析：选 B。递归栈上的 6 个结点都是"已生成但子结点尚未全部生成"的结点，全部是活结点；而扩展结点按定义是"当前正在生成其子结点"的那一个，任一时刻有且仅有一个，即路径最深处的那个结点。A 把两者的数量对调了；C 漏掉了根结点，且错误地认为多个结点可以同时扩展；D 混淆了"扩展结点是活结点的子集"这一包含关系——扩展结点一定是活结点，但活结点不一定是扩展结点。
2下列关于约束函数与限界函数的说法，正确的是？
A两者都用于排除不满足问题约束条件的分支，只是叫法不同
B求图的 m 着色方案数时，必须同时使用约束函数和限界函数
C限界函数剪掉的分支中可能存在可行解，但这些可行解都不会优于当前最优解
D限界函数的值越紧（越接近真实最优值），剪支越少，算法越慢
解析：选 C。这正是最优性剪支与可行性剪支的关键差别：约束函数剪掉的子树里一个可行解都没有；限界函数剪掉的子树里可能有大量可行解，只是它们的目标值都不可能超过已知的 best，所以丢掉无害。A 错在把两者混为一谈，约束函数管合法性、限界函数管优劣。B 错在 m 着色只要求可行方案、没有目标函数，因此没有限界函数。D 说反了：界越紧，bound 越接近真实最优值，越容易触发"bound 不优于 best"的条件，剪支越多、算法越快；界越松（如取 +∞）则一次也剪不掉。
3某同学给 0/1 背包的回溯算法加了很强的限界函数，实测 n=40 时只访问了约 3000 个结点。他据此断言"该算法的时间复杂度是 O(n2)"。这一断言的错误在于？
A没有错，实测数据就是复杂度的依据
B错在应该算成 O(n3)，因为 3000 ≈ 403/20
C复杂度描述的是最坏情况，而总存在使所有剪支失效的实例，此时仍需访问 Θ(2n) 个结点
D错在限界函数本身的计算耗时被忽略了，加上后应为 O(n·2n) 的常数倍
解析：选 C。渐进复杂度是对所有规模为 n 的输入取最坏值，不能由某一组"好数据"的实测反推。对 0/1 背包，只要构造出所有物品都能装下、且价值密度全部相等的实例，限界函数给出的上界将始终大于 best，一次也剪不掉，算法退化为访问全部 Θ(2n) 个结点。A 混淆了实测性能与渐进上界；B 只是在凑数字，没有任何理论依据；D 指出的"忽略了 bound 的计算代价"确实是个疏漏（它会带来 O(n) 的因子），但这只是次要问题，根本错误在于用单个实例的结点数冒充最坏情况的阶。
