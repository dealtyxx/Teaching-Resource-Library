全排列 · 交换法

—

学习目标

  1. 能够刻画排列树的结构：树深、各层分支数、叶子数与结点总数，并说明它与子集树的本质区别。
  2. 能够默写交换法（swap 法）生成全排列的递归框架，指出"做选择—递归深入—撤销现场"分别对应哪两次 swap。
  3. 能够论证交换法为何天然保证"各位置元素互不相同"，从而不需要显式的重复性约束函数。
  4. 能够推导全排列问题的时间复杂度 O(n·n!) 与空间复杂度 O(n)。
  5. 能够对比交换法与标记数组法（used[]）在输出顺序与现场维护上的差异。

一、排列树与交换法

解向量 · 分支结构 · 现场维护
定义 1 · 排列树

当解向量 (x0, …, xn-1) 的各分量取自同一集合且要求两两不同（即一个解就是 n 个元素的某个排列）时，其解空间树称为排列树（permutation tree）。根到叶的每条路径对应一个排列：根有 n 个分支，第 1 层每个结点有 n−1 个分支，……第 i 层每个结点有 n−i 个分支。因此叶子数为 n!，恰是 n 个元素的全排列个数。与子集树"每个元素选/不选、分支数恒为 2"不同，排列树的分支数逐层递减。

定义 2 · 交换法的循环不变式

交换法用一个共享数组 a[] 就地生成排列。递归进入 perm(i) 时始终维持不变式：a[0..i−1] 是已经定好的前缀，a[i..n−1] 恰是尚未使用的全部元素（顺序任意）。第 i 层的 for 循环 for j=i..n−1 依次把 a[j] 交换到位置 i，就等价于"让第 i 位取遍所有剩余元素"。正因为候选只在 a[i..n−1] 中选取，已用元素绝不会被重复放置——这就是排列树无需显式约束函数的原因。

// ── 排列树 · 交换法生成 1..n 的全排列 ───────────── // a[] ：待排列元素，初值 a[k] = k+1；n：元素个数 int n, a[MAXN]; void perm(int i) { // i：当前要确定第 i 个位置的元素 if (i >= n) { // ① 前 n 位都定好 → 得到一个排列 for (int k = 0; k < n; k++) cout << a[k] << ' '; cout << '\n'; return; } for (int j = i; j < n; j++) { // ② 让 a[i] 依次取遍 a[i..n-1] swap(a[i], a[j]); // ③ 做选择：把 a[j] 换到第 i 位 perm(i + 1); // ④ 递归深入，确定后续位置 swap(a[i], a[j]); // ⑤ 撤销：换回，恢复剩余元素集合 } } perm(0); // 从第 0 位启动
第 ⑤ 步不可省：交换法修改的是共享数组 a[]，属于"动了全局状态"。若省掉换回，进入下一轮 j 时 a[i..n−1] 已被打乱、剩余元素集合被污染，会漏排列且产生重复。这与幂集"覆盖式赋值 x[i]=0/1 可免撤销"（隐式回溯）形成鲜明对照。

二、复杂度与两种实现

O(n·n!) · swap 法 vs 标记法
排列树叶子数 = n!，每个叶子对应一个完整排列 各层分支数 n, n−1, …, 1 连乘 结点总数 N = n!·∑m=0n 1/m! ≈ e·n! = Θ(n!) m=n−i，级数收敛到 e≈2.718 每到一个叶子需 O(n) 时间输出/复制该排列 解向量长度为 n ⇒ 时间 T(n) = Θ(n!)·O(n) = O(n·n!) 叶子数 × 单叶代价（内部结点的 swap 是 O(1)，被叶子输出主导） 递归深度 ≤ n，全程只用一份共享数组 a[] ⇒ 空间 O(n) 就地交换，不为分支复制数组
对比项交换法 swap标记数组法 used[]
候选来源剩余元素 a[i..n−1]值 1..n 中 used[v]==false 者
去重方式结构性保证（不会选到已用元素）显式 used[] 标记
输出顺序非字典序（取决于 swap 打乱）字典序（值从小到大枚举）
额外空间O(1)（就地）O(n)（used 数组 + x 解向量）
撤销操作swap 换回（必需）used[v]=false（必需）
时间复杂度O(n·n!)O(n·n!)
选择建议：只要求"生成全部排列、顺序无所谓"用交换法最省（就地、无需 used）；若要求字典序输出或需要"当前值是否已用"的快速判断，用标记法更自然。n 皇后（§08）正是在交换法骨架上加一个对角线约束函数 valid()，把排列树剪成 n 皇后的解空间树。
易错点
  • 把排列树当成子集树。子集树分支数恒为 2、深度 n、叶子 2n；排列树分支数逐层从 n 递减到 1、叶子 n!。二者结点规模完全不同。
  • 循环写成 for j=0..n−1。必须从 j=i 起。若从 0 起，会把已固定的前缀 a[0..i−1] 也换进来，破坏不变式，产生重复且残缺的"排列"。
  • 忘记第 ⑤ 步换回。交换法动了共享数组，撤销是强制的；漏掉会污染兄弟分支的剩余元素集合，典型症状是"只有第一条排列对，后面全乱"。
  • 误以为交换法输出是字典序。交换法的顺序由 swap 决定，通常不是字典序；要字典序须改用标记法（值从小到大枚举）或对结果排序。
  • 给纯全排列强行加"约束函数"去重。排列树的互异性由"只从剩余元素中选"结构性保证，不存在也不需要重复性约束函数；约束函数只在具体问题（如 n 皇后对角线冲突）里才出现。
  • 断言"加剪支后复杂度低于 O(n!)"。输出全部 n! 个排列本身就需要 Ω(n!) 下界，最坏情况无法突破；剪支只在带约束的派生问题（n 皇后）里减少实际访问的结点数。
本节小结
  • 排列树：解为 n 元素排列时的解空间树，第 i 层分支数 n−i，叶子 n!，结点总数 Θ(n!)。
  • 交换法：for j=i..n−1: swap(a[i],a[j]) → perm(i+1) → swap 换回，靠"只从剩余元素 a[i..n−1] 中选"结构性保证互异，无需显式约束函数。
  • 两次 swap 分别是做选择与撤销现场；因修改共享数组，撤销强制不可省。
  • 时间复杂度 O(n·n!)（n! 个叶子、每叶 O(n) 输出），空间复杂度 O(n)（就地交换 + 递归深度）。
  • 交换法输出非字典序、O(1) 额外空间；标记法用 used[] 输出字典序、O(n) 额外空间；n 皇后即在交换法上加对角线约束。
1用交换法生成 1…n 的全排列，其解空间树是排列树。当 n=4 时，叶子数与"访问到叶子时的输出总代价"分别是？
A叶子 24=16，输出代价 O(24)
B叶子 4!=24，输出全部排列代价 O(4·4!)=O(96)
C叶子 4!=24，输出代价 O(4!)=O(24)
D叶子 44=256，输出代价 O(4·44)
解析：选 B。排列树叶子数是全排列个数 n!=4!=24（A 把它当成子集树 2n、D 当成 nn 都错）。每到一个叶子要把长度为 n=4 的排列输出一遍，代价 O(n)，共 n! 个叶子，故总输出代价 O(n·n!)=O(4·24)=O(96)。C 漏掉了"每个排列输出需 O(n)"这个因子，把总代价错算成 O(n!)。
2若把交换法框架中的第 ⑤ 步 swap(a[i], a[j])（换回）删掉，程序行为会怎样？
A无影响，输出依然是全部 n! 个正确排列，只是顺序变了
B会正确输出，但时间复杂度上升到 O(n·n!2)
Ca[i..n−1] 的剩余元素集合被污染，导致漏排列并出现重复/非法输出
D程序死循环，永远无法结束
解析：选 C。交换法修改的是共享数组 a[]，属于"改动了全局状态"，撤销是强制的。不换回时，进入同一层的下一个 j 之前，a[i..n−1] 已经被上一分支永久打乱，"剩余元素恰为未使用元素"的循环不变式被破坏，于是既会漏掉某些排列、又会重复或输出非法结果。递归深度仍受 i<n 控制，不会死循环（D 错）；A、B 都错在以为撤销可省。
3关于交换法与标记数组法（used[]）生成全排列，下列说法正确的是？
A两者输出顺序相同，都保证字典序
B交换法需要 O(n) 的 used 数组，标记法则不需要任何额外空间
C标记法按值从小到大枚举，输出字典序；交换法输出通常非字典序
D标记法可以省去撤销操作，交换法则必须撤销
解析：选 C。标记法在每层从值 1 到 n 顺序枚举未用元素，天然产生字典序；交换法把候选元素 swap 到位，顺序被打乱，通常非字典序。A 错在说两者顺序相同。B 把两者的空间说反了：标记法才需要 O(n) 的 used[] 数组，交换法是就地操作、额外空间 O(1)。D 错在两者都必须撤销——标记法要 used[v]=false、交换法要 swap 换回，凡改动共享状态都得恢复现场。
