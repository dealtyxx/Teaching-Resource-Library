学习目标

  1. 能够把任务分配（指派）问题建模为排列树上的最优化搜索，写出目标函数 min Σ C[i][x[i]]。
  2. 能够构造并证明本问题的限界函数（下界）：已用成本 + 后续各行未用列最小值之和，说明它为何不会高估真实完成成本。
  3. 能够写出最小化问题的剪支判据 bound ≥ best ⇒ 剪支，并解释它与最大化问题取上界的对称性。
  4. 能够对比限界回溯与纯全排列枚举在访问结点数上的差距，理解"好的 best 值使限界更有效"。
  5. 能够指出限界方向取反（最小化误用上界）会静默丢失最优解，属最难排查的错误。

一、问题建模

指派问题 · 排列树 · 目标函数
定义 1 · 任务分配问题

有 n 个人与 n 项任务，把第 i 个人指派给任务 j 的成本为 C[i][j]。要求给每人分配互不相同的一项任务（即一个一一对应），使总成本最小。解向量 x = (x0, …, xn-1) 中 xi 表示第 i 个人所分到的任务号，且 x 必须是 {0,…,n−1} 的一个排列。因此解空间是一棵排列树，叶子数 n!。

目标：minx ∈ 排列 Σi=0n−1 C[i][x[i]]
与 §07 的关系：任务分配就是"带目标函数的全排列问题"。§07 只是枚举全部排列；这里要在排列中挑成本最小的那个。这一步之差，正是约束函数问题升级为限界函数问题的分水岭。

二、限界函数（下界）

为什么行最小值之和不会高估
定义 2 · 限界函数

设已给前 i 个人分配完毕、累计成本为 cost，已用任务集合为 used。对还没分配的每一行 r（r = i, …, n−1），它最终必须落到某个尚未使用的列上，其成本至少是该行在未用列中的最小元。于是定义下界：

bound = cost + Σr=in−1 min{ C[r][j] : j 未被使用 }
真实完成成本 = cost + Σr=in−1 C[r][xr]，其中 xr 是某个未用列 每行必占一个不同的未用列 对每一行 r：C[r][xr] ≥ min{未用列的 C[r][j]} 最小元不大于任何具体取值 逐行求和：Σ C[r][xr] ≥ Σ 行最小元 不等式可加 ⇒ bound ≤ 真实完成成本，下界永不高估 这就是"可采纳/admissible"下界 该估计放松了"各行占用列互不相同"的约束（允许两行取同一最小列），松弛只会让界更小，仍是合法下界 松弛 = 去掉部分约束求更易算的界
// ── 任务分配 · 限界回溯（最小化）──────────────── int n, C[N][N], best = INF, x[N], bestx[N]; bool used[N]; int bound(int cost, int i) { // 下界 = 已用成本 + 后续各行未用列最小值之和 int lb = cost; for (int r = i; r < n; r++) { int mn = INF; for (int j = 0; j < n; j++) if (!used[j]) mn = min(mn, C[r][j]); lb += mn; } return lb; } void dfs(int i, int cost) { // i：正在给第 i 个人分配；cost：前 i 人累计成本 if (i >= n) { // 叶子 → 一个完整分配方案 if (cost < best) { best = cost; copy(x, bestx); } return; } for (int j = 0; j < n; j++) if (!used[j]) { used[j] = true; x[i] = j; // 做选择 int nc = cost + C[i][j]; if (bound(nc, i + 1) < best) // 限界剪支：下界 ≥ best 则整支砍掉 dfs(i + 1, nc); used[j] = false; // 撤销（回溯还原 used） } }
最小化：bound ≥ best ⇒ 剪支  （对偶）最大化：bound ≤ best ⇒ 剪支
方向绝不能反：最小化问题必须用下界，且当 下界 ≥ 当前最优 best 时才可剪。若误用上界或把判据写成 bound ≤ best，就可能把含最优解的子树剪掉，程序不报错却给出错误答案——这是最优性剪支最隐蔽的 bug。

三、限界 vs 枚举

同样 n!，实际结点差一个数量级
排列树叶子 n!，纯枚举访问全部叶子 ⇒ Θ(n!) 个完整方案 "全排列枚举"按钮的行为 限界回溯在内部结点用 bound 判死，大量子树未生成即被剪 bound ≥ best 的分支整支跳过 单结点 bound 计算 O(n2)（n 行 × 扫 n 列取最小） 这是限界的额外常数开销 最坏时间仍 O(n!·n2)：存在使 bound 始终 < best 的实例，一次也剪不掉 剪支不改指数阶 越早得到小的 best，bound ≥ best 越易成立、剪支越猛 ⇒ 好的初始解是加速关键 可先用贪心求一个 best 初值
本页对照实验：对示例 4×4 矩阵，两种方法都给出最优成本 13（分配 x=(1,0,2,3)），但"限界回溯"访问的结点数明显少于"全排列枚举"的 24 个叶子——点两个按钮对比 访问结点 计数即可直观看到限界的收益。
易错点
  • 限界方向取反。最小化用下界、最大化用上界；方向反了会剪掉含最优解的分支，得到错误答案且不报错，极难排查。
  • 剪支判据写反。最小化是 bound ≥ best 剪支（即只在 bound < best 时深入）。写成 bound ≤ best 会把好分支全剪掉。
  • 下界取得"太紧以致高估"。限界函数宁松勿紧到越界：只要出现一次 bound > 真实完成成本，就可能误剪最优解。行最小值和之所以安全，正因它是松弛下界，永不高估。
  • 忘记撤销 used[]。used[j] 是共享状态，回溯时必须 used[j]=false 还原，否则后续兄弟分支会误以为该列已被占。
  • 把它当成只需约束函数的问题。任务分配有目标函数，是最优化问题，约束函数（列互异）与限界函数（下界）两者都要；只有限界函数才带来数量级加速。
  • 误以为限界把复杂度降为多项式。最坏仍 O(n!·n2)；限界只压低平均/实际结点数。指派问题若要多项式精确解应用匈牙利算法 O(n3)，那是另一套方法。
本节小结
  • 建模：任务分配 = 排列树上最小化 Σ C[i][x[i]]，是"带目标函数的全排列"，属最优化问题。
  • 限界函数（下界）= 已用成本 + 后续各行未用列最小值之和；它是松弛下界，永不高估真实完成成本，因而可安全用于剪支。
  • 剪支判据：最小化 bound ≥ best 剪支（只在 bound < best 时深入）；最大化对偶为 bound ≤ best 剪支。方向与判据都不可写反。
  • 约束 + 限界缺一不可：列互异靠约束（used[]），效率靠限界；越早得到小 best 剪支越有效。
  • 最坏复杂度仍 O(n!·n2)，限界只降实际结点数；示例矩阵最优成本 13。
1任务分配（最小化）中，限界函数取"已用成本 + 后续各行未用列最小值之和"。它为何是一个合法的可用于剪支的界？
A因为它恰好等于真实完成成本，估计毫无误差
B因为每行真实成本 ≥ 该行未用列最小元，求和后该界 ≤ 真实完成成本，是不高估的下界
C因为它是真实完成成本的上界，最小化问题用上界剪支
D因为它总是大于 best，从而能剪掉所有分支
解析：选 B。最小化问题需要一个不高估的下界：每个未分配行最终占某未用列，其成本不小于该行在未用列上的最小元，逐行求和便得 bound ≤ 真实完成成本。因此若连这个乐观下界都已 ≥ best，真实成本更不可能优于 best，可安全剪掉。A 错在它一般严格小于真实成本（允许多行取同一最小列，是松弛）；C 把下界说成上界、方向全反；D 是无稽之谈，界若恒大于 best 则连最优解也被剪。
2某同学把最小化任务分配的剪支条件写成"当 bound ≤ best 时剪支"。会发生什么？
A没问题，效果与 bound ≥ best 剪支等价
B恰好剪掉最有希望（下界更小）的分支，会漏掉最优解甚至找不到任何解
C只是变慢，答案仍然正确
D会导致数组越界崩溃
解析：选 B。正确判据是 bound ≥ best 才剪（下界已不优于当前最优，才没希望）。写成 bound ≤ best 恰好相反：下界越小说明越有希望，却被当作"该剪"砍掉，于是最有前途的分支全被误杀，最优解被漏掉。C 错在这不是变慢而是结果错误；D 与判据方向无关，不会越界。
3关于限界回溯与全排列枚举在任务分配上的比较，错误的是？
A两者的解空间都是排列树，叶子数都是 n!
B越早得到较小的 best，限界函数越容易触发剪支，搜索越快
C加入限界函数后，最坏时间复杂度从 O(n!) 降为多项式 O(n2)
D限界回溯在每个结点多花 O(n2) 计算下界，但通常靠剪支省下的结点数远超这点开销
解析：选 C（错误项）。限界不改变最坏复杂度阶：总存在使 bound 始终小于 best、一次也剪不掉的实例，此时仍需访问 Θ(n!) 个结点，加上每结点 O(n2) 的界计算，最坏为 O(n!·n2)，仍是指数级。若要多项式精确求解指派问题，应改用匈牙利算法 O(n3)。A、B、D 均正确，其中 B、D 点出了限界的收益与代价的权衡。
