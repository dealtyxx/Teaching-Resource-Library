学习目标

  1. 能够把 n 皇后问题建模为解向量 q[0..n−1]，说明"用行下标做维度、列号做取值"如何自动消去行冲突。
  2. 能够推导并默写对角线冲突的判定式 |q[i]−q[k]| = |i−k|，解释为什么它同时覆盖两条对角线。
  3. 能够写出 n 皇后的约束函数 place()，并说明本问题只有约束函数、没有限界函数的原因。
  4. 能够对比两种解空间组织：n 叉树（q[i]∈{0..n−1}）与排列树（列的排列），指出各自还需检查哪些冲突。
  5. 能够说出n 皇后解的规模特征（如 4 皇后 2 解、8 皇后 92 解，且解数随 n 非单调）与最坏情况的指数复杂度。

一、问题建模与三类冲突

行 / 列 / 对角线
定义 1 · 解向量

在 n×n 棋盘上放 n 个皇后，使任意两个不在同一行、同一列或同一对角线上。关键建模：既然每行恰好放一个皇后，就用行下标 i 作为解向量的维度，用 q[i] ∈ {0,1,…,n−1} 表示第 i 行皇后所在的列。这样解就是定长向量 q = (q0, …, qn-1)，且"每行一个皇后"被建模天然满足——剩下只需排除列冲突与对角线冲突。

定义 2 · 对角线冲突判定

第 i 行、第 k 行的两个皇后位于坐标 (i, q[i]) 与 (k, q[k])。它们在同一条对角线上，当且仅当"行差的绝对值等于列差的绝对值"：

同列：q[i] = q[k]  同对角线：|q[i] − q[k]| = |i − k|
为什么一条式子能同时管两条对角线？主对角线（↘）上 行−列 为常数 ⇒ i−q[i]=k−q[k] ⇒ i−k=q[i]−q[k]；副对角线（↙）上 行+列 为常数 ⇒ i+q[i]=k+q[k] ⇒ i−k=q[k]−q[i]。两种情形合并即 |i−k|=|q[i]−q[k]|。
对照演示：上方公式牌写的正是 |q[k]−q[i]| ≠ |i−k|（不冲突的条件）。放置第 k 行皇后时，只要它与前面每一行都满足该不等式且不同列，即为合法。

二、回溯算法与约束函数

只需约束，不需限界
// ── n 皇后 · 逐行放置的回溯算法 ─────────────────── // q[i]：第 i 行皇后所在的列；n：皇后数 = 棋盘阶数 int n, q[MAXN], cnt = 0; bool place(int k) { // 约束函数：第 k 行是否与前 k 行冲突 for (int i = 0; i < k; i++) if (q[i] == q[k] || abs(q[i]-q[k]) == abs(i-k)) // 同列 或 同对角线 return false; return true; } void queen(int k) { // 逐行放置，k 为当前行（扩展结点层次） if (k >= n) { cnt++; record(q); return; } // n 行放满 → 得到一个解 for (int c = 0; c < n; c++) { // 枚举第 k 行的每一列 q[k] = c; // 做选择 if (place(k)) // 约束剪支：合法才深入 queen(k + 1); // 递归放下一行 } // c 循环靠覆盖式赋值 q[k]=c，无需显式撤销 }
性质 · 为什么没有限界函数

n 皇后是一个判定/枚举问题——目标是"找出所有合法布局"或"找到任一解"，没有目标函数可优化。因此它只需要管"合法不合法"的约束函数 place()，而不存在管"值得不值得"的限界函数。限界函数只在带目标函数的最优化问题（如下一节的任务分配、第 6 章的背包/TSP）里才出现。

两种解空间组织（本页两个按钮的差别）：「搜索过程」按 q[i]∈{0..n−1} 组织成n 叉树，place() 需同时查列冲突和对角线冲突；「轮播解」用交换法把列做成一个排列（排列树），列冲突已被结构性排除，valid() 只需查对角线 |q[k]−q[i]|=i−k。两者殊途同归。

三、复杂度与解的规模

指数级 · 解数非单调
若视作 q[i]∈{0..n−1} 的 n 叉树，结点上界 O(nn) 深度 n、每层 n 个分支 列冲突约束把"可延伸到叶子"的路径压到列的排列，即至多 n! 条 不同列 ⇔ 列号是一个排列 对角线约束在 n! 之上进一步剪支，实际访问结点远少于 n! 大量部分布局提前被判死 每个结点 place() 检查 O(n)，故最坏时间 O(n·n!) 量级，随 n 指数增长 剪支只降常数与实际结点数，不改指数阶 空间 O(n)：只存一条根到当前行的路径 q[] 与递归栈 回溯法的固有优势

注意解数的非单调：6 皇后只有 4 个解，反而少于 5 皇后的 10 个。解的数量由对角线约束的组合结构决定，不随 n 单调增长；不能想当然认为"棋盘越大解越多"。8 皇后的 92 解是最常考的数字（其中本质不同的只有 12 个，其余为旋转/镜像）。
易错点
  • 对角线判定写错。正确式是 |q[i]−q[k]| = |i−k|（行差绝对值 = 列差绝对值）。漏掉绝对值就只判了一条对角线，会漏掉另一条方向上的冲突。
  • 误以为 n 皇后需要限界函数。它是求可行解/全部解的问题，没有目标函数，只用约束函数 place()；把它和最优化问题混为一谈是概念性错误。
  • 用排列树时还去重复查同列。交换法生成列的排列已结构性保证不同列，此时只需查对角线；若用 n 叉树组织，才必须同时查列与对角线。
  • "找一个解"与"找全部解"的收尾写反。找任一解时递归应短路返回（if(...&&dfs(k+1)) return true;）；找全部解时到叶子只 cnt++/record 后 return 继续枚举，不可提前 return true。
  • 认为解数随 n 单调递增。反例：6 皇后 4 解 < 5 皇后 10 解。解数由组合结构决定，非单调。
  • 断言剪支把复杂度降为多项式。最坏情况仍是指数级；总能构造使约束很晚才触发的规模，剪支只改善实际结点数与常数因子。
本节小结
  • 建模：q[i]=第 i 行皇后的列号，行冲突被"每行一个"天然消去，只剩列冲突 q[i]=q[k] 与对角线冲突 |q[i]−q[k]|=|i−k|。
  • 对角线判定一式两用：主对角线 行−列 恒定、副对角线 行+列 恒定，合并即 |i−k|=|q[i]−q[k]|。
  • 只用约束函数 place()、无限界函数：n 皇后是枚举/判定问题，无目标函数可优化。
  • 解空间可组织成 n 叉树（查列+对角线）或 排列树（列冲突自动排除，只查对角线）；时间最坏指数级，空间仅 O(n)。
  • 解数非单调：4→2、5→10、6→4、7→40、8→92（8 皇后 92 解须记牢）。
1第 2 行皇后在第 5 列、第 5 行皇后在第 8 列（下标从 0 计，即 i=2,q[i]=5 与 k=5,q[k]=8）。这两个皇后是否冲突？
A不冲突，列号 5≠8，行号 2≠5
B冲突，因为 |q[i]−q[k]|=|5−8|=3=|2−5|=|i−k|，在同一对角线上
C不冲突，因为对角线只看 q[i]+q[k] 是否相等
D无法判断，还需要知道棋盘阶数 n
解析：选 B。虽然不同行、不同列，但 |i−k|=|2−5|=3，|q[i]−q[k]|=|5−8|=3，两者相等，说明二者行差等于列差，位于同一条对角线，冲突。A 只查了行、列忽略了对角线；C 把判定式记成"列号之和相等"是错的（正确是行差绝对值=列差绝对值）；D 错在对角线判定与 n 无关，只看两皇后的相对坐标。
2关于 n 皇后回溯算法中的剪支函数，正确的说法是？
A既要用约束函数排除冲突，也要用限界函数剪掉"皇后个数偏少"的分支
B只需约束函数 place()；n 皇后无目标函数，不存在限界函数
C只需限界函数，约束由排列树结构自动完成，无需额外判断
D约束函数和限界函数在 n 皇后里是同一个函数的两个名字
解析：选 B。限界函数用于最优性剪支，只在有目标函数的最优化问题里出现；n 皇后要"找出所有合法布局"，没有任何值要最大化或最小化，因此不存在限界函数，只有做可行性剪支的约束函数 place()。A、D 都错把限界函数强加进来；C 错在即便用排列树也仍需 valid() 查对角线冲突，约束判断不能省。
3用交换法把列做成排列来求 n 皇后（本页"轮播解"按钮的做法），下列判断正确的是？
A此时约束函数需同时检查列冲突与对角线冲突
B列冲突被排列结构自动排除，约束函数只需检查对角线冲突
C排列树的叶子数是 nn，比 n 叉树更多
D用排列树后就不再需要撤销现场
解析：选 B。交换法生成的是列号的一个排列，任意两行的列号必然不同，列冲突被结构性排除，故 valid() 只剩下检查对角线 |q[k]−q[i]|=i−k 一项。A 多此一举；C 说反了——排列树叶子是 n!，少于 n 叉树的 nn；D 错在交换法修改共享数组 q[]，swap 后必须换回，撤销不可省。
