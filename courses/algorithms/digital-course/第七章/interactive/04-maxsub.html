① 状态定义

State Definition
状态定义

dp[i] 表示在所有以 a[i] 为最后一个元素的连续子段中，元素之和的最大值（i = 0, 1, …, n−1）。
注意三个要点：① 子段必须连续；② 必须以 a[i] 结尾，即 a[i] 一定被选；③ 起点位置不限。

为什么必须「以 a[i] 结尾」而不是「前 i 个的答案」

若定义 g[i] = 前 i 个元素中的最大子段和，则 g[i] 与 g[i−1] 之间无法直接转移：要判断 a[i] 能否接到某个子段后面，必须知道「那个子段是否恰好在 i−1 处结束」，而 g[i−1] 里没有这个信息——这就是有后效性。
加上「以 a[i] 结尾」这个约束后，dp[i−1] 恰好携带了「一个在 i−1 处结束的最优子段」，a[i] 就能无歧义地接上去，无后效性得以满足。
代价是答案不在 dp[n−1]，而是 max0≤i<n dp[i]。这是「限制结尾位置」这类状态设计的通用套路，LIS 同理。

② 状态转移方程 ③ 边界 ④ 计算顺序

Transition
dp[i] = a[i]　　　　　　　当 dp[i−1] ≤ 0
dp[i] = dp[i−1] + a[i]　当 dp[i−1] > 0

合并写成一行即为：dp[i] = max( a[i], dp[i−1] + a[i] ) = a[i] + max(0, dp[i−1])。

决策的含义

处理到 a[i] 时只有两个选择：
· 接在后面——把 a[i] 拼到「以 a[i−1] 结尾的最优子段」之后，得 dp[i−1] + a[i]；
· 另起炉灶——丢弃前面所有元素，从 a[i] 重新开始，得 a[i]。
关键洞察：只要 dp[i−1] ≤ 0，把它带上就是纯粹的拖累，一定要另起炉灶。这也是 Kadane 算法「前缀和一变负就清零」的直觉来源。

边界条件

dp[0] = a[0]（第一个元素前面无物可接）。
等价写法：引入虚拟的 dp[−1] = 0 并使用 dp[i] = a[i] + max(0, dp[i−1])，此时 i 可从 0 统一开始，代码更简洁。

计算顺序 · 答案位置

dp[i] 只依赖 dp[i−1]，故 i 从 0 递增到 n−1 单趟扫描即可。
答案 ans = max0≤i<n dp[i]，需要在扫描过程中同步维护全局最大值，而不是最后取 dp[n−1]。

③ 例题演算 · A = [−2, 1, −3, 4, −1, 2, 1, −5, 4]

Worked Example

④ C++ 代码

Implementation
// 版本一：标准 DP 填表，Θ(n) 时间 / Θ(n) 空间 int maxSubSum(const vector<int>& a) { int n = a.size(); vector<int> dp(n); dp[0] = a[0]; // 边界 int ans = dp[0]; for (int i = 1; i < n; ++i) { dp[i] = max(a[i], dp[i - 1] + a[i]); // 转移 ans = max(ans, dp[i]); // 答案是整张表的最大值 } return ans; }
// 版本二：Kadane 滚动变量，Θ(n) 时间 / Θ(1) 空间，并记录最优子段起止下标 int kadane(const vector<int>& a, int& bestL, int& bestR) { int n = a.size(); int cur = a[0], ans = a[0]; // cur 即 dp[i] int curL = 0; // 当前子段的起点 bestL = bestR = 0; for (int i = 1; i < n; ++i) { if (cur <= 0) { cur = a[i]; curL = i; } // 另起炉灶：起点重置 else cur += a[i]; // 接在后面：起点不变 if (cur > ans) { ans = cur; bestL = curL; bestR = i; } } return ans; } // 调用示例：a = {-2,1,-3,4,-1,2,1,-5,4} // 返回 6，bestL = 3，bestR = 6，即子段 [4,-1,2,1]
记录下标的要点：起点 curL 只在「另起炉灶」的那一刻更新；而 bestL/bestR 只在刷新全局最优时才拷贝。若把 bestL 直接写成 curL 的同步赋值，遇到「当前段变大但还没超过历史最优」的情况就会记错区间。

⑤ 复杂度分析

Complexity
解法思路时间空间
枚举全部子段枚举起点 i、终点 j，再累加求和O(n3)O(1)
枚举 + 前缀和枚举 i、j，用 sum[j]−sum[i−1] 求和O(n2)O(n)
分治法（第 4 章）左半 / 右半 / 跨中点三者取大O(n log n)O(log n) 栈
动态规划（Kadane）dp[i] = max(a[i], dp[i−1]+a[i])Θ(n)Θ(1)
与分治法的对比（呼应第 4 章 06-maxsub）

分治法把数组从中点劈开，递归求左半最大子段和、右半最大子段和，再额外花 O(n) 求「必过中点」的最大子段和，三者取最大。递推式 T(n) = 2T(n/2) + Θ(n)，由主定理得 T(n) = Θ(n log n)。
动态规划之所以更快，是因为它换了一个划分子问题的角度：分治按位置对半切，跨界情形必须单独花 O(n) 处理；DP 按「子段的结尾在哪」划分，任意子段都恰好属于唯一一类，不存在跨界情形，于是每个状态的转移降为 O(1)。
一句话：分治的代价花在「合并」，DP 通过更聪明的状态定义把合并代价消灭了。

⑥ 特殊情形 · 全为负数怎么办

Edge Case
这是本题最经典的陷阱。设 a = [−3, −1, −5, −2]，答案取决于题目是否允许空子段——两种题意会给出完全不同的答案。
题意定义a = [−3,−1,−5,−2] 的答案实现要点
不允许空子段
（教材默认、多数考题）		子段至少含 1 个元素−1（即最大的那个元素）ans 初始化为 a[0]，绝不能初始化为 0
允许空子段允许选空，规定空段和为 00ans 初始化为 0，或在最后 return max(ans, 0)
// 常见错误写法：ans 初始化为 0 int ans = 0; // ← 全负数组会错误地返回 0 int cur = 0; for (int i = 0; i < n; ++i) { cur = max(a[i], cur + a[i]); ans = max(ans, cur); } // 正确写法（不允许空子段）：以 a[0] 为基准 int ans = a[0], cur = a[0]; // ← 全负时返回最大的那个负数 for (int i = 1; i < n; ++i) { cur = max(a[i], cur + a[i]); ans = max(ans, cur); }
做题建议：拿到题先看样例或数据范围里有没有负数。凡是 a[i] 可能全为负，就必须把 ans 初始化为 a[0]（或 INT_MIN）而不是 0。教材（李春葆）默认「子段非空」，因此标准答案是 −1 而非 0。

⑦ 易错点

Pitfalls
易错点
  • 把答案写成 dp[n−1]。由于状态限定「以 a[i] 结尾」，答案是 max{dp[i]}。本例 dp[8]=5，而正确答案是 6。
  • 全负数组把 ans 初始化为 0，导致返回 0。见上一节。
  • 把「子段」当成「子序列」。子段（subarray / 连续子序列）要求元素下标连续；子序列（subsequence）可以跳着取。若允许跳着取，全取正数即可，问题变得平凡。
  • 记录起止下标时把 bestL 与 curL 同步更新。curL 每次「另起炉灶」都变，但 bestL 只在刷新全局最优时才该更新。
  • 误以为 dp[i−1] < 0 才另起炉灶、等于 0 时无所谓。dp[i−1] = 0 时两种决策结果相同，取 <= 或 < 都不影响最优值，但会影响记录到的子段起点（是否包含一段和为 0 的前缀）。若题目要求「长度最短的最优子段」需格外注意。
  • 用 int 存和导致溢出。n 达 105、元素达 109 时和可达 1014，要用 long long。

本节小结

Summary
本节小结
  • 状态定义：dp[i] = 以 a[i] 结尾的最大子段和。加上「以 a[i] 结尾」是为了满足无后效性。
  • 转移方程：dp[i] = max( a[i], dp[i−1] + a[i] )，对应「另起炉灶」与「接在后面」两种决策；边界 dp[0] = a[0]。
  • 答案为 max{dp[i]} 而非 dp[n−1]，需在扫描中同步维护。
  • 复杂度 Θ(n) 时间、滚动后 Θ(1) 空间，优于分治法的 O(n log n)；提速来源是按「结尾位置」划分子问题从而消除了跨界合并。
  • 全负数组是最经典陷阱：不允许空子段时答案是最大的那个负数，ans 必须初始化为 a[0]。
  • 记录最优子段：curL 在「另起炉灶」时重置，bestL/bestR 只在刷新全局最优时拷贝。

自测题

点击选项查看解析
1对 a = [−3, −1, −5, −2]（题目规定子段非空），Kadane 算法应返回？
A0，因为不选任何元素最优
B−1
C−11，即全部元素之和
D−2，即最后一个元素
解析：选 B。子段非空时至少要选一个元素，而任意两个及以上负数相加只会更小，所以最优解就是单个最大的元素 −1（下标 1）。逐项：dp = [−3, −1, −5, −2]，max 为 −1。A 正是「ans 初始化为 0」这个经典 bug 的产物——只有题目明确允许空子段时 0 才是合法答案；C 把「最大子段和」误解成「全部求和」；D 只是随手取了末位元素，忽略了要在整张 dp 表上取最大值。
2为什么状态要定义成「以 a[i] 结尾的最大子段和」，而不是「前 i 个元素中的最大子段和」？
A两种定义等价，前者只是写起来短一些
B后者不满足无后效性：无法判断 a[i] 能否接到前面的最优子段之后
C后者会使复杂度升到 O(n2)
D后者无法处理负数
解析：选 B。「前 i 个的最大子段和」这个数字里丢失了「那个最优子段的右端点在哪」这一关键信息，于是无法判定 a[i] 能否与之相连——状态信息不足即有后效性。加上「以 a[i] 结尾」的约束后，dp[i−1] 就精确地代表「一个在 i−1 处结束的最优子段」，转移立刻变得无歧义。A 是错的：两者数值通常不同（本例 dp[8]=5，而「前 9 个的最大子段和」是 6）。C 张冠李戴，问题在于写不出正确的转移而非慢；D 与负数无关，两种定义都能处理负数。
3关于分治法 O(n log n) 与 DP 的 Θ(n)，下列说法正确的是？
A分治法慢是因为递归调用的常数开销大
B分治按位置对半切，必须额外花 O(n) 处理「跨中点」的子段；DP 按「结尾位置」划分，任意子段恰属唯一一类，无跨界情形
C分治法不满足最优子结构，所以效率低
D分治法必须额外开 O(n) 的辅助数组，所以更慢
解析：选 B。差距来自子问题的划分方式：分治的三类情形（全在左、全在右、跨中点）中第三类无法由子问题直接给出，只能现场 O(n) 扫描，于是 T(n) = 2T(n/2) + Θ(n) = Θ(n log n)；DP 换用「按子段的右端点归类」，每个子段有且只有一个右端点，因而不存在需要现场合并的第三类，单个状态转移降到 O(1)，总计 Θ(n)。A 混淆了常数因子与渐近阶——即便消除递归开销，log n 因子依然存在；C 说反了，分治法同样依赖最优子结构，它是正确的算法，只是划分方式不够经济；D 的分治实现只需 O(log n) 的递归栈，并不需要 O(n) 辅助数组。
