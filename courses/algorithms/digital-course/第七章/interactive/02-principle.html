学习目标

Learning Objectives

本节学完后你应当

  1. 能复述并运用动态规划四步法：划阶段 → 定义状态 → 写转移方程与边界 → 定计算顺序。
  2. 能在给定的多段图上，按阶段逐格手算出全部 f 值并回溯出最短路径。
  3. 能写出多段图最短路的逆序法与顺序法两套转移方程，并显式声明边界（f(t)=0 / g(s)=0）。
  4. 能说明顺序法与逆序法各自的适用场合，以及为什么它们的最优值必然相等。
  5. 能用 C++ 实现多段图最短路，并分析其 O(n + e) 复杂度。

四步法 · 在这个多段图上逐步展开

The Four Steps, Concretely
1
划阶段（stage）：按「离终点还有几段」把结点分层。本图共 5 个阶段，第 k 阶段的结点只能走到第 k+1 阶段。阶段是决策的先后次序，划错阶段后面全错。判断标准：同一阶段内的结点之间没有边，且每条边恰好跨一个阶段。
2
定义状态（state）：状态必须「信息足够」，即知道它就能独立地往后决策——这就是无后效性。本题取 f(x) = 从结点 x 出发到终点 E 的最短路径长度。注意状态只含「当前在哪个结点」，不含「怎么走到这里的」，因为后续代价与来路无关。
3
写转移方程与边界：在 x 处的决策是「下一步走哪条出边」。枚举所有出边取最小值即得逆序方程；边界必须显式声明。
4
定计算顺序：f(x) 依赖它后继的 f 值，所以要从终点向源点、按阶段递减计算（阶段 3 → 2 → 1 → 0）。顺序错了会读到未计算的 INF。

① 状态定义 ② 转移方程 ③ 边界 ④ 顺序

逆序法 Backward
状态定义 · 逆序法

f(x) 表示从结点 x 出发、沿有向边走到终点 t 的最短路径长度；nxt(x) 记录取到最小值时选的下一个结点，用于回溯路径。

f(x) = min(x,y)∈E { c(x, y) + f(y) }
边界条件

f(t) = 0（终点到自身距离为 0），其余结点初始化为 +∞（INF）。
这一条极易被漏写。若不置 f(E)=0，最后一阶段的 f(D1)、f(D2) 会与 INF 相加而全部失效；若不把其余结点初始化为 INF，未算过的结点会被误当作「距离 0 可达」。

计算顺序

按阶段从大到小（4 → 3 → 2 → 1 → 0）依次求解。一般图上则按逆拓扑序计算。理由：f(x) 依赖其所有后继的 f，必须先算完后继。

最优性原理（Principle of Optimality）

若 A → … → x → … → E 是一条最短路径，则其中从 x 到 E 的那一段必然是 x 到 E 的最短路径。
反证：若存在更短的 x→E 路径，用它替换原段可得到比原路径更短的 A→E 路径，与原路径最短矛盾。
正是这条性质使得「用子问题的最优解拼出大问题的最优解」是合法的——它就是最优子结构在多段图上的具体形态。

顺序法 vs 逆序法

Forward vs Backward
状态定义 · 顺序法

g(x) 表示从源点 s 出发走到结点 x 的最短路径长度；pre(x) 记录最优决策的前驱结点。

g(x) = min(y,x)∈E { g(y) + c(y, x) }　　边界 g(s) = 0
g(A) = 0 边界 g(B1) = 4，g(B2) = 2，g(B3) = 3 均由 A 而来 g(C1) = min(4+3, 2+4, 3+5) = min(7, 6, 8) = 6 ← B2 g(C2) = min(4+6, 2+2, 3+3) = min(10, 4, 6) = 4 ← B2 g(D1) = min(6+2, 4+4) = 8 ← C1（与 C2 并列，任取） g(D2) = min(6+5, 4+1) = 5 ← C2 g(E) = min(8+3, 5+4) = 9 ← D2，与逆序法结果一致
对比维度逆序法（backward）顺序法（forward）
状态含义f(x)：x → 终点的最短距离g(x)：源点 → x 的最短距离
转移依据枚举 x 的出边（后继）枚举 x 的入边（前驱）
边界f(t) = 0g(s) = 0
计算顺序阶段递减（逆拓扑序）阶段递增（拓扑序）
答案位置f(s)g(t)
路径回溯存 nxt，从 s 正着读出存 pre，从 t 倒着读出后再反转
更适合单源：一个起点问到所有终点的场景；也便于剪枝单汇：多个起点问到同一终点；也便于边流式读入时在线更新
为什么两者结果必然相同？同一条 A→E 路径的长度是固定的，两种方法只是把这条路径的求和过程分别「从右往左」和「从左往右」拆开做，最优性原理保证任一子段都是最优的，因此最优值 f(s) = g(t)。选哪一种只取决于「哪一端的边更容易枚举」和「题目问的是哪一端」。

C++ 代码

Implementation
// 多段图最短路径 · 逆序法（结点已按拓扑序编号：0 = 源点 s，n-1 = 终点 t） const int MAXV = 1005, INF = 0x3f3f3f3f; struct Edge { int to, w; }; vector<Edge> G[MAXV]; // G[x]：x 的所有出边 int f[MAXV], nxt[MAXV]; void backward(int n) { int t = n - 1; for (int x = 0; x < n; ++x) { f[x] = INF; nxt[x] = -1; } f[t] = 0; // ③ 边界：终点到自身为 0 for (int x = t - 1; x >= 0; --x) // ④ 顺序：逆拓扑序，先算后继 for (int k = 0; k < (int)G[x].size(); ++k) { int y = G[x][k].to, w = G[x][k].w; if (f[y] < INF && w + f[y] < f[x]) // ② 转移：min{c(x,y)+f(y)} { f[x] = w + f[y]; nxt[x] = y; } } } // 回溯输出最短路径：源点 0 沿 nxt 一路走到终点 void printPath(int n) { for (int x = 0; x != -1; x = nxt[x]) { cout << x; if (nxt[x] != -1) cout << " -> "; } cout << "\nlength = " << f[0] << "\n"; }
// 多段图最短路径 · 顺序法（需要反向邻接表 RG[x]：x 的所有入边） vector<Edge> RG[MAXV]; // RG[x] 中的 to 表示「前驱结点 y」 int g[MAXV], pre[MAXV]; void forward_(int n) { for (int x = 0; x < n; ++x) { g[x] = INF; pre[x] = -1; } g[0] = 0; // 边界：源点为 0 for (int x = 1; x < n; ++x) // 顺序：拓扑序，先算前驱 for (int k = 0; k < (int)RG[x].size(); ++k) { int y = RG[x][k].to, w = RG[x][k].w; if (g[y] < INF && g[y] + w < g[x]) { g[x] = g[y] + w; pre[x] = y; } } }

易错点

Pitfalls
易错点
  • 漏写边界 f(t)=0：最常见的错误。没有它，最后一阶段结点会与 INF 相加，整张表失效。
  • 其余结点没初始化为 INF：C++ 中全局数组默认 0，未算过的结点会被当成「0 距离可达」，得到荒谬的小值。用 memset(f, 0x3f, sizeof f) 是常用写法。
  • INF 相加溢出：若直接写 f[x] = w + f[y] 而不先判 f[y] < INF，当 INF 取 INT_MAX 时会整型溢出变成负数。取 0x3f3f3f3f（约 109）的好处正是两个 INF 相加仍为正且不溢出。
  • 计算顺序与依赖方向不符：逆序法必须按阶段递减算。若照抄顺序法的循环方向，读到的全是 INF。
  • 把「阶段」和「状态」混为一谈：阶段是决策的时间轴（第几步），状态是该时刻的处境描述（在哪个结点）。同一阶段可以有多个状态。
  • 回溯方向记反：逆序法存的是 nxt（后继），从源点正着读；顺序法存的是 pre（前驱），从终点倒着读、最后还要 reverse。两者搞混会输出一条倒过来的路径。
  • 忽视「边只跨一个阶段」的前提：若图中存在同阶段内部的边或跨多阶段的边，就不能简单按阶段编号推进，需要先做真正的拓扑排序。

本节小结

Summary
本节小结
  • 四步法：划阶段 → 定义状态 → 写转移方程与边界 → 定计算顺序。四步缺一不可，尤以边界与顺序最易被忽略。
  • 逆序法：f(x) = min{ c(x,y) + f(y) }，边界 f(t) = 0，按阶段递减计算，答案为 f(s)。
  • 顺序法：g(x) = min{ g(y) + c(y,x) }，边界 g(s) = 0，按阶段递增计算，答案为 g(t)。两者最优值必然相等。
  • 最优性原理保证子路径也最优，这是把大问题拆成子问题的合法性依据。
  • 本例答案：A → B2 → C2 → D2 → E，长度 9。
  • 复杂度 Θ(n + e)（邻接表），把指数级的路径枚举降为线性。

自测题

点击选项查看解析
1用逆序法求本节多段图时，若漏写边界 f(E) = 0，而全部结点都初始化为 INF，程序会输出什么？
A仍然得到正确答案 9，因为 INF 会在比较中被淘汰
B所有 f 值都保持 INF，得不到任何有效路径
C得到 0，因为没有任何边被松弛
D结果偏大但仍是一条合法路径的长度
解析：选 B。递推是一条「从边界长出来」的链：f(D1) 依赖 f(E)，f(C1) 依赖 f(D)，……若 f(E) 不置 0，代码里的守卫条件 if (f[y] < INF) 会让所有松弛全部跳过，于是 f 全表保持 INF。这说明边界不是「额外补充」，而是整个递推的唯一信息来源。A 把「淘汰 INF」误当成「能产生有效值」，但没有任何有效值可产生；C 混淆了「未初始化为 0」和「INF」两种初值——若真把全部初值设成 0，则会输出 0 这个荒谬答案；D 错在根本没有任何路径被构造出来。
2关于顺序法与逆序法，下列说法正确的是？
A逆序法一定比顺序法快，因为它可以提前剪枝
B两者求出的最优值可能不同，应取较小者
C两者最优值必然相等；选择哪种取决于枚举出边还是入边更方便、以及题目问哪一端
D顺序法不需要边界条件，因为它从源点自然开始
解析：选 C。同一条 A→E 路径的长度是客观确定的，两种方法只是把这条路径的求和「从左往右」或「从右往左」拆开算，最优性原理保证任何子段都最优，故 f(s) = g(t) = 9。A 错：两者都恰好松弛每条边一次，同为 Θ(n+e)，剪枝与方向无关；B 是典型误解，若二者结果不同一定是代码写错了，而不是「取较小者」；D 错得最隐蔽——顺序法同样需要边界 g(s) = 0 且其余为 INF，「从源点开始」正是靠这条边界表达的。
3在多段图上，「状态」与「阶段」的关系是？
A一个阶段对应一个状态，二者是同一概念的两种叫法
B阶段是决策的先后次序，一个阶段中可以包含多个状态
C状态数一定等于阶段数乘以边数
D只要状态定义正确，就不必划分阶段
解析：选 B。阶段是「走到第几步」这条时间轴，状态是「此刻处在什么局面」。本图阶段 1 就同时含 B1、B2、B3 三个状态。A 只在每阶段恰有一个状态的退化情形下成立（那种问题往往一维递推即可）；C 是凭空构造的公式，状态数由结点数决定，与边数无关；D 反了因果——阶段划分正是计算顺序的来源，不划阶段就无法保证「依赖先算完」，即使状态定义再正确也可能读到未计算的值。
