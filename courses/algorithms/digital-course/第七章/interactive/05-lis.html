最长递增子序列

dp[i]=以 a[i] 结尾的 LIS 长度。动画展示每个位置的转移，最后高亮一条最优序列。

学习目标

Learning Objectives

本节学完后你应当

  1. 能写出 LIS 的状态定义、转移方程与边界 dp[i] = 1，并解释边界的含义。
  2. 能实现 O(n2) 的经典 DP，并用 pre[] 记录前驱回溯打印出一条具体的 LIS。
  3. 能讲清 O(n log n) 贪心 + 二分优化的核心思想：维护「长度为 k 的递增子序列的最小结尾」数组 tail。
  4. 能说明 tail 数组本身不一定是一条合法 LIS，只有长度是可靠的。
  5. 能根据「严格递增 / 非递减」正确选择 lower_bound / upper_bound。
LIS 长度—
dp[i]=max{dp[j]}+1 (j<i 且 a[j]<a[i])

① 状态定义 ② 转移方程 ③ 边界 ④ 顺序

O(n²) 经典解法
状态定义

dp[i] 表示以 a[i] 为最后一个元素的最长严格递增子序列的长度（i = 0, 1, …, n−1）。
与最大子段和同理，「以 a[i] 结尾」这个约束是为了满足无后效性：只有知道子序列的末尾是谁，才能判断 a[i] 能否接上去。子序列不要求连续，但要求下标递增。

dp[i] = max{ dp[j] } + 1　　其中 0 ≤ j < i 且 a[j] < a[i]
dp[i] = 1　　当不存在满足 j < i 且 a[j] < a[i] 的 j
边界条件 · 初始化

dp[i] = 1（对所有 i）。含义是：每个元素自身就构成一个长度为 1 的递增子序列。
这条初始化同时承担了两个作用：① 处理「a[i] 前面没有任何比它小的元素」的情形；② 让转移写成「取 max」时天然有一个下界，无需再单独判断。若忘记初始化为 1（默认为 0），所有 dp 值会整体少 1。

计算顺序 · 答案位置

dp[i] 依赖所有 j < i，故 i 从小到大，内层 j 从 0 扫到 i−1。
答案 ans = max0≤i<n dp[i]，同样不是 dp[n−1]。

例题演算 · A = [10, 9, 2, 5, 3, 7, 101, 18]

Worked Example
dp[0] = 1 a[0]=10，前无元素 dp[1] = 1 a[1]=9，前面 10 不小于 9 dp[2] = 1 a[2]=2，前面无更小者 dp[3] = dp[2] + 1 = 2 a[3]=5，可接在 2 之后；pre[3]=2 dp[4] = dp[2] + 1 = 2 a[4]=3，可接在 2 之后；pre[4]=2 dp[5] = max(dp[2], dp[3], dp[4]) + 1 = 2 + 1 = 3 a[5]=7，接在 5 或 3 之后；pre[5]=3 dp[6] = dp[5] + 1 = 4 a[6]=101 比所有前项都大；pre[6]=5 dp[7] = dp[5] + 1 = 4 a[7]=18，可接 7 之后（101 太大）；pre[7]=5

答案：LIS 长度 = 4。从 dp 最大值所在的 i = 6 出发沿 pre 回溯：6 → 5 → 3 → 2，反转后得下标 [2, 3, 5, 6]，对应子序列 2 → 5 → 7 → 101。
注意 LIS 通常不唯一：[2, 3, 7, 101]、[2, 3, 7, 18] 也都是长度为 4 的合法解。

③ C++ 代码 · O(n²) + 路径回溯

Implementation
// O(n^2) 经典 DP，并用 pre[] 回溯打印一条具体的 LIS int lisN2(const vector<int>& a, vector<int>& seq) { int n = a.size(); vector<int> dp(n, 1), pre(n, -1); // ③ 边界：每个元素自成长度 1 int best = 0; // 最优值所在下标 for (int i = 1; i < n; ++i) { // ④ 顺序：i 递增 for (int j = 0; j < i; ++j) if (a[j] < a[i] && dp[j] + 1 > dp[i]) { dp[i] = dp[j] + 1; // ② 转移 pre[i] = j; // 记录前驱，供回溯 } if (dp[i] > dp[best]) best = i; } // 回溯：从 best 沿 pre 一路向前，再反转 seq.clear(); for (int i = best; i != -1; i = pre[i]) seq.push_back(a[i]); reverse(seq.begin(), seq.end()); return dp[best]; }
回溯的通用套路：DP 只给出最优值；要还原最优解本身，需要额外一个 pre[]（或 choice[]）数组，在每次刷新 dp[i] 的同时记录「这个最优值是从哪个状态转移来的」。这套「dp 存值 + pre 存决策 + 逆向回溯 + reverse」的模式在 LCS、背包、多段图中反复出现。

④ O(n log n) 优化 · 贪心 + 二分

Patience Sorting
辅助数组的定义（本节最关键的一句话）

tail[k] 表示：在已扫描过的前缀中，所有长度为 k+1 的递增子序列里，结尾元素的最小值（k 从 0 开始计）。
换句话说，tail[k] 回答的是「要凑出长度 k+1 的递增子序列，结尾最小能小到多少」。

为什么维护「最小结尾」是对的

贪心直觉：结尾越小，后面越容易接上新元素，因此在长度相同的所有子序列中，只保留结尾最小的那个一定不吃亏。
关键性质：tail 数组严格递增。反证——若 tail[k] ≥ tail[k+1]，取那条长度为 k+2、结尾为 tail[k+1] 的子序列，砍掉最后一个元素得到一条长度 k+1、结尾 < tail[k+1] ≤ tail[k] 的子序列，与 tail[k] 是最小结尾矛盾。
正因为 tail 严格递增，才能用二分查找定位插入位置，把每步的 O(n) 降到 O(log n)。

算法流程

依次扫描每个 a[i]：
· 若 a[i] > tail 的最后一个元素，说明它能把当前最长的子序列再延长一位 → 追加到 tail 末尾，LIS 长度 +1；
· 否则，在 tail 中用二分找到第一个 ≥ a[i] 的位置 p，用 a[i] 替换 tail[p]。含义是：长度为 p+1 的子序列现在有了一个更小的结尾，未来更容易接续。替换不改变 tail 的长度。
扫描结束后，tail 的长度即为 LIS 的长度。

a[0] = 10 → tail 为空，追加 → tail = [10] len = 1 a[1] = 9 → 9 < 10，二分定位 p=0，替换 → tail = [9] len 仍为 1，结尾变小 a[2] = 2 → 2 < 9，p=0，替换 → tail = [2] len 仍为 1 a[3] = 5 → 5 > 2，追加 → tail = [2, 5] len = 2 a[4] = 3 → 3 < 5，p=1，替换 → tail = [2, 3] len 仍为 2，为后续留出空间 a[5] = 7 → 7 > 3，追加 → tail = [2, 3, 7] len = 3 a[6] = 101 → 追加 → tail = [2, 3, 7, 101] len = 4 a[7] = 18 → 18 < 101，p=3，替换 → tail = [2, 3, 7, 18] len 仍为 4 ← 答案
务必注意：tail 数组本身不一定是原序列中的一条合法子序列！它只是「各长度的最小结尾」的记录，元素可能来自被替换后已经失效的组合。只有 tail 的长度是可靠的答案。本例最后 tail = [2,3,7,18] 恰好合法纯属巧合。
若一定要输出具体的 LIS，需在替换时额外记录每个 a[i] 被放到的下标位置以及当时的前驱，再回溯——或者干脆用 O(n2) 版本。
// O(n log n)：贪心 + 二分，只求长度 int lisNLogN(const vector<int>& a) { vector<int> tail; // tail[k] = 长度 k+1 的递增子序列的最小结尾 for (int i = 0; i < (int)a.size(); ++i) { // 严格递增 LIS 用 lower_bound：找第一个 >= a[i] 的位置 auto it = lower_bound(tail.begin(), tail.end(), a[i]); if (it == tail.end()) tail.push_back(a[i]); // 比所有结尾都大 → 延长 else *it = a[i]; // 否则替换，压低结尾 } return tail.size(); } // 若求「最长不下降子序列」（允许相等），改用 upper_bound： // auto it = upper_bound(tail.begin(), tail.end(), a[i]); // lower_bound 找第一个 >= x，会把相等元素挡在外面（严格递增）； // upper_bound 找第一个 > x，允许相等元素被追加（非递减）。
// O(n log n) 进阶：同时还原一条具体的 LIS int lisNLogNPath(const vector<int>& a, vector<int>& seq) { int n = a.size(); vector<int> tail, idx; // idx[k]：tail[k] 对应的原下标 vector<int> pre(n, -1); // pre[i]：a[i] 在 LIS 中的前驱下标 for (int i = 0; i < n; ++i) { int p = lower_bound(tail.begin(), tail.end(), a[i]) - tail.begin(); if (p > 0) pre[i] = idx[p - 1]; // 接在长度 p 的那条之后 if (p == (int)tail.size()) { tail.push_back(a[i]); idx.push_back(i); } else { tail[p] = a[i]; idx[p] = i; } } seq.clear(); for (int i = idx.back(); i != -1; i = pre[i]) seq.push_back(a[i]); reverse(seq.begin(), seq.end()); return tail.size(); }

⑥ 易错点

Pitfalls
易错点
  • 忘记把 dp 初始化为 1（默认 0），导致全部答案少 1。边界 dp[i] = 1 表示「元素自身构成长度 1 的子序列」。
  • 把答案写成 dp[n−1]。答案是 max{dp[i]}；本例 dp[7] = 4 恰好等于答案纯属巧合，换成 A = [1,2,3,0] 时 dp[3] = 1 而答案是 3。
  • 误以为 tail 数组就是一条 LIS。它只保证长度正确；元素组合可能根本不构成原序列的子序列。
  • lower_bound 与 upper_bound 用反。严格递增（不允许相等）用 lower_bound；非递减（允许相等）用 upper_bound。用反会让答案偏大或偏小 1 甚至更多。
  • 把「子序列」当成「子段」。LIS 的元素不要求连续，只要求下标递增；若要求连续那是另一道简单得多的题（O(n) 扫描即可）。
  • 比较写成 a[j] ≤ a[i]。严格递增必须是 a[j] < a[i]，否则相等元素会被串起来。
  • 回溯时忘记 reverse。沿 pre 回溯得到的是倒序，必须反转后再输出。

本节小结

Summary
本节小结
  • 状态定义：dp[i] = 以 a[i] 结尾的最长递增子序列长度；转移 dp[i] = max{dp[j] | j < i, a[j] < a[i]} + 1；边界 dp[i] = 1；答案 max{dp[i]}。
  • 用 pre[i] 记录前驱，从最优下标沿 pre 回溯并 reverse，即可打印出一条具体的 LIS（LIS 通常不唯一）。
  • O(n log n) 优化的核心是维护 tail[k] = 长度 k+1 的递增子序列的最小结尾；tail 严格递增，故可二分。
  • 扫描规则：比末尾大就追加（长度 +1），否则二分找第一个 ≥ a[i] 的位置替换（长度不变）。
  • tail 只保证长度正确，本身不一定是合法子序列。
  • 严格递增用 lower_bound，非递减用 upper_bound。

1O(n log n) 解法结束后 tail = [2, 3, 7, 18]。关于它，正确的说法是？
Atail 就是原序列的一条 LIS，可以直接输出
B只有 tail 的长度 4 是可靠答案，tail 的内容不保证构成原序列的子序列
Ctail 是原序列排序后的前 4 个元素
Dtail[k] 表示长度为 k+1 的递增子序列的最大结尾
解析：选 B。tail[k] 记录的是「长度 k+1 的递增子序列所能达到的最小结尾」，各个位置的值可能来自不同的、彼此不兼容的子序列，因此拼在一起未必是原序列中真实存在的子序列。本例最后 [2,3,7,18] 恰好合法只是巧合——若把 a[7] 换成一个更早出现的小值，就会露馅。A 正是最常见的误用；C 完全无关，tail 与排序结果没有必然联系（本例排序后前 4 个是 2,3,5,7）；D 把「最小」说反了，若维护最大结尾，后续元素反而更难接上，贪心根本不成立。
2若题目改为求最长不下降子序列（允许相邻相等，如 [1,3,3,5] 长度为 4），O(n log n) 代码该如何修改？
A把 tail 的维护规则由「最小结尾」改为「最大结尾」
B把 lower_bound 改成 upper_bound（找第一个 > a[i] 的位置）
C把比较符 a[j] < a[i] 改成 a[j] > a[i]
D无需修改，两种问题的答案总是相同
解析：选 B。lower_bound 找第一个 ≥ a[i] 的位置，遇到与 a[i] 相等的结尾时会执行「替换」，从而阻止相等元素被串接——这正是严格递增所需；upper_bound 找第一个 > a[i] 的位置，相等的结尾会被跳过，于是 a[i] 可以追加在它后面，得到非递减序列。A 会直接摧毁贪心的正确性：结尾越大越难接续，「最大结尾」根本不满足可交换论证，且 tail 也不再严格递增，二分失去前提；C 把方向弄反了，那求的是递减子序列；D 明显错误，对 [1,3,3,5] 严格递增答案为 3、不下降答案为 4。
3对 A = [1, 2, 3, 0]，O(n2) 解法算出 dp = [1, 2, 3, 1]。LIS 长度是？
A1，即 dp[n−1]
B3，即 max{dp[i]}
C4，因为数组有 4 个元素
D7，即 dp 数组之和
解析：选 B，LIS 为 [1,2,3]，长度 3。这道题专门用来打掉「答案 = dp 最后一格」的惯性——由于状态被限定为以 a[i] 结尾，dp[3] = 1 只说明「以 0 结尾的 LIS 长度是 1」，与全局答案无关。A 正是这个错误；C 忽略了 0 破坏了递增性；D 把「长度」误当成累加量，dp 之和没有任何意义。凡是「以 i 结尾」型状态定义，都要记得答案在 max{dp[i]} 而非 dp[n−1]。
