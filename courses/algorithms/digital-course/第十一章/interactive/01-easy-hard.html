一、把「快慢」说清楚：输入规模与多项式时间

Input size & polynomial time

整章理论的地基只有一句话：复杂度是关于输入规模的函数。规模定义错了，后面全错——伪多项式的坑就是从这里挖出来的。

定义 1.1 · 输入规模

一个问题实例的输入规模（input size） n，指在合理编码下写出该实例所需的二进制位数（或字符数）。要点：一个整数 W 的输入规模是 ⌈log2(W+1)⌉ 位，不是 W 本身；一个 n 个顶点的图，规模是 O(n2) 位（邻接矩阵）或 O((n+m) log n) 位（邻接表）。

定义 1.2 · 多项式时间算法

设算法 A 在规模为 n 的最坏输入上的运行时间为 T(n)。若存在常数 k > 0 与 n0，使得对一切 n ≥ n0 都有 T(n) ≤ nk，即 T(n) = O(nk)，则称 A 是多项式时间算法（polynomial-time algorithm）。若一个问题存在多项式时间算法，就称该问题是易解的（tractable）；否则（目前只有 2Ω(n) 量级的算法）称为难解的（intractable）。

易解 ⟺ ∃ k，T(n) = O(nk)
性质 1.1 · 为什么偏偏以「多项式」划线

① 封闭性：多项式对加法、乘法、复合封闭——poly + poly、poly · poly、poly(poly(n)) 仍是多项式。所以「多项式时间子程序调用多项式次」整体仍是多项式，理论推导不会失控。
② 模型无关：合理的顺序计算模型（图灵机、RAM、真实计算机）之间可以相互多项式时间模拟，因此「是否多项式」不随机器模型改变，是一个健壮（robust）的分类标准。
③ 经验吻合：现实中被找到的多项式算法，指数 k 大多是 1~4；一旦落到指数级，规模稍增就彻底不可行。

二、比「难解」更极端：不可计算与停机问题

Undecidability · Halting Problem

「难解」是算得出但太慢，「不可计算」是根本不存在算法——不是人类暂时没想出来，而是数学上已被证明永远不会有。停机问题是这一层次的代表。

定义 1.3 · 停机问题

停机问题（Halting Problem）：给定任意程序 P 的源码与任意输入 x，判定「P 在输入 x 上最终会停机，还是永远运行下去」。图灵（A. Turing, 1936）证明：不存在任何算法能对所有 (P, x) 给出正确回答，即停机问题是不可判定的（undecidable）。

定理 1.1 · 停机问题不可判定

用反证法。假设存在一个万能判定器 H(P, x)：当 P 在 x 上停机时返回 true，否则返回 false，并且 H 自己永远停机。我们用 H 造出一个「专门跟自己作对」的程序 D，再把 D 的源码喂给 D 自己，必然导出矛盾。

// 反证假设：存在万能停机判定器（这是我们要推翻的东西） bool H(string P, string x); // P 在输入 x 上停机 → true；否则 → false // 对角线构造：D 只接受一个参数 —— 某个程序的源码 void D(string P) { if (H(P, P)) // H 断言「P 喂给自己会停」 while (true) ; // D 就偏偏死循环 else // H 断言「P 喂给自己不会停」 return; // D 就偏偏立刻停机 } // 致命一问：运行 D(D)，即把 D 的源码喂给 D 自己，它到底停不停？
假设 H 存在，按上面代码构造出 D 反证假设 情形一：若 D(D) 停机 ⇒ H(D,D) = true ⇒ D 走 while(true) 分支 ⇒ D(D) 不停机 矛盾 情形二：若 D(D) 不停机 ⇒ H(D,D) = false ⇒ D 走 return 分支 ⇒ D(D) 确实停机 矛盾 两种情形穷尽且皆矛盾 ⇒ 假设不成立 ⇒ 判定器 H 不存在 证毕
「对角线」体现在哪里？把所有程序排成表格的行、所有输入排成列，H 的回答就填满一张无穷大的表。D(D) 取的恰好是这张表的对角线格子（第 i 个程序喂第 i 个程序），并把每一格的答案取反。取反后得到的这一行，与表中任何一行都至少差一格，于是「D 这个程序不在所有程序的表里」——荒谬。这与康托尔（Cantor）证明实数不可数的对角线手法完全一致。
不要误读：不可判定说的是不存在对所有 (P, x) 都正确的通用算法。对某些具体程序（例如只有一个 for 循环、没有递归的程序），我们当然能判断它会停机。编译器的死循环警告、静态分析工具都是在做「部分正确」的近似，而非解决停机问题。

三、伪多项式：O(nW) 究竟「伪」在哪里

Pseudo-polynomial
定义 1.4 · 伪多项式时间算法

若算法的运行时间是输入中数值大小（如背包容量 W、金额 t）的多项式，但不是输入编码长度的多项式，则称它为伪多项式时间算法（pseudo-polynomial-time algorithm）。「伪」字的全部含义就是：它只有在你用一元（unary）方式数数字时才像多项式，而真实输入是二进制写的。

// 0/1 背包的经典动态规划：时间 O(nW)，空间 O(W) int knapsack(vector<int> w, vector<int> v, int W) { int n = w.size(); vector<int> f(W + 1, 0); // 表格宽度取决于「数值」W for (int i = 0; i < n; i++) for (int c = W; c >= w[i]; c--) // 内层循环跑 W 次 f[c] = max(f[c], f[c - w[i]] + v[i]); return f[W]; } // 输入里 W 只写了 log2(W) 位，循环却跑了 W = 2^(log2 W) 次 —— 指数
0/1 背包 DP 的运行时间 T = O(n·W) n 件物品 × 容量 W 但 W 在输入中以二进制书写，只占 m = ⌈log2W⌉ 位 编码长度 故输入规模 N = O(n·b + m)，其中 b 是单个重量/价值的位数 规模定义 回代 W = 2m，得 T = O(n · 2m) 关于 N 是指数 ⇒ O(nW) 关于数值是多项式，关于输入规模是指数 故称「伪」
算一笔直观账：把 W 从 1 000 改成 1 000 000，输入文件只多写了约 10 个二进制位（几乎没变长），但 DP 表格和运行时间涨了 1000 倍。真正的多项式算法绝不会因为「同一个数字多写几位」就爆炸——这正是伪多项式露馅的地方。

存在伪多项式算法的 NPC 问题称为弱 NP 完全（weakly NP-complete）；连伪多项式算法都不可能有的（除非 P = NP）称为强 NP 完全（strongly NP-complete）。

易错点
  • 把「多项式时间」直接等同于「跑得快」。n100 是多项式却毫无实用价值，2n/1000 在小 n 时反而更快。多项式 / 指数是理论上健壮的分类线，不是工程效率承诺。
  • 把 O(nW) 当成多项式算法，进而以为「背包已经被多项式解决了，所以 P = NP」。错在把数值 W 当成了输入规模。
  • 混淆「难解」与「不可计算」。TSP 是难解但完全可算（枚举即可）；停机问题是不可计算，再快的机器也无解。
  • 用平均情况或最好情况给问题定性。本章所有复杂性类都按最坏情况定义——快速排序平均 O(n log n)、最坏 O(n2)，但它仍是多项式算法。
  • 认为「不可判定」意味着对任何具体程序都无法判断是否停机。不可判定针对的是通用判定器，个别实例往往能判断。
本节小结
  • 输入规模 n = 编码长度（位数），不是输入里数字的大小；这是判断伪多项式的唯一标尺。
  • 多项式时间算法：∃ k 使 T(n) = O(nk)。存在这样算法的问题称为易解，否则称为难解。
  • 以多项式划线的三条理由：对加/乘/复合封闭、跨计算模型不变、与工程经验吻合。
  • 停机问题不可判定，用对角线法反证：构造与 H 处处唱反调的 D，运行 D(D) 必然矛盾。
  • 0/1 背包 O(nW) 是伪多项式：W 只占 log2W 位，故 O(nW) = O(n·2m)，相对输入规模是指数的。
  • 难度三层：易解 ⊂ 难解（仍可算） ⊂ 不可计算（无算法）。
10/1 背包的动态规划时间为 O(nW)。关于它的正确说法是？
A它是多项式时间算法，因为 n 和 W 都是输入里的量
B它是伪多项式时间算法，因为 W 的二进制编码只有 log2W 位，相对输入规模 O(nW) 是指数的
C它是指数时间算法，因为代码里有两重嵌套循环
D由于背包是 NPC 问题，这个算法必然是错的
解析：选 B。输入规模按编码长度算：写下 W 只需 m = ⌈log2W⌉ 位，于是 W = 2m，O(nW) = O(n·2m) 关于规模是指数的。A 错在把数值当规模；C 错在「两重循环」与多项式/指数无关（矩阵乘法三重循环仍是多项式）；D 错在算法本身完全正确，只是运行时间不是真多项式。
2关于停机问题，下列哪种说法是准确的？
A存在判定算法，但需要指数时间，所以实际不可用
B目前还没人想出算法，属于未解决的公开问题（像 P vs NP 那样）
C已被证明不存在对所有 (程序, 输入) 都给出正确答案的算法，它是不可判定的
D对任何一个具体程序，我们都无法判断它是否会停机
解析：选 C。A、B 把「不可计算」误当成「太慢」或「暂时没解决」——停机问题的不可判定性早在 1936 年就被证明了，不是开放问题。D 过度推广：不可判定针对的是通用判定器；对「for i in 1..10: print(i)」这种具体程序当然能判断它会停机。
3下列时间复杂度中，哪一个属于多项式时间？
AT(n) = n100
BT(n) = 2n
CT(n) = n!
DT(n) = 22n
解析：选 A。多项式的判据是「存在常数 k 使 T(n) = O(nk)」，k = 100 也算数——尽管 n100 在实践中比 2n 在小 n 时还慢得多。这正说明多项式 ≠ 实用，它只是一条理论上健壮的分界线。B、D 是指数，C 比指数还快地增长（n! ≈ (n/e)n）。顺带一提：2log2n = n 是多项式，别被指数的外形骗了。
