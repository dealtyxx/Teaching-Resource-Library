一、什么是容器适配器

Container Adapter
定义

容器适配器（Container Adapter）不是新的数据结构，而是对已有序列容器的一层接口封装：它把底层容器的通用接口裁剪、改名成某种特定数据结构应有的受限接口，只暴露该结构允许的操作。
C++ 标准库提供三个适配器：stack（栈）、queue（队列）、priority_queue（优先队列）。

适配器 = 底层容器 + 受限的接口视图

例如 stack 内部保存一个 deque，把 push_back 改名为 push、pop_back 改名为 pop、back 改名为 top，并不提供 begin() / end() / operator[]。这样在类型层面就禁止了"从栈中间取元素"这类违反 LIFO 语义的操作——用接口约束保证语义正确，这是适配器最大的价值。

// 三个适配器的模板声明（简化） template<class T, class Container = deque<T>> class stack; template<class T, class Container = deque<T>> class queue; template<class T, class Container = vector<T>, class Compare = less<typename Container::value_type>> class priority_queue;
适配器默认底层可选底层底层必须提供暴露的接口
stackdequevector、listback / push_back / pop_backpush / pop / top / empty / size
queuedequelist（不能用 vector）front / back / push_back / pop_frontpush / pop / front / back / empty / size
priority_queuevectordequefront / push_back / pop_back + 随机访问迭代器push / pop / top / empty / size
为什么 queue 不能用 vector 作底层？queue 需要 pop_front()（从队首删除），而 vector 没有这个成员函数——即使自己实现，头部删除也是 O(n)。deque 与 list 都提供 O(1) 的 pop_front()，所以只有它们可用。这也再次说明：选底层容器的依据是复杂度与接口，不是喜好。

二、stack 与 queue 的代码用法

含底层容器替换语法
// ===== stack：后进先出 LIFO ===== #include <stack> #include <vector> #include <deque> using namespace std; stack<int> s; // 默认底层为 deque<int> stack<int, vector<int>> s2; // 显式指定底层为 vector —— 内存更紧凑 stack<int, list<int>> s3; // 也可以用 list s.push(10); // O(1)，实为底层 push_back s.push(20); cout << s.top(); // 20，O(1)，实为底层 back() s.pop(); // 删除栈顶，O(1)；注意 pop 不返回值！ cout << s.size() << s.empty(); // 1 false // s[0] ← 编译错误：stack 不提供下标访问，这正是适配器的意义 // ===== queue：先进先出 FIFO ===== #include <queue> queue<int> q; // 默认底层 deque<int> queue<int, list<int>> q2; // 可换成 list // queue<int, vector<int>> q3; ← 编译错误：vector 无 pop_front() q.push(1); // 入队（队尾），O(1) q.push(2); cout << q.front(); // 1，队首元素 cout << q.back(); // 2，队尾元素 q.pop(); // 出队（队首），O(1)
接口细节：pop() 的返回类型是 void，不返回被弹出的元素。要取值必须先 top()（或 front()）再 pop()。这是为异常安全考虑的设计——若 pop 同时返回对象，拷贝构造抛异常时元素已被删除且无法恢复。

三、priority_queue 优先队列

第三个适配器 · 底层是二叉堆
定义

优先队列（Priority Queue）：出队顺序不按入队先后，而按优先级——每次弹出的都是当前优先级最高的元素。C++ 的 priority_queue 默认是大顶堆（top 为最大值），底层用 vector 存储一棵完全二叉树形式的二叉堆（Binary Heap）。

性质

堆性质：大顶堆中任意结点的值都不小于其子结点的值，故根结点（数组下标 0）恒为最大值。下标 i 的左右孩子为 2i+1、2i+2，父结点为 (i−1)/2——正因为是完全二叉树，才能用连续数组而非指针存储。

操作含义内部动作复杂度
top()取优先级最高的元素直接读根结点O(1)
push(x)插入元素尾部追加后向上筛选（sift-up）O(log n)
pop()删除优先级最高的元素末元素移到根后向下筛选（sift-down）O(log n)
size() / empty()元素个数 / 是否为空转发给底层 vectorO(1)
建堆（由 n 个元素构造）批量建立自底向上 heapifyO(n)

push / pop 为 O(log n) 的原因：完全二叉树的高度为 ⌊log2n⌋，筛选操作沿着一条根到叶的路径进行，最多走树高那么多层。

// ===== priority_queue：优先队列 ===== #include <queue> #include <functional> // greater<int> priority_queue<int> pq; // 默认大顶堆：top 是最大值 pq.push(3); pq.push(9); pq.push(5); // 每次 O(log n) cout << pq.top(); // 9，O(1) pq.pop(); // 弹出 9，O(log n) cout << pq.top(); // 5 // 小顶堆：必须写满三个模板参数（这是最常被记错的语法） priority_queue<int, vector<int>, greater<int>> minHeap; minHeap.push(3); minHeap.push(9); minHeap.push(5); cout << minHeap.top(); // 3，最小值 // 自定义优先级：注意比较函数的方向与直觉相反 struct Task { int id, pri; }; struct Cmp { bool operator()(const Task& a, const Task& b) const { return a.pri < b.pri; // 返回 true 表示 a 优先级"低于" b } // 故这里得到的是 pri 最大者先出队 }; priority_queue<Task, vector<Task>, Cmp> tasks;
最易错的一点：priority_queue 的比较器语义与 sort 相反。sort 传 less 得升序，而 priority_queue 传 less（默认）得大顶堆（降序出队）；要小顶堆必须传 greater。记法：比较器判定为"小"的那个元素排在堆的底部、最后出队。
典型应用：Dijkstra 最短路（每次取距离最小的顶点）、Huffman 编码（每次取权值最小的两棵树）、Top-K 问题（维护大小为 K 的小顶堆，O(n log K)）、任务调度。后续第 6、7 章会反复使用。

四、关联容器

Associative Containers · 红黑树 vs 哈希表
定义

关联容器（Associative Container）：按关键字（key）而非位置来组织和访问元素的容器。分两大族：
① 有序关联容器 set / multiset / map / multimap，底层为红黑树（一种自平衡二叉搜索树），所有操作 O(log n)，元素按 key 有序；
② 无序关联容器 unordered_set / unordered_map 等，底层为哈希表，平均与均摊 O(1)，元素无序，最坏（大量冲突）退化为 O(n)。

// ===== 有序关联容器：红黑树，O(log n)，自动有序 ===== #include <set> #include <map> set<int> st; st.insert(30); st.insert(10); st.insert(20); // 各 O(log n) for (int x : st) cout << x << ' '; // 输出 10 20 30 —— 自动升序 if (st.count(20)) cout << "存在"; // 查找 O(log n) auto it = st.lower_bound(15); // 首个 >= 15 的元素，O(log n) st.erase(10); // 删除 O(log n) map<string, int> cnt; cnt["apple"] = 3; // 插入或修改，O(log n) cnt["pear"]++; // 键不存在时自动值初始化为 0 再自增 for (auto& [k, v] : cnt) // C++17 结构化绑定 cout << k << ":" << v << endl; // 按 key 字典序输出 // ===== 无序关联容器：哈希表，均摊 O(1)，无序 ===== #include <unordered_set> #include <unordered_map> unordered_set<int> us = {30, 10, 20}; cout << us.count(20); // 查找均摊 O(1) // 遍历顺序取决于哈希值，不保证有序，也不保证两次运行一致 unordered_map<string, int> um; um["apple"] = 3; // 均摊 O(1) // um.lower_bound("a"); ← 编译错误：无序容器没有 lower_bound
对比项set / map（有序）unordered_set / unordered_map（无序）
底层结构红黑树（自平衡 BST）哈希表（拉链法）
查找 / 插入 / 删除（平均）O(log n)均摊 O(1)
查找 / 插入 / 删除（最坏）O(log n)（有保证）O(n)（全部冲突时）
元素顺序按 key 升序，遍历有序无序，随哈希实现而变
范围查询 lower_bound / upper_bound支持，O(log n)不支持
对 key 的要求可比较（定义 <）可哈希（特化 std::hash）+ 可判等
内存开销每结点 3 个指针 + 颜色位桶数组 + 链表结点
适用场景需有序遍历、区间查询、名次统计只做存在性判断与快速取值
选择准则：只需要"查得快"⇒ unordered_*；一旦需要有序遍历、区间查询或最坏情况有保证 ⇒ set / map。带 multi 前缀的版本允许重复关键字（multiset / multimap），普通版本会自动去重。
容器适配器Container Adapter 栈Stack, LIFO 队列Queue, FIFO 优先队列Priority Queue 二叉堆Binary Heap 红黑树Red-Black Tree 哈希表Hash Table
易错点
  • 以为适配器是全新的数据结构。stack / queue / priority_queue 都没有自己的存储，只是给底层容器套了一层受限接口；它们甚至不提供迭代器，无法用范围 for 遍历。
  • 用 vector 作 queue 的底层。编译失败，因为 vector 没有 pop_front()。stack 可以用 vector（只需 push_back / pop_back），queue 不行。
  • 期望 pop() 返回被删元素。它返回 void。必须写成 int x = s.top(); s.pop(); 两步。
  • 写小顶堆时漏掉中间的模板参数。必须写 priority_queue<int, vector<int>, greater<int>>，不能省略 vector<int>——模板参数没有"跳过"语法。
  • 把 priority_queue 的比较器方向与 sort 混同。两者语义相反：less 在 sort 中得升序，在 priority_queue 中得大顶堆。
  • 用 map[key] 判断键是否存在。operator[] 在键不存在时会插入一个默认值元素，导致 map 悄悄变大。判存在应用 count(key) 或 find(key) != end()。
  • 认为 unordered_map 永远比 map 快。哈希冲突严重时退化为 O(n)；且 unordered_map 不支持 lower_bound、遍历无序。有序需求下只能用 map。
  • 对 set 中的元素直接修改。set 的元素是 const 的，修改会破坏树的有序性。正确做法是先 erase 再 insert。
本节小结
  • 容器适配器是对底层序列容器的接口封装，用受限接口保证数据结构语义；stack / queue 默认底层为 deque，priority_queue 默认为 vector。
  • 底层可替换：stack<int, vector<int>> 合法；queue<int, vector<int>> 不合法（vector 无 pop_front）。
  • priority_queue 底层是二叉堆：top O(1)，push / pop 均为 O(log n)，批量建堆 O(n)；默认大顶堆，小顶堆需写 greater<int> 作第三个模板参数。
  • set / map 基于红黑树：所有操作 O(log n)（最坏亦有保证），元素按 key 有序，支持 lower_bound 区间查询。
  • unordered_set / unordered_map 基于哈希表：均摊 O(1)，最坏 O(n)，元素无序，不支持区间查询。
  • 选型口诀：要顺序用 map，要速度用 unordered_map；要 LIFO 用 stack，要 FIFO 用 queue，要按优先级用 priority_queue。
1下列声明中无法通过编译的是？
Astack<int, vector<int>> s;
Bqueue<int, vector<int>> q;
Cqueue<int, list<int>> q;
Dpriority_queue<int, vector<int>, greater<int>> pq;
解析：正确答案 B。queue 需要底层容器提供 front()、back()、push_back()、pop_front()，而 vector 没有 pop_front（因为头部删除是 O(n)，标准库刻意不提供），故实例化失败。
A 合法：stack 只需 back / push_back / pop_back，vector 全部具备。
C 合法：list 提供 pop_front，O(1)。
D 合法：这正是小顶堆的标准写法。
要点：适配器对底层容器的要求就是它自己接口所需的那几个成员函数。
2关于 priority_queue<int> pq;（默认参数），下列说法正确的是？
A它是小顶堆，top() 返回最小值，push 为 O(1)
B它是大顶堆，top() 为 O(1)，push 与 pop 均为 O(log n)
C它底层是红黑树，所有操作 O(log n)
D它保持元素完全有序，可以用范围 for 按序遍历
解析：正确答案 B。默认比较器是 less<int>，得到大顶堆；根结点即最大值，故 top() 是 O(1)；push 需向上筛选、pop 需向下筛选，路径长度为树高 ⌊log2n⌋，故均为 O(log n)。
A 两处都错：默认是大顶堆，且 push 不是 O(1)。
C 错在底层是二叉堆（存于 vector 中的完全二叉树），不是红黑树；红黑树是 set/map 的底层。
D 是最深的误解：堆只保证根是最值，整体并不有序；而且 priority_queue 作为适配器根本不提供迭代器，无法用范围 for 遍历。要有序输出只能反复 top + pop。
3统计一篇英文文章中各单词的出现次数，并要求最终按字典序输出结果。最合适的容器与理由是？
Aunordered_map<string,int>，均摊 O(1) 最快，输出时顺序无所谓
Bmap<string,int>，插入 O(log n) 且遍历时天然按字典序
Cvector<pair<string,int>>，可以随机访问
Dpriority_queue<string>，可以按优先级输出
解析：正确答案 B。map 基于红黑树，中序遍历天然给出 key 的升序（字符串即字典序），一次范围 for 即可完成有序输出，插入与累加均为 O(log n)。
A 是最具迷惑性的：unordered_map 的查找确实更快，但它无序，最后仍需把全部条目拷到 vector 再 sort，多出 O(m log m) 的排序与一次完整拷贝。若题目不要求有序，A 才是更优选择——注意审题。
C 的 vector 每次统计都要 O(n) 顺序查找该单词是否已存在，总代价 O(n·m)。
D 的 priority_queue 无法记录"次数"这个附加值，也不支持按 key 查找已有元素。
