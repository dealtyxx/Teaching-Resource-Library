一、STL 五大组件

Standard Template Library
定义

STL（Standard Template Library，标准模板库）是 C++ 标准库中基于泛型编程思想设计的组件集合，由容器（Container）、迭代器（Iterator）、算法（Algorithm）、容器适配器（Adapter）、函数对象（Function Object）五部分构成。其核心设计是：算法不直接依赖容器，而是通过迭代器访问数据，从而使 m 个算法与 n 个容器只需 m + n 份代码，而非 m × n 份。

算法 ── 迭代器 ── 容器　（迭代器是解耦二者的"胶水"）
// STL 最小完整示例：容器 + 迭代器 + 算法 #include <iostream> #include <vector> // 序列容器 #include <algorithm> // sort / find / count 等泛型算法 using namespace std; int main() { vector<int> v; // 声明一个空的 int 向量 v.push_back(7); // 尾部插入，均摊 O(1) v.push_back(2); v.push_back(9); v.push_back(1); sort(v.begin(), v.end()); // 升序排序，O(n log n) auto it = find(v.begin(), v.end(), 9); // 顺序查找，O(n) if (it != v.end()) cout << "找到 9，下标 = " << (it - v.begin()) << endl; for (int x : v) cout << x << ' '; // 范围 for，输出 1 2 7 9 cout << endl; return 0; }
迭代器区间约定：STL 一律使用左闭右开区间 [begin, end)。end() 指向"最后一个元素的下一个位置"，不可解引用。因此空容器满足 begin() == end()，元素个数恰为 end() - begin()。
// 泛型的威力：同一个 sort 调用形式适用于不同容器/不同排序规则 #include <functional> // greater<int> 等函数对象 sort(v.begin(), v.end(), greater<int>()); // 降序：传入函数对象 sort(v.begin(), v.end(), [](int a, int b) { return abs(a) < abs(b); // 按绝对值升序：传入 lambda }); sort(a, a + n); // 原生数组也能用：指针即迭代器

最后一行说明了迭代器抽象的精髓：原生指针本身就满足随机访问迭代器的全部要求，所以为容器写的算法可以原封不动地用在数组上。

易错点
  • 以为 std::sort 是快速排序、最坏 O(n2)。它是内省排序：递归深度超过 2·log2n 时自动切换堆排序，因此最坏也是 O(n log n)。但它不稳定，需要稳定性时用 stable_sort。
  • 对未排序区间调用 binary_search / lower_bound。编译能过、运行不报错，但结果是错的。二分查找的前置条件是区间已按同一比较规则有序。
  • 对 list 调用 std::sort。编译报错，原因是迭代器类别不满足。应使用 l.sort()。
  • 把 end() 当作最后一个元素。它是"尾后位置"，解引用是未定义行为。区间恒为左闭右开 [begin, end)。
  • 认为 unordered_map 一定比 map 快。哈希表是均摊 O(1)，大量冲突时退化为 O(n)；且它不保证有序。需要按键有序遍历、或需要 lower_bound 时必须用 map。
  • 在遍历中直接插入/删除元素。vector 的插删会使插入点之后的迭代器全部失效，扩容更是使所有迭代器失效；正确写法是 it = v.erase(it); 接住返回值。
本节小结
  • STL 五大组件：容器、迭代器、算法、容器适配器、函数对象；迭代器把算法与容器解耦，使代码量从 m×n 降为 m+n。
  • 标准用法：#include <vector> → vector<int> v; → v.push_back(x); → sort(v.begin(), v.end());。
  • 迭代器区间恒为左闭右开 [begin, end)，end() 不可解引用；原生指针即随机访问迭代器。
  • std::sort 是内省排序，平均与最坏均 O(n log n)，但不稳定；stable_sort 稳定。
  • 选容器看复杂度表：随机访问选 vector / deque；频繁中间插删且已持有迭代器选 list；按键查找选 map（有序，O(log n)）或 unordered_map（无序，均摊 O(1)）。
1关于 std::sort(v.begin(), v.end())，下列说法正确的是？
A它就是标准的快速排序，最坏情况为 O(n2)
B它是冒泡排序的高效实现，复杂度 O(n2)
C它是内省排序，平均与最坏均为 O(n log n)，但不保证稳定
D它是归并排序，因此既是 O(n log n) 又是稳定的
解析：正确答案 C。std::sort 的主流实现是 Introsort（内省排序）：以快排划分为主，当递归深度超过约 2·log2n 时切换堆排序以避免退化，子区间长度小于阈值（通常 16）时改用插入排序减少常数开销。
A 是最常见的误解——正是"切换堆排序"这一步消除了 O(n2) 的最坏情况。
B 完全错误。
D 的迷惑点在于把"O(n log n)"与"稳定"绑定：归并排序确实两者兼备，但 std::sort 用的不是归并；要稳定必须显式用 stable_sort。
2需要维护一批学号，要求能按学号从小到大遍历，且插入与查找都要快。最合适的容器是？
Avector，插入 O(1)、访问 O(1)
Bunordered_set，查找均摊 O(1) 最快
Cset，插入与查找均为 O(log n) 且天然有序
Dlist，插入 O(1) 最快
解析：正确答案 C。set 基于红黑树，中序遍历天然升序，插入 / 查找 / 删除均为 O(log n)，同时满足两项要求。
B 是最具迷惑性的：unordered_set 查找确实更快（均摊 O(1)），但它基于哈希表，元素无序，无法满足"按学号从小到大遍历"——需要有序时必须付出 O(log n) 的代价。
A 的 vector 若要保持有序，每次插入需移动元素，是 O(n)。
D 的 list 插入 O(1) 的前提是已知位置；按值查找是 O(n)，且无法保持有序。
3下列代码存在问题，问题在哪里？
list<int> l = {3,1,2}; sort(l.begin(), l.end());
A没问题，可以正常编译运行
B能编译，但结果错误
C编译失败，因为 list 只提供双向迭代器，而 std::sort 要求随机访问迭代器
D编译失败，因为 list 不支持初始化列表
解析：正确答案 C。std::sort 内部需要 it + k、it2 - it1 这类随机访问操作来做划分，而 list 的节点在内存中不连续，其迭代器只支持 ++ / --（双向迭代器），因此模板实例化失败。
正确写法是调用成员函数 l.sort();，它是专为链表设计的归并排序，O(n log n) 且只改指针不搬数据。
B 错在这是编译期就能发现的类型错误，不会留到运行期；D 错在 list 支持初始化列表。
本题说明：迭代器分类不是理论装饰，它直接决定哪些算法可用。
