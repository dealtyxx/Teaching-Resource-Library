学习目标

  1. 能够复述算法的严格定义，并说明它与"程序"的三点区别。
  2. 能够逐条解释五大特性各自解决什么问题，以及违反后会产生什么后果。
  3. 能够判定给定的一段描述是否构成算法，并指出它违反了哪一条特性。
  4. 能够写出欧几里得算法的 C++ 实现，并说明它为什么满足有穷性。

一、算法的定义

Definition of Algorithm
定义

算法（Algorithm）是求解某一特定问题的一组有限的指令序列。对于该问题的任何一个合法输入，算法都能在执行有限步之后终止，并产生满足要求的输出。

这个定义中有三个关键词必须抠住："特定问题"说明算法是有适用范围的（gcd 算法不能拿来排序）；"有限的指令序列"说明算法本身长度有限，不能是无穷长的描述；"执行有限步之后终止"说明算法的运行过程也必须有限。二者缺一不可——一个只有 3 行的死循环程序，描述有限但运行无限，仍然不是算法。

三、五大特性详解

为什么必要 · 违反后会怎样
性质 1

有穷性（Finiteness）：算法必须在执行有限步之后终止，且每一步都在有限时间内完成。
为什么必要：算法的目的是"给出答案"。若永不终止，就永远拿不到输出，算法失去意义。
违反后果：程序死循环、进程挂起、资源被无限占用。
反例：while (x != 0) x = x + 2; 当 x 为正奇数时 x 永远不等于 0，该过程不是算法。

性质 2

确定性（Definiteness）：算法的每一条指令都有确切的含义，不存在二义性；相同的输入在相同的条件下只能得到相同的执行路径。
为什么必要：算法要能被机械地执行，执行者（人或计算机）不能在中途"自行判断"。
违反后果：不同执行者得到不同结果，算法不可复现、无法验证正确性。
反例："把数组适当地调整一下，使它看起来比较有序" ——"适当"和"比较有序"含糊不清，无法机械执行。

性质 3

可行性（Effectiveness）：算法中的每一步都必须是基本运算，原则上可以用纸笔在有限时间内精确完成。
为什么必要：确保算法能被真实的计算模型实现，而不是停留在数学描述层面。
违反后果：算法在纸面上"正确"，却无法编码实现。
反例："取 x 为 π 的精确十进制值" ——π 是无理数，无穷不循环，不可能在有限步内精确写出。又如"求解一个一般的丢番图方程"（希尔伯特第十问题）已被证明不存在通用算法。

性质 4

有输入（Input）：算法有零个或多个输入，输入取自某个特定的对象集合（即问题的合法输入域）。
为什么必要：输入刻画了算法的作用对象与适用范围。
说明：注意是"零个或多个"——例如"打印 1 到 100 的所有素数"没有外部输入，数据已内嵌在算法中，它仍然是合法算法。

性质 5

有输出（Output）：算法有一个或多个输出，输出是与输入有确定关系的量，即问题的解。
为什么必要：没有输出的计算过程无法向外界传递结果，等于什么也没做。
违反后果：算法"跑完了"但无人知道答案。
反例：一个只在内部把数组排好序、既不返回也不打印、结束时局部变量全部销毁的过程，对外没有任何可观测结果。
注意：与输入不同，输出至少要有一个，不能为零。

记忆口诀："有穷、确定、可行；零入、必出"。前三条约束算法的过程，后两条约束算法的接口。

四、算法 vs 程序

Algorithm vs. Program

两者常被混用，但在本课程中必须区分：算法是解决问题的方法与步骤（思想层面），程序是算法在某种程序设计语言下的具体实现（代码层面）。同一个算法可以有 C++、Java、Python 等多种程序实现。

对比项算法 Algorithm程序 Program
本质求解问题的方法与步骤算法用某种语言的具体表述
描述方式自然语言、流程图、伪代码必须是特定程序设计语言的语法
有穷性必须满足，否则不是算法不要求，如操作系统是"死循环"程序
与机器的关系与语言、机器无关依赖语言、编译器、运行环境
关注点正确性、复杂度可读性、可维护性、工程实现
经典结论：操作系统是一个"永不终止"的程序，它不是算法——因为它违反有穷性。但操作系统内部的进程调度、页面置换等模块，每一次调用都在有限步内结束，那些是算法。所以：程序不一定是算法，算法可以用程序实现。

五、实例：欧几里得算法

Euclidean Algorithm · 上方演示的 C++ 实现
定理

对任意整数 a > 0、b > 0，有 gcd(a, b) = gcd(b, a mod b)。
证明要点：若 d 同时整除 a 与 b，则 d 也整除 a − ⌊a/b⌋·b = a mod b；反之亦然。故 {a,b} 与 {b, a mod b} 的公约数集合完全相同，最大者自然相等。

// 欧几里得（辗转相除）算法：求 a 与 b 的最大公约数 // 输入：整数 a > 0, b >= 0 输出：gcd(a, b) int gcd(int a, int b) { while (b != 0) { // b 变为 0 时停机 —— 有穷性的保证 int t = a % b; // 余数 t 满足 0 <= t < b a = b; b = t; // 新的 b 严格小于旧的 b } return a; // 有输出：返回最大公约数 } // 递归写法，逻辑等价 int gcd2(int a, int b) { return b == 0 ? a : gcd2(b, a % b); }

五大特性逐条验证：

1
有穷性：每轮循环后新的 b 等于旧的 a mod b，满足 0 ≤ 新b < 旧b。非负整数序列严格递减必在有限步内到达 0，循环必然终止。
2
确定性：%、赋值、比较均为语义明确的运算，无歧义。
3
可行性：取模与赋值都是基本运算，纸笔可算（演示中 1071 与 462 只需 4 步）。
4
有输入：两个整数 a、b。
5
有输出：一个整数 gcd(a, b)。

步数上界推导（为什么很快）：考察连续两轮迭代。

设当前为 (a, b)，且 a ≥ b 一轮之后自动满足 若 b ≤ a/2，则 a mod b < b ≤ a/2 余数小于除数 若 b > a/2，则 a mod b = a − b < a/2 此时商恰为 1 ⇒ 两种情形都有 a mod b < a/2 每两轮至少减半 ⇒ 迭代次数 ≤ 2·log2a = O(log a) 对数级，极快
T(a, b) = O(log min(a, b))

演示中 gcd(1071, 462) 仅用 4 步得到 21，而 log2462 ≈ 8.9，与上界吻合。相比之下，"从 min(a,b) 开始逐个往下试除"的朴素算法是 O(min(a,b))，当 a、b 达到 109 量级时前者约 30 步，后者约 109 步。

易错点
  • 把有穷性理解成"运行时间短"。有穷性只要求步数有限，不要求快。一个需要执行 2100 步的算法虽然实际跑不完，但它满足有穷性；而一个每步都很快的死循环不满足有穷性。"能否终止"是定性问题，"跑多久"是 §03 复杂度的定量问题，两者不可混淆。
  • 认为输入必须至少一个。输入可以是零个（如"输出前 100 个素数"），但输出必须至少一个。两者不对称，考试常在此设陷阱。
  • 把程序等同于算法。操作系统、服务器守护进程都是不终止的程序，它们不是算法；算法必须终止。
  • 混淆确定性与可行性。确定性说的是"指令是否有歧义"，可行性说的是"指令能否在有限步内精确完成"。"取 π 的精确值"含义十分明确（满足确定性），但不可行。
  • 认为确定性等于"没有随机"。严格定义下的确定性指每步含义明确；随机化算法（如随机快排）每步语义仍然明确，只是引入了随机源，属于对经典定义的扩展，并非违反确定性。
本节小结
  • 算法是求解特定问题的有限指令序列，对任何合法输入都能在有限步内终止并给出正确输出。
  • 五大特性：有穷性、确定性、可行性、有输入（零个或多个）、有输出（至少一个）。前三条约束过程，后两条约束接口。
  • 算法 ≠ 程序：算法与语言无关且必须有穷；程序是算法的语言实现，可以不有穷（如操作系统）。
  • 欧几里得算法基于 gcd(a,b) = gcd(b, a mod b)，因"每两轮 a 至少减半"而终止，时间复杂度 O(log min(a,b))。
  • 判定"是不是算法"的标准动作：逐条比对五大特性，找出被违反的那一条。
1下列关于算法特性的说法，正确的是？
A算法必须有至少一个输入和至少一个输出
B满足有穷性意味着算法的运行时间足够短，可以接受
C算法可以没有输入，但必须至少有一个输出
D用 C++ 写出的、能通过编译的代码就一定是算法
解析：正确答案 C。
A 错在输入可以为零个，如"输出前 100 个素数"内嵌了全部数据，仍是合法算法。
B 是最典型的误解：有穷性只要求步数有限，不对时间长短作要求；执行 2100 步的算法仍满足有穷性。
D 错在能编译的代码可能是死循环（违反有穷性），程序不等于算法。
2"把数组中较大的那些元素往后挪一挪，使数组大致有序"——这段描述违反了算法的哪条特性？
A有穷性
B确定性
C可行性
D有输出
解析：正确答案 B。"较大"没有给出比较基准，"挪一挪"没有说明挪多少位，"大致有序"没有可判定的终止条件——这些都是二义性，不同执行者会得到不同结果，违反确定性。
它并不违反可行性（C）：挪动元素本身是完全可以用纸笔完成的基本操作，问题出在"指令说不清楚"而非"做不到"。这正是确定性与可行性的分界线。
3对 gcd(a, b) 的欧几里得算法，下列说法错误的是？
A循环必然终止，因为 b 构成严格递减的非负整数序列
B其时间复杂度为 O(min(a, b))，因为最多做 min(a,b) 次取模
C每经过两轮迭代，a 的值至少减半
D它的正确性依赖于 gcd(a, b) = gcd(b, a mod b) 这一定理
解析：错误的是 B，故选 B。O(min(a,b)) 是"逐个试除"朴素算法的复杂度。欧几里得算法由 C 所述的"两轮减半"性质可得迭代次数为 O(log min(a,b))——例如 a、b 约为 109 时仅需约 30 轮，而非 109 轮。A、C、D 分别是终止性论证、减半推导与正确性依据，均正确。
