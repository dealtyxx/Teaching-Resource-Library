一、时间复杂度的形式化定义

Time Complexity
定义

问题规模（Problem Size）n：刻画输入数据量大小的参数。排序问题中 n 是元素个数，矩阵运算中 n 是阶数，图算法中常用顶点数 n 与边数 e。

定义

基本操作（Basic Operation）：算法中最主要、执行次数与总运行时间成正比的那个操作。排序算法取"元素比较"，矩阵乘法取"乘法"，查找算法取"关键字比较"。

定义

时间复杂度（Time Complexity）：设算法对规模为 n 的输入所执行的基本操作次数为 T(n)，则 T(n) 称为该算法的时间复杂度（的精确表达）。通常我们只关心 n 充分大时 T(n) 的增长数量级，记作 T(n) = O(f(n))。

T(n) = 算法在规模为 n 的输入上执行的基本操作次数
为什么不用"秒"来度量？同一算法在不同 CPU、不同编译器、不同负载下的秒数完全不同，无法比较两个算法的优劣。而基本操作次数只取决于算法本身与输入规模，与硬件无关。这就是"事前分析估算法"优于"事后统计法"的原因。

二、例题：从代码数循环次数推导 T(n)

最核心的基本功

例 1（嵌套循环，上三角）：求下列代码段的时间复杂度，以 cnt++ 为基本操作。

// 例 1：内层循环上界依赖外层变量 int cnt = 0; for (int i = 1; i <= n; i++) // 外层执行 n 次 for (int j = i; j <= n; j++) // 内层执行 n - i + 1 次 cnt++; // 基本操作

推导：固定外层的 i，内层 j 从 i 走到 n，执行 n − i + 1 次。对 i 求和：

T(n) = ∑i=1n (n − i + 1) 按外层逐层累加 　　 = n + (n−1) + (n−2) + … + 2 + 1 展开，i=1 时为 n，i=n 时为 1 　　 = ∑k=1n k 换元 k = n − i + 1，只是倒序 　　 = n(n+1)/2 等差数列求和公式 　　 = n2/2 + n/2 展开 ⇒ T(n) = O(n2) 保留最高次项，舍去系数 1/2 与低阶项 n/2
T(n) = n(n+1)/2 = O(n2)

验算：n = 4 时公式给 4×5/2 = 10；手工数 4+3+2+1 = 10，吻合。注意这里内层不是每次都跑 n 次，所以精确值是 n2/2 而非 n2——但两者同阶，都是 O(n2)。

例 2（步长倍增，对数阶）：

// 例 2：循环变量以乘法方式增长 int cnt = 0; for (int i = 1; i <= n; i = i * 2) cnt++;
设循环体共执行 m 次 待求 i 的取值依次为 1, 2, 4, …, 2m−1 每次翻倍 循环继续的条件：2m−1 ≤ n 最后一次仍进入循环体 两边取以 2 为底的对数：m − 1 ≤ log2n ⇒ m = ⌊log2n⌋ + 1 = O(log n) 对数阶
识别口诀：循环变量做加法递增 ⇒ 线性相关；循环变量做乘除法变化 ⇒ 对数相关。这是判断 O(n) 与 O(log n) 的最快方法。

例 3（并列 vs 嵌套）：两条法则可以处理绝大多数代码段。

性质

加法法则（并列结构）：若程序由两段先后执行的代码构成，T1(n) = O(f(n))，T2(n) = O(g(n))，则总复杂度 T(n) = O(max(f(n), g(n)))。
乘法法则（嵌套结构）：若一段复杂度为 O(g(n)) 的代码被嵌套在执行 O(f(n)) 次的循环中，则 T(n) = O(f(n)·g(n))。

三、空间复杂度

Space Complexity · 与时间同等重要
定义

空间复杂度（Space Complexity）S(n)：算法在执行过程中所需辅助存储空间的数量级，是问题规模 n 的函数。
注意"辅助"二字：输入数据本身占用的空间不计入，只统计算法额外申请的临时变量、辅助数组、递归调用栈等。

S(n) = 算法运行期间额外占用的存储单元数
算法 / 结构额外空间来源S(n)名称
冒泡排序 / 插入排序1 个临时变量O(1)原地（in-place）算法
二分查找（迭代版）low / high / mid 三个变量O(1)原地
二分查找（递归版）递归栈深度 log2nO(log n)对数辅助空间
归并排序与原数组等长的辅助数组O(n)非原地
快速排序（平均）递归栈深度O(log n)—
计数排序计数数组，k 为值域大小O(n + k)以空间换时间
时空权衡（Time-Space Tradeoff）：降低时间往往要付出空间代价，反之亦然。计数排序用 O(n+k) 空间把排序时间降到 O(n+k)，突破了比较排序 Ω(n log n) 的下界；哈希表用额外空间把查找降到均摊 O(1)。分析算法时两者都要报告，不能只说时间。

易错点
  • 把 O(n2/2) 写进答案。渐进复杂度中常数因子必须舍去，n2/2、3n2、n2+100n 统统写作 O(n2)。同理 O(2n) 应写成 O(n)。
  • 看到双重循环就断定 O(n2)。要看内层实际执行次数：内层为 j = i; j <= n 时总数是 n(n+1)/2（仍是 O(n2)），但内层为 j *= 2 时总数是 O(n log n)，内层若与 n 无关则只是 O(n)。
  • 把空间复杂度算成"数组总长度"。S(n) 只统计辅助空间。对长度为 n 的输入数组做冒泡排序，S(n) = O(1) 而不是 O(n)——输入本身不计入。
  • 忘记递归调用栈也占空间。递归版二分查找时间是 O(log n)，空间也是 O(log n)（栈深度），不是 O(1)。这是笔试高频陷阱。
  • 用运行秒数比较两个算法。秒数依赖硬件与编译器；O(n2) 的算法在快机器上可能比 O(n log n) 在慢机器上更快，但 n 增大后必然反超。复杂度比较的是趋势，不是某一次的实测值。
  • 对数的底数纠结。O(log2n)、O(log10n)、O(ln n) 是同一个数量级，因为换底只差常数因子 logab。故统一写 O(log n)。
本节小结
  • T(n) 定义为算法在规模 n 的输入上执行的基本操作次数；用次数而非秒数度量，才能做到与硬件无关。
  • 推导 T(n) 的标准动作：确定基本操作 → 按循环层次写求和式 → 用求和公式化简 → 保留最高阶项、舍去常数。
  • 循环变量做加法递增得线性相关；做乘除法变化得对数相关。并列用加法法则取 max，嵌套用乘法法则相乘。
  • S(n) 只统计辅助空间，输入数据不计；递归算法必须把调用栈深度算进去。
  • 等级序列：O(1) < O(log n) < O(n) < O(n log n) < O(n2) < O(n3) < O(2n) < O(n!)；O(n2) 的实用规模约 104，O(2n) 约 26。
1下列代码段以 x++ 为基本操作，其时间复杂度为？
for (int i = 1; i <= n; i++) for (int j = 1; j <= i; j++) x++;
AO(n)
BO(n log n)
CO(n2)
DO(n2/2)
解析：正确答案 C。T(n) = ∑i=1n i = n(n+1)/2 = n2/2 + n/2 = O(n2)。
D 是最具迷惑性的选项：n(n+1)/2 的精确值确实约为 n2/2，但渐进记号中必须舍去常数因子，写 O(n2/2) 是不规范的——O(n2/2) 与 O(n2) 是同一个集合，按惯例只写后者。
A 错在忽略了内层循环随 i 增长；B 是把 j <= i 误看成 j *= 2 的结果。
2对长度为 n 的数组执行递归版二分查找，其时间复杂度和空间复杂度分别是？
AO(log n) 和 O(1)
BO(log n) 和 O(log n)
CO(log n) 和 O(n)
DO(n) 和 O(log n)
解析：正确答案 B。每次递归把区间减半，递归深度为 ⌊log2n⌋+1，故时间 O(log n)。
A 是最常见的错误：它是迭代版的答案。递归版每层都要在调用栈上压入一帧（保存 low、high、返回地址），栈深度等于递归深度 log n，因此空间是 O(log n) 而非 O(1)。
C 把栈深度误当作元素个数；D 混淆了顺序查找。
教训：分析递归算法的空间时，永远先问"栈有多深"。
3某算法的精确操作次数为 T(n) = 3n2 + 100n·log2n + 5000。下列说法正确的是？
A因为 5000 很大，n 较小时该算法很慢，故复杂度应记为 O(5000)
B因为 100n·log2n 的系数最大，故复杂度为 O(n log n)
C复杂度为 O(n2)，因为 n 充分大时 n2 项占绝对主导
D复杂度为 O(3n2)，系数 3 必须保留以体现实际代价
解析：正确答案 C。渐进分析关心的是 n → ∞ 时的增长趋势：n2 增长快于 n log n，n log n 又快于常数，因此只保留最高阶项 n2 并舍去系数。
A、B 都犯了"用小规模下的数值大小判断阶"的错误——系数 100 再大，当 n 超过某个 n0 后 3n2 必然超过 100n·log2n（约 n > 500 时）。
D 错在渐进记号按定义已允许乘以任意正常数 c，保留系数没有意义。
注意：常数因子在工程上仍然重要，但它属于"常数优化"，不属于复杂度等级的讨论范畴。
