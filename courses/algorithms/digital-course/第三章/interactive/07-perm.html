全排列生成

上方演示为递归交换法（swap-based generation）：逐层把每个候选元素换到当前位置。注意它不按字典序输出——真正的字典序生成算法见本页第三节。

学习目标

  1. 能够写出递归交换法生成全排列的代码，并论证它为何能不重不漏地生成全部 n! 个排列。
  2. 能够写出字典序生成算法（next_permutation）的三步操作，并手工模拟一次。
  3. 能够指出两种算法生成顺序的差别，说明交换法为何不产生字典序。
  4. 能够推导全排列生成的时间复杂度 Θ(n!)（输出全部排列时为 Θ(n·n!)）。
常见标注错误提醒：很多资料把上方这种"递归 + 交换"的写法称为"字典序全排列"，这是不准确的。以 n = 3 为例，交换法的实际输出顺序是
123, 132, 213, 231, 321, 312
而真正的字典序应为
123, 132, 213, 231, 312, 321
最后两项恰好颠倒。本页已据此更正命名，并在第三节补充真正的字典序算法。

一、问题与解空间

Permutation
定义

n 个互异元素 a[0..n−1] 的一个排列（permutation）是把这 n 个元素排成一列的一种有序安排。全排列指全部这样的安排构成的集合，其个数为
n! = n × (n−1) × … × 2 × 1。
排列型解空间与 §06 的子集型解空间的本质区别在于：子集只关心"取不取"，排列还关心"次序"。

穷举全排列的实用上限约为 n = 11。12! 已接近 5×108，再加上每个排列 O(n) 的处理代价就超过 109。这一条是 §08 n 皇后与 §09 TSP 只能取小规模的根本原因。

二、算法一：递归交换法

Swap-based Generation · 上方演示所用
思路

设 dfs(i) 的职责是"把 a[i..n−1] 这段后缀的全部排列都生成一遍，而 a[0..i−1] 保持不动"。做法是：让 a[i] 依次与 a[i], a[i+1], …, a[n−1] 交换——即依次尝试让每一个尚未使用的元素坐上第 i 号位置——每次交换后递归处理 i+1，返回时把交换换回来（回溯）。

// ===== 算法一：递归交换法生成全排列 ===== int a[20], n; void dfs(int i) { if (i == n) { // 前 n 个位置都定好了 output(a, n); return; } for (int j = i; j < n; j++) { // 让 a[j] 来坐第 i 号位置 swap(a[i], a[j]); // ① 交换（做出选择） dfs(i + 1); // ② 递归处理后缀 swap(a[i], a[j]); // ③ 换回来（撤销选择，必不可少） } } // 调用：for(i) a[i]=i+1; dfs(0);
正确性（不重不漏）

对 n−i 施归纳法。
不漏：任取一个目标排列 P。P 在第 i 号位置上的元素必定是 a[i..n−1] 中的某一个，设它当前位于下标 j，则循环的第 j−i+1 次迭代恰好把它换到位置 i；由归纳假设，dfs(i+1) 会生成剩余 n−i−1 个元素的全部排列，其中必含 P 的后缀。故 P 一定被生成。
不重：循环的不同迭代把不同的元素放到位置 i（因元素互异），故不同迭代产生的排列在第 i 位就已不同；同一迭代内部由归纳假设互不相同。故无重复。
关键前提是第 ③ 步的"换回来"：它保证每次迭代开始时 a[i..n−1] 都恢复成同一个集合，否则"每个元素恰好被放到位置 i 一次"的论证不成立。

第一步 设 T(m) 为对长度 m 的后缀生成全排列的时间，则 T(m) = m · T(m−1) + O(m) m 次迭代，每次一对交换 O(1) 第二步 展开得 T(n) = Θ(n!) 递归树的叶子数恰为 n!，内部结点数为 ∑k n!/k! < e·n! 第三步 若每个排列还需 O(n) 输出/处理，则总时间 Θ(n · n!) 与幂集的 n·2n 同理 第四步 空间：递归栈深 n，数组原地交换 故空间 Θ(n)
T(n) = Θ(n!) （仅生成）  /  Θ(n · n!) （含输出）  空间 Θ(n)
n = 3 的完整生成过程（可对照上方演示逐步验证）：初始 a = [1,2,3]
序号i=0 的交换i=1 的交换输出
1swap(0,0) → [1,2,3]swap(1,1)123
2 swap(1,2)132
3swap(0,1) → [2,1,3]swap(1,1)213
4 swap(1,2)231
5swap(0,2) → [3,2,1]swap(1,1)321
6 swap(1,2)312
请特别注意第 5、6 行：当 j = 2 时执行 swap(a[0], a[2])，数组变成 [3,2,1] 而非 [3,1,2]——因为交换是"对调"而不是"取出后把余下元素左移"，剩余元素 {2,1} 的相对次序被打乱成了降序。于是先输出 321、后输出 312，违反字典序。
结论：交换法生成的是"全部 n! 个排列"，但顺序不是字典序。它做到了集合正确（不重不漏），却没有顺序保证。若题目只要求"输出所有排列"，交换法完全够用且效率最高；若题目要求"按字典序输出"或"求下一个排列"，必须改用下一节的算法（或把交换法的结果全部存下来再排序，代价 O(n!·log(n!)·n)，得不偿失）。

三、算法二：字典序生成（next_permutation）

Lexicographic Generation
定义

两个等长序列的字典序（lexicographic order）比较：从左往右找到第一个不同的位置，谁在该位上的元素小谁就小。字典序全排列生成要求按此序从最小排列（升序）依次输出到最大排列（降序）。

算法（三步法）

给定当前排列 a[0..n−1]，求它的下一个字典序排列：
① 找枢轴：从右往左找第一个满足 a[i] < a[i+1] 的下标 i。若不存在（整个序列降序），说明当前已是最后一个排列。
② 找后继：从右往左找第一个满足 a[j] > a[i] 的下标 j（j > i）。
③ 交换并反转：交换 a[i] 与 a[j]，然后把 a[i+1..n−1] 整段反转。

// ===== 算法二：字典序生成（等价于 STL 的 std::next_permutation）===== void reverseRange(int a[], int l, int r) { while (l < r) { swap(a[l], a[r]); l++; r--; } } bool nextPermutation(int a[], int n) { // ① 从右往左找第一个 a[i] < a[i+1]（"上升点"/枢轴） int i = n - 2; while (i >= 0 && a[i] >= a[i + 1]) i--; if (i < 0) { // 整个序列降序 ⟹ 已是最后一个排列 reverseRange(a, 0, n - 1); // 回到最小排列（可选） return false; } // ② 从右往左找第一个大于 a[i] 的 a[j] int j = n - 1; while (a[j] <= a[i]) j--; // ③ 交换后，把 i 之后的后缀反转（降序 ⟹ 升序，即取最小） swap(a[i], a[j]); reverseRange(a, i + 1, n - 1); return true; } // 按字典序输出全部 n! 个排列 void allPermLex(int a[], int n) { sort(a, a + n); // 必须先升序排序，从最小排列开始 do { output(a, n); } while (nextPermutation(a, n)); }
为什么第 ① 步找"从右往左第一个上升点" a[i+1..n−1] 已是降序，说明该后缀已达到它自己的最大排列，无法在不动 a[i] 的前提下变大，故必须抬高 a[i] 为什么第 ② 步从右往左找 后缀是降序的，从右往左第一个大于 a[i] 的元素就是"所有大于 a[i] 的候选中最小的那个"，换上去才能保证增量最小 为什么第 ③ 步交换后后缀仍降序 a[j] 与 a[i] 对调后，后缀各元素的降序性质不被破坏（可验证 a[j−1] ≥ a[i] ≥ a[j+1]） 为什么要反转后缀 前缀已抬高到"下一个"，后缀应取其最小排列即升序；把降序整段反转即得升序，O(n) 完成

易错点
  • 把交换法称作"字典序生成"：本节开头已详述——交换法只保证集合正确，不保证顺序。这是教辅资料中流传最广的错误标注之一。
  • 交换法忘记"换回来"（第 ③ 步 swap）：数组状态被污染，后续迭代的起点不再是同一个集合，会同时产生重复与遗漏。
  • 交换法处理含重复元素的序列：例如 [1,1,2] 会输出 6 个排列而实际只有 3 个不同排列。去重需在循环内加判断（跳过与之前已尝试过的相同元素），或改用 next_permutation。
  • next_permutation 使用前忘记排序：不从最小排列（升序）开始，就只能得到当前排列之后的那部分，而不是全部 n! 个。
  • 第 ② 步写成"从左往右找第一个大于 a[i] 的元素"：由于后缀降序，从左往右找到的是最大的那个候选，换上去会跳过许多排列，生成顺序错误。必须从右往左。
  • 第 ③ 步只交换而忘记反转后缀：交换后的后缀仍是降序（即该前缀下的最大排列），会直接跳到"下一组前缀"，漏掉大量排列。反转这一步不可省。
  • 第 ① 步的判定写成 a[i] > a[i+1] 或用 > 代替 ≥：在含重复元素时，a[i] >= a[i+1] 与 a[i] <= a[i] 这类边界会导致死循环或漏解，须严格按上文代码的比较方向书写。
  • 把复杂度写成 O(2n)：排列型解空间是 n!，n ≥ 4 起就大于 2n，n = 12 时相差约 105 倍。
本节小结
  • n 个互异元素的全排列共 n! 个；穷举全排列的实用上限约 n = 11，这是 §08、§09 只能取小规模的根源。
  • 递归交换法：让 a[i] 依次与 a[i..n−1] 交换 → 递归 → 换回来。正确性靠"每个未用元素恰好被放到位置 i 一次"保证不重不漏；"换回来"是该论证成立的前提。
  • 交换法不产生字典序：n = 3 时输出 123, 132, 213, 231, 321, 312，末两项与字典序（…, 312, 321）相反。原因是 swap 会打乱剩余元素的相对次序。
  • 字典序生成（next_permutation）三步：① 从右找第一个 a[i] < a[i+1]；② 从右找第一个 a[j] > a[i]；③ 交换 a[i]、a[j] 后反转 a[i+1..n−1]。单次均摊 O(1)、最坏 O(n)，空间 O(1)，且天然支持重复元素。
  • 复杂度：生成全排列 Θ(n!)，若需输出每个排列则为 Θ(n·n!)；交换法空间 Θ(n)（递归栈），字典序法空间 Θ(1)。
  • 选用：搜索剪支用交换法，按序输出/求下一个排列用 next_permutation。
1对 a = [1,2,3] 运行递归交换法（for(j=i..n-1){swap(a[i],a[j]); dfs(i+1); swap(a[i],a[j]);}），实际输出顺序是？
A123, 132, 213, 231, 312, 321
B123, 132, 213, 231, 321, 312
C123, 213, 312, 132, 231, 321
D321, 312, 231, 213, 132, 123
解析：B 正确。前四项与字典序一致，但当 i=0、j=2 时执行 swap(a[0],a[2])，数组由 [1,2,3] 变成 [3,2,1]（不是 [3,1,2]！），此时后两位是 {2,1} 的降序状态，于是先输出 321 再输出 312。A 是字典序的正确答案，也是本题最大的陷阱——很多资料正是误把 A 当成交换法的输出。C 是"固定后缀、轮换首位"等其他生成法的顺序。D 是降序生成，需从 [3,2,1] 出发才可能得到。
2用 next_permutation 三步法求 2 3 5 4 1 的下一个字典序排列，结果是？
A2 3 5 1 4
B2 4 1 3 5
C2 4 5 3 1
D2 3 4 5 1
解析：B 正确。①从右找第一个 a[i] < a[i+1]：a[3]=4 > a[4]=1 不满足，a[2]=5 > a[3]=4 不满足，a[1]=3 < a[2]=5 满足，故 i = 1（枢轴 3）。②从右找第一个大于 3 的元素：a[4]=1 否，a[3]=4 是，故 j = 3。③交换得 2 4 5 3 1，再反转 a[2..4]（"5 3 1"→"1 3 5"），得 2 4 1 3 5。选 C 的错误是只交换、忘了反转后缀——这会跳过 24135、24153 等一大批排列，是本算法最高频的实现错误。选 D 是字典序的前一个方向。选 A 只在末两位上做文章，未意识到必须先抬高枢轴。
3关于两种全排列生成算法，下列说法正确的是？
A交换法虽不按字典序，但它生成的排列个数少于 n!，所以更快
Bnext_permutation 每次调用都是 O(n)，故总时间为 O(n2·n!)
C两者生成的排列集合相同（都是全部 n! 个），仅顺序不同；交换法便于剪支，字典序法空间为 O(1) 且天然处理重复元素
D把交换法的输出结果排序后就得到字典序，且这样做的代价可忽略
解析：C 正确，完整概括了两者的异同。A 错得离谱：交换法生成的恰好是全部 n! 个排列（这正是它的正确性所在），一个不多一个不少。B 高估了：next_permutation 单次最坏为 O(n)，但均摊为 O(1)（因为大多数调用只需扫描很短的后缀），生成全部排列的总时间是 Θ(n·n!)，其中的 n 来自输出而非算法本身。D 在结论上可行但"代价可忽略"是错的：要存下 n! 个长度为 n 的排列需 O(n·n!) 空间，n = 10 时已是数十 GB，实践中完全不可接受。
