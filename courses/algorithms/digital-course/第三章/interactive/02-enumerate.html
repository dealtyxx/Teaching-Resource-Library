三种列举方式

多重循环、递归回溯、位运算枚举子集 — 同一幂集三种实现对比。

学习目标

  1. 能够写出三种列举方式的代码骨架：多重循环（k 重 for）、递归回溯（选/不选）、位运算掩码。
  2. 能够判断给定问题的解空间形态，据此选择最合适的列举方式。
  3. 能够解释为什么位运算法在 n > 20 时开销已不可接受、在 n > 31 时还会发生整型溢出。
  4. 能够说明递归回溯与位运算枚举子集时生成顺序的差异，并验证两者都做到不重不漏。

一、方式一：多重循环

Nested Loops · 最直观的列举
定义

多重循环列举（nested-loop enumeration）：当解空间可以写成"k 个下标各自独立取值"的形式时，用 k 重 for 循环逐层遍历。循环层数 k 在编译期固定，因此只适用于 k 是常数（通常 k ≤ 3∼4）的场合。

典型场景：从数组 a[0..n−1] 中枚举一个三元组（i, j, k），要求 i < j < k。约定 i < j < k 是为了保证同一组元素只被枚举一次——这就是"不重不漏"在多重循环中的具体落实方式。

// 多重循环：枚举全部无序三元组 (a[i], a[j], a[k])，i < j < k // 例：三数之和 —— 找出和恰为 T 的一组 bool threeSum(int a[], int n, int T, int r[3]) { for (int i = 0; i < n; i++) // 第 1 层 for (int j = i + 1; j < n; j++) // 第 2 层，从 i+1 起，避免重复 for (int k = j + 1; k < n; k++) { // 第 3 层 if (a[i] + a[j] + a[k] == T) { // 约束检验 r[0] = a[i]; r[1] = a[j]; r[2] = a[k]; return true; } } return false; } // 枚举次数 C(n,3) = n(n-1)(n-2)/6 = Θ(n³)
为什么多重循环枚举不了幂集：子集的"元素个数"本身是变化的（从 0 到 n），而 for 循环的层数在写代码时就固定了。要用多重循环枚举 n 元素的全部子集，就得写 n 重循环——但 n 是运行期变量，语法上无法做到。这正是递归回溯与位运算存在的理由：它们用"递归深度"或"二进制位数"来代替"循环层数"，从而把层数变成运行期可变的量。
特例：若 n 本身是小常数（如固定 3 个骰子、固定 4 位密码），多重循环最直观也最快，无函数调用开销。教材中"百钱买百鸡""水仙花数"这类题目都属此类。

二、方式二：递归回溯（选 / 不选）

Recursive Backtracking
原理

把"为 n 个元素各作一次二选一决策"建模成一棵二叉判定树：第 i 层的两条分支分别代表"选 a[i]"与"不选 a[i]"。从根走到第 n 层叶子的每一条路径，恰好对应一个子集；树共有 2n 个叶子，故不重不漏。

// 递归回溯枚举幂集：path 保存当前已作出的选择 int a[] = {1, 2, 3}, n = 3; int path[32], top = 0; void dfs(int i) { if (i == n) { // 递归出口：n 个决策全部作完 output(path, top); // 得到一个子集 return; } path[top++] = a[i]; // ① 选 a[i] dfs(i + 1); top--; // 回溯：撤销选择（关键！） dfs(i + 1); // ② 不选 a[i] } // 调用：dfs(0); 共产生 2^n 个子集
递归树共 2n+1−1 个结点 满二叉树，深度 n 每个叶子输出一个子集，输出耗时 O(n) 最坏要打印 n 个元素 总时间 T(n) = O(n·2n)，递归栈深度 O(n) 故空间为 O(n)
递归法的独有优势：可以在中途剪支。例如求"和不超过 W 的子集"，一旦当前累加和已超过 W，就可以直接 return，不再展开这棵子树。位运算法必须把 mask 完整生成后才能判断，无法剪支——这是第 5 章回溯法的伏笔。

三、方式三：位运算掩码

Bitmask Enumeration
性质

长度为 n 的 0/1 向量与区间 [0, 2n) 内的整数一一对应（双射）。因此让整数 mask 遍历 0 ∼ 2n−1，就等价于遍历了全部 2n 个子集。这是位运算枚举法正确性的全部依据。

// 位运算枚举幂集：mask 的第 i 位为 1 ⟺ 选中 a[i] void powerSet(int a[], int n) { for (int mask = 0; mask < (1 << n); mask++) { for (int i = 0; i < n; i++) if ((mask >> i) & 1) // 取出第 i 位 printf("%d ", a[i]); printf("\n"); } } // 常用位技巧： // mask & (1 << i) 判断第 i 位是否为 1 // mask | (1 << i) 置第 i 位为 1 // mask & ~(1 << i) 置第 i 位为 0 // mask & (mask - 1) 抹掉最低位的 1（可用来数 1 的个数）
|{ mask : 0 ≤ mask < 2n }| = 2n = |2S|
规模上限（务必记住）：位运算法用一个 int 的二进制位表示整个子集，因此 n ≤ 31 才能用 int（1 << 31 已使 int 溢出为负），n ≤ 63 才能用 long long（须写 1LL << n）。但这只是"能不能表示"的上限；从"跑不跑得完"看，n > 20 时 2n > 106、n > 25 时已过 3×107，实际可用范围是 n ≤ 20∼25。

四、三种方式对比与选用

选用建议推荐方式理由
枚举固定个数的元素（三数之和、两两配对）多重循环层数固定，代码最短、常数最小、无递归开销
枚举全部子集，n ≤ 20，且无剪支需求位运算无递归、无栈开销，mask 本身可直接作数组下标（状压 DP 的基础）
枚举全部子集，n > 20 或需要剪支递归回溯可在中途判断并放弃整棵子树，实际枚举量远小于 2n
枚举排列（TSP、n 皇后、任务分配）递归回溯位掩码只能表示"选或不选"，无法直接表达元素的顺序
需要按特定顺序（如字典序）输出专用生成算法见 §07 的 next_permutation 三步法
生成顺序不同但集合相同：对 a = [1,2,3]，位运算法按 mask 递增输出 ∅, {1}, {2}, {1,2}, {3}, {1,3}, {2,3}, {1,2,3}；上面的递归法（先选后不选）则输出 {1,2,3}, {1,2}, {1,3}, {1}, {2,3}, {2}, {3}, ∅。顺序不同，但都恰好是这 8 个子集——可在上方演示中分别点击两个按钮对比。若题目对输出顺序有要求，必须显式排序或改用指定的生成算法。
易错点
  • 多重循环内层从 0 而非 i+1 开始：会把 (a[0],a[1]) 与 (a[1],a[0]) 当成两个不同解，造成重复枚举；若题目要求无序组合，必须写 j = i + 1。
  • 递归回溯忘记回溯（漏掉 top--）：path 会不断累积，后续所有子集都被污染。"选 → 递归 → 撤销"必须三步齐全。
  • 误把 mask & (1 << i) 的结果直接当作 0/1 使用：它的值是 0 或 2i，不是 0 或 1；作布尔判断没问题，但若要参与算术必须写 (mask >> i) & 1。
  • 运算符优先级：& 的优先级低于 ==，因此 if (mask & 1 << i == 0) 会被解析成 mask & (1 << (i == 0))，必须加括号写成 if ((mask & (1 << i)) == 0)。
  • n ≥ 31 时写 1 << n：int 左移 31 位以上是未定义行为，须改用 1LL << n；不过此时更应反省是否选错了算法。
  • 循环上界写成 mask <= (1 << n)：会多枚举一次，且该次结果与空集重复。
本节小结
  • 多重循环：层数编译期固定，适合 k 元组（k ≤ 3∼4）；内层从 i+1 起可避免重复。无法枚举幂集，因为层数不能随 n 变化。
  • 递归回溯：用递归深度代替循环层数，对每个元素作"选 / 不选"二选一；必须"选 → 递归 → 撤销"三步齐全。唯一支持中途剪支的方式，也是排列型解空间的唯一选择。
  • 位运算掩码：利用 0/1 向量与 [0, 2n) 整数的双射；写法最简、常数最小，但只能枚举子集、不能剪支，且受 int 位宽限制（n ≤ 31，实用 n ≤ 20∼25）。
  • 三种方式的时间同为 O(n·2n) 量级（多重循环为 O(nk)），差别在可表达性与可剪支性，而不在渐进复杂度。
  • 生成顺序因方式而异，但生成的集合相同；对输出顺序有要求时须额外处理。
1要枚举 n 个元素的全部子集，且 n 在运行时才确定，下列方式中无法直接实现的是？
A多重循环（n 重 for）
B递归回溯（选 / 不选）
C位运算掩码（mask 从 0 到 2n−1）
DB 与 C 都无法实现
解析：A 无法实现。for 循环的层数必须在写代码时确定，而 n 是运行期变量，语法上写不出"n 重循环"。B 用递归深度、C 用二进制位数来充当"层数"，两者的层数都随 n 自动变化，故都可行。选 D 的常见误区是认为位运算受 n 限制而"不可用"——n ≤ 31 时它完全可用，且是最简洁的写法；受限不等于无法实现。
2下列 C++ 判断语句中，能正确判定"mask 的第 i 位为 1"的是？
Aif (mask & 1 << i == 1)
Bif (mask & (1 << i) == 1)
Cif ((mask >> i) & 1)
Dif (mask / (1 << i) == 1)
解析：C 正确：先右移 i 位把目标位挪到最低位，再与 1 相与，结果恰为 0 或 1。A 和 B 都栽在优先级上——== 优先级高于 &，A 实际计算 mask & (1 << (i == 1))，B 实际计算 mask & ((1 << i) == 1)，都不是本意。此外即使加对括号，(mask & (1 << i)) == 1 也只在 i = 0 时才可能成立，因为该式的值是 0 或 2i。D 错误：mask 中高于第 i 位的 1 也会被算进商里，例如 mask = 0b110、i = 1 时商为 3 而非 1。
3某问题需枚举 n = 28 个物品的全部子集，但存在一个强剪支条件：一旦已选物品的重量和超过 W 即可放弃。应优先选择哪种列举方式？
A位运算掩码，因为它常数最小、没有函数调用开销
B递归回溯，因为它能在中途放弃整棵子树
C多重循环，因为 28 是常数，可以写 28 重 for
D三者等价，因为渐进复杂度都是 O(n·2n)
解析：B 正确。位运算法必须把 mask 完整生成后才能计算重量，228 ≈ 2.7×108 个 mask 一个都省不掉；递归回溯在第 k 层就能发现超重并直接 return，一次剪支省掉的是 2n−k 个候选解，实际枚举量往往低一两个数量级。A 的"常数小"在这里被"无法剪支"完全抵消。C 虽然理论上可写但工程上荒谬，且一旦 n 改变代码就得重写。D 混淆了最坏渐进复杂度与实际运行量——剪支不改变最坏复杂度，却能极大改善实际表现，这正是第 5 章回溯法的核心思想。
