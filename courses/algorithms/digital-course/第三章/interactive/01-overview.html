一、什么是穷举法

Definition & Framework
定义

穷举法（brute force，又称蛮力法、暴力法、枚举法）是一种基于问题陈述与定义直接求解的策略：把问题的解空间（solution space）中的所有候选解不重不漏地一一列举出来，对每个候选解检验它是否满足问题的约束条件；在最优化问题中，再从所有可行解中选出目标函数值最优的一个。

性质

穷举法的正确性是天然保证的——只要列举做到了"不重不漏"，最优解必定被考察过一次，因此不可能被漏掉。穷举法的全部困难不在正确性，而在效率：解空间往往随规模 n 呈 2n 或 n! 增长。

注意：穷举法 ≠ 无脑循环。它的精髓在于"系统地列举"——必须先想清楚解空间的结构（是子集？是排列？是 k 元组？），再选择与该结构匹配的列举手段。列举方式选错，往往会产生重复解或遗漏解。

二、三步框架与通用伪代码模板

General Template
1
确定解空间 S：明确"一个候选解长什么样"。例如：n 个物品的取舍 → 长度为 n 的 0/1 向量；n 个任务的指派 → 1..n 的一个排列。解空间的形式决定了第 2 步用什么循环。
2
系统列举：用多重循环、递归回溯或位运算掩码，保证 S 中每个元素恰好被访问一次（不重不漏）。
3
逐一检验：对每个候选解 x 判断约束条件；若是最优化问题，同时用目标函数 f(x) 更新当前最优解。
最优解 = arg maxx ∈ S, 满足约束(x) f(x)
// ============ 穷举法通用伪代码模板 ============ // S ：解空间（全体候选解） // 约束 ：可行性判定谓词 // f ：目标函数（求最大值为例） best = -INF; bestX = null; for 每个候选解 x in 解空间 S: if 满足约束(x): // ① 可行性检验 if f(x) > best: // ② 最优性比较 best = f(x); bestX = x; // ③ 更新最优解 return bestX;
第一步 写出解空间的"形状" 这决定了 for 循环的层数或递归的分支数 第二步 把"每个候选解 x in S"替换成具体的列举代码 子集用位掩码，排列用交换递归，k 元组用 k 重循环 第三步 把"满足约束"替换成具体的判定函数 n 皇后中即对角线检查，背包中即容量检查 第四步 若只需可行解（非最优化），把 ②③ 换成"找到即返回" 可提前终止，但最坏情况复杂度不变
只求可行解的变体：若问题只问"存不存在"，把模板中的最优更新换成 if 满足约束(x): return x; 即可；若要统计解的个数，换成 cnt++;。三种变体共用同一套列举骨架，这正是模板的价值。

三、例题演算：子集和问题

Subset Sum · 走完三步框架
问题

子集和问题（subset sum problem）：给定正整数集合 a = {a0, a1, …, an−1} 和目标值 T，问是否存在 a 的一个子集，其元素之和恰为 T？若存在，输出任意一个。

1
确定解空间：一个候选解就是"每个元素选或不选"，即长度为 n 的 0/1 向量 x = (x0, …, xn−1)，xi ∈ {0,1}。故 |S| = 2n。
2
系统列举：用整数 mask 从 0 到 2n−1，mask 的第 i 个二进制位即 xi。每个 mask 对应唯一子集，2n 个 mask 恰好对应 2n 个子集——不重不漏。
3
逐一检验：累加被选中的元素，判断是否等于 T。
// 子集和问题：穷举法（n <= 20 时可用） bool subsetSum(int a[], int n, int T, int ans[], int &m) { for (int mask = 0; mask < (1 << n); mask++) { // ① 列举 2^n 个候选解 int sum = 0; for (int i = 0; i < n; i++) if ((mask >> i) & 1) sum += a[i]; // 第 i 位为 1 表示选中 a[i] if (sum == T) { // ② 约束检验 m = 0; for (int i = 0; i < n; i++) if ((mask >> i) & 1) ans[m++] = a[i]; // ③ 记录解 return true; } } return false; }
手工演算：取 a = {3, 5, 7}，T = 10。mask 从 000 到 111 共 8 个：
000→{}和 0；001→{3}和 3；010→{5}和 5；011→{3,5}和 8；100→{7}和 7；101→{3,7}和 10 ✓。
在第 6 个候选解处命中，返回 {3,7}。注意 mask 的第 0 位对应 a[0]=3，因此 1012 表示选 a[0] 与 a[2]，而不是 a[0] 与 a[1]。

四、复杂度与适用范围

Complexity Analysis

子集和穷举的时间为外层 2n 次乘以内层 O(n) 次累加，即 O(n·2n)；空间为 O(n)（只存当前解）。更一般地：

k 元组nk三数之和、枚举坐标k=3 时 8000k=3 时 27000k ≤ 3∼4
排列n!TSP、任务分配、n 皇后约 2.4×1018天文数字n ≤ 11 左右

经验法则：现代 CPU 每秒约处理 108∼109 次基本操作。2n 型穷举在 n > 25 后已难以接受；n! 型穷举在 n > 11 后基本不可能（12! ≈ 4.79×108 已到极限）。这正是后续章节引入分治（第 4 章）、回溯剪支（第 5 章）、分支限界（第 6 章）、动态规划（第 7 章）、贪心（第 8 章）的根本动因。
易错点
  • 把"穷举"等同于"随便写几层循环"：没有先刻画解空间就动手，最常见的后果是重复计数（同一子集被枚举两次）或遗漏（漏掉空集或全集）。
  • 忘记枚举空解：位掩码要从 mask = 0 开始，循环条件是 mask < (1 << n) 而非 mask ≤ (1 << n) 或 mask < (1 << n) − 1。
  • 在 n ≥ 31 时写 1 << n：int 会溢出，须写 1LL << n；但此时 2n 早已超出可算范围，说明选错了算法。
  • 误以为"提前 return 可行解"能改善最坏情况复杂度：平均可能变快，但最坏仍是 O(2n)，复杂度分析必须按最坏情况给出。
  • 把 2n 与 n! 的大小关系记反：当 n ≥ 4 时 n! > 2n，且差距迅速拉大（可在右侧演示中拖动 n 观察两条柱的长度）。
本节小结
  • 穷举法（brute force）= 不重不漏地列举解空间中的全部候选解 + 逐一检验约束与最优性；正确性天然成立，瓶颈在效率。
  • 通用模板只有三行骨架：for 每个候选解 x ∈ S → if 满足约束(x) → 更新最优解。求可行解、求最优解、求解的个数三种任务共用这一骨架。
  • 三步框架：确定解空间 → 系统列举 → 逐一检验。第一步最关键，它决定了第二步用循环、递归还是位掩码。
  • 子集型解空间规模 2n，排列型规模 n!；实用上限分别约为 n ≤ 25 与 n ≤ 11。
  • 穷举法是算法设计的"基线"：它给出正确答案的下界参照，后续所有优化方法都以"在保证正确的前提下缩小或跳过解空间"为目标。
1用穷举法求解"从 n 个互异整数中选出若干个使其和恰为 T"，若采用位掩码列举，下列循环写法中正确且不重不漏的是？
Afor (int mask = 1; mask <= (1 << n); mask++)
Bfor (int mask = 0; mask < (1 << n); mask++)
Cfor (int mask = 0; mask <= (1 << n); mask++)
Dfor (int mask = 1; mask < (1 << n) − 1; mask++)
解析：n 个元素的子集共 2n 个，对应 mask 取值 0, 1, …, 2n−1，故 B 正确。A 从 1 开始漏掉了空集，且上界取到 2n（对应第 n+1 位为 1）会多枚举一个非法值。C 同样多枚举了 mask = 2n，此时 (mask >> i) & 1 对所有 i < n 都为 0，会把空集重复枚举一次。D 既漏空集又漏全集。注意"漏掉空集"在 T = 0 或允许空子集的题面下就是错解。
2某问题的解空间是 1..n 的全部排列，检验一个候选解需 O(n) 时间。当 n = 12 时，穷举法的总操作数最接近下列哪一项？
A约 4×103
B约 5×108
C约 6×109
D约 4×103（因为 212 = 4096）
解析：总操作数 = 候选解个数 × 单次检验代价 = 12! × 12。12! = 479001600 ≈ 4.79×108，再乘 12 得约 5.7×109，故选 C。选 B 的错误在于忘记乘上检验代价 O(n)——这是复杂度分析中最常见的漏项。选 A/D 的错误在于把排列型解空间误认成子集型：n! 与 2n 在 n = 12 时相差约 105 倍。
3关于穷举法，下列说法错误的是？
A只要列举做到不重不漏，穷举法一定能得到最优解
B穷举法常被用作验证其他复杂算法正确性的对拍基准
C找到第一个可行解就返回，可把最坏时间复杂度从 O(2n) 降到 O(n)
D穷举法的空间复杂度通常远低于时间复杂度，因为无需保存已考察过的候选解
解析：C 错误。提前返回只影响平均情况或幸运情况；当不存在可行解、或可行解恰好排在列举顺序的最后时，仍需遍历全部 2n 个候选解，最坏复杂度不变。复杂度分析若无特别说明一律按最坏情况。A 正确，这是穷举法的正确性保证。B 正确，小规模对拍是穷举法在工程中的主要用途。D 正确，模板中只需 O(n) 空间保存当前候选解与当前最优解。
