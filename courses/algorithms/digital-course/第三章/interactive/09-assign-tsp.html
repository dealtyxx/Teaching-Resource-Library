一、两个问题的形式化

Assignment & TSP
定义（指派问题）

指派问题（assignment problem）：有 n 个人和 n 项任务，第 i 人做第 j 项任务的成本为 C[i][j]。要求给每人分配恰好一项任务、每项任务恰好一人做（即一个排列 π），使总成本 Σi C[i][π(i)] 最小。

定义（旅行商问题）

旅行商问题（TSP，travelling salesman problem）：给定 n 座城市及两两距离 D[i][j]，求一条从某城出发、经过每座城恰好一次再回到出发城的回路（哈密顿回路），使总路程最短。

共同点：两者的解都是一个排列，都可用穷举法「列举所有排列 → 逐一计算目标值 → 取最优」。区别在于指派问题有多项式算法（匈牙利算法 O(n3)），而 TSP 至今没有多项式精确算法。

二、解空间规模与复杂度

为什么穷举只能对付小 n
指派问题：n! 种分配  |  TSP：固定起点后 (n−1)! 条有向回路（对称距离再 ÷2）
复杂度

枚举一个排列后，计算其目标值需 O(n)（累加 n 项）。故穷举总时间为 Θ(n·n!)（指派）与 Θ(n·(n−1)!)=Θ(n!)（TSP）。TSP 固定起点可去掉 n 个「旋转等价」的回路，对称距离下再去掉「反向等价」，故本质不同的回路只有 (n−1)!/2 条。

阶乘爆炸：n 每加 1，枚举量乘以 n。穷举法只适合 n≤10~12 的小规模；再大就必须换动态规划（Held–Karp，O(n2·2n)）、分支限界（第 6 章）或近似算法。

三、C++ 穷举实现

与上方两个演示一致
// ===== 指派问题：枚举全部 n! 个排列，取总成本最小 ===== // C[i][j] = 第 i 人做第 j 项任务的成本 int assign(int C[][N], int n) { int perm[N]; for (int i = 0; i < n; ++i) perm[i] = i; // 初始排列 0,1,…,n-1 int best = INT_MAX; do { int s = 0; for (int i = 0; i < n; ++i) s += C[i][perm[i]]; // O(n) 累加 best = min(best, s); } while (next_permutation(perm, perm + n)); // 遍历 n! 个排列 return best; } // ===== TSP：固定起点城市 0，排列其余 n-1 座城市 ===== int tsp(int D[][N], int n) { int perm[N]; for (int i = 0; i < n - 1; ++i) perm[i] = i + 1; // 城市 1..n-1 int best = INT_MAX; do { int s = D[0][perm[0]]; // 起点 0 → 第一城 for (int i = 0; i + 1 < n - 1; ++i) s += D[perm[i]][perm[i + 1]]; // 相邻城市间距离 s += D[perm[n - 2]][0]; // 最后一城 → 回到起点 best = min(best, s); } while (next_permutation(perm, perm + n - 1)); // (n-1)! 条回路 return best; }
固定起点的作用：回路「0→2→3→1→0」与「2→3→1→0→2」是同一条环，只是起点不同。固定城市 0 为起点可一次性排除这 n 个旋转副本，把枚举量从 n! 降到 (n−1)!。

Worked Example
指派成本矩阵（左侧演示）：C = [[9,2,7,8],[6,4,3,7],[5,8,1,8],[7,6,9,4]]。求最小总成本分配。
观察各行/列的小值：C[2][2]=1、C[0][1]=2 都很小，尝试同时选中 取分配 π = (人0→任务1, 人1→任务0, 人2→任务2, 人3→任务3) 总成本 = C[0][1]+C[1][0]+C[2][2]+C[3][3] = 2 + 6 + 1 + 4 = 13 四项分列不同列，合法 穷举全部 4! = 24 个排列验证，13 即为最小值

五、易错点

Common Pitfalls
易错点
  • 把 TSP 回路数记成 n!：固定起点后应是 (n−1)!；若距离对称还要再 ÷2（正反两向同长）。
  • 穷举 TSP 时忘记加「回到起点」那条边 D[末城][起点]，算出的是路径而非回路。
  • 指派问题误用贪心：每行各取最小值往往列冲突（多人抢同一任务），不是合法分配，贪心也不保证最优。
  • 复杂度只写 n!，漏掉每个排列 O(n) 的求值，正确是 Θ(n·n!)。
  • 用 next_permutation 前忘记把数组排成升序：它只从当前排列生成「字典序更大」的下一个，起始若非最小排列会漏掉一部分。
  • 混淆「NP 难」与「无解」：TSP 有解且穷举必能找到最优，只是时间不可接受；NP 难说的是效率，不是可行性。
本节小结
  • 指派问题与 TSP 的解都是排列，穷举法「列举排列 → 求值 → 取最优」通用。
  • 枚举量：指派 n!、TSP 固定起点 (n−1)!（对称再 ÷2）；每次求值 O(n)，总复杂度 Θ(n·n!)。
  • 阶乘爆炸使穷举只适合 n≤10~12；用 next_permutation 可简洁实现全排列枚举。
  • 演示数据核对：指派最小成本 13，TSP 最短回路 0→2→3→1→0 长 21。
  • TSP 是 NP 难问题，大规模须换动态规划（Held–Karp O(n22n)）、分支限界或近似算法。

1用穷举法求解 n 个城市的对称 TSP，固定一个起点后需要考察的本质不同回路条数是？
An!
B(n−1)!
C(n−1)!/2
D2n
解析：选 C。固定起点排除 n 个旋转等价回路，得 (n−1)!；对称距离下每条回路与其反向回路等长，再除以 2，得 (n−1)!/2。A 未固定起点；B 是有向（非对称）情形；D 是子集数，与排列无关。
2穷举法求解 n 阶指派问题的时间复杂度是？
AΘ(n!)
BΘ(n·n!)
CΘ(n3)
DΘ(2n)
解析：选 B。共 n! 个排列，每个排列累加 n 项成本需 O(n)，故 Θ(n·n!)。A 漏掉了每次求值的 O(n)；C 是匈牙利算法（多项式精确解）的复杂度，不是穷举；D 是子集型搜索的规模。
3关于「TSP 是 NP 难问题」，下列理解正确的是？
ATSP 无解，任何算法都求不出答案
B只要计算机够快，多项式时间内一定能精确求解
C穷举一定能得到最优解，但时间随 n 阶乘增长而不可接受，目前无已知多项式精确算法
DNP 难意味着近似算法也不可能有效
解析：选 C。NP 难刻画的是求解效率而非可行性：穷举必能找到最优解，只是耗时阶乘级。B 错在「多项式精确算法是否存在」正是 P vs NP 未解难题；A 混淆了难解与无解；D 错在度量 TSP（满足三角不等式）有 Christofides 等常数比近似算法，近似恰恰是应对 NP 难的常用手段。
