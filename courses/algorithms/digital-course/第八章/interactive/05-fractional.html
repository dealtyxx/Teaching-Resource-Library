学习目标

  1. 能够写出分数背包问题的数学规划形式：目标函数、容量约束与 0 ≤ xi ≤ 1。
  2. 能够用交换论证完整证明「按单位价值 vi/wi 降序装入」的最优性。
  3. 能够手工计算 w=[10,20,30]、v=[60,100,120]、W=50 的最优值 240 及各 xi 取值。
  4. 能够说清分数背包可贪心、0/1 背包必须 DP 的根本差别在于可分割性。
  5. 能够实现 C++ 代码并规避浮点比较带来的排序隐患。

问题的数学表述

Fractional Knapsack Problem
定义

给定 n 件物品，第 i 件重 wi > 0、价值 vi > 0，背包容量为 W。物品可以任意分割：取走比例 xi ∈ [0, 1] 时，占用重量 xiwi、获得价值 xivi。求各 xi 使总价值最大。

max Σi=1n xi vi
s.t.　Σi=1n xi wi ≤ W　，　0 ≤ xi ≤ 1 (i = 1, 2, …, n)
与 0/1 背包的唯一差别：0/1 背包要求 xi ∈ {0, 1}（整数约束），分数背包放宽为 xi ∈ [0, 1]（连续约束）。就是这一处放宽，让问题从 NP 难变成了 O(n log n) 可解。
贪心准则

定义第 i 件物品的单位价值（性价比）ri = vi / wi。将物品按 ri 降序排列，依次整件装入；当剩余容量不足以装下当前物品时，按比例装入剩余容量对应的一部分，然后结束。

正确性论证 · 交换论证

为什么按 v/w 降序一定最优？
定理

若物品已按单位价值降序排列 v1/w1 ≥ v2/w2 ≥ … ≥ vn/wn，则上述贪心策略得到的解 G 是分数背包问题的最优解。

证明（交换论证） 设 G = (g1, …, gn) 为贪心解，O = (o1, …, on) 为任一最优解（分量即各 xi）   预备：若 Σwi > W，则任何最优解都恰好装满背包   否则尚有剩余容量，可再装入任一未装满物品的一小部分，价值严格增加，与最优矛盾   （若 Σwi ≤ W 则全装即最优，命题平凡成立）   若 G = O，命题成立；否则设 i 为第一处分歧下标，即 gk = ok (k < i) 而 gi ≠ oi 由贪心构造，gi 取的是"容量允许下的最大可能值" ⇒ gi > oi 关键 令 δ = (gi − oi) · wi > 0，即 O 在物品 i 上"少装"的重量   O 也装满了 W，且前 i−1 项与 G 相同 ⇒ O 必在某些下标 j > i 上多装了物品，其重量之和恰为 δ，记为 δj（Σj>i δj = δ）   构造 O'：把这 δ 重量的 j 类物品(j > i)撤出，改装 δ 重量的物品 i   【验可行性】总重量不变，仍恰为 W ✔   物品 i 的比例变为 oi + δ/wi = gi ≤ 1，未超存量；各 δj 撤出后比例 ≥ 0 ✔   ⇒ O' 满足全部约束 ✔ 可分割性在此发挥作用   【验不劣性】价值变化量   Δ = δ · (vi/wi) − Σj>i δj · (vj/wj)   由排序知对每个 j > i 有 vj/wj ≤ vi/wi   ⇒ Σj>i δj · (vj/wj) ≤ (Σj>i δj) · (vi/wi) = δ · (vi/wi)   ⇒ Δ ≥ 0，即 val(O') ≥ val(O) ✔ 此处用到贪心准则本身   又 O 最优 ⇒ val(O') ≤ val(O) ⇒ val(O') = val(O)，故 O' 也最优 且 O' 与 G 的公共前缀已延长到第 i 位 对 i 归纳：至多 n 次替换后得 O(n) = G，且始终最优 ∴ 贪心解 G 最优 ∎
证明的灵魂：不劣性一步用到的不等式 vj/wj ≤ vi/wi 正是贪心准则本身。这是交换论证的通用规律——如果你的证明里从头到尾没用上贪心准则，那一定写错了。

为什么 0/1 背包不能贪？

可分割性是分水岭
根本差别

上面证明中「撤出 δ 重量的 j 类物品、改装 δ 重量的物品 i」这一步，依赖物品能被任意切分。在 0/1 背包中物品是整块的：想多装物品 i，只能整件装或整件不装；想腾地方，也只能整件撤出——重量对不上，交换构造直接失效，定理不成立。

对比分数背包0/1 背包
变量取值xi ∈ [0, 1] 连续xi ∈ {0, 1} 整数
能否贪心能，按 v/w 降序不能（反例见下）
算法排序 + 扫描动态规划
时间复杂度O(n log n)O(n·W) 伪多项式
容量是否用满总能恰好装满（若物品够）常有容量浪费
W=50 时本页数据240（A + B + 2/3·C）220（B + C）；贪心只得 160
问题难度P（多项式可解）NP 难（判定版本 NP 完全）
重要结论：分数背包的最优值（240）是同一实例 0/1 背包最优值（220）的上界。这一性质被分支限界法用作剪枝的界函数，也是 0/1 背包近似算法的分析基础。

C++ 实现与复杂度

排序 + 一遍扫描
// 分数背包 · 按单位价值降序装入 // 时间 O(n log n)，空间 O(1)（不计输入） struct Item { int w, v; }; double fractionalKnapsack(vector<Item> a, int W) { // ① 按 v/w 降序。用交叉相乘做整数比较，避免浮点精度与整除截断 sort(a.begin(), a.end(), [](const Item &x, const Item &y) { return (long long)x.v * y.w > (long long)y.v * x.w; // x.v/x.w > y.v/y.w }); double val = 0; int left = W; // 剩余容量 for (auto &it : a) { // ② 一遍扫描 O(n) if (left == 0) break; if (it.w <= left) { // 整件装得下 left -= it.w; val += it.v; } else { // 装不下 → 切一刀，恰好填满 val += 1.0 * it.v * left / it.w; left = 0; break; // 背包已满，后面的物品不必再看 } } return val; }
T(n) = O(n log n)（排序） + O(n)（扫描） = O(n log n)　　S(n) = O(1)
阶段时间说明
按 v/w 降序排序O(n log n)算法瓶颈
扫描装包O(n)最多切一刀后即终止
合计O(n log n)空间 O(1)
理论最优（选读）O(n)用线性时间选择反复求单位价值中位数并划分，可去掉排序，达到期望/最坏 O(n)

易错点
  • 用整数除法比较单位价值。C++ 中 x.v / x.w 两个 int 相除是整除，(v=3,w=2) 与 (v=1,w=1) 都算作 1，排序失去区分度且不报错。应改用交叉相乘的整数比较。
  • 按价值 vi 降序或按重量 wi 升序排序。都是错的。反例：w=[10,20]、v=[60,100]、W=20，按 v 降序会先装 B(20,100) 塞满得 100，而按 v/w 降序装 A 全部 + B 的一半得 60+50=110。
  • 把分数背包的贪心搬到 0/1 背包上。本页数据即反例：贪心 160，最优 220。
  • 切分时忘记按比例折算价值，写成整件加 vi，导致答案虚高。
  • 切完最后一刀后没有 break，继续循环虽因 left = 0 不再累加，但逻辑不清晰；更糟的是若把条件写成 left >= 0 会产生死循环或错误累加。
  • 返回类型用 int。分数背包的最优值一般不是整数（本页恰好是 240，但换成 W = 45 就会出现小数），必须用 double。
本节小结
  • 分数背包：max Σxivi，s.t. Σxiwi ≤ W，0 ≤ xi ≤ 1。
  • 贪心准则：按单位价值 vi/wi 降序装入，最后一件按比例切分填满。
  • 交换论证：最优解必装满背包；在第一处分歧处 gi > oi，把 O 中 δ 重量的低性价比物品换成物品 i，可行性由可分割性保证，不劣性由 vj/wj ≤ vi/wi 保证。
  • 本页数据答案：xA = 1、xB = 1、xC = 2/3，最优值 240。
  • 0/1 背包同数据贪心只得 160、最优 220：可分割性是能否贪心的分水岭。分数背包最优值还是 0/1 背包最优值的上界。
  • 复杂度 O(n log n)，排序主导；理论上可用线性时间选择降到 O(n)。
1已知 w = [10, 20, 30]、v = [60, 100, 120]、W = 50。分数背包的最优值是多少？
A160
B220
C240
D280
解析：单位价值 6.0 > 5.0 > 4.0，整装 A(10, 60) 与 B(20, 100) 后剩余容量 20，取 C 的 2/3 得 120 × 2/3 = 80，合计 240，选 C。
A 的 160 是把同一数据当成 0/1 背包做贪心的（错误）结果——剩下 20 装不下整件 C 只好放弃。
B 的 220 是 0/1 背包的最优值（B + C 恰好装满 50）。这两个干扰项专门用来检验你是否分清了两个模型。
D 的 280 = 60 + 100 + 120 是三件物品的价值总和，但它们总重 60 > W = 50，根本装不下。
2分数背包可以贪心而 0/1 背包不行，根本原因是？
A分数背包的物品数量通常更少
B物品可任意分割，剩余容量总能被单位价值次高者恰好填满，当前选择不改变后续子问题的形态
C0/1 背包不具有最优子结构
D分数背包中各物品的 v/w 一定互不相同
解析：B 正确。可分割性带来两个后果：其一，装到"卡住"时可以切一刀恰好填满，绝不浪费容量；其二，交换论证中"撤出 δ 重量、换进 δ 重量"这一构造才成立。0/1 背包里物品是整块的，重量对不上，交换直接失效。
C 是常见误解——0/1 背包恰恰具有最优子结构，这正是它能写出 DP 转移方程的原因；它缺的是贪心选择性质。
A 与问题规模有关、与性质无关。
D 不成立，单位价值相同的物品完全可以存在，且丝毫不影响贪心的正确性。
3若排序比较函数写成 return x.v / x.w > y.v / y.w;（v、w 均为 int），会发生什么？
A结果始终正确，只是写法不够优雅
B触发整数除法截断，如 3/2 与 1/1 都得 1，单位价值不同的物品被判为相等，排序错乱导致答案次优
C编译报错，int 不能参与除法比较
D只影响运行效率，不影响正确性
解析：C++ 中两个 int 相除执行整数除法，小数部分被直接丢弃。(v=3, w=2) 的真实单位价值 1.5 与 (v=1, w=1) 的 1.0 都会被算成 1，比较器认为二者"相等"，排序结果不受控，贪心顺序被打乱，最终输出次优解，选 B。
C 错——这段代码能正常编译、能正常运行，只是悄悄给出错误答案，这才是它真正危险的地方。
A、D 都低估了后果：这是正确性 bug 而非风格或性能问题。
改成浮点除法可解决大部分情形，但仍有精度隐患；最稳妥的是交叉相乘 (long long)x.v * y.w > (long long)y.v * x.w。
