Canonical 币制（如人民币）可贪；否则可能翻车。对比两种币制。

问题与贪心策略

硬币找零 Coin Change
定义

给定面额集合 coins = {c1, …, ck}（每种面额无限供应）与目标金额 amount，求凑出 amount 所用硬币数最少的方案。

min  Σ xi   s.t.  Σ ci · xi = amount，  xi ∈ ℤ≥0
贪心准则

把面额降序排列，每一步都取不超过当前剩余金额的最大面额，直到凑满或无法继续。

关键结论：这个贪心并非对所有币制都正确。只有当币制是 canonical（规范）时——如人民币 / 美元硬币——贪心才保证最优；否则可能给出次优解。

正例：canonical 币制

[1,5,10,25] 凑 41 · 对应上方左卡
面额降序 [25,10,5,1]，剩余 left = 41 取 25：left = 41 − 25 = 16，已用 1 枚 取 10：left = 16 − 10 = 6，已用 2 枚 取 5：left = 6 − 5 = 1，已用 3 枚 取 1：left = 1 − 1 = 0，已用 4 枚 凑满 贪心结果 = 25+10+5+1 = 4 枚，且这就是最优
为什么这里贪心对？[1,5,10,25] 满足"每个较大面额都能被较小面额整齐组合"，取最大面额永远不会逼得后续用更多小币来弥补。这类币制称为 canonical。

反例：非 canonical 币制

[1,3,4] 凑 6 · 对应上方右卡 · 逐步自检
贪心（错）：面额降序 [4,3,1]，剩余 left = 6 取 4：left = 6 − 4 = 2，已用 1 枚 抢了 4，反而用不上 3 4 > 2、3 > 2 都装不下，只能取 1：left = 2 − 1 = 1（2 枚） 再取 1：left = 1 − 1 = 0（3 枚） 贪心结果 = 4+1+1 = 3 枚 最优解：3 + 3 = 6，仅 2 枚 比贪心少 1 枚 根因：贪心贪了看似最大的 4，反而错过"两个 3 恰好凑 6"的更优组合
更夸张的反例：币制 [1,15,25] 凑 30，贪心先拿 25，再补 5 个 1 共 6 枚；最优是 15 + 15 = 2 枚。面额之间没有整除式包含关系时，贪心极易翻车。

通用解法 · 完全背包 DP

对任意币制都正确
状态转移

设 dp[x] 为凑出金额 x 所需最少硬币数，dp[0] = 0，其余初始化为 +∞：

dp[x] = minc ∈ coins, c ≤ x ( dp[x − c] + 1 )
对 [1,3,4] 逐格填 dp（自检）： dp[0] = 0；dp[1] = dp[0]+1 = 1；dp[2] = dp[1]+1 = 2 dp[3] = min( dp[2]+1，dp[0]+1(取3) ) = min(3,1) = 1 dp[4] = min( dp[3]+1，dp[1]+1(取3)，dp[0]+1(取4) ) = min(2,2,1) = 1 dp[5] = min( dp[4]+1，dp[2]+1(取3)，dp[1]+1(取4) ) = min(2,3,2) = 2 dp[6] = min( dp[5]+1，dp[3]+1(取3)，dp[2]+1(取4) ) = min(3,2,3) = 2 与最优 3+3 一致
// 贪心找零：仅对 canonical 币制正确 int greedyCoin(vector<int> coins, int amount) { sort(coins.rbegin(), coins.rend()); // 面额降序 int cnt = 0; for (int c : coins) while (amount >= c) { amount -= c; ++cnt; } // 尽量多取大面额 return amount == 0 ? cnt : -1; // 凑不出返回 -1 } // 通用找零：完全背包 DP，对任意币制都正确 int dpCoin(vector<int> &coins, int amount) { const int INF = 1e9; vector<int> dp(amount + 1, INF); dp[0] = 0; for (int x = 1; x <= amount; ++x) for (int c : coins) if (c <= x && dp[x - c] + 1 < dp[x]) dp[x] = dp[x - c] + 1; // 状态转移 return dp[amount] >= INF ? -1 : dp[amount]; }
贪心 T = O(k log k + amount)　　DP T = O(amount · k)，S = O(amount)
易错点
  • 默认贪心永远对。贪心找零只在 canonical 币制成立；[1,3,4]、[1,15,25] 等都会给出次优解。
  • 以为贪心"换个取法"就能修对。纯"每次取最大面额"在 [1,3,4] 凑 6 上无论如何都得 3 枚，唯一正解是 DP。
  • DP 忘记把 dp 初始化为 +∞、只置 dp[0]=0。否则无法区分"凑不出"与"0 枚"。
  • 把找零 DP 当 0/1 背包写。硬币可重复使用，是完全背包，同一面额可反复取。
  • 用 dp[x−c]+1 前不判 c ≤ x。会访问非法负下标或越界。
  • 凑不出时返回 0 而非标记失败。应返回 −1 或保留 +∞，避免误报"0 枚即成功"。
本节小结
  • 贪心找零 = 每次取不超过剩余金额的最大面额，O(k log k + amount)。
  • 贪心只对 canonical 币制正确；[1,5,10,25] 凑 41 得 4 枚且最优。
  • 反例 [1,3,4] 凑 6：贪心 4+1+1 = 3 枚，最优 3+3 = 2 枚；[1,15,25] 凑 30 差距更大（6 vs 2）。
  • 通用正解是完全背包 DP：dp[x] = min(dp[x−c]) + 1，O(amount·k)，对任意币制都对。
  • 选贪心还是 DP，取决于币制是否 canonical——不确定时用 DP 最稳妥。
1面额 [1,3,4] 凑 6，"每次取最大面额"贪心与真正最优分别用几枚硬币？
A2 枚 和 2 枚
B3 枚 和 2 枚
C3 枚 和 3 枚
D2 枚 和 3 枚
解析：贪心先取 4，剩 2 只能用 1+1，共 4+1+1 = 3 枚；最优是 3+3 = 2 枚。贪心因抢了看似最大的 4，反而错过"两个 3 恰好凑 6"，故选 B。
2关于贪心找零的正确性，下列说法正确的是？
A只要面额里含 1，贪心就一定最优
B贪心仅对 canonical 币制最优，一般币制需用完全背包 DP
C贪心对任意币制都最优，DP 只是更慢的等价写法
D找零问题不存在多项式时间的最优算法
解析：[1,3,4] 含 1 却在凑 6 时翻车，故 A、C 错。对固定 amount 有 O(amount·k) 的 DP，故 D 错。正确的是 B：贪心只在 canonical 币制成立，一般币制必须 DP。
3完全背包解找零，正确的状态转移是（dp[x] 为凑出 x 的最少硬币数）？
Adp[x] = dp[x−1] + 1
Bdp[x] = minc≤x( dp[x−c] + 1 )，dp[0]=0，其余初值 +∞
Cdp[x] = maxc≤x( dp[x−c] + 1 )
Ddp[x] = dp[x−c] + dp[c]
解析：凑出 x 的最后一枚硬币面额为某个 c ≤ x，剩下 x−c 的最少枚数即 dp[x−c]，加 1 后对所有 c 取最小（选 B）。求"最少"故用 min 不是 max（C 错）；A 只考虑面额 1，D 语义不通。dp[0]=0、其余置 +∞ 才能区分"凑不出"。
