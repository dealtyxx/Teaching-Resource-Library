贪心法的形式化描述

先把话说清楚，才能证明
定义

贪心法（greedy algorithm）：把问题的解看作一个由若干决策组成的序列。算法按某个固定的贪心准则（greedy criterion）逐步做出决策，每一步都在当前可行的候选中选取该准则下最好的一个，选定后不再回溯、不再修改。最终得到的决策序列即为算法的输出解 G。

贪心选择性质

存在某一个最优解，它包含贪心算法所做的第一步选择。
注意措辞是"存在一个"而不是"每一个"——最优解可能有很多个，我们只需要证明其中至少有一个与贪心的第一步相容，就足以让贪心"不吃亏地走下去"。

最优子结构

做出第一步贪心选择 g1 之后，原问题退化为一个规模更小的同类子问题 P'；并且
「g1 ∪ P' 的最优解」＝「原问题 P 的最优解」。
即：整体最优必然包含子问题的最优。

为什么两条都要？最优子结构是贪心与动态规划共有的前提；贪心选择性质是贪心独有的额外要求。0/1 背包有最优子结构（所以能 DP），但没有贪心选择性质（所以不能贪）——这正是两者的分水岭。

核心方法论 · 交换论证

exchange argument · 本章唯一必须掌握的证明技术
证明目标

设 G 为贪心算法输出的解，需证明 G 是最优解。
直接证明"G 最优"很困难；交换论证的思路是反过来：任取一个最优解 O，通过一系列保持可行、保持不劣的替换，把 O 一步步"改造"成 G。既然每步替换都不使解变差，而起点 O 是最优的，那么终点 G 也必然最优。

记 G = ⟨g1, g2, …, gk⟩ 为贪心解，O 为任意一个最优解 设定对象 ① 若 O = G，命题直接成立；否则设 i 为二者的第一处分歧下标 定位分歧点    即 g1…gi−1 与 O 的前 i−1 项完全相同，而 gi ≠ oi ② 构造 O' ：把 O 中的 oi 替换为贪心的选择 gi（必要时同步删去一个冲突元素） 做交换 ③ 验证可行性：O' 仍满足问题的全部约束 必须验证 1 ④ 验证不劣性：val(O') ≥ val(O)（最大化）或 cost(O') ≤ cost(O)（最小化） 必须验证 2    这一步必须用到贪心准则本身——gi 是当前准则下最好的，所以换进来不会更差 ⑤ 由 O 最优知 val(O') ≤ val(O)，结合④得 val(O') = val(O)，故 O' 也是最优解 夹逼    且 O' 与 G 的公共前缀长度 ≥ i，严格比 O 更接近 G ⑥ 对分歧点下标作归纳：重复②~⑤ 至多 k 次，得最优解 O(k) = G 归纳收尾 ∴ G 是最优解 ∎
写证明时的三个得分点：①明确指出"第一处分歧"；②交换后分别验证可行性与不劣性，缺一不可；③说明替换有限次终止（因为公共前缀长度每次至少 +1，而解长有限）。
变体

贪心保持领先（greedy stays ahead）：另一种等价写法。对每个 j，用归纳法证明"贪心解的前 j 项在某个度量上不劣于任意可行解的前 j 项"，再推出整体不劣。活动安排既可用交换论证也可用领先论证——第 02 节两种都会展示。

反例：0/1 背包按性价比贪心

贪心（按 v/w 降序，物品不可分割）：   取 A：剩余容量 50 − 10 = 40，累计价值 60   取 B：剩余容量 40 − 20 = 20，累计价值 60 + 100 = 160   看 C：wC = 30 > 20，装不下，跳过 留下 20 的容量白白浪费   贪心结果 = 160（已用重量 30，浪费 20） 最优解（0/1 背包）：   放弃"性价比最高"的 A，取 B + C：重量 20 + 30 = 50 恰好装满   最优值 = 100 + 120 = 220 比贪心多 60 对照：若物品可分割（分数背包），贪心取 A + B + (2/3)·C   = 60 + 100 + 120 × 20/30 = 60 + 100 + 80 = 240，此时贪心确实最优
根本原因

0/1 背包中"是否取物品 i"会改变剩余容量，而不同剩余容量下的最优组合完全不同——只保留一个候选必然丢失最优解，因此不满足贪心选择性质。分数背包允许任意分割，剩余容量总能被单位价值次高的物品"灌满"，当前选择不影响后续问题的形态，故贪心成立。可分割性是分水岭。

选错方法比写错代码更致命
对比维度贪心法动态规划
每步保留的候选数1 个（不回退）多个状态全部保留

贪心算法的代码骨架

C++ · 排序 + 一遍扫描
// 贪心法通用骨架：排序确定考察顺序，再一遍扫描逐个决策 // 时间 O(n log n) —— 排序主导；空间 O(1)（不计输入与排序栈） struct Item { int w, v; }; bool cmp(const Item &x, const Item &y) { // ① 贪心准则：本例按单位价值降序（不同问题只需替换这一行） return (long long)x.v * y.w > (long long)y.v * x.w; // x.v/x.w > y.v/y.w，避免浮点误差 } double greedy(Item a[], int n, int W) { sort(a, a + n, cmp); // ② 一次排序 O(n log n) double val = 0; int left = W; for (int i = 0; i < n && left > 0; ++i) { // ③ 一遍扫描 O(n) if (a[i].w <= left) { // 可行性检查 left -= a[i].w; val += a[i].v; // 整件装入 } else { val += 1.0 * a[i].v * left / a[i].w; // 分数背包才允许这一行 left = 0; } } return val; }
T(n) = O(n log n) （排序） + O(n) （扫描） = O(n log n)　　S(n) = O(1)
易错点
  • 只验证例子不写证明。贪心策略在若干组数据上正确，不代表普遍正确；考试中"证明策略最优"通常是主要得分点。
  • 误以为最优子结构就够了。0/1 背包同样有最优子结构，但贪心失败。缺的是贪心选择性质。
  • 把"存在一个最优解包含贪心选择"读成"所有最优解都包含"。后者往往不成立（最优解常不唯一），也不是证明所需。
  • 交换后只验证可行性、漏掉不劣性（或反之）。两条都要写。
  • 贪心准则用浮点数比较排序，如 x.v/x.w > y.v/y.w，在数据较大时可能因精度导致排序不稳定；改用交叉相乘的整数比较更稳妥。
  • 忘记贪心失败时是"静默"的——程序不会报错，只会给出一个看起来合理的次优解。
本节小结
  • 贪心法 = 按固定准则逐步做不可回退的局部最优决策。
  • 正确性需要两条性质：贪心选择性质（存在一个最优解含贪心第一步）与最优子结构（整体最优含子问题最优）。前者是贪心独有的门槛。
  • 交换论证是本章的证明主武器：定位第一处分歧 → 交换 → 验可行 → 验不劣 → 夹逼得 O' 仍最优 → 归纳把 O 改造成 G。
  • 典型反例：w=[10,20,30]、v=[60,100,120]、W=50 时，0/1 背包贪心得 160，最优 220；可分割时贪心得 240 且最优。可分割性是能否贪心的分水岭。
  • 贪心典型复杂度 O(n log n)，由排序主导；无法贪心时退回动态规划。
1关于贪心选择性质与最优子结构，下列说法正确的是？
A只要问题具有最优子结构，贪心法就一定正确
B贪心选择性质是指「存在一个最优解包含贪心所做的第一步选择」
C动态规划不要求最优子结构，只有贪心才要求
D贪心选择性质与最优子结构是同一件事的两种说法
解析：A 错——0/1 背包具有最优子结构（所以能写出 DP 方程），但按性价比贪心会得到 160 而非 220，可见最优子结构远不足以支持贪心。C 错——最优子结构恰恰是动态规划的前提之一，是二者共有的性质。D 错——两条性质相互独立：最优子结构说的是"整体最优含子问题最优"，贪心选择性质说的是"第一步可以放心地按准则定死"，后者是贪心额外背负的证明义务。故选 B，注意是"存在一个"而非"所有"。
2用交换论证证明贪心最优时，把最优解 O 在第一处分歧点的选择替换成贪心的选择得到 O' 后，必须验证哪两件事？
AO' 的元素个数不变，且字典序比 O 更小
BO' 仍然可行，且 O' 的目标值不劣于 O
CO' 与贪心解 G 完全相同
D产生 O' 的算法比产生 O 的算法运行更快
解析：交换论证的两根支柱就是可行性与不劣性，缺一则整条论证断裂。A 的字典序与最优性无关（元素个数在某些问题中确实不变，但那是结论不是要验证的条件）。C 是常见误解：如果一次交换就能得到 O'=G，就不需要归纳了；通法是每次交换只把公共前缀延长至少 1 位，再靠归纳走完。D 把"证明最优性"与"分析效率"混为一谈，二者完全无关。
3已知 w = [10, 20, 30]、v = [60, 100, 120]、W = 50。若物品不可分割（0/1 背包），按 v/w 降序贪心得到的总价值与真正的最优值分别是？
A220 和 220
B160 和 220
C240 和 240
D160 和 160
解析：贪心按单位价值 6.0 > 5.0 > 4.0 排序，先取 A（剩 40，值 60），再取 B（剩 20，值 160），C 重 30 装不下，最终 160，白白浪费 20 的容量。最优解要"忍住"不拿性价比最高的 A，改取 B+C 恰好填满 50，得 220。选项 C 的 240 是分数背包的答案（A + B + 2/3·C = 60+100+80），把可分割与不可分割两个模型混淆了——这正是本节最需要分清的一条界线。A 误以为贪心也能拿到 220，D 误以为 160 已是最优。
