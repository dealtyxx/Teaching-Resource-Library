本章学习目标

Chapter Objectives

学完本章，你应当能够

  1. 准确陈述贪心法成立的两大前提：贪心选择性质（greedy-choice property）与最优子结构（optimal substructure），并说明二者的区别。
  2. 独立写出交换论证（exchange argument）的完整证明骨架，并用它证明活动安排、分数背包、田忌赛马、单机 SPT 调度等策略的最优性。
  3. 识别贪心失效的典型场景，并能给出具体反例数据（0/1 背包按性价比贪心、非标准币制的零钱兑换）。
  4. 实现本章全部算法的 C++ 代码，并分析时间复杂度——本章绝大多数算法为 O(n log n)，由排序或堆操作主导。
  5. 判别一个新问题应当用贪心还是动态规划，并说明判据。
  6. 解释哈夫曼编码中前缀码、带权路径长度 WPL 的含义与计算方法。

贪心法 vs 动态规划

何时能贪、何时必须 DP
对比维度贪心法 Greedy动态规划 Dynamic Programming
决策方式每步做一次局部最优选择，选定后不回退枚举当前步的所有决策，取其中最优
依赖性质贪心选择性质 + 最优子结构最优子结构 + 重叠子问题
子问题数量每层只保留 1 个子问题，形成一条链每层保留多个状态，形成一张 DAG
典型复杂度O(n log n)（排序主导）O(n·W)、O(n2)、O(n3) 等
正确性来源必须单独证明（交换论证 / 归纳）由状态转移方程的穷举性天然保证
典型例题活动安排、分数背包、哈夫曼编码0/1 背包、最长公共子序列、矩阵连乘
用错的后果输出可行但次优的解（最危险：不报错）状态空间过大导致超时或超内存
判据

能贪的信号：当前这一步的最优选择不改变剩余子问题的形态与可行性——即"选完就可以把它从问题中彻底删掉"。例如活动安排选定最早结束的活动后，剩下的仍是同类型的活动安排问题；分数背包因为物品可分割，装满剩余容量的方式与已装内容无关。

判据

必须 DP 的信号：当前选择会影响后续可选集合的结构，必须同时保留多个候选状态。例如 0/1 背包中"取不取物品 i"会改变剩余容量，而不同剩余容量下的最优组合完全不同，只留一个候选必然丢失最优解。

关键提醒：贪心算法即使策略错误也会顺利输出一个可行解，不会崩溃、不会报错。因此「写完就必须证明或找反例」是本章唯一的安全阀。
