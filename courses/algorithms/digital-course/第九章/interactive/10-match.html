二分图最大匹配

一、匹配、增广路与匈牙利算法

Bipartite Matching
基本定义

图 G = (X ∪ Y, E) 若顶点能分成 X、Y 两部且每条边一端在 X、一端在 Y，则为二分图。边集 M ⊆ E 若两两不共端点，称 M 为一个匹配；边数最多的匹配称最大匹配。被 M 覆盖的点叫匹配点，否则为未匹配点。

交替路 / 增广路

一条路径若其边交替地属于 M 与不属于 M，称为交替路。若一条交替路的两个端点都是未匹配点，称为增广路。增广路上非匹配边比匹配边多一条；把路径上"匹配"与"非匹配"身份全部翻转，匹配数就 +1。

Berge 定理

匹配 M 是最大匹配，当且仅当图中不存在关于 M 的增广路。

这条定理是所有匹配算法的正确性基石：只要还能找到增广路就翻转（匹配 +1），找不到时即为最大匹配。

匈牙利算法 依次为每个左点 u 尝试找一条增广路 找到则匹配数 +1 DFS 找路 u 试探每个邻居 v：若 v 未匹配，直接配上；否则递归让 v 当前的对象 matchR[v] 另寻出路 腾出 v 给 u 让路成功 若 matchR[v] 找到了别的匹配，则 v 改配 u，返回成功 沿增广路翻转 复杂度 每个左点一次 DFS 遍历 O(E) 条边，共 V 个点，O(V·E) used[] 每轮重置

二、König 定理与对偶关系

最大匹配 = 最小点覆盖
点覆盖 / 独立集

点覆盖：一个顶点子集 C，使每条边至少有一个端点在 C 中；点数最少的叫最小点覆盖。独立集：一个两两无边相连的顶点子集；点数最多的叫最大独立集。

König 定理

在二分图中，最大匹配的边数 = 最小点覆盖的点数。

König 二分图：最大匹配 |M*| = 最小点覆盖 |C*| 互为对偶 补集关系 任意图中，C 是点覆盖 ⇔ V−C 是独立集 覆盖每条边 = 补集内部无边 推论 最大独立集 = n − 最小点覆盖 = n − 最大匹配 n 为总点数，二分图专属 DAG 最小路径覆盖 拆点建二分图后 = n − 最大匹配 同一套对偶的常见应用
建模成最大流：把二分图匹配转成网络流——建源 s 连向每个左点（容量 1）、每个右点连向汇 t（容量 1）、原二分图的边从左指向右（容量 1）。此网络的最大流 = 最大匹配；每条 s→左→右→t 的增广路恰对应一次匹配增广。由于是单位容量网络，用 Dinic 求解复杂度为 O(E√V)，优于匈牙利的 O(V·E)。

三、规范 C++ 代码

匈牙利算法
// 匈牙利算法 —— 二分图最大匹配，O(V·E) const int N = 505; int nl, nr; // 左部点数 nl、右部点数 nr vector<int> g[N]; // g[u]：左点 u 邻接的右点列表 int matchR[N]; // matchR[v]：与右点 v 匹配的左点，-1 表示未匹配 bool used[N]; // 本次 DFS 中右点是否已被访问 bool dfs(int u) { // 尝试为左点 u 找增广路 for (int v : g[u]) { if (used[v]) continue; // 同一轮不重复试探同一右点 used[v] = true; // v 未匹配，或 v 当前的对象能另寻出路 → u 配 v if (matchR[v] == -1 || dfs(matchR[v])) { matchR[v] = u; return true; } } return false; } int hungarian() { int cnt = 0; fill(matchR, matchR + nr, -1); for (int u = 0; u < nl; u++) { fill(used, used + nr, false); // ★ 每个左点开始前必须清空 used if (dfs(u)) cnt++; // 找到增广路，匹配数 +1 } return cnt; }
递归 dfs(matchR[v]) 的含义：右点 v 已被左点 matchR[v] 占用时，就递归地让那个左点去另找一个右点。若它成功让出，v 就空出来配给 u——这一串"让位"正是沿增广路翻转匹配的过程。used[] 防止同一轮里两个左点争夺同一右点导致死循环。
易错点
  • 每个左点开始前忘记清空 used[]：used 只在"为当前左点找增广路"这一轮内有效，不重置会漏配甚至死循环。
  • 匹配数组只更新单侧：网络流写法要同时维护 matchL 与 matchR；匈牙利写法靠 matchR + DFS 回溯隐式维护左侧，别再手动写乱。
  • 误以为"最大匹配 = 最小点覆盖"对一般图都成立：König 定理仅限二分图；一般图的最大匹配要用带花树（Blossom）。
  • 把最大独立集算成 n − 最大匹配却忘了它经由 König：该式是"n − 最小点覆盖"，只因二分图里最小点覆盖 = 最大匹配才成立。
  • 增广路理解错：增广路两端必须都是未匹配点，且边交替属于/不属于 M；漏掉任一条件翻转后匹配数不增。
  • 用最大流建模时容量没设为 1：源→左、左→右、右→汇的容量都应为 1，否则求出的不是匹配。
本节小结
  • 匹配是两两不共端点的边集；增广路是两端均未匹配的交替路，翻转它使匹配数 +1。
  • Berge 定理：M 最大 ⇔ 无增广路——这是所有匹配算法"找不到增广路即停止"的依据。
  • 匈牙利算法为每个左点 DFS 找增广路（递归让位），复杂度 O(V·E)，每轮务必重置 used[]。
  • König 定理（仅二分图）：最大匹配 = 最小点覆盖；由补集关系推出最大独立集 = n − 最大匹配。
  • 匹配可建模为单位容量最大流（源→左→右→汇各容量 1），用 Dinic 求解为 O(E√V)。
1关于"增广路"，下列描述正确的是？
A任意一条连接两个未匹配点的路径
B边交替属于/不属于 M、且两端点都未匹配的路径；翻转后匹配数 +1
C全部由匹配边组成的路径
D连接两个已匹配点的最短路径
解析：B 正确。增广路必须同时满足两点：边在 M 与非 M 之间交替；两个端点都是未匹配点。这样路径上非匹配边比匹配边多一条，翻转身份后匹配数恰好 +1。A 漏掉"交替"这一关键约束。C、D 都不符合定义——增广路以非匹配边开头结尾、两端未匹配。由 Berge 定理，不存在增广路即为最大匹配。
2König 定理陈述的是什么？其适用范围？
A任意图中，最大匹配 = 最小点覆盖
B二分图中，最大匹配的边数 = 最小点覆盖的点数
C二分图中，最大匹配 = 最大独立集
D任意图中，最大独立集 = n − 最大匹配
解析：B 正确。König 定理专属二分图：最大匹配 = 最小点覆盖。A 错在"任意图"——一般图不成立，需用带花树求匹配。C 错：最大匹配与最大独立集不相等，正确关系是"最大独立集 = n − 最大匹配"（经由 König：n − 最小点覆盖）。D 的等式在二分图里对，但"任意图"错——它依赖 König，故仅限二分图。
3匈牙利算法实现中，为什么每次为一个新的左点找增广路之前都要清空 used[]？
A为了统计访问过的右点数量
Bused[] 只在为当前左点找一条增广路的这一轮内有效，用来防止同一轮里重复试探同一右点、避免死循环；换一个左点必须重置
C不清空也完全正确，只是稍慢
Dused[] 记录的是最终匹配结果，清空会丢失匹配
解析：B 正确。used[v] 标记"在本轮（为当前左点找增广路）中右点 v 是否已被试探过"，作用是防止递归让位时两个左点反复争抢同一右点而死循环。它是单轮临时状态，为下一个左点服务时必须清零。C 错：不清空会导致后续左点看到残留的 used 标记而漏找增广路，结果偏小甚至出错。D 混淆了 used 与 matchR——真正记录匹配的是 matchR[]，used 只是临时访问标记。
