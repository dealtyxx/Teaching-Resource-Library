一、用 BFS 找最短增广路

Edmonds-Karp
Edmonds-Karp 算法

Edmonds-Karp 是 Ford-Fulkerson 方法的具体化：每一轮都用 BFS 在残量网络中找一条边数最少（最短）的 s→t 增广路，沿路推入瓶颈流量。用 BFS 而非任意找路，是 EK 相对朴素 FF 的唯一改动，却把复杂度从依赖流值的 O(E·|f*|) 改进为与容量数值无关的 O(V·E2)。

为什么"最短"能带来改进：任意找路（如 DFS）可能反复走很长的路、每次只增广一点点，轮数与容量挂钩。BFS 保证每次增广路是残量图中边数最少的，配合下面的引理，可证增广的总次数被 O(V·E) 这个纯粹由图规模决定的量卡住，与容量多大无关。

二、复杂度 O(V·E²) 的论证

关键边计数
记号 δf(s, v) = 残量网络中 s 到 v 的最短边数（BFS 层数） 每次增广前重新 BFS 引理 1 随着不断增广，对每个 v，δf(s, v) 单调不减 增广只可能新增反向边，不会缩短 s 到任何点的距离 关键边 一次增广中，残量恰等于瓶颈 Δ 而被"用光"的边 (u, v) 称为关键边；此时 δ(s, v) = δ(s, u) + 1 它在最短增广路上 引理 2 (u, v) 再次成为关键边前，必须先由反向边 (v, u) 复活，那时 δ(s, u) = δ(s, v) + 1 (v,u) 在某条最短路上 推论 两次关键之间 δ(s, u) 至少增加 2 由引理 1、2 合并 计数 δ(s, u) ∈ [0, V]，故每条边至多关键 O(V) 次；边数 O(E)（含反向），关键事件共 O(V·E) 每次增广至少产生一条关键边 总计 增广次数 O(V·E)，每轮 BFS O(E)，总时间 O(V·E2) 与容量数值无关

三、规范 C++ 代码

BFS 版最大流
// Edmonds-Karp —— BFS 找最短增广路，O(V·E^2)。成对存边，e[i^1] 为反向边 const int N = 1005, INF = 0x3f3f3f3f; struct Edge { int to, cap; }; vector<Edge> e; vector<int> g[N]; int S, T, n, pre[N]; // pre[v]：BFS 树中进入 v 的边下标 void addEdge(int u, int v, int c) { g[u].push_back(e.size()); e.push_back({v, c}); g[v].push_back(e.size()); e.push_back({u, 0}); } bool bfs() { // 找一条最短增广路，成功则 pre[] 记录路径 fill(pre, pre + n, -1); queue<int> q; q.push(S); pre[S] = -2; // -2 标记源已访问，区别于 -1 while (!q.empty()) { int u = q.front(); q.pop(); for (int id : g[u]) { Edge &ed = e[id]; if (pre[ed.to] == -1 && ed.cap > 0) { // 未访问且有残量 pre[ed.to] = id; if (ed.to == T) return true; q.push(ed.to); } } } return false; } int maxflow() { int flow = 0; while (bfs()) { int d = INF; for (int v = T; v != S; v = e[pre[v] ^ 1].to) // 回溯找瓶颈 d = min(d, e[pre[v]].cap); for (int v = T; v != S; v = e[pre[v] ^ 1].to) { // 再回溯一次更新残量 e[pre[v]].cap -= d; // 正向 −Δ e[pre[v] ^ 1].cap += d; // 反向 +Δ } flow += d; } return flow; }
回溯技巧：pre[v] 存"进入 v 的边下标"，那么这条边的反向边 e[pre[v]^1].to 恰是 v 的前驱结点。于是 v = e[pre[v]^1].to 即可沿增广路一路回到 S，两趟循环分别求瓶颈与更新残量。
易错点
  • 把 EK 的 BFS 写成 DFS：那就退回朴素 FF，丢掉 O(V·E2) 的保证，大容量图上可能极慢。
  • BFS 里用 vis 标记却忘了区分源点：源点也要标记已访问（这里用 pre[S]=−2），否则可能把源当未访问重复入队。
  • 回溯前驱时把 e[pre[v]^1].to 写成 e[pre[v]].to：后者是 v 自己，前驱应由反向边取得。
  • 只回溯一趟就边求瓶颈边更新：瓶颈要先整条求出再更新，否则前面改了残量会影响后面求 min。
  • 误以为"增广次数取决于容量"：EK 的增广次数是 O(V·E)，与容量数值无关，这正是它优于朴素 FF 的地方。
  • 把复杂度记成 O(V2·E)：那是 Dinic；EK 是 O(V·E2)，别混淆。
本节小结
  • Edmonds-Karp = Ford-Fulkerson + BFS 找边数最少的增广路，是对朴素 FF 的最小而关键的改动。
  • 关键引理：增广过程中残量图内 δf(s, v) 单调不减；一条边两次成为瓶颈之间 δ(s, u) 至少 +2。
  • 由 δ ∈ [0, V] 得每边至多关键 O(V) 次，边数 O(E)，故增广次数 O(V·E)。
  • 每轮 BFS O(E)，总复杂度 O(V·E2)，与容量数值无关，克服了朴素 FF 的伪多项式缺陷。
  • 实现要点：BFS 记前驱边、回溯先求瓶颈再更新残量、正向 −Δ 反向 +Δ；下一节 Dinic 用分层图进一步降到 O(V2·E)。
1Edmonds-Karp 相对朴素 Ford-Fulkerson 的核心改动是什么？
A不再需要反向边
B每次用 BFS 找边数最少的增广路，而不是任意找路
C改用 Dijkstra 找容量最大的增广路
D把有向图改成无向图处理
解析：B 正确。EK 就是"FF + BFS 找最短增广路"，其余（残量网络、反向边、正减反加）与 FF 完全一致，所以 A 错。C 描述的是另一类"最大容量增广路"策略，不是 EK。D 与网络流无关。正因为改用 BFS，才能证出与容量无关的 O(V·E2)。
2Edmonds-Karp 的时间复杂度及其含义，正确的是？
AO(E·|f*|)，随容量数值增长
BO(V·E2)，与容量数值无关
CO(V2·E)，与容量数值无关
DO(V3)，仅适用于稠密图
解析：B 正确。增广次数 O(V·E)（每边至多关键 O(V) 次），每轮 BFS O(E)，相乘得 O(V·E2)，且不含流值，故与容量数值无关。A 是朴素 FF 的伪多项式复杂度——EK 的意义正是摆脱它。C 是 Dinic 的复杂度，常被与 EK 混淆。D 不是 EK 的结论。
3EK 复杂度证明中，"每条边至多成为 O(V) 次关键边"依赖于哪条事实？
A每次增广后残量图中 δ(s, v) 单调不减，且一条边两次关键之间 δ(s, u) 至少增加 2
B每条边的容量至多为 V
CBFS 每次只访问 V 个结点
D增广路长度恒定不变
解析：A 正确。关键计数的核心是两条引理：δf(s, v) 随增广单调不减；边 (u, v) 两次成为关键边之间，δ(s, u) 至少 +2。由于 δ(s, u) 的取值范围是 [0, V]，故每条边至多关键 O(V) 次，从而增广次数 O(V·E)。B 与容量无关（EK 复杂度本就与容量数值无关）。C 只是单次 BFS 的代价，不解释关键次数。D 恰恰错误——增广路长度是单调不减而非不变。
