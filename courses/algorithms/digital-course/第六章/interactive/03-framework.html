学习目标

  1. 能够默写队列式与优先队列式分支限界法的完整 C++ 框架，并指出限界剪支在框架中的位置。
  2. 能够复述分支限界法的五步标准流程：初始化 → 取扩展结点 → 生成全部子结点 → 限界与可行性筛选 → 循环直至表空。
  3. 能够说明两种框架的唯一结构差异（活结点表的数据结构）如何导致完全不同的搜索顺序。
  4. 能够解释为什么优先队列式在代价单调时「首次取出叶结点即得最优解」。
FIFO

队列式分支限界法

先进先出 ＝ 解空间树上的 BFS。单位权最短路、迷宫问题最爱。

// ==== 队列式（FIFO）分支限界 · 最小化 ==== struct Node { int level, cost; State s; }; int fifoBB(State root) { queue<Node> q; // 活结点表 = 普通队列 q.push({0, 0, root}); int best = INF; // 最小化 ⇒ 初值 +∞ while (!q.empty()) { Node u = q.front(); q.pop(); // ① u 成为扩展结点 E-node if (isLeaf(u)) { // 完整可行解 best = min(best, u.cost); continue; // u 变死结点 } for (Node v : children(u)) { // ② 一次生成全部子结点 if (!feasible(v)) continue; // ③ 约束函数：不可行则丢弃 if (lb(v) >= best) continue; // ④ 限界函数：无希望则剪支 q.push(v); // ⑤ 存活 ⇒ 入队尾 } } // 队空 ⇒ 搜索结束 return best; }
Best-first

优先队列式分支限界法

按 ub/lb 取堆顶（LC ＝ Least Cost）。更激进地逼近最优。

// ==== 优先队列式（LC）分支限界 · 最小化 ==== struct Node { int level, cost, lb; State s; // STL 默认大顶堆 ⇒ 反向比较得小顶堆 bool operator<(const Node& o) const { return lb > o.lb; // lb 小者先出队 } }; int lcBB(State root) { priority_queue<Node> pq; // 活结点表 = 优先队列 Node r{0, 0, 0, root}; r.lb = lowerBound(r); pq.push(r); int best = INF; while (!pq.empty()) { Node u = pq.top(); pq.pop(); // ① 取 lb 最小者作扩展结点 if (u.lb >= best) break; // 堆顶都没希望 ⇒ 全表无希望 if (isLeaf(u)) { best = u.cost; break; // 首次取出叶结点即最优 } for (Node v : children(u)) { if (!feasible(v)) continue; v.lb = lowerBound(v); if (v.lb >= best) continue; pq.push(v); } } return best; }
一行之差：把上面两段代码逐行对照，会发现结构完全一致——queue 换成 priority_queue、front() 换成 top()，再给结点加一个 lb 字段作为优先级，就完成了从 FIFO 到 LC 的转换。「活结点表的数据结构决定搜索顺序」这句话，在代码层面就是这么朴素。

一、分支限界法的标准流程

五步循环 · 与代码逐条对应

无论队列式还是优先队列式，主循环都是下面五步。把这五步背下来，任何一道分支限界题都能照着填空。

1
初始化：建立空的活结点表，把根结点（对应空的部分解）放入表中；同时把全局最优值 best 初始化为一个平凡值——最大化问题取 −∞ 或 0，最小化问题取 +∞（或用贪心先求出一个可行解的真实值作为初值，可大幅加速剪支）。
2
取出扩展结点：若活结点表为空则算法结束；否则按表的组织规则取出一个结点作为扩展结点 E-node——队列式取队首，优先队列式取限界值最优的堆顶。
3
生成全部子结点：若扩展结点已是叶结点（对应一个完整可行解），则用其真实目标值更新 best，该结点直接变死结点；否则依照问题的分支规则，一次性生成它的全部子结点。这一步就是「分支」（branch）。
4
筛选子结点：对每个新生成的子结点依次做两道检查——先用约束函数判断是否满足问题的可行性约束（如背包不超重、任务不重复分配），再用限界函数计算其限界值并与 best 比较。任一检查未通过即丢弃（该子结点直接成为死结点），两项都通过才加入活结点表。这一步就是「限界」（bound）。
5
循环与终止：扩展结点的全部子结点处理完毕后，它自身成为死结点，永不再被访问；回到第 2 步继续。终止条件为：活结点表变空（已穷尽全部有希望的分支），或在优先队列式中取出了第一个叶结点（代价单调时即最优解），或堆顶结点的限界值已不优于 best（说明全表都没希望）。
初始化 → 取 E-node → 生成全部子结点 → 可行性 ∧ 限界双筛 → 入表 / 丢弃 → 循环
与回溯法流程的对照：回溯法的第 3 步是「生成一个子结点并立即深入」，第 5 步是「无路可走则退回父结点换下一个子结点」。分支限界法没有「退回」这一步——因为它把全部子结点一次性摆进了活结点表，退回也无处可退。

二、两种框架的行为差异

同一棵树，两条路线
行为队列式 FIFO优先队列式 LC
取出规则q.front()pq.top()（按 lb / ub 排序）
结点是否需存限界值不必（只在筛选时临时算）必须存为字段，作为堆的比较键
扩展顺序严格按层，同层按生成先后按潜力跳跃，层与层之间来回穿插
首次到达叶结点是「最浅」的解，未必最优代价单调时即最优解，可立即返回
best 的增长曲线缓慢改善往往很早就逼近最优，剪支随即变强
活结点表峰值可能很大（整层结点同时在表中）通常更小（坏分支早被剪掉）
实现难度低中（需定义比较器、注意堆的大小顶方向）
性质 · LC 为何能「首次取叶即最优」

设 lb 合法且满足：叶结点处 lb ＝ 其真实代价（估计精确）。若从优先队列中取出的结点 u 恰为叶结点，则表中其余任何结点 x 都满足 lb(x) ≥ lb(u) ＝ cost(u)。而 x 子树内任何解的代价 ≥ lb(x) ≥ cost(u)，故不可能存在更优解 ⇒ u 即最优解，可立即返回。这正是 A* 算法最优性证明的雏形（见本章第 8 节）。

注意前提：「首次取叶即最优」要求 lb 在叶结点处等于真实代价，且 lb 合法。若限界函数在叶结点处仍是一个粗略估计（例如把叶也当成部分解去估），这个结论就不成立，必须继续搜完整个表。

三、复杂度分析

两种框架的时空开销
记 M ＝ 算法实际扩展的结点数，d ＝ 每个结点的分支数（子结点个数） 队列式：出/入队均 Θ(1) ⇒ 时间 Θ(M · d · (B + 1))，B 为单次限界计算代价 优先队列式：堆操作 Θ(log|L|)，|L| 为活结点表长度 ⇒ 时间 Θ(M · d · (B + log|L|)) 空间：两者均为 Θ(|L|max)，即活结点表峰值 这是分支限界的主要瓶颈 最坏情况 M ＝ Θ(2n)（子集树）或 Θ(n!)（排列树），限界完全失效 若还需回溯输出方案，每个结点要么存父指针（空间 Θ(|L|)、路径回溯 Θ(树高)），要么直接存部分解（空间放大到 Θ(|L| · n)）
工程提示：优先队列式虽多一个 log 因子，但由于 M 通常显著小于队列式，实际运行往往快数个量级。这是「用更聪明的调度换更少的搜索量」的典型例子。
易错点
  • C++ 的 priority_queue 默认是大顶堆。最小化问题要取 lb 最小者，必须把比较运算符写成 return lb > o.lb;（反向），或使用 greater<> 比较器。写反了会变成「专挑最没希望的扩展」，慢到无法忍受。
  • 把限界剪支写在取出结点之后而完全不在入队之前做——虽然结果正确，但无希望的结点仍然进了表，白白撑大空间。标准做法是入队前先剪一遍，出队后再补剪一遍（因为 best 可能在它排队期间变好了）。
  • 在队列式框架中误以为「第一个到达的叶结点就是最优解」——只有每条边代价相同（如单位权最短路）时才成立。一般情形必须搜完全表。
  • 忘记扩展结点在生成完子结点后就是死结点，试图给它加 visited 标记再回头访问，逻辑混乱。
  • 结点里只存 cost 不存父指针或部分解，最后只能报出最优值而无法输出最优方案。
  • 优先队列中存了大对象（如整个 vector 部分解）却按值拷贝，导致堆操作的常数急剧膨胀。
本节小结
  • 五步流程：初始化活结点表并放入根结点 → 取队首/堆顶作扩展结点 → 生成其全部子结点 → 逐个做可行性与限界筛选决定入表或丢弃 → 重复直到表空或提前终止。
  • 两套框架结构完全一致，唯一差别是活结点表用 queue 还是 priority_queue，以及结点是否携带限界值字段。
  • LC 的优势：早得好 best ⇒ 剪支门槛高 ⇒ 搜索规模小；代价单调且 lb 在叶处精确时，首次取出叶结点即最优解。
  • 复杂度：时间 Θ(M·d·(B+log|L|))，空间 Θ(|L|max)。最坏仍为指数级，空间是主要瓶颈。
  • 本页动画是静态结点的出队顺序对比，用于建立「表的组织方式决定搜索顺序」的直觉，不是完整的扩展-剪支过程。
1用 C++ 的 priority_queue<Node> 实现最小化问题的 LC 分支限界，Node 的比较运算符应写成？
Abool operator<(const Node& o) const { return lb < o.lb; }
Bbool operator<(const Node& o) const { return lb > o.lb; }
Cbool operator>(const Node& o) const { return lb < o.lb; }
D不需要定义，STL 会自动按 lb 从小到大排序
解析：B 正确。priority_queue 默认使用 less<T> 且堆顶是「最大」元素，因此要让 lb 小者排在堆顶，必须把「小于」的语义反过来定义为 lb > o.lb。A 是最常见的错误写法，会得到大顶堆——每次挑出最没希望的结点先扩展，效率灾难。C 定义的是 operator>，而默认比较器只调用 operator<，编译期就会报错（除非显式指定 greater<Node> 作为第三个模板参数，但那时容器声明也要跟着改）。D 错：STL 不知道你想按哪个字段排序，必须显式提供比较方式。
2在分支限界法的五步流程中，「限界剪支」这一动作最恰当的位置是？
A只在子结点入表前做一次即可
B只在结点出表后做一次即可
C入表前先剪一遍，出表后再补剪一遍，两处都做效果最好
D在生成子结点之前对扩展结点做，可省下生成开销
解析：C 正确。入表前剪，可以避免无希望的结点白占活结点表空间；但一个结点从入表到出表可能等待很久，期间 best 已被其他分支改善，原本「有希望」的它现在可能已经没希望了，所以出表后还应再用最新的 best 补剪一次。A 漏了 best 会变好这一动态因素，B 让活结点表被垃圾结点撑爆（这在内存受限时是致命的），两者都只做对了一半。D 看似聪明其实是循环论证：扩展结点是从表里取出来的，它入表时已被剪过一次，出表时再剪就是 C 所说的第二道——D 描述的其实是 B，且「省下生成开销」的说法混淆了两个不同的结点层级。
3某同学用队列式分支限界求 0/1 背包最优值，程序在取出第一个叶结点时就返回其价值。这样做？
A正确。队列式按层扩展，第一个叶结点必然最优
B错误。队列式的出队顺序与目标值无关，必须搜完全表才能确定最优
C错误。应改为取出第一个叶结点后再多扩展一层
D正确，但仅当所有物品重量相同时成立
解析：B 正确。「首次取叶即最优」是优先队列式的性质，其依据是堆顶的限界值不劣于表中其余任何结点。队列式按生成先后出队，与结点的好坏毫无关系——第一个到达的叶结点只是「最早被生成的那条分支」，完全可能很差。A 混淆了两种框架。C 的「多扩展一层」是凭空发明的补丁，无任何理论依据，仍不能保证最优。D 的迷惑性最强：物品重量相同并不能让先到达的叶更优，因为背包的目标是价值最大而非层数最少；单位权保证「先到即最短」的结论适用于以边数为代价的最短路问题，不能平移到背包上。
