一、分支限界法的三要素

E-node · live-node list · bounding function

分支限界法在解空间树上搜索，但与回溯法「一条路走到黑再退回」不同：它一次性生成一个结点的全部子结点（这就是「分支」branch），再用估计值把没希望的子树整个丢掉（这就是「限界」bound）。要把这句话讲精确，需要三个术语。

定义 1 · 扩展结点

扩展结点（E-结点，E-node，expanding node）指当前正在生成子结点的那个结点。分支限界法的每一轮循环恰好有一个扩展结点；一旦它的全部子结点都被生成完毕，它就变成死结点（dead node），不再参与搜索。

定义 2 · 活结点表

活结点表（live-node list）指所有已经生成、但尚未被扩展的结点构成的集合。活结点（live node）即「自身已生成、子结点还没生成完」的结点。活结点表用队列或优先队列组织，其组织方式直接决定了搜索顺序，因而衍生出两种分支限界法。

定义 3 · 限界函数

限界函数（bounding function）是对「以某结点为根的子树内所能取得的最优目标值」的一个估计。求最大值问题用上界 ub（upper bound），要求 ub(x) ≥ 该子树内任何可行解的值；求最小值问题用下界 lb（lower bound），要求 lb(x) ≤ 该子树内任何可行解的代价。

性质 · 三要素的联动

算法主循环可概括为一句话：从活结点表中取出一个结点作为扩展结点 → 生成其全部子结点 → 用限界函数与可行性条件筛选 → 存活者加入活结点表。因此，活结点表的组织方式决定「先搜哪里」，限界函数决定「哪里不必搜」，二者共同决定算法效率。

活结点表 ＝ {已生成 ∧ 未扩展完} · 扩展结点 ∈ 活结点表 · 死结点 ＝ 已扩展完 ∨ 被剪支
分支branch：生成全部子结点 限界bound：用估计值剪掉子树 扩展结点E-node 活结点live node 死结点dead node 解空间树solution space tree

二、两类分支限界法

FIFO 分支限界 vs LC 分支限界

活结点表用什么数据结构组织，就得到什么样的分支限界法。教材中这两个名称必须准确记住，考试常直接考中英文对应。

定义 4 · 队列式分支限界法

队列式分支限界法（FIFO 分支限界法，FIFO branch and bound）用普通队列（先进先出）组织活结点表。每次取队首结点作为扩展结点，其子结点从队尾入队。它按结点生成的先后次序扩展，因而是解空间树上的广度优先搜索。

定义 5 · 优先队列式分支限界法

优先队列式分支限界法（LC 分支限界法，LC branch and bound；LC ＝ Least Cost，最小耗费优先）用优先队列组织活结点表。每次取限界值最有希望的结点作为扩展结点——最大化问题取 ub 最大者，最小化问题取 lb 最小者。它按结点的优先级而非生成次序扩展，因而是最佳优先搜索（best-first search）。

对比项队列式（FIFO）优先队列式（LC）
活结点表结构队列 queue优先队列 priority_queue（堆）
取出规则队首（最早生成者）限界值最优者
本质搜索序广度优先 BFS最佳优先 best-first
单次出队代价Θ(1)Θ(log n)，n 为表长
典型应用单位权最短路、迷宫、八皇后可行解0/1 背包最优解、TSP、任务分配、A*
找到最优解的时机常需搜完整个表首次取出叶结点即最优（代价单调时）
关键直觉：FIFO 是「按辈分排队」，LC 是「按潜力插队」。LC 每次都赌在最有希望的分支上，因此往往更早得到一个好的 best 值，从而让限界函数剪掉更多子树——好的 best 值本身就是最强的剪支武器。

三、回溯法 vs 分支限界法 · 完整对照

四个维度逐一辨析
维度回溯法 backtracking分支限界法 branch and bound
搜索方式深度优先（DFS），一次只沿一条路径向下广度优先或最佳优先，一次生成全部子结点
活结点组织系统递归栈（隐式），栈顶即扩展结点显式队列 / 优先队列
扩展结点的命运成为扩展结点后可反复被返回（回溯），沿另一子分支继续成为扩展结点后一次性生成全部子结点，随即变死结点，不再返回
求解目标找出全部解，或任一可行解找出最优解（某种意义下的极值）
剪支依据约束函数（可行性）＋ 限界函数（最优性）同样两类，但限界函数是主力，且与全局 best 联动
空间复杂度Θ(树高)，通常 Θ(n)Θ(活结点数)，最坏可达 Θ(2n)
典型题N 皇后所有解、全排列、图的全部路径、子集和最短路径、0/1 背包最优值、TSP、任务分配、八数码
常见误解澄清：「分支限界一定比回溯快」是错的。若问题要求枚举全部解，分支限界毫无优势且空间开销更大；若解空间极深而宽度很小，回溯法的 Θ(n) 空间也远优于分支限界的指数级活结点表。两者是互补而非替代关系。
// 分支限界法的通用骨架（以最大化问题为例） // 三要素在代码中的落点已用注释标出 double branchAndBound() { Container live; // ← 要素二：活结点表（queue 或 priority_queue） live.push(root); double best = -INF; // 当前已知最优可行解 while (!live.empty()) { Node u = live.take(); // ← 要素一：取出扩展结点 E-node if (u.isLeaf()) { best = max(best, u.value); continue; } for (Node v : u.children()) { // 分支：一次生成全部子结点 if (!feasible(v)) continue; // 约束函数：不可行则丢弃 if (ub(v) <= best) continue; // ← 要素三：限界剪支 live.push(v); // 存活者成为新的活结点 } // u 的子结点已全部生成 ⇒ u 成为死结点，自然被丢弃 } return best; }

把 Container 换成 queue<Node> 就是队列式分支限界；换成 priority_queue<Node>（按 ub 降序）就是优先队列式分支限界。两种框架的差异仅此一行。

四、复杂度概览

为什么分支限界仍是指数级
设解空间树共 N 个结点，单个结点的限界计算耗时 B 分支限界的两项主要开销 最坏情况：无任何剪支 ⇒ 时间 Θ(N · (B + log N))，log N 来自优先队列的插入/删除 子集树 N = Θ(2n)，排列树 N = Θ(n!) 这是问题本身的规模，剪支只能降常数与实际分支数 空间：活结点表最坏同时容纳 Θ(N) 个结点 ⇒ 空间 Θ(2n) 或 Θ(n!) 结论：分支限界不改变最坏复杂度阶，只在平均意义上大幅缩小实际搜索的结点数
与回溯法的空间对比：回溯法的空间是 Θ(树高)＝Θ(n)，因为栈中只存一条根到当前结点的路径；分支限界必须显式保存所有活结点，空间是其致命短板。这正是 IDA*、迭代加深等混合技术出现的原因。
易错点
  • 把「活结点表」等同于「已访问结点集合」——活结点表只装已生成但未扩展完的结点，扩展完的死结点必须移出。
  • 认为扩展结点在分支限界中也会被「回溯」回来——不会。一个结点一旦成为扩展结点并生成完全部子结点，立刻变成死结点，不再有第二次机会。这是与回溯法最本质的区别。
  • 混淆「队列式 ＝ BFS」与「优先队列式 ＝ DFS」——优先队列式是最佳优先，不是深度优先；它的搜索路径可能在树中来回跳跃，既不像 BFS 也不像 DFS。
  • 把 LC 的 LC 误读成 "Lowest Child"——LC ＝ Least Cost（最小耗费）。
  • 误以为分支限界法只能求最优解不能求可行解——它当然能求可行解，只是「杀鸡用牛刀」，此时限界函数退化为纯约束函数，优势荡然无存。
  • 忘记分支限界同样需要约束函数做可行性剪支。限界函数管「最优性」，约束函数管「合法性」，两者缺一不可。
本节小结
  • 三要素：扩展结点（正在生成子结点的结点）、活结点表（已生成未扩展完的结点集合）、限界函数（对子树内最优值的估计）。
  • 一句话流程：从活结点表取扩展结点 → 生成全部子结点 → 可行性 + 限界双重筛选 → 存活者入表 → 扩展结点变死结点。
  • 两种形态：队列式（FIFO，普通队列，广度优先）与优先队列式（LC，优先队列，最佳优先）。二者仅活结点表的数据结构不同。
  • 与回溯法的分水岭：回溯法 DFS＋隐式栈＋求全部解＋Θ(n) 空间；分支限界 BFS/最佳优先＋显式队列＋求最优解＋指数级空间。
  • 复杂度真相：分支限界不降低最坏复杂度阶，其价值在于用限界函数把平均搜索规模压下来。
1关于分支限界法中的「扩展结点」，下列说法正确的是？
A扩展结点是活结点表中限界值最优的结点
B扩展结点一旦生成完全部子结点即成为死结点，不会再被扩展
C算法运行过程中可以同时存在多个扩展结点
D扩展结点在生成一个子结点后会立即被换成该子结点
解析：B 正确，这是分支限界与回溯法的本质分野。A 只在优先队列式中成立，队列式取的是队首而非最优者，故 A 以偏概全。C 错：每一轮循环有且仅有一个扩展结点。D 描述的恰恰是回溯法的行为——回溯法生成一个子结点就立刻下沉过去；分支限界则要一次生成全部子结点后才换人，这正是「分支」二字的含义。
2某问题要求「输出图中从 s 到 t 的所有简单路径」。选用哪种方法更合适？为什么？
A回溯法。目标是枚举全部解，分支限界无优势且空间开销大
B队列式分支限界法。BFS 能保证不重不漏地枚举
C优先队列式分支限界法。按路径长度排序输出更规整
D两者等价，任选其一即可
解析：A 正确。分支限界的全部威力来自「用限界函数剪掉不可能含最优解的子树」，而要求全部解时根本无解可剪——每一条路径都是要输出的答案，限界函数无用武之地。此时分支限界退化为一个空间开销 Θ(2n) 的低效 BFS，而回溯法只需 Θ(n) 栈空间。B 的「不重不漏」回溯法同样做得到，且更省空间。C 是典型迷惑项：排序输出是后处理需求，不构成选择搜索策略的理由，且 LC 的优先级是限界值不是最终路径长。D 忽略了空间复杂度的巨大差异。
3下列关于队列式与优先队列式分支限界法的比较，错误的是？
A队列式按结点生成的先后次序扩展，本质是解空间树上的 BFS
B优先队列式的单次取出代价为 Θ(log n)，高于队列式的 Θ(1)
C优先队列式是深度优先搜索，因为它总是往最深的分支钻
D优先队列式常能更早得到较好的 best 值，从而增强后续剪支
解析：C 错误，是本题答案。优先队列式是最佳优先搜索（best-first），它依据限界值挑选结点，搜索点可能在树的不同深度、不同分支间来回跳跃——既非 DFS 也非 BFS。「往最深处钻」只是它在限界函数很紧时看起来的表象，一旦某深层结点的限界值变差，它会立刻转去扩展浅层的兄弟结点。A、B、D 均正确；D 揭示了 LC 的核心优势：早得好 best ⇒ 剪支门槛更高 ⇒ 搜索规模更小。
