一、限界函数的定义与合法性

为什么剪支不会剪掉最优解

限界函数是整个分支限界法的理论基石。它必须满足一个严格的条件，否则算法虽然跑得飞快，却会给出错误答案——这正是本章第 6 节要重点纠正的经典陷阱。

定义 · 限界函数

设结点 x 位于解空间树上，记 S(x) 为「以 x 为根的子树中所有可行解」构成的集合，记 val(y) 为可行解 y 的目标值。
对最大化问题，函数 ub(·) 称为合法的上界函数，当且仅当对任意结点 x 与任意 y ∈ S(x)，都有 ub(x) ≥ val(y)。
对最小化问题，函数 lb(·) 称为合法的下界函数，当且仅当对任意结点 x 与任意 y ∈ S(x)，都有 lb(x) ≤ val(y)。

最大化：ub(x) ≥ maxy∈S(x) val(y)   ·   最小化：lb(x) ≤ miny∈S(x) val(y)
定理 · 剪支的正确性

设 best 是算法当前已找到的某个真实可行解的目标值。若 ub(·) 是合法上界函数，则当 ub(x) ≤ best 时丢弃结点 x 的整棵子树，不会使算法丢失最优解。

设 y* 是子树 S(x) 中的任意可行解 要证明丢弃它们都不亏 由上界合法性：val(y*) ≤ ub(x) 定义直接给出 由剪支条件：ub(x) ≤ best 这是触发剪支的前提 传递可得：val(y*) ≤ best 不等式串联 而 best 对应的解是已经握在手里的真实可行解 关键：best 不是估计值 ⇒ 子树 S(x) 内不存在严格优于已知解的可行解 ⇒ 整棵子树可安全丢弃 ∎
证明中最容易被忽略的一环：best 必须来自一个真实构造出来的可行解，而不能是另一个估计值。若用估计值当 best，上面的推理链在最后一步断裂——你只能得出「子树内没有比某个估计更好的解」，这毫无意义。因此代码中 best 只在到达叶结点并验证可行时才更新。
推论 · 剪支条件用 ≤ 还是 <

若只需求出一个最优解，用 ub(x) ≤ best 剪支（丢弃「不严格更优」的子树）即可，剪支力度更大。若需求出全部最优解，必须放宽为 ub(x) < best，否则会漏掉与当前 best 目标值相同的其他最优解。浮点比较时还需加 ε：ub(x) ≤ best + 1e-9。

二、紧与松：限界函数的质量

tightness · 剪支力度与计算代价的权衡

合法性只是「及格线」。同一个问题可以有无穷多个合法上界，它们的效率天差地别。

性质 · 限界越紧，剪支越强

若 ub1 与 ub2 都合法且对任意结点 x 有 ub1(x) ≤ ub2(x)，则称 ub1 更紧（tighter）。此时凡 ub2 能剪掉的结点 ub1 必能剪掉，故 ub1 搜索的结点数不多于 ub2。最紧的合法上界就是子树内的真实最优值本身——但那需要先解出子问题，等于没说。

0/1 背包的三种上界表达式紧度单点代价评价
平凡上界ub ＝ 全部物品价值之和极松Θ(1)合法但几乎剪不掉任何结点
密度上界ub ＝ cv ＋ 剩余容量 × 最大密度较紧Θ(1)实用，预处理出最大密度即可
分数背包松弛ub ＝ cv ＋ 分数背包最优值很紧Θ(n)本章第 6 节采用；前提是按密度降序
权衡：限界越紧，每个结点省下的子树越多，但每个结点自身的计算越贵。总耗时 ≈ 实际搜索结点数 × 单点限界代价。若一个「超紧」上界要花 Θ(n2) 计算，却只比 Θ(1) 的粗上界多剪 5% 的结点，那是得不偿失。工程上通常先用廉价上界快筛，只在通过快筛的结点上再算昂贵上界。

三、对称情形：最小化问题的下界剪支

上方演示只做了 ub，这里补齐 lb

页面顶部的仪表盘演示的是最大化问题（ub 剪支）。教材中大量问题——TSP、任务分配、最短路——都是最小化问题，此时一切符号对称翻转。

项目最大化问题（如 0/1 背包）最小化问题（如 TSP / 任务分配）
限界函数上界 ub（乐观估计，往高了估）下界 lb（乐观估计，往低了估）
合法性要求ub(x) ≥ 子树内任何解的值lb(x) ≤ 子树内任何解的代价
best 的含义已知最大可行值，单调不减已知最小可行代价，单调不增
剪支判据ub(x) ≤ best ⇒ 剪lb(x) ≥ best ⇒ 剪
优先队列排序ub 大者优先出队lb 小者优先出队
best 初值−∞（或 0）+∞（或某贪心解的代价）
最小化剪支：lb(x) ≥ best ⇒ 丢弃 S(x)   （因 ∀y∈S(x)，val(y) ≥ lb(x) ≥ best）
示例 · 任务分配问题的下界

n 项任务分配给 n 个人，c[i][j] 为第 i 人做第 j 项任务的代价，求总代价最小的分配方案。设结点 x 已为前 k 个人指派完任务，累计代价为 cost。则一个合法下界为：

lb(x) = cost + Σi=k..n−1 minj 未分配 c[i][j]

解释：剩下每个人至少要付出其所在行中未分配列的最小代价。这是把「每列只能用一次」这条约束松弛掉后的最优值——允许多人抢同一项任务，代价当然只会更低，故必为真实代价的下界。松弛问题的最优值一定是原问题最优值的下界，这是构造下界函数的万能套路。

示例 · TSP 的下界

设结点 x 对应一条已走的部分路径 v0→…→vk，已走代价为 cost，未访问城市集合为 U。则：

lb(x) = cost + minEdge(vk) + Σu∈U minEdge(u)

其中 minEdge(u) 表示从 u 出发的最短一条边。解释：完整回路中，当前端点 vk 还要再出去一条边，每个未访问城市也各要出去一条边，这些边的长度都不会小于各自的最短出边。同样是松弛：把「这些出边必须首尾相接构成一条回路」的约束丢掉了。

统一记忆法：无论 ub 还是 lb，限界函数都是在解一个放宽了约束的简化问题。约束越少 ⇒ 解越「乐观」⇒ 一定不劣于原问题 ⇒ 自动满足合法性。构造限界函数时，先问自己：「我可以扔掉哪条约束，使剩下的问题能在多项式时间内解出来？」

四、限界判据的代码落点

C++ 实现
// ============ 最大化：0/1 背包的上界与剪支 ============ // 前提：items 已按价值密度 v/w 降序排列（合法性的必要条件！） struct Item { int w, v; }; Item it[MAXN]; int n, W; int best = 0; // 已知最优可行解，最大化 ⇒ 初值取 0 // 分数背包松弛上界：从第 i 件起，用剩余容量贪心装填 double ub(int i, int cw, int cv) { int left = W - cw; double b = cv; for (int k = i; k < n && left > 0; ++k) { if (it[k].w <= left) { left -= it[k].w; b += it[k].v; } // 整件装入 else { b += (double)it[k].v * left / it[k].w; break; } // 切一刀装满 } return b; } void expand(Node u) { for (Node v : u.children()) { if (v.cw > W) continue; // ① 约束函数：超重不可行 if (ub(v.i, v.cw, v.cv) <= best + EPS) continue; // ② 限界剪支 pq.push(v); // ③ 存活 ⇒ 进活结点表 } } // ============ 最小化：任务分配的下界与剪支 ============ int c[MAXN][MAXN]; int bestCost = INT_MAX; // 最小化 ⇒ 初值取 +∞ // 行最小元松弛下界：已分配代价 + 每个未分配行的最小可用代价 int lb(int k, int cost, bool used[]) { int b = cost; for (int i = k; i < n; ++i) { int mn = INT_MAX; for (int j = 0; j < n; ++j) if (!used[j]) mn = min(mn, c[i][j]); b += mn; // 松弛：允许多行抢同一列 } return b; } void expandMin(Node u) { for (Node v : u.children()) if (lb(v.k, v.cost, v.used) < bestCost) // 注意方向：lb ≥ best 才剪 pq.push(v); }
代码要点：①②③ 三行的顺序不可颠倒——必须先判可行性再算限界。原因有二：一是不可行结点上限界函数的语义未定义（如背包中 left ＝ W − cw 会变成负数）；二是可行性判断通常是 Θ(1)，先做能省下昂贵的限界计算。

五、复杂度分析

限界函数带来的开销与收益
限界函数单次计算预处理对总时间的影响
平凡上界（总价值）Θ(1)Θ(n)结点数近似 2n，形同暴力
最大密度上界Θ(1)Θ(n)结点数明显下降

易错点
  • 最致命：使用了不合法的限界函数——上界比子树内真实最优值还小（或下界比真实最小代价还大）。此时算法照跑不误，只是答案错了，且小数据往往「碰巧」正确，极难发现。本章第 6 节有一个真实案例。
  • 把 best 设成估计值而非真实可行解的值，导致剪支定理的证明链条断裂。
  • 最小化问题误用 lb ≤ best 剪支——方向反了，会把所有有希望的结点全剪掉，只剩最差解。
  • 浮点上界与整数 best 直接比较，因精度误差把恰好等于最优值的结点误剪。应写 ub <= best + 1e-9 或把上界向下取整为整数。
  • 求全部最优解时仍用 ≤ 剪支，导致只输出第一个最优解。
  • 在不可行结点上调用限界函数，产生负容量、越界等未定义行为。
  • 盲目追求「更紧」的限界，把单点代价推到 Θ(n2) 甚至 Θ(n3)，总时间反而变长。
本节小结
  • 合法性是限界函数的生命线：最大化要求 ub(x) ≥ 子树内任何可行解的值；最小化要求 lb(x) ≤ 子树内任何可行解的代价。
  • 剪支正确性定理：ub(x) ≤ best ⇒ 子树内无严格更优解 ⇒ 可安全丢弃。证明依赖 best 是真实可行解的值。
  • 两种情形对称：最大化用 ub、ub ≤ best 剪、best 初值 −∞、ub 大者优先；最小化用 lb、lb ≥ best 剪、best 初值 +∞、lb 小者优先。
  • 构造套路：限界函数 ＝ 松弛问题的最优值。扔掉一条难约束（0/1 整性、排列唯一性、回路连通性），把剩下的问题多项式时间解掉。
  • 紧度权衡：限界越紧剪支越强，但单点代价越高。总耗时 ≈ 结点数 × 单点代价，需综合权衡。
1对某最大化问题，已知一个上界函数满足：存在结点 x 与可行解 y ∈ S(x)，使得 ub(x) < val(y)。使用该函数按 ub ≤ best 剪支，后果是？
A算法变慢，但答案仍然正确
B算法一定会死循环
C算法可能输出比真实最优值小的答案，且不会报错
D算法一定输出错误答案
解析：C 正确。上界被低估意味着某些含最优解的子树可能满足 ub ≤ best 而被误剪，最优解就此丢失，算法只能返回一个次优值——而且它不会有任何异常提示，这才是最危险的地方。A 完全说反了：不合法的上界只会剪得更狠、跑得更快，代价是正确性。B 无关：剪支不影响终止性，解空间树有限，必然终止。D 说得太绝对：是否真的丢失最优解，还取决于 DFS/BFS 恰好在什么时刻找到了多好的 best——如果最优解碰巧在被误剪之前就被找到，答案仍然正确。这种「时对时错」正是本章第 6 节原代码的真实处境。
2TSP 中，某同学把下界写成 lb(x) ＝ 已走代价 cost（不加任何未来估计）。这个下界函数是否合法？剪支效果如何？
A不合法，因为它没有考虑未访问的城市
B合法（边权非负时），但极松，剪支力度很弱
C合法且很紧，因为已走代价是确定值而非估计
D合法性取决于城市数量的奇偶性
解析：B 正确。边权非负时，完整回路的代价 ＝ 已走代价 ＋ 剩余各边代价 ≥ 已走代价，故 lb ＝ cost 确实是合法下界。但它把「未来还要走很多边」这一信息完全丢弃，估计极其乐观、极其松，几乎剪不掉任何结点——退化成了纯暴力枚举。A 混淆了「合法」与「紧」：不考虑未来不违反合法性，只损失紧度。C 错在把「确定」当成「紧」——紧度衡量的是估计值与子树真实最优值的接近程度，cost 离完整回路代价差得很远。D 是无中生有的干扰项。顺带一提：若边权可为负，lb ＝ cost 就不再合法了。
3关于剪支判据中 best 的更新时机，下列做法正确的是？
A每扩展一个结点就用该结点的 ub 更新 best，让 best 尽快变大
B只在到达叶结点（构造出完整可行解）时用其真实目标值更新 best
C先用贪心算法算出一个 ub 作为 best 初值，可加速剪支
D用当前活结点表中最大的 ub 作为 best
解析：B 正确。剪支定理的证明中，「best 是真实可行解的值」是不可动摇的前提；只有叶结点（或已构造出完整方案的结点）才提供真实值。A、D 都是用估计值冒充 best，会把「ub ≤ best」变成两个估计值的比较，推理链断裂，可能剪掉真正的最优解。C 是最具迷惑性的一项：用贪心解预热 best 确实是标准加速技巧，但必须用贪心解的真实目标值，而不是它的 ub。贪心构造出的是一个货真价实的可行解，其值是最优值的下界，用作 best 初值完全合法且非常有效；而贪心的 ub 是上界，用它当 best 会剪掉一切。选项 C 恰恰把「贪心解的值」偷换成了「贪心算出的 ub」。
