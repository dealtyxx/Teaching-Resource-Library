二路归并 · 分裂与合并

先递归对半分，再线性合并两个有序段。稳定、最坏 Θ(n log n)，额外 O(n) 空间。

一、算法思想

Merge Sort · 二路归并
定义

二路归并排序（2-way Merge Sort）：把待排序区间 a[l..r] 从中点 m 一分为二，递归地分别排好 a[l..m] 与 a[m+1..r]，再把这两个已有序的子段线性地合并成一个有序段。当区间长度为 1 时天然有序，递归终止。

性质

归并排序的"重活"在合并：分解只是算一次中点（Θ(1)），合并要扫描全区间（Θ(n)）。这与快速排序"重活在分解（划分）、合并为空操作"恰好互补。也正因为分解与数据内容无关，归并排序的比较次数只取决于 n，与输入的初始排列无关，最好=平均=最坏=Θ(n log n)。

1
分解 Divide — 取 m = l + (r−l)/2，把 a[l..r] 分成 a[l..m] 与 a[m+1..r]，代价 Θ(1)。
2
求解 Conquer — 递归调用 mergeSort 排好左右两段；长度为 1 时直接返回。
3
合并 Combine — 用双指针扫描两个有序段，每次取较小者放入辅助数组，代价 Θ(n)。

二、C++ 实现

merge + mergeSort
// ---------- 合并 a[l..m] 与 a[m+1..r] 两个有序段 ---------- void merge(int a[], int tmp[], int l, int m, int r) { int i = l; // 左段游标 int j = m + 1; // 右段游标 int k = l; // 辅助数组写入位置 while (i <= m && j <= r) { // 关键：相等时取【左段】，这一个 '=' 决定了归并排序的稳定性 if (a[i] <= a[j]) tmp[k++] = a[i++]; else tmp[k++] = a[j++]; } while (i <= m) tmp[k++] = a[i++]; // 左段还有剩余，直接搬 while (j <= r) tmp[k++] = a[j++]; // 右段还有剩余，直接搬 for (int t = l; t <= r; ++t) a[t] = tmp[t]; // 写回原数组 } // ---------- 归并排序主过程 ---------- void mergeSort(int a[], int tmp[], int l, int r) { if (l >= r) return; // 出口：长度 <= 1，天然有序 int m = l + (r - l) / 2; // 分解：防溢出写法 mergeSort(a, tmp, l, m); // 求解左半 mergeSort(a, tmp, m + 1, r); // 求解右半 merge(a, tmp, l, m, r); // 合并：Θ(n) } // ---------- 调用入口：辅助数组只分配一次 ---------- void mergeSort(int a[], int n) { int* tmp = new int[n]; // O(n) 辅助空间，全程复用 mergeSort(a, tmp, 0, n - 1); delete[] tmp; }
工程细节：辅助数组 tmp 应在入口一次性分配并全程复用。若写在 merge 内部每次 new/delete，虽然峰值空间仍是 O(n)，但会产生 O(n) 次内存申请，常数因子急剧变大。
// ---------- 非递归（自底向上）二路归并：省掉递归栈 ---------- void mergeSortBU(int a[], int n) { int* tmp = new int[n]; for (int len = 1; len < n; len *= 2) // 段长 1,2,4,8,… 共 ceil(log2 n) 趟 for (int l = 0; l + len < n; l += 2 * len) { int m = l + len - 1; int r = min(l + 2 * len - 1, n - 1); // 末段可能不足，取 min merge(a, tmp, l, m, r); } delete[] tmp; }

三、复杂度分析（含完整推导）

时间 / 空间
T(n) = 2T(n/2) + Θ(n)  ⇒  T(n) = Θ(n log n)
T(1) = 1；T(n) = 2T(n/2) + cn 合并一趟扫描全区间，代价 cn T(n) = 2[2T(n/4) + cn/2] + cn = 4T(n/4) + 2cn 　　 = 4[2T(n/8) + cn/4] + 2cn = 8T(n/8) + 3cn 　　 … 　　 = 2kT(n/2k) + k·cn 第 k 步通式：每层新增 cn 令 n/2k = 1 ⇒ k = log2n T(n) = n·T(1) + cn·log2n = n + cn log2n ∴ T(n) = Θ(n log n) 主定理校验：a=2, b=2, d=1；log22 = 1 = d ⇒ 情形② ⇒ Θ(n1 log n)
换个角度看（递归树）：递归树共 log2n+1 层，第 k 层有 2k 个结点、每个结点合并 n/2k 个元素，整层工作量恒为 2k × c·n/2k = cn，与 k 无关。所以总量 = 每层 cn × log2n 层 = Θ(n log n)。这正是主定理情形②"各层均衡"的图像。

3.1 空间复杂度：为什么必须要 O(n) 辅助数组

性质

合并两个有序段时，若就地把右段的小元素插到左段中间，就必须把左段剩余元素整体后移，单次合并代价从 Θ(n) 恶化为 Θ(n2)。为保持合并的线性代价，必须借助一块与区间等长的辅助空间，把结果先"抄"出来再写回。因此归并排序的辅助空间为 O(n)，它不是原地（in-place）排序。

空间组成大小说明
辅助数组 tmpO(n)合并结果的暂存区，全程复用一块即可
递归栈O(log n)递归深度恰为 log2n（每次严格对半，不会退化）
合计O(n)O(n) 吸收 O(log n)
辨析：「辅助空间 O(n)」指的是额外开销，不包含存放输入本身的那 n 个单元。另外，存在原地归并算法（如 block merge / 旋转法），可把辅助空间降到 O(1) 或 O(√n)，但常数因子很大，教材与考试中一律按 O(n) 作答。

四、稳定性：那一个 "=" 号的作用

本节重点
定义

稳定性（Stability）：排序前后，关键字相等的记录相对先后次序保持不变，则算法稳定。

定理

使用 if (a[i] <= a[j]) tmp[k++]=a[i++]; 的二路归并排序是稳定的。

证明思路（对区间长度作归纳）： ① 长度为 1 的区间平凡稳定。 ② 设左段 a[l..m]、右段 a[m+1..r] 经递归后各自内部已稳定。 ③ 注意左段中任一元素的原始下标恒小于右段中任一元素的原始下标。 ④ 合并时若 a[i] == a[j]（左右各有一个相等元素），条件 a[i] <= a[j] 成立 ⇒ 先取左段的 a[i]； 　 于是原始下标小的那个仍然被先写入，相对次序不变。 ⑤ 若相等元素都在同一段内，由归纳假设该段内部次序已保持。 ∴ 合并后整个区间保持稳定，归纳完成。 ∎
把 "≤" 写成 "<" 会怎样？此时 a[i]==a[j] 不满足 a[i] < a[j]，会走 else 分支先取右段的元素，原本在后面的记录被排到了前面 ⇒ 算法立即变为不稳定。
反例：a = [2a, 2b]，l=0, m=0, r=1，左段 {2a}、右段 {2b}。用 ≤ 得 (2a, 2b) 保序；用 < 得 (2b, 2a) 逆序。
排序结果的"字面值"完全相同，肉眼看不出差别——这正是这个错误极难被测出、却在多关键字排序（如先按成绩排、再按姓名排）中造成严重后果的原因。
推论：归并排序的稳定性来自"相等时优先取左（下标更小的）段"这一条规则，与递归结构无关。同理，任何合并型算法只要遵守这条规则都能保持稳定；而快速排序因存在跨距离交换，无论怎样调整比较符号都无法变稳定。

五、例题

Worked Example
题目：用二路归并排序对 (8, 3, 5, 1, 9, 2, 7, 4) 排序，写出每一趟（自底向上）的结果，并统计归并趟数。
初始：[8] [3] [5] [1] [9] [2] [7] [4]  共 8 个长度为 1 的有序段 第 1 趟（len=1）：[3 8] [1 5] [2 9] [4 7] 第 2 趟（len=2）：[1 3 5 8] [2 4 7 9] 第 3 趟（len=4）：[1 2 3 4 5 7 8 9]  完成 趟数 = ⌈log28⌉ = 3；每趟比较与移动均为 Θ(n)，总代价 3×8 = 24 次移动量级 ⇒ Θ(n log n)
细看第 2 趟的一次合并：合并 [3 8] 与 [1 5]。i 指 3、j 指 1：3≤1 不成立 ⇒ 取 1；i 指 3、j 指 5：3≤5 ⇒ 取 3；i 指 8、j 指 5：8≤5 不成立 ⇒ 取 5；右段耗尽，收尾循环把 8 直接搬入 ⇒ 得 [1 3 5 8]。收尾的两个 while 不可省，否则剩余元素会丢失。

七、易错点

Common Pitfalls
易错点
  • 把 a[i] <= a[j] 写成 a[i] < a[j]：排序结果的数值序列完全正确，但稳定性丢失，测试很难发现，多关键字排序时才暴露。
  • 省略合并末尾的两个收尾 while：其中一段先耗尽后，另一段的剩余元素没有被搬入，结果丢数据。
  • 中点写成 m = (l + r) / 2：l、r 都很大时 l+r 可能整型溢出为负，应写 m = l + (r - l) / 2。
  • 递归写成 mergeSort(a,tmp,l,m) 与 mergeSort(a,tmp,m,r)（右半从 m 而非 m+1 开始）：区间不缩小 ⇒ 无限递归。
  • 忘记 merge 结束后把 tmp 写回 a，导致下一层合并读到的是旧数据。
  • 把辅助数组放在 merge 内部反复 new/delete：复杂度的阶不变，但常数因子暴涨。
  • 误答"归并排序空间复杂度 O(log n)"——那只是递归栈，辅助数组的 O(n) 才是主导项。
  • 误答"归并排序最好情形是 O(n)"。已有序时仍要做完整的 log n 趟合并，没有提前退出机制（除非人为加"若 a[m] ≤ a[m+1] 则跳过合并"的优化，那才能让有序输入降到 Θ(n)）。
本节小结
  • 归并排序 = 对半分解（Θ(1)）+ 递归 + 线性合并（Θ(n)），与快排的结构恰好互补。
  • 递推式 T(n)=2T(n/2)+Θ(n)，展开得 T(n)=2kT(n/2k)+k·cn，令 k=log2n ⇒ Θ(n log n)；主定理情形②。
  • 最好 = 平均 = 最坏 = Θ(n log n)，与输入排列无关，无退化风险。
  • 稳定的根源是合并时用 a[i] ≤ a[j] 优先取左段；改成 < 立即变不稳定。
  • 辅助空间 O(n)（辅助数组，用于保证合并是线性的）+ O(log n) 递归栈，合计 O(n)，不是原地排序。
  • 适用于要求稳定、要求最坏保证、链表排序与外部排序（多路归并）的场合。

自测题

点击选项查看解析
1若把 merge 中的判断 if (a[i] <= a[j]) 改成 if (a[i] < a[j])，会产生什么后果？
A排序结果出错，会出现逆序对
B时间复杂度退化为 O(n2)
C排序结果的数值序列仍然正确，但算法由稳定变为不稳定
D相等元素会被丢失一个，数组长度变短
解析：选 C。当 a[i]==a[j] 时，< 不成立 ⇒ 走 else 先取右段元素，原本靠前的左段相等元素被排到后面，相对次序颠倒 ⇒ 不稳定；但由于两者关键字相等，输出的数值序列看起来完全一样。
A 错在有序性不受影响（取的仍是当前两段中较小者）；B 错在合并仍是一趟线性扫描，与比较符号无关；D 错在两个分支都只是"取一个、指针前进一步"，元素总数守恒。本题的价值在于：结果"看起来对"不等于算法性质没变。
2对 n 个元素做二路归并排序（数组实现），其空间复杂度是？
AO(1)，因为可以就地合并
BO(log n)，即递归栈的深度
CO(n)，由辅助数组主导
DO(n log n)，每层递归各需一个长度 n 的辅助数组
解析：选 C。合并必须借助长度为 O(n) 的辅助数组才能保持线性代价；递归栈虽为 O(log n)，但被 O(n) 吸收，合计 O(n)。
A 错：朴素就地合并会把单次合并推到 Θ(n2)，标准算法不这么做；B 是最常见的错答——只记住了递归栈而漏掉主导项；D 是另一个迷惑项：辅助数组全程只需一块并反复复用（同一时刻只有一次合并在写它），不会每层各占一块，所以不是 O(n log n)。
3下列关于归并排序与快速排序的说法，正确的是？
A两者的最坏时间复杂度都是 O(n log n)
B归并排序在输入已有序时只需 O(n) 时间
C归并排序的比较次数与输入的初始排列无关，快速排序则强烈依赖于输入
D两者都是原地排序，辅助空间均为 O(log n)
解析：选 C。归并每次严格从中点对半分，递归树形状只由 n 决定；快排的划分位置由数据决定，最好 Θ(n log n)、最坏 Θ(n2)。
A 错在快排最坏是 O(n2)；B 是典型混淆——"有序时更快"是插入排序/冒泡排序的性质，标准归并排序没有提前退出机制，有序输入仍要做满 log n 趟合并（若额外加上"a[m] ≤ a[m+1] 就跳过合并"的判断才能达到 Θ(n)）；D 错在归并需要 O(n) 辅助数组，不是原地排序。
