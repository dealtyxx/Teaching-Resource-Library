问题与下界

两个都 ≤ OPT 的可算界
定义 · 多机调度（最小化 makespan）

给定 n 个独立任务，加工时间分别为 p1,…,pn，以及 m 台同型机器。把每个任务整体分配给某台机器，机器 k 的负载为其上任务加工时间之和。目标是最小化最大机器负载（即完工时间 makespan，记 Cmax）。当 m ≥ 2 时该问题是 NP-难的。

下界 LB = max( maxi pi , (Σi pi)/m )，且 LB ≤ OPT： ① 某台机器必须完整加工最大的那个任务，故 OPT ≥ maxi pi ② m 台机器 makespan 各不超过 OPT，总能力 ≥ 总工作量：m·OPT ≥ Σpi，故 OPT ≥ (Σpi)/m ∴ OPT ≥ max( max pi , Σpi/m ) = LB 证近似比就靠它夹住 OPT

List 调度：2 − 1/m 近似

任意到达序，来一个放最空的机器
设 List 调度得到 makespan C，达到 C 的机器上最后放入的任务为 j，其开始时刻为 sj ① j 被放入时，该机器是当时负载最小的 贪心/List 规则    故 sj ≤ 此刻各机器负载的平均 ≤ (Σi≠j pi)/m = (Σpi − pj)/m ② C = sj + pj ≤ (Σpi − pj)/m + pj = (Σpi)/m + pj·(m−1)/m　(★) ③ 两个下界：(Σpi)/m ≤ OPT，且 pj ≤ maxi pi ≤ OPT ④ 代入 (★)：C ≤ OPT + OPT·(m−1)/m = OPT·(2 − 1/m) ∴ List 调度是 (2 − 1/m)-近似 ∎
CList ≤ ( 2 − 1/m ) · OPT

LPT：4/3 − 1/(3m) 近似

先降序排，再放最空机器
LPT = Longest Processing Time first：先把任务按加工时间降序排列，再逐个放入当前负载最小的机器。仅仅"先排序"就把近似比从 2−1/m 改进到 4/3−1/(3m)。
设 makespan 由机器 M 决定，M 上最后放入的任务为 j（临界任务）。仍有通用界：    C ≤ (Σpi)/m + pj·(m−1)/m ≤ OPT + pj·(m−1)/m　(★) 情形一：pj ≤ OPT/3（临界任务较小）    代入 (★)：C ≤ OPT + (OPT/3)·(m−1)/m = OPT·(1 + (m−1)/(3m)) = OPT·(4/3 − 1/(3m)) 情形二：pj > OPT/3（临界任务较大）    因 LPT 降序，排在 j 之前的任务都 ≥ pj > OPT/3；在最优解里每台机器至多放 2 个这样的大任务（放 3 个就 > OPT）    于是大任务不超过 2m 个，而任务数 ≤ 2m 时 LPT 恰好求得最优解，故 C = OPT，比值 = 1 两种情形都满足 C ≤ OPT·(4/3 − 1/(3m)) ∴ LPT 是 (4/3 − 1/(3m))-近似，且该界是紧的 ∎
CLPT ≤ ( 4/3 − 1/(3m) ) · OPT　　（4/3 < 2，故优于 List）

LPT 的代码骨架

C++ · 降序 + 放最空机器
// LPT：最长处理时间优先，近似比 4/3 − 1/(3m) long long lpt(vector<int>& p, int m) { sort(p.rbegin(), p.rend()); // 关键：按加工时间降序 vector<long long> load(m, 0); // 各机器当前负载 for (int t : p) { int k = 0; // 找当前最空的机器 for (int i = 1; i < m; ++i) if (load[i] < load[k]) k = i; load[k] += t; // 放入，负载更新 } return *max_element(load.begin(), load.end()); // makespan }

易错点
  • 近似比方向记反。2−1/m 与 4/3−1/(3m) 都是 Cmax/OPT 的上界（≥1），不是下界；调度只会比最优差，不会更好。
  • 把 List 界与 LPT 界混用。任意到达序 = 2−1/m；先降序排序 = 4/3−1/(3m)。因 4/3 < 2，LPT 严格更优。
  • 以为 m 越大近似越准。恰相反：m→∞ 时 List→2、LPT→4/3，界变差（离 1 更远）；m=1 时两者都=1。
  • 下界只用平均 Σp/m。必须取 max( max pi , Σp/m )：当某单个任务特别大时，平均值会严重低估 OPT。
  • 以为 LPT 一定给最优解。不是，它只是近似；紧例中 LPT/OPT 达到 4/3−1/(3m)。只有当任务数 ≤ 2m（每机至多 2 个）时 LPT 才必然最优。
  • 把最小化 makespan 误当成最大化。本问题是最小化最大负载，越小越好，近似比是对上界的控制。
本节小结
  • 多机调度目标是最小化 makespan；下界 LB = max( max pi , Σpi/m ) ≤ OPT，是所有近似比证明的支点。
  • List 调度（任意序，放最空机器）的核心不等式 C ≤ (Σp)/m + pj(m−1)/m，得 (2 − 1/m)-近似。
  • LPT（先降序）分两情形：临界任务 ≤ OPT/3 直接得界；> OPT/3 则大任务 ≤ 2m 个、LPT 恰最优。合得 (4/3 − 1/(3m))-近似，且紧。
  • 近似比随 m 增大而变差：List 逼近 2、LPT 逼近 4/3；m=1 时均为 1。
1m = 4 台机器，用任意到达序的 List 调度，其近似比的理论上界是？
A4/3 − 1/12 = 5/4
B2 − 1/4 = 7/4
C2
D4/3
解析：List（任意序）的界是 2 − 1/m，代入 m=4 得 2 − 1/4 = 7/4。A 是 LPT 的界（4/3 − 1/(3m) = 4/3 − 1/12 = 5/4），题目问的是 List 不是 LPT。C、D 是 m→∞ 的极限，不是 m=4 的准确值。
2关于 LPT 近似比 4/3 − 1/(3m) 的证明，"临界任务较小"那一情形的假设是？
Apj ≤ OPT/2
Bpj ≤ OPT/3，代入通用界即得 4/3 − 1/(3m)
Cpj ≥ OPT/3，此时 LPT 一定最优
Dpj = OPT，只有一个任务
解析：临界任务 pj ≤ OPT/3 时，代入 C ≤ OPT + pj(m−1)/m ≤ OPT + (OPT/3)(m−1)/m = OPT(4/3 − 1/(3m))，正是 B。C 把情形搞反了——pj > OPT/3（较大）那一情形才用"大任务 ≤ 2m 个、LPT 最优"的论证。A 的 OPT/2 得不到 4/3 的系数。
3下界为什么要取 LB = max( max pi , Σpi/m ) 而不是只用 Σpi/m？
A没区别，两者总是相等
B当某个任务特别大（pi > Σp/m）时，平均值会低估 OPT，必须用 max pi 补上
C因为 Σpi/m 可能大于 OPT
Dmax pi 总是比 Σpi/m 大
解析：OPT 同时 ≥ max pi（某机必须整块加工最大任务）和 ≥ Σp/m（总工作量摊到 m 台）。若某任务超大（如一个任务 = 全部工作量的一大半），仅 Σp/m 会远低于真实 OPT，故取两者的较大者才是有效下界，B 对。C 错——Σp/m 恒 ≤ OPT。D 错——两者谁大取决于实例（任务均匀时平均更大）。
