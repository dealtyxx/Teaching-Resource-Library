蒙特卡罗 · 主元素

随机抽元素检查是否出现 > n/2 次。返回 true 则一定对（偏真）；false 可能漏。重复 k 次错误率 < 2⁻ᵏ。

学习目标

  1. 能够写出蒙特卡罗算法的正式定义，以及 p-正确、优势、偏真/偏假等术语的含义。

  5. 能够写出主元素判定的 C++ 实现并分析其时间复杂度。

主元素问题的正式定义

majority element
定义 · 主元素

设 T[0..n−1] 是含 n 个元素的数组。若某个值 x 在 T 中出现的次数严格大于 n/2，则称 x 为 T 的主元素（majority element）。
两个直接推论：① 主元素至多只有一个（若有两个，出现次数之和 > n，矛盾）；② 若随机抽取一个位置 i，则 T[i] 恰为主元素的概率 > 1/2（因为主元素占据了超过一半的位置）。
判定问题：给定 T，判断"T 中是否存在主元素"。

算法 · 随机抽样判定

majority(T, n)：随机取 i ∈ {0,…,n−1}，令 x = T[i]；扫描一遍统计 x 的出现次数 c；若 c > n/2 返回 true，否则返回 false。
时间为 O(n)——确定，与随机结果无关；空间 O(1)。

正确性分析

情形 A：T 无主元素。则任何 x 的出现次数都 ≤ n/2，算法必然返回 false，永不出错。
情形 B：T 有主元素 m。若抽中的 T[i] = m（概率 > 1/2），则 c > n/2，返回 true，正确；若抽中的是非主元素（概率 < 1/2），则 c ≤ n/2，返回 false，出错（漏报）。
综上：算法返回 true 时一定正确；只有返回 false 时才可能出错，且出错概率 < 1/2。故它是 1/2-正确的，优势为 2×(1/2) − 1 = 0（是"临界"的偏向型算法，靠重复来放大）。

偏真与偏假：蒙特卡罗算法的两种偏向

本页演示的是偏真型 —— 这个区分是本节的核心概念
定义 · 偏真蒙特卡罗算法

偏真（true-biased）蒙特卡罗算法：对任意实例，若算法返回 true，则答案一定是 true（无假阳性，no false positive）；只有返回 false 时才可能出错（可能漏掉一个真实的"是"）。
形式化：Pr[输出 true | 真答案为 false] = 0，Pr[输出 false | 真答案为 true] ≤ ε。
本页的主元素算法正是偏真型：它只在"亲眼数到某元素出现 > n/2 次"时才说 true，这是铁证，不可能错。

定义 · 偏假蒙特卡罗算法

偏假（false-biased）蒙特卡罗算法：若算法返回 false，则答案一定是 false（无假阴性）；只有返回 true 时才可能出错。
典型例子：Miller-Rabin 素性测试的"合数"侧——算法找到一个证据（witness）就断言 n 是合数，这个断言必然正确；但它说"n 是素数"时，n 有可能是伪素数（对该底数恰好通过测试的合数）。以"n 是素数吗？"为判定问题来看，Miller-Rabin 就是偏假的。
另一例：矩阵乘积验证（Freivalds 算法）判断 A×B = C 是否成立——找到随机向量 r 使 A(Br) ≠ Cr 就断定"不相等"，此断言必对；说"相等"则可能错。

为什么"偏向"如此重要

因为只有单侧出错的算法才能靠简单重复把错误率指数压低。
偏真型：重复 k 次，只要有任何一次返回 true，就立即断定答案为 true（因为 true 是铁证）；只有 k 次全部返回 false 才输出 false。于是"输出 false 却错了"要求 k 次全部漏报，概率 ≤ (1/2)k。
偏假型对称：k 次里只要有一次返回 false 就输出 false；全 true 才输出 true。
若算法双侧都可能错（如 BPP 型），就不能这样"一票否决"，必须改用多数表决（majority vote），错误率仍指数下降但需要 Chernoff 界来证明，常数更差。

错误率推导：从 1/2 到 2−k

本章最核心的一条推导
设 T 确有主元素 m，其出现次数 c(m) > n/2 只有这种情形才可能出错 ① 单次调用随机抽到位置 i，抽中主元素的概率    p = c(m)/n > (n/2)/n = 1/2 主元素占位超过一半 ② 故单次调用失败（抽中非主元素、返回 false）的概率    q = 1 − p < 1 − 1/2 = 1/2 单次错误率 ≤ 1/2 ③ 独立重复调用 k 次（每次重新抽取随机位置，随机位互相独立） ④ 因偏真性："输出 false 却错了" ⟺ k 次全部失败 任何一次 true 都会立刻正确终止 ⑤ 由独立性，联合概率等于各次概率之积：    Pr[k 次全错] = qk < (1/2)k = 2−k 指数下降 ⑥ 而"输出 true 却错了"的概率恒为 0（偏真，无假阳性） ∴ 重复 k 次的算法是 (1 − 2−k)-正确的，时间仍为 O(k·n)，确定 ∎
Pr[错误] ≤ 2−k　　⟹　　欲使 Pr[错误] ≤ ε，取 k ≥ log2(1/ε)
重复次数 k错误率上界 2−k直观对照总时间

注意错误率的下降有多"便宜"：k 是线性地增加时间，错误率却是指数地下降。只要付出 60 倍的常数代价，错误概率就低于计算机内存自发翻转比特的概率——此时再纠结"算法可能出错"已无实际意义。这与 §02 数值概率算法"多一位精度要多 100 倍时间"形成鲜明对比：压错误率很便宜，提精度很贵。

C++ 实现

单次判定 + k 次放大
// ① 单次蒙特卡罗判定：随机抽一个元素，数它出现多少次 // 时间 O(n)（确定），空间 O(1) // 偏真：返回 true 一定正确；返回 false 时错误概率 < 1/2 bool majorityOnce(int T[], int n) { int i = rand() % n; // 唯一的随机点 int x = T[i], c = 0; for (int j = 0; j < n; ++j) if (T[j] == x) ++c; // 亲自数一遍 —— 这就是 true 为铁证的原因 return c > n / 2; // 注意是严格大于 } // ② 概率放大（amplification）：独立重复 k 次 // 偏真型的综合规则：任一次 true 立刻返回 true；全 false 才返回 false // 时间 O(k·n)（确定），错误率 < 2^(-k) bool majorityMC(int T[], int n, int k) { for (int t = 0; t < k; ++t) if (majorityOnce(T, n)) return true; // 铁证，可立即结论 return false; // k 次全没抽中 —— 可能漏，概率 < 2^(-k) } // ③ 按目标错误率 eps 自动确定 k：k = ceil(log2(1/eps)) bool majorityEps(int T[], int n, double eps) { int k = (int)ceil(log2(1.0 / eps)); return majorityMC(T, n, k); } // 【对照】确定性解法：Boyer-Moore 摩尔投票，O(n) 时间 O(1) 空间且绝不出错 // 说明蒙特卡罗并非此题的最佳解 —— 本题只是用来演示"错误率放大"这一技术 bool majorityExact(int T[], int n) { int cand = T[0], cnt = 0; for (int j = 0; j < n; ++j) { // 第一遍：抵消，选出候选 if (cnt == 0) { cand = T[j]; cnt = 1; } else cnt += (T[j] == cand) ? 1 : -1; } int c = 0; for (int j = 0; j < n; ++j) if (T[j] == cand) ++c; // 第二遍：验证 return c > n / 2; }

易错点
  • 把 2−k 当成"任何情形下的错误率"。它只是"有主元素却输出 false"这一侧的上界；另一侧（无主元素却输出 true）的概率是严格的 0。混为一谈就丢掉了"偏真"这个关键性质。
  • k 次重复时没有重新抽取随机数。若复用同一个随机位置，k 次结果完全相同，错误率仍是 1/2，独立性是指数下降的前提。
  • 把偏真型的综合规则写成"多数表决"。偏真型应当"一票通过"（任一次 true 即输出 true）；改用多数表决反而更弱——k 次里 1 次 true、k−1 次 false，多数表决会错误地输出 false，而事实上那 1 次 true 已是铁证。
  • 把 Miller-Rabin 说成"偏真"。取决于判定问题怎么问。以"n 是合数吗？"提问它是偏真；以"n 是素数吗？"提问它是偏假。答题时务必先说清判定问题的方向。
  • 写成 c >= n/2。主元素要求严格大于 n/2；用 >= 时 n 为偶数会把"恰好一半"误判为主元素。
  • 认为蒙特卡罗算法的运行时间也是随机的。不是——本算法无论抽中什么，都恰好扫描 k 遍数组，时间是确定的 O(kn)。时间随机的是拉斯维加斯（§04）。
本节小结
  • 主元素：出现次数严格大于 n/2 的值，至多一个；随机抽一个位置抽中它的概率 > 1/2。
  • 随机抽样判定算法时间确定 O(n)，结果可能错——这正是蒙特卡罗算法的标志。
  • 它是偏真（true-biased）算法：返回 true 是亲自数出来的铁证，一定正确；只有返回 false 时才可能漏报。对称地，Miller-Rabin 素性测试在"n 是素数吗"这一提法下是偏假算法。
  • 错误率推导：单次失败概率 q < 1/2 ⟹ 独立重复 k 次全错的概率 < (1/2)k = 2−k；欲达到错误率 ε 只需 k ≥ log2(1/ε)。
  • 单侧偏差是能靠"一票通过/一票否决"简单放大的前提；双侧偏差算法必须改用多数表决。
  • 时间线性增长换错误率指数下降，代价极低——与 §02 数值概率"多一位精度花 100 倍时间"形成对比。

解析：算法返回 true 的唯一途径是完整扫描一遍、数到 x 出现次数确实 > n/2——这是直接验证而非概率推断，因此绝无假阳性。这正是"偏真（true-biased）"的含义。A 和 C 把出错的那一侧搞反了：1/2 与 2−k 都是返回 false 时的错误率上界（漏报概率）。D 与随机化无关——算法对任意排列的数组行为相同，随机性来自算法内部抽样而非输入顺序。
2若希望主元素判定算法的错误概率不超过 0.1%（即 10−3），至少需要独立重复调用多少次？
A3 次
B7 次
C10 次
D1000 次
解析：错误率上界为 2−k，要求 2−k ≤ 10−3，即 k ≥ log2(1000) ≈ 9.97，取 k = 10（2−10 = 1/1024 ≈ 0.098% ≤ 0.1% ✓；而 k = 9 时 2−9 ≈ 0.195% > 0.1% ✗）。A 是误把关系当成线性（以为 3 次就到千分之一）；B 对应 2−7 ≈ 0.78%，还差一个数量级；D 把"错误率 10−3"直接当成了重复次数，忽略了指数下降这一核心——正因为是指数下降，只需 10 次而非 1000 次，这才是概率放大技术真正的威力所在。
3关于偏真（true-biased）与偏假（false-biased）蒙特卡罗算法，下列说法正确的是？
A两者本质相同，只是叫法不同，都可以用多数表决放大
B偏真算法返回 false 时一定正确，返回 true 时可能错
C偏假算法一旦返回 false 便可立即断定答案为 false，只有 k 次全部返回 true 时才输出 true
D蒙特卡罗算法必然是单侧偏差的，不存在双侧都可能出错的情形
解析：C 正确——"偏假"意味着 false 是铁证（无假阴性），所以可以"一票否决"，只有全部 k 次都说 true 才输出 true。B 把偏真的定义说反了：偏真是 true 一定对、false 可能错（本节主元素算法即是）。A 错在两处：偏向的方向不同会导致综合规则相反（一票通过 vs 一票否决），且对单侧偏差算法用多数表决反而更弱——1 次 true、9 次 false 时多数表决会输出 false，可那 1 次 true 已经是铁证了。D 错——存在双侧偏差的蒙特卡罗算法（对应复杂性类 BPP），此时才必须用多数表决，并借助 Chernoff 界证明错误率仍指数下降。
