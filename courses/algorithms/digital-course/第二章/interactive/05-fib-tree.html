Fib(n) 递归树

朴素递归指数级调用；大量重复子问题。对比记忆化调用次数。

学习目标

  1. 能够画出 Fib(n) 的递归树，并从树上指认重复子问题（overlapping subproblems）。
  2. 能够推导朴素递归的递推式 T(n)=T(n−1)+T(n−2)+O(1)，并说明其解为 Θ(φn) ≈ Θ(1.618n)。
  3. 能够写出朴素递归、记忆化递归、自底向上迭代三种 C++ 实现，并对比其时间与空间复杂度。
  4. 能够解释记忆化为何把指数降为线性，以及它为什么不能降低递归深度。
结果—
调用次数0
记忆化后每个 k 只算一次 → O(n)。
怎样读这两个按钮：点"朴素递归"，画布上会长出一棵枝繁叶茂的递归树——树上每一个圆点就是一次函数调用，你会看到 fib(4)、fib(3) 等相同数字在不同分支上反复出现，这就是重复子问题。
点"记忆化"，画布只剩一行文字，这不是演示做得潦草，而恰恰是结果本身：那棵大树被"压扁"了。凡是第二次及以后遇到的 fib(k)，都在 dp[k] 里直接查表返回，对应的整棵子树被一次剪掉，永远不会展开。于是原本 O(1.618n) 个结点坍缩成一条 O(n) 长的链——"没有画面"正是"重复子问题已被全部合并"的可视化结果。请对比上方"调用次数"统计：n=8 时朴素约 67 次，记忆化仅约 15 次。

一、斐波那契数列与它的递归树

Fibonacci · Recursion Tree
定义 · 斐波那契数列

F(0) = 0，F(1) = 1，F(n) = F(n−1) + F(n−2)（n ≥ 2）。这是定义递归（§03 第①类）的典型：递推式是数列定义自带的，照抄即可成为代码。

F(n) = 0（n=0）；　F(n) = 1（n=1）；　F(n) = F(n−1) + F(n−2)（n ≥ 2）
性质 · 重复子问题

若一个递归算法的递归树中，同一个子问题在不同分支上被反复求解，则称该问题具有重复子问题（overlapping subproblems）性质。这正是"递归树结点数远多于不同子问题个数"的原因，也是记忆化与动态规划能够生效的前提条件。

fib(5) 的递归树（对照页面动画）： 　　　　　　　　　　　fib(5) 　　　　　　　／　　　　　　　＼ 　　　　fib(4)　　　　　　　　　fib(3)　★ 　　　／　　＼　　　　　　　　／　　＼ 　fib(3)★　 fib(2)△　　　fib(2)△　fib(1) 　／　＼　　　／　＼　　　　／　＼ fib(2)△ fib(1) fib(1) fib(0) fib(1) fib(0) ／　＼ fib(1) fib(0) ★ fib(3) 被完整计算了 2 次　　△ fib(2) 被完整计算了 3 次 不同子问题只有 6 个（fib(0)…fib(5)），树上却有 15 个结点。 n 越大差距越离谱：n=40 时不同子问题 41 个，结点约 3.3 亿 个。
为什么叫"重复"而不是"多次调用"：关键在于这些调用的参数完全相同、结果必然相同，却被从头到尾重算一遍——包括它下面整棵子树。相比之下，归并排序的递归树上每个结点处理的是不同的子数组，虽然结点也很多，但没有一次是白算的，因此归并排序无法用记忆化加速。能否记忆化，取决于是否存在"参数相同的重复调用"。

二、方法一：朴素递归及其复杂度

Naive Recursion · Θ(φn)
// 方法一：朴素递归 —— 直接照抄定义 long long fib1(int n) { if (n <= 1) return n; // 出口：F(0)=0, F(1)=1 return fib1(n - 1) + fib1(n - 2); // 递归体：两个子问题 }
【建立递推式】每层做 O(1) 的加法，产生两个子问题： T(n) = T(n−1) + T(n−2) + c，　T(0) = T(1) = c 【解法一：直接数调用次数】设 C(n) 为总调用次数，则 C(0) = C(1) = 1，C(n) = C(n−1) + C(n−2) + 1 令 D(n) = C(n) + 1，得 D(n) = D(n−1) + D(n−2)　化成纯 Fib 递推 ⇒ C(n) = 2·F(n+1) − 1 验证：C(8) = 2·F(9) − 1 = 2·34 − 1 = 67　与页面统计一致 【解法二：特征方程】齐次递推 T(n) = T(n−1) + T(n−2) 的特征方程为 x2 = x + 1　⇒　x = (1 ± √5)/2 正根 φ = (1+√5)/2 ≈ 1.6180（黄金比 golden ratio），负根 ψ ≈ −0.618 通解 T(n) = A·φn + B·ψn，其中 |ψ| < 1 ⇒ ψn → 0 ⇒ T(n) = Θ(φn) ≈ Θ(1.618n)　　指数级！ 【空间】递归树高度 = n（最左那条链 n→n−1→…→0） ⇒ S(n) = Θ(n)　　时间数结点、空间数树高（§04 定理 2.1）
常见的粗略上界 O(2n) 对不对？对，但不紧。因为递归树不是满二叉树（右子树 fib(n−2) 比左子树矮一层），结点数少于 2n。紧确界是 Θ(φn)。考试若问"渐进时间复杂度"，答 O(2n) 一般算对，但答 Θ(1.618n) 更准确；若问"调用次数的精确表达式"，答 2F(n+1)−1。

三、方法二：记忆化递归

Memoization · 自顶向下 Θ(n)
定义 · 记忆化

记忆化（memoization）是在递归的基础上增设一张备忘录（memo table）：每算完一个子问题就把结果存入表中；再次遇到相同参数的调用时直接查表返回，不再展开其子树。它保留了递归"自顶向下、按需计算"的写法，同时消除了重复计算。

// 方法二：记忆化递归（自顶向下 top-down） long long memo[100]; bool vis[100]; // 用 vis 而非 memo[k]!=0，因 F(0)=0 是合法值 long long fib2(int n) { if (n <= 1) return n; // 出口 if (vis[n]) return memo[n]; // ★查表命中 ⇒ 整棵子树被剪掉 vis[n] = true; return memo[n] = fib2(n - 1) + fib2(n - 2); }
【为什么变成线性】 带 ★ 标记的那一行，把"重复子问题"全部拦截在展开之前。 状态总数 = n+1 个（对应 fib(0) … fib(n)）， 每个状态只被真正计算一次，每次计算做 O(1) 工作， ⇒ 时间 T(n) = (n+1) × O(1) = Θ(n) 【空间】备忘录数组 Θ(n) ＋ 递归栈深度 Θ(n) ⇒ S(n) = Θ(n)　　注意：递归深度没有因记忆化而变小！ 【调用次数验算 n=8】 真正展开的结点：fib(8), fib(7), …, fib(2)　共 7 个 每个展开结点发出 2 次调用 ⇒ 14 次，再加最外层 1 次 ⇒ 共 15 次调用（页面统计值），相比朴素的 67 次减少 78%
把"剪枝"看清楚：在朴素递归树中，fib(3) 出现 2 次、fib(2) 出现 3 次，每一次出现都要展开整棵子树。记忆化后，只有第一次出现时才展开，之后的每一次都在圆点处直接截断。于是这棵原本 Θ(1.618n) 个结点的"灌木丛"，被压成了一条 n 长的细链加若干个查表叶子。这就是页面上"记忆化"按钮画面变空的真正含义。

四、方法三：自底向上迭代递推

Bottom-Up Iteration · Θ(n) 时间 / Θ(1) 空间
思路转换：既然每个 fib(k) 最终都要算，而且 fib(k) 只依赖 fib(k−1) 与 fib(k−2)，那就干脆不要递归——从最小的 F(0)、F(1) 出发，顺着编号从小往大推，一路推到 F(n)。这叫自底向上（bottom-up），是动态规划的标准形态（第 7 章）。而且推的时候只需记住最近两个值，连数组都可以省掉。
// 方法三之一：自底向上 + 数组（便于回查任意 F(k)） long long fib3(int n) { if (n <= 1) return n; vector<long long> f(n + 1); f[0] = 0; f[1] = 1; for (int k = 2; k <= n; ++k) f[k] = f[k - 1] + f[k - 2]; // 时间 O(n)，空间 O(n) return f[n]; } // 方法三之二：滚动变量优化 —— 空间降到 O(1)（推荐） long long fib4(int n) { if (n <= 1) return n; long long a = 0, b = 1; // a=F(k-2), b=F(k-1) for (int k = 2; k <= n; ++k) { long long t = a + b; // t = F(k) a = b; b = t; // 向前滚动一格 } return b; // 时间 O(n)，空间 O(1)，无递归栈 }
fib4(8) 的滚动过程： 初始　　 a=F(0)=0，b=F(1)=1 k=2　t=0+1=1　 ⇒ a=1, b=1　　(F(2)=1) k=3　t=1+1=2　 ⇒ a=1, b=2　　(F(3)=2) k=4　t=1+2=3　 ⇒ a=2, b=3　　(F(4)=3) k=5　t=2+3=5　 ⇒ a=3, b=5　　(F(5)=5) k=6　t=3+5=8　 ⇒ a=5, b=8　　(F(6)=8) k=7　t=5+8=13　⇒ a=8, b=13　 (F(7)=13) k=8　t=8+13=21 ⇒ a=13, b=21　(F(8)=21) 共 7 次加法，无任何函数调用、无栈帧。

这条优化路径是全书的主线：「朴素递归（指数）→ 发现重复子问题 → 记忆化（多项式）→ 改写为自底向上递推 → 滚动数组压缩空间」。§08 的 0/1 背包会把完全相同的四步再走一遍，第 7 章动态规划则把它上升为通用方法论。
易错点
  • 用 memo[k] != 0 判断是否已算过。F(0)=0 本身就是合法结果，会被误判成"没算过"而反复重算。应另设 vis[] 标记数组，或把备忘录初始化为 −1 这类不可能出现的值。
  • 以为记忆化能防止栈溢出。记忆化把时间从 Θ(1.618n) 降到 Θ(n)，但最左那条调用链 n→n−1→…→0 照样要走一遍，递归深度仍是 n。n=106 时记忆化版依然栈溢出，必须改自底向上。
  • 把空间复杂度算成 Θ(1.618n)。栈帧用完即弹，空间只取决于树高（Θ(n)），不是结点总数。见 §04 定理 2.1。
  • 认为所有递归都能靠记忆化加速。前提是存在参数相同的重复调用。归并排序、快速排序的每个递归调用处理的子数组互不相同，记忆化毫无用处，只会白白浪费空间。
  • 把 Θ(2n) 当成紧确界。2n 只是上界，紧确界是 Θ(φn)，因为右子树比左子树矮一层，树并不满。
  • 滚动变量更新顺序写反。写成 a = b; b = a + b; 会让 b 变成 2b（a 已被覆盖）。必须先用临时变量 t 存好和，再依次赋值。
  • 忘记 long long 溢出。F(47) 已超过 int 上限（约 2.1×109），F(93) 超过 long long。复杂度对了不代表结果对。
本节小结
  • Fib 的递归树上，同一个 fib(k) 在不同分支被反复完整求解——这就是重复子问题；fib(5) 有 15 个结点却只有 6 个不同子问题，n=40 时结点数达 3.3 亿。
  • 朴素递归：T(n)=T(n−1)+T(n−2)+O(1)，特征方程 x2=x+1 的正根 φ=(1+√5)/2≈1.618 ⇒ 时间 Θ(φn)，精确调用次数 2F(n+1)−1；空间 Θ(n)（树高）。
  • 记忆化递归：查表命中即剪掉整棵子树，状态数 n+1 × 每状态 O(1) ⇒ 时间 Θ(n)、空间 Θ(n)；但递归深度仍是 n，防不了栈溢出。
  • 自底向上迭代：从 F(0)、F(1) 顺推到 F(n)，时间 Θ(n)；用滚动变量只保留最近两项，空间降到 Θ(1)、无递归栈，是本节的最优解。
  • 优化主线：朴素递归 → 发现重复子问题 → 记忆化 → 自底向上递推 → 滚动数组。§08 背包与第 7 章动态规划将重走这四步。
1朴素递归 fib(n) 的紧确时间复杂度是？
AΘ(n2)，因为有两个递归分支
BΘ(2n)，因为是二叉递归树
CΘ(φn)，φ = (1+√5)/2 ≈ 1.618
DΘ(n!)
解析：选 C。齐次递推 T(n)=T(n−1)+T(n−2) 的特征方程为 x2=x+1，正根即黄金比 φ≈1.618，通解中 φn 项占主导（另一根 |ψ|≈0.618<1，其幂趋于 0），故 T(n)=Θ(φn)。
B 是最需要辨析的选项：Θ(2n) 只是上界而非紧确界。若递归树是满二叉树才有 2n，但右子树 fib(n−2) 比左子树 fib(n−1) 矮一层，树是"歪"的，结点数明显少于 2n。精确调用次数为 2F(n+1)−1。
A 错：两个分支不代表平方，指数级的根源是"每层结点数翻倍式增长"。D 错得更远，n! 增长远快于 φn。
2要计算 F(106) mod p，下列哪种方法最合适？
A朴素递归，代码最简洁
B记忆化递归，时间已经是 Θ(n) 了，足够快
C自底向上滚动变量迭代
D三种都不行，必须用通项公式 (φn−ψn)/√5
解析：选 C。
A 显然不行：Θ(1.6181000000) 是天文数字。
B 是本题的核心陷阱：记忆化的时间确实是 Θ(n)=106，看似可行；但它的递归深度也是 106，按 §04 的估算（1~8 MB 栈）必然栈溢出，程序根本跑不到出结果。记忆化优化的是时间，不是栈深。
D 错：Binet 公式在 n 很大时浮点精度完全失效，且题目要求取模，浮点法无法取模。
C 的滚动迭代时间 Θ(n)、空间 Θ(1)、零递归栈，是唯一稳妥的选择。（若追求更快可用矩阵快速幂 Θ(log n)。）
3下列哪一个算法不能通过"记忆化"获得渐进复杂度上的改善？
A朴素递归求斐波那契数
B朴素递归求组合数 C(n,k) = C(n−1,k−1) + C(n−1,k)
C归并排序 mergeSort(a, l, r)
D0/1 背包的朴素递归 dfs(i, c)
解析：选 C。记忆化生效的唯一前提是存在重复子问题——即出现参数完全相同的重复调用。
A：fib(k) 被反复调用，有重复。B：杨辉三角中 C(n−1,k) 会被上方两个格子共同引用，有重复。D：dfs(i,c) 中同一个 (i,c) 会被多条选择路径到达，有重复（详见 §08）。
C 中 mergeSort(a,l,r) 的每次调用处理的是互不相交的子区间，没有任何两次调用的 (l,r) 相同。加了备忘录只会白占 O(n) 空间、多做一次哈希查找，复杂度依旧 Θ(n log n)。
结论：递归树上结点多 ≠ 有重复子问题。要看是否"同参数重算"。
