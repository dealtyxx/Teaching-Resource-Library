一、三类递归的判定标准

分类依据：递归性"长"在哪里
判定原则

三类递归的划分依据不是"问题难不难"，而是递归性最初来自何处：来自数学定义本身？来自数据结构的定义？还是来自人为设计的求解策略？据此提问三句话即可完成判定。

类别判定提问递归性来源递归模型从哪来典型例子
① 定义递归
（recursively
defined function）		 这个问题的数学定义本身是不是递推式？ 问题的定义式 照抄定义，无需设计 n! = n×(n−1)!；F(n)=F(n−1)+F(n−2)；C(n,k)=C(n−1,k−1)+C(n−1,k)；Ackermann 函数
② 数据结构递归
（recursive
data structure）		 处理的数据结构是不是用自身定义的？ 数据结构的定义 照着结构的定义拆 二叉树 = 根 + 左子树 + 右子树；链表 = 首结点 + 剩余链表；广义表；目录树；图 DFS
③ 问题求解递归
（recursive
solution method）		 定义和结构都不递归，是我想出的策略把它变小的？ 算法设计者的策略 需要人去构思，是本章难点 汉诺塔；0/1 背包；归并/快速排序；八皇后；求全排列
为什么阶乘是"定义递归"而不是"问题求解递归"？因为 n! = n × (n−1)! 这条式子是阶乘这个数学对象自带的，教科书上就这么定义，你不需要发明任何策略，把定义抄成代码即可。
而汉诺塔的题面只说"每次移一个盘、大盘不能压小盘"，题面里根本没有任何递推式；"先把上面 n−1 个搬到中间柱"这一步是算法设计者构思出来的——正是这一构思把问题规模从 n 降到 n−1。递推式是被"想"出来的，就属于第 ③ 类。
一句话判据：定义里现成有 ⇒ ①；数据结构里现成有 ⇒ ②；两者都没有、要自己造 ⇒ ③。
再辨析两组易混：
· 斐波那契 vs 归并排序：Fib 的 F(n)=F(n−1)+F(n−2) 是数列定义（①）；归并排序的"分成两半各自排好再归并"是排序策略（③），"排序"本身的定义里没有任何递归。
· 二叉树求高度 vs 二叉树上的最优划分：求高度只是顺着"树 = 根 + 两棵子树"这个结构定义走（②）；而"把树剖分成 k 段使代价最小"要自己设计划分策略（③）。
· 同一个问题可能兼具多类特征，分类是为了帮你找到递归模型，不必纠结唯一归属。

二、数据结构递归范例：二叉树遍历

Binary Tree Traversal · C++
定义 · 二叉树的递归定义

二叉树（binary tree）或者是空树；或者由一个根结点和两棵互不相交的、分别称为左子树与右子树的二叉树构成。——注意定义的最后两个字又是"二叉树"，结构本身就是递归的，因此对它的一切操作天然写成递归最简洁。

// 结点定义 struct Node { int val; Node *left, *right; }; // 先序 preorder：根 → 左 → 右 void preorder(Node *p) { if (p == nullptr) return; // 出口：空树，什么都不做 visit(p); // ① 访问根 preorder(p->left); // ② 递归左子树 preorder(p->right); // ③ 递归右子树 } // 中序 inorder：左 → 根 → 右 void inorder(Node *p) { if (p == nullptr) return; inorder(p->left); visit(p); // ← visit 挪到两次递归的中间 inorder(p->right); } // 后序 postorder：左 → 右 → 根 void postorder(Node *p) { if (p == nullptr) return; postorder(p->left); postorder(p->right); visit(p); // ← visit 挪到两次递归之后 } // 另一个数据结构递归：求树高 h(T) = 1 + max(h(左), h(右)) int height(Node *p) { if (p == nullptr) return 0; // 空树高度为 0 return 1 + max(height(p->left), height(p->right)); }
三种遍历的本质：代码骨架完全相同，唯一区别是 visit(p) 这一行放在两次递归调用的前 / 中 / 后。递归调用的顺序（先左后右）三者一致，因此每个结点被"经过"三次（进入、左子树回来、右子树回来），在第几次经过时才输出，就决定了它是先序、中序还是后序。
以页面演示中的树为例：　　　　1 　　　　　　　　　　　　　　 ／　＼ 　　　　　　　　　　　　　　2　　　3 　　　　　　　　　　　　 ／　＼ 　　　　　　　　　　　　4　　　5 先序 preorder（根左右）：1 → 2 → 4 → 5 → 3　与页面动画一致 中序 inorder　(左根右)：4 → 2 → 5 → 1 → 3 后序 postorder(左右根)：4 → 5 → 2 → 3 → 1
遍历visit 位置本例序列第一个被访问的最后一个被访问的典型用途
先序 preorder两次递归之前1 2 4 5 3根最右下的结点复制树、输出表达式前缀式、序列化
中序 inorder两次递归之间4 2 5 1 3最左下的结点最右下的结点BST 中序即升序、输出中缀式
后序 postorder两次递归之后4 5 2 3 1最左下的结点根释放树/删除结点、求树高、求子树聚合值、后缀式
为什么"删除整棵树"必须用后序？因为释放一个结点后就再也拿不到它的 left / right 指针了。后序保证先把两棵子树处理干净，最后才动根。同理，"计算每个子树的规模/高度"这类需要子问题结果才能算父结点的任务，一律是后序。

三、复杂度分析

树遍历递归的时间与空间
设树有 n 个结点，高度为 h。 【时间】每个结点恰好被调用一次，每次做 O(1) 工作（判空 + visit）： T(n) = T(n左) + T(n右) + O(1)，其中 n左 + n右 = n − 1 调用总次数 = n 个非空结点 + (n+1) 个空指针分支 = 2n + 1 ⇒ T(n) = Θ(n)　　与树的形状无关！ 【空间】栈中同时存在的栈帧数 = 当前所在结点的深度： S(n) = O(h) 　完全/平衡二叉树：h = ⌊log2n⌋ + 1 ⇒ S(n) = O(log n)　最好情况 　单支树（退化成链）：h = n　　　　⇒ S(n) = O(n)　　　最坏情况
结论对照：树遍历的时间永远是 Θ(n)（每个结点都要访问一遍，跑不掉）；但空间取决于树的形状而非结点数。106 个结点的平衡树只需约 20 层栈，而 106 个结点的单支树需要 106 层栈 —— 后者必然栈溢出，这正是下一小节"何时不该用递归"的现实动机。

四、何时不该用递归

适用边界与改写途径
场景为什么递归不合适应该怎么做
递归深度可能很大
（> 105 量级）		 每层一个栈帧，1 MB 线程栈通常撑不过约 104~105 层 ⇒ 栈溢出。且这是运行期崩溃，编译器不报错。 改迭代：单链递归改 while 循环；多分支递归用显式栈模拟
存在大量重复子问题 朴素递归会把同一个子问题反复重算，复杂度指数爆炸（Fib：Θ(1.618n)） 加记忆化（§05、§08），或改自底向上递推 / 动态规划（第 7 章）
递归只是"披着皮的循环" 如 sum(1..n)、数组求和、线性查找：没有分支、深度等于 n，递归带来 O(n) 栈开销却零收益，可读性也不比循环强 直接写 for 循环，空间 O(n) → O(1)
存在闭式解（公式） 1+2+…+n 有公式 n(n+1)/2，Θ(1) 就能算完，递归 Θ(n) 纯属浪费 直接套公式
对常数因子极敏感的热点代码 函数调用有压栈/跳转/寄存器保存开销，比循环体慢数倍 循环展开、迭代改写
嵌入式 / 内核 / 实时系统 栈空间极小（可能仅几 KB）且要求最坏情况可静态预估，递归深度不定 ⇒ 不可接受 规范常直接禁止递归（如 MISRA-C 规则）
反过来说，什么时候该用递归：① 数据结构本身是递归的（树、图、广义表）——迭代版要手写栈，反而更容易出错；② 分治、回溯、DFS 这类天然多分支的算法；③ 递归深度有明确上界（如 O(log n)）；④ 追求代码可读性、原型验证阶段。递归的价值是"表达力"，代价是"栈空间 + 调用开销"。
// 途径一：单链递归 → 直接改循环（线性求和） int sumRec(int a[], int n) { // 空间 O(n)，不推荐 if (n == 0) return 0; return sumRec(a, n - 1) + a[n - 1]; } int sumIter(int a[], int n) { // 空间 O(1)，推荐 int s = 0; for (int i = 0; i < n; ++i) s += a[i]; return s; } // 途径二：多分支递归 → 显式栈模拟（先序遍历的迭代版） // 注意：右子树先入栈，才能保证左子树先出栈被访问 void preorderIter(Node *root) { if (root == nullptr) return; stack<Node*> st; st.push(root); while (!st.empty()) { Node *p = st.top(); st.pop(); visit(p); if (p->right) st.push(p->right); // 右先入 if (p->left) st.push(p->left); // 左后入 → 先出 } }
显式栈的实质：把编译器替你做的事手工做一遍——用自己的 stack 保存"还没处理完的结点"，替代系统栈保存栈帧。好处是栈开在堆上，容量可达 GB 级，不受 1 MB 线程栈限制；代价是代码变长、易错（中序、后序的迭代版明显更难写）。详见 §04。
易错点
  • 把三类递归当成"难度分级"。分类看的是递归性的来源，不是难易。Ackermann 函数极难算却属于①（定义递归），二分查找很简单却属于③（求解策略递归）。
  • 认为"归并排序属于数据结构递归"。它处理的是数组——数组是线性结构，定义里没有递归；"一分为二"是人为设计的分治策略，故属于第③类。
  • 树遍历漏写空指针出口。if (p == nullptr) return; 是唯一的出口，漏掉则会对空指针解引用 ⇒ 段错误。注意出口是"指针为空"而非"叶子结点"，按叶子写会漏掉单孩子结点的情况。
  • 误以为遍历的空间复杂度是 O(log n)。只有平衡树才是 O(log n)；单支树退化为 O(n)。分析空间必须先问"树的形状是什么"。
  • 先序迭代版把左子树先入栈。栈是后进先出，左先入会导致右子树先被访问，序列变成"根右左"。必须右先入、左后入。
  • 用后序遍历去做需要先序的事（或反之）。释放树必须后序（否则先释放根就丢了子树指针）；复制树必须先序（要先建出根，才能挂子树）。看任务是"父依赖子"还是"子依赖父"来选。
本节小结
  • 三类递归的判定看"递归性来源"：来自数学定义式 ⇒ 定义递归（阶乘、Fib、组合数）；来自数据结构定义 ⇒ 数据结构递归（树、链表、图 DFS）；来自设计者构思的策略 ⇒ 问题求解递归（汉诺塔、背包、分治排序）。
  • 阶乘属于①而非③，因为 n!=n×(n−1)! 是定义自带的，无需发明；汉诺塔的"先搬 n−1 个"是想出来的，故属于③。
  • 二叉树的三种遍历代码骨架完全相同，只是 visit(p) 位于两次递归调用的前 / 中 / 后。本例序列：先序 1 2 4 5 3、中序 4 2 5 1 3、后序 4 5 2 3 1。
  • 树遍历时间恒为 Θ(n)（与形状无关）；空间为 O(h)：平衡树 O(log n)，单支树 O(n)。
  • 不该用递归的典型场景：递归深度过大、存在大量重复子问题、递归只是"披皮的循环"、已有闭式公式、嵌入式/实时系统。改写途径：单链递归 → for 循环；多分支递归 → 显式栈模拟。
1归并排序（merge sort）属于哪一类递归？
A定义递归——因为"排序"这个概念的定义中含有递归
B数据结构递归——因为它把数组不断拆成子数组
C问题求解递归——"一分为二再归并"是人为设计的求解策略
D不属于递归，因为它可以写成迭代（自底向上归并）
解析：选 C。
A 错：排序的定义是"使序列非降"，定义里没有任何递推式；对照阶乘 n!=n×(n−1)!，那才叫定义递归。
B 是最迷惑的选项：它处理的是数组，而数组是线性结构，其定义不含自身；"拆成子数组"是算法主动切的，不是结构本身长成那样。若换成"遍历二叉树"，那才是数据结构递归。
D 错："能改成迭代"不改变它是递归算法的事实——所有递归理论上都能改成迭代（用显式栈），否则任何递归都不算递归了。
判据：定义里现成有 ⇒ ①；数据结构里现成有 ⇒ ②；要自己构思 ⇒ ③。
2某二叉树的中序遍历为 4 2 5 1 3，后序遍历为 4 5 2 3 1，则其先序遍历为？
A1 2 3 4 5
B1 2 4 5 3
C1 3 2 4 5
D4 2 5 3 1
解析：选 B。后序的最后一个一定是根 ⇒ 根 = 1。在中序 4 2 5 1 3 中定位 1，左边 {4,2,5} 是左子树、右边 {3} 是右子树。
对左子树递归：后序 4 5 2 ⇒ 子根 = 2；中序 4 2 5 ⇒ 左孩子 4、右孩子 5。右子树只有 3。
还原出的树即页面演示中的树，先序（根左右）= 1 → 2 → 4 → 5 → 3。
A 错：这是中序结果的形态（若该树是 BST），不是先序。C 错：先访问了右子树 3。D 错：这是"左右根"顺序，且与已知后序矛盾。
要点：先序定根、后序定根、中序分左右；只有"中序 + 先序"或"中序 + 后序"才能唯一确定一棵二叉树。
3对一棵含 n = 106 个结点的二叉树做递归先序遍历，下列说法正确的是？
A时间 Θ(n log n)，空间 Θ(log n)
B时间 Θ(n)，空间必为 Θ(log n)，因为二叉树高度就是 log n
C时间 Θ(n)；空间 O(h)，若树退化成单支链则 h = n，很可能栈溢出
D时间 Θ(n)，空间 Θ(1)，因为遍历没有申请任何额外内存
解析：选 C。
时间：每个结点恰访问一次、每次 O(1)，故 Θ(n)，与树的形状无关；A 中的 log n 因子凭空多出来了。
B 错在"必为"：h = log2n 只对平衡树成立。一棵每个结点只有右孩子的单支树，高度就是 n = 106，栈深 106 层 ⇒ 按 1 MB 线程栈算必然溢出。
D 错：递归隐式使用系统栈，栈帧数 = 当前深度，绝不是 Θ(1)。
此题正是"何时不该用递归"的现实场景：深度不可控时应改用显式栈的迭代版。
