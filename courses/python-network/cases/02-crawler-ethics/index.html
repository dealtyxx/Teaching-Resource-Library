多线程爬虫的效率与伦理边界

章节定位

本案例落在第 2 章「多线程与多进程编程」的 2.1 节。网络请求属于典型的 I/O 密集型任务——线程大部分时间在等待响应，正好适合用 threading 与线程池并发提速。可当同样的 threading 技术被用来对一个网站发起成百上千并发请求时，效率的另一面就是破坏。因此本节把 threading 模块、线程池、GIL 这三个知识点，与「职业伦理」「法治意识」直接绑在一起讲：学会开线程之前，先学会为线程装上刹车。

背景导入：10 倍效率的诱惑与代价

单线程爬虫一次只等一个响应；换成多线程或线程池，数十个请求同时在途，数据采集效率可以提升 10 到 100 倍。电商价格监控、舆情分析、学术数据采集，都建立在这种并发能力之上。

但效率一旦失控，就会越过法律与伦理的边界。下面四个真实判例，是每一个写爬虫的人都该先读一遍的「前车之鉴」。

📁今日头条诉趣头条 不正当竞争案2018不正当竞争

趣头条通过爬虫抓取「今日头条」的全站内容并在自家产品中呈现。法院认定：擅自抓取、使用竞争对手投入大量成本形成的数据，破坏了公平竞争秩序。即使技术上完全可行，也不代表法律允许。

⚖️ 结果：法院判决趣头条赔偿 500 万元，认定构成不正当竞争

📁大众点评诉百度地图 数据抓取案2016数据权属

百度地图大量抓取「大众点评」的用户评论数据用于自身服务。法院支持大众点评的主张：用户生成内容是平台长期运营积累的成果，数据权属受法律保护，不能被随意搬运。

⚖️ 结果：判决百度停止抓取并赔偿

📁LinkedIn 诉 hiQ 数据抓取案2022 · 美国公开数据边界

hiQ 抓取 LinkedIn 上公开的用户资料用于商业分析。案件几经反复，最终确立一条对中国从业者同样有启示的原则：公开数据 ≠ 可以随意抓取，未经授权的大规模采集依然可能违法。

⚖️ 结果：历经多次上诉，hiQ 最终败诉

📁12306 抢票插件被封案2018拒绝服务风险

某抢票软件以极高频率轮询 12306 接口，占用大量服务器资源，引发普通用户投诉。过度请求本质上就是一种拒绝服务式攻击，既损害系统稳定，也破坏了购票的公平秩序。

⚖️ 结果：12306 封禁相关 IP，工信部介入要求规范抢票软件

⚠️技术滥用的四种社会危害

服务器负载——DDoS 式爬取可致网站瘫痪；数据泄露——爬取手机号、住址等个人隐私；不正当竞争——窃取他人商业数据；破坏公平——抢票插件挤占普通用户的正当权益。

结论：I/O 密集型任务（如爬虫的网络等待）里，线程在等待时会释放 GIL，多线程能显著提速；而 CPU 密集型任务里，GIL 让线程无法真正并行，多线程甚至比单线程还慢——这时只能靠多进程绕过 GIL。

技术讲解

一个「守规矩」的爬虫，和一个「野蛮」的爬虫，代码差别往往只在几行克制。下面是合规爬虫 EthicalCrawler 的核心抓取逻辑——它在真正发请求之前，先过了 robots.txt、请求间隔、身份标识、限流响应这四道关。

import urllib.robotparser
from time import sleep
import requests


class EthicalCrawler:
    """符合伦理规范的爬虫：线程数 ≤ 5、请求间隔 ≥ 1 秒、尊重 429"""

    def __init__(self, num_threads=3, delay=1.0):
        self.num_threads = min(num_threads, 5)   # 线程数封顶，保护对方服务器
        self.delay = delay                        # 请求间隔（秒）
        self.robot_parsers = {}

    def can_fetch(self, url):
        """检查 robots.txt 是否允许抓取该 URL"""
        from urllib.parse import urlparse
        base = "{0.scheme}://{0.netloc}".format(urlparse(url))
        if base not in self.robot_parsers:
            rp = urllib.robotparser.RobotFileParser()
            rp.set_url(base + "/robots.txt")
            try:
                rp.read()
            except Exception:
                return False            # 读不到就保守处理：不抓
            self.robot_parsers[base] = rp
        return self.robot_parsers[base].can_fetch("*", url)

    def fetch_url(self, url):
        # 1. 先查 robots.txt 是否允许抓取
        if not self.can_fetch(url):
            print("跳过（robots 禁止）: " + url)
            return
        # 2. 主动 sleep，拉开请求间隔，给服务器喘息
        sleep(self.delay)
        # 3. 带上表明身份的 User-Agent，声明用途与联系方式
        headers = {"User-Agent": "EthicalCrawler/1.0 (+mailto:me@example.com)"}
        resp = requests.get(url, headers=headers, timeout=10)
        # 4. 尊重 429：对方喊停就退避，而不是硬闯
        if resp.status_code == 429:
            print("收到 429，退避 10 秒: " + url)
            sleep(10)
            return
        print("合规抓取成功: " + url + "  状态 " + str(resp.status_code))

🔒为什么爬虫适合多线程，密码破解却不适合？

关键在 GIL。网络请求是 I/O 密集型：线程在等待响应时会释放 GIL，其他线程趁机干活，所以多线程能提速。而纯计算是 CPU 密集型：GIL 保证同一时刻只有一个线程执行字节码，多线程无法真正并行，想加速只能用多进程绕开 GIL——这正是上面对比图揭示的分界线。

思政引导

🧭职业伦理· robots.txt 与合理使用

  • robots.txt 是网站所有者的意愿表达：其中的 Disallow 明确写着「不希望被爬取」，遵守它是程序员的职业道德。
  • 合理使用原则：学术研究、新闻报道可以适度引用，但不能大规模商业化利用，更不能损害原网站的正当利益。
  • 身份透明：用 User-Agent 声明自己是谁、为何而来，而不是伪装、隐匿、绕过反爬——技术人的体面，藏在这些细节里。

⚖️法治意识· 爬虫头顶的四部法律

  • 《反不正当竞争法》第 12 条：禁止擅自抓取竞争对手数据（今日头条案的判决依据）。
  • 《网络安全法》第 44 条：未经授权不得收集个人信息。
  • 《数据安全法》：数据采集需遵守合法、正当、必要原则。
  • 《个人信息保护法》：禁止以非法方式获取个人信息。
  • 三条判例启示：今日头条案——技术可行不等于法律允许；LinkedIn 案——公开数据不等于可随意抓取；12306 案——过度请求等于拒绝服务攻击。

🤝社会责任· 合规爬虫的五个硬要求

  • 保护服务器资源：请求间隔 ≥ 1 秒、线程数 ≤ 5、避免在业务高峰期爬取。
  • 尊重限流：收到 429 就退避等待，而不是换 IP 继续硬闯。
  • 表明身份：UA 中写清用途与联系方式，让对方能找到你。
  • 保护用户隐私：不爬手机号、身份证号等未公开的个人信息，必要时做数据脱敏。
  • 你写下的 num_threads 默认值，可能就是别人服务器上的一场雪崩——把责任感写进默认参数里。

🌱人文素养· 换位思考与技术向善

  • 换位思考：如果你的网站被爬垮、你的数据被窃取，你会怎么想？把这一问放在写代码之前。
  • 技术是工具，人心定善恶：同样的多线程爬虫，可以窃取商业数据，也可以做疫情数据统计、环境监测等公益之事。
  • 克制是一种能力：能写出 50 线程的人很多，愿意把它压到 5 线程的人，才真正理解工程师的分寸。
