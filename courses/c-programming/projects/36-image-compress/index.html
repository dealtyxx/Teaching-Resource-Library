行程编码（RLE）是最朴素的图像压缩：连续相同的像素记成”（值, 重复数）“对—— 200 200 200 200 四字节压成 (200,4) 两字节。国旗这类大色块图压缩比可达数倍；噪声图却会膨胀（每个孤立像素都要花 2 字节记）。

指针在这里全员上阵，堪称模块六毕业汇演：

  • 读指针 p 贪吃连续段（项目 32 的偏移 + 项目 35 的游标纪律）；
  • 哨兵 end = src + n 防越界（项目 35 的护栏落地）；
  • 写指针 q 双游标产出（*q++ = val 的惯用法）；
  • 指针相减 q - dst 直接得输出字节数——地址算术的收官一式。

rle.c
#include <stdint.h>

/*
 * RLE行程压缩(指针版)
 * 返回压缩后字节数;dst须预留2倍空间(防膨胀)
 */
int rle_encode(const uint8_t *src, int n,
               uint8_t *dst) {
    const uint8_t *p   = src;        /* 读指针 */
    const uint8_t *end = src + n;    /* 越界哨兵 */
    uint8_t *q = dst;                /* 写指针 */
    while (p < end) {
        uint8_t val = *p;
        uint8_t run = 1;
        /* 贪吃连续相同字节(上限255) */
        while (p + run < end
               && p[run] == val && run < 255)
            run++;
        *q++ = val;                  /* 写(值,长度)对 */
        *q++ = run;
        p += run;                    /* 读指针跳过整段 */
    }
    return (int)(q - dst);           /* 指针相减=字节数 */
}

💡 读指针 p 贪吃连续段、写指针 q 产出 (值,长度) 对、q - dst 指针相减直接得字节数—— 这是指针三大件（移动/解引用/相减）的实战合奏。切到噪声图看"负压缩"： 压缩的本质是消灭冗余，没有冗余的数据不可压缩（信息论香农定理的直观版）。 所以 dst 必须按 2n 预留——防的就是这个最坏情况。

素养与思政

很多年里，中国每卖一台 DVD 要向国外专利池缴纳数十元许可费——编解码标准受制于人，制造大国只挣辛苦钱。今天，自主的 AVS3 标准已用于央视 8K 超高清频道，压缩效率比肩国际最新标准。 标准之争的地基，正是你今天写的这类算法：指针在字节流上的每一次精准腾挪，都是性能优化的最小单元。从缴专利费到定标准，路是一行行性能敏感的代码铺出来的。 模块六毕业的你，已经站在这条路的起点。
