北斗串口报文环形缓存

基础必做 北斗场景 ★★★★ 约 100 分钟

学习目标：理解嵌入式数据缓存机制

数组边界取模运算环形缓冲区

场景导入：字节说来就来，程序却在忙

北斗模块通过串口发送 NMEA 报文，字节以 115200 波特率”说来就来”；而主程序可能正忙着算坐标。字节来了没人接，就丢了。 嵌入式的标准解法是环形缓冲区（Ring Buffer）：

  • 一个普通数组 buf[N] + 两个下标：tail（写入位置）、head（读取位置）；
  • 每次写后 tail = (tail + 1) % N——取模运算让下标走到尾部自动回绕到 0，直的数组变成”圆”；
  • count 记录存量：写满（count == N）拒绝写入，读空（count == 0）拒绝读取。

这是模块一取余运算（%）在工程中的高光时刻，也是数组边界控制的实战首秀。

串口每收到 1 字节就写入 tail；主程序空闲时从 head 读走。
已读出：（空）丢弃字节：0
ring_buf.c
#include <stdio.h>
#define N 8

char buf[N];
int head = 0, tail = 0, count = 0;

/* 串口中断:每收到1字节调用 */
int ring_write(char ch) {
    if (count == N) return -1;    /* 满:丢弃并报错 */
    buf[tail] = ch;
    tail = (tail + 1) % N;        /* 到尾部自动回绕 */
    count++;
    return 0;
}

/* 主循环:取1字节处理 */
int ring_read(char *out) {
    if (count == 0) return -1;    /* 空:无数据 */
    *out = buf[head];
    head = (head + 1) % N;
    count--;
    return 0;
}

💡 环形缓冲区解决的是速度不匹配：串口字节说来就来（中断），主程序却可能正忙。 数组本是直的，(tail+1)%N 一个取模让它首尾相接变成"圆"。 连续写 8 个字节把它写满，再多写一个——看看丢包计数。

素养与思政

生产快、消费慢，数据会溢出；生产慢、消费快，处理器会空转。环形缓冲区的智慧在于用空间换从容——不强求两端同步，而是给突发留出余地。 都江堰不筑高坝硬堵，而以鱼嘴分水、飞沙堰泄洪，两千年调蓄岷江的丰枯。好的工程从不硬碰硬，而是给变化留缓冲——这既是李冰的治水之道，也是你这 20 行 C 代码里的设计哲学。
