云平台题库导入导出

进阶选做 平台应用 ★★★★★ 约 140 分钟

文件批量处理格式转换数据交互

场景导入：老师上传的 CSV，你敢直接入库吗

在线教育平台的日常：老师批量上传 CSV 题库、平台导出给另一所学校。平台级文件交互的第一原则：

永远假设上传的文件是坏的。

字段缺失、难度超纲、编码混乱……坏行必然存在。健壮的导入器三层设防：

  • sscanf(...) != 4 —— 字段数不对，整行拒收（返回值验收，项目 44 的锁钥原则）；
  • 范围校验 —— 难度必须 1~5，超纲拦截（第 3 章的类型自觉）；
  • 报行号 —— “第 3 行字段缺失”让老师能自己修文件，“导入失败”只会让他打客服电话。

坏行处理用 continue 剔坏保好（项目 15），好数据一条不少、坏数据一条不进。

quiz_io.c
#include <stdio.h>
#include <string.h>

typedef struct {
    int  id;
    char stem[64];
    char ans[32];
    int  diff;      /* 难度1~5 */
} Quiz;

/* 导入:逐行解析+逐行校验,坏行报行号 */
int import_csv(const char *path, Quiz qs[], int cap) {
    FILE *fp = fopen(path, "r");
    if (fp == NULL) return -1;
    char line[160];
    int n = 0, lineno = 0;
    while (n < cap && fgets(line, 160, fp)) {
        lineno++;
        Quiz q;
        /* %63[^,]:读到逗号为止,限宽防溢出 */
        int got = sscanf(line, "%d,%63[^,],%31[^,],%d",
                     &q.id, q.stem, q.ans, &q.diff);
        if (got != 4) {              /* 字段不全 */
            printf("第%d行:字段数错误,跳过\n", lineno);
            continue;                /* 项目15:剔坏保好 */
        }
        if (q.diff < 1 || q.diff > 5) {
            printf("第%d行:难度%d超范围\n", lineno, q.diff);
            continue;
        }
        qs[n++] = q;
    }
    fclose(fp);
    return n;
}

💡 平台级导入的铁律：永远假设上传的文件是坏的。三层防线全在代码里： sscanf 返回值查字段数、范围校验拦超纲难度、`%63[^,]` 限宽防溢出。 坏行处理用 continue 剔坏保好（项目 15），且必须报行号——"导入失败"和"第 3 行字段缺失"， 对用户是两个世界。格式转换（CSV↔JSON）则是平台互通的日常：数据不变，衣服常换。

VibeCoding 三段迭代提示

  1. 手写基础版：实现 CSV 导入（含字段数与难度范围校验）+ 导出。用实验里的坏数据自测：拒收行数对得上吗？
  2. AI 优化进阶版：让 AI 增加 JSON 导出。审查两个刁钻点：题干含引号怎么转义？最后一条记录后面不能有逗号——AI 常在这两处翻车。
  3. 信创加固定稿版：题干含逗号的场景（CSV 的老大难：加引号包裹并解析）；导入前先全文件”预检”再入库（发现坏行先报告、经确认再导入——事务思维，项目 41 转账问题的续篇）；限制单文件最大行数防资源耗尽。
