简易计算器（加减乘除）

学习目标：理解多分支程序逻辑

if-else if多分支选择

场景导入：一个运算符，四条路

计算器是”多分支选择”的经典教材：用户给出运算符 op，程序根据它是 +、-、* 还是 / 走不同的计算路径——外加一条”不认识的运算符”兜底路径。

但真正的工程问题藏在除法里：除数为 0 怎么办？ 整数除以 0 在多数平台会直接让程序崩溃（除零异常）。所以除法分支内部必须再嵌一层判断——这是你第一次见到”分支套分支”。

互动实验：四则运算的分支选择

if-else if · 除零防护
12 / 3 = 4.00

💡 除法分支里又嵌了一层 if：先判 b 是否为 0，再决定算不算。 这是「先防护、后计算」的工程套路——第 2 章审查 AI 代码时找的就是这种防护。 另外注意：浮点数用 b == 0 判断严格为零可以， 但判断"约等于零"就要用第 3 章的容差比较了。

main.c
1#include <stdio.h>
2 
3int main(void) {
4    float a = 12.0f, b = 3.0f;
5    char op = '/';
6    if (op == '+') {
7        printf("= %.2f\n", a + b);
8    } else if (op == '-') {
9        printf("= %.2f\n", a - b);
10    } else if (op == '*') {
11        printf("= %.2f\n", a * b);
12    } else if (op == '/') {
13        if (b == 0) {
14            printf("错误：除数不能为 0\n");
15        } else {
16            printf("= %.2f\n", a / b);
17        }
18    } else {
19        printf("错误：不支持的运算符\n");
20    }
21    return 0;
22}
运行结果
= 4.00

素养与思政

1996 年阿丽亚娜 5 号火箭首飞 37 秒后爆炸，直接原因是一次未受保护的数值转换溢出——一个”不会发生”的输入，摧毁了 5 亿美元的任务。 除零防护看似小题大做，实则是工程师的职业本能：凡是外部输入，皆不可信；凡是危险操作，先设防线。你写下的每一个防护分支，都是在为使用者的安全买保险。
