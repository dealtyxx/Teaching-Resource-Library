流水线传感器批量采样

进阶选做 信创场景 ★★★ 约 90 分钟

学习目标：掌握工业数据循环处理思维

循环过滤数据筛选异常值处理

场景导入：坏数据不能停产线

产线温度巡检仪每分钟采 20 个点。传感器偶尔断线（读数 -999）或短路（999）——这些异常值若直接进统计，平均温度会被拉到荒谬的负数。

处理原则是工业软件的共识：跳过坏点，不停产线。C 语言的表达就是 continue：

if (t[i] < lo || t[i] > hi) {
    skipped++;
    continue;   /* 本圈到此为止，直接进入下一圈 */
}
/* continue 之后的语句，坏点永远执行不到 */

对比模块内学过的 break：break 是”全线停工”，continue 是”这件次品扔掉，下一件继续”。

💡 continue 与 break 的区别： break 是"整条循环到此为止"，continue 是"这一圈到此为止，下一圈继续"。 剔除异常值要用 continue——不能因为一个坏点就停掉整条产线。 再想深一层：如果把 -999 也算进平均值，20 个点的平均温度会被拉低到多少？不过滤的统计就是错误的统计。

line_filter.c（随采样实时生成）
#include <stdio.h>

int main(void) {
    int t[20] = {52,61,-999,58,47,66,999,55,49,71,63,-999,44,57,68,51,999,60,46,59};
    int lo = 20, hi = 90;       /* 合格温度区间(°C) */
    int kept = 0, skipped = 0, sum = 0;
    for (int i = 0; i < 20; i++) {
        if (t[i] < lo || t[i] > hi) {
            skipped++;
            continue;   /* 异常值:跳过本圈剩余语句,直接下一圈 */
        }
        kept++;         /* continue 之后的代码,异常值执行不到 */
        sum += t[i];
    }
    printf("有效:%d 剔除:%d\n", kept, skipped);
    if (kept > 0)
        printf("平均温度:%.1f°C\n", (float)sum / kept);
    return 0;
}
运行结果
有效:16 剔除:4
平均温度:56.7°C

VibeCoding 三段迭代提示

  1. 手写基础版：20 个采样点，剔除范围外值，输出有效数、剔除数、平均值。先想清楚：kept 和 skipped 加起来必须等于 20——这是你的自检公式。
  2. AI 优化进阶版：让 AI 增加”连续 3 个异常则报传感器故障”的逻辑。审查它的”连续计数器”在遇到正常值时清零了吗？没清零就是 bug。
  3. 信创加固定稿版：kept=0 时的除零防护；把 -999/999 定义为 SENSOR_FAULT_OPEN/SENSOR_FAULT_SHORT 宏；思考”剔除多少比例以上说明产线本身有问题”——过滤器也需要被监控。

素养与思政

高铁轮对的出厂检测要经过上百个测点的循环扫描，一个超差就整轮报废；国产大飞机 C919 的每根线缆都被自动测试台逐一”点名”。 中国制造从”能用”到”精良”，靠的不是口号，是一条条产线上”剔除不合格”的循环日复一日地转。 你写的 continue，就是质检员手起手落的那个动作——对次品毫不留情，对流程绝不打断。
