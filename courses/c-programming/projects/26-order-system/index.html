自助点餐系统（模块化）

基础必做 生活应用 ★★★★ 约 100 分钟

学习目标：理解模块化程序设计思想

多函数拆分功能模块化

场景导入：把 200 行的 main 拆成 6 个函数

真实的点餐机要做的事：显示菜单、加菜、撤单、算钱、打折、出票。全塞进 main 里就是 200 行”面条代码”——改打折规则时，你得在面条堆里找那三行。

模块化设计的做法是：按职责拆函数，每个函数只做一件事：

main() 只当总调度：
  show_menu() → add_item() → calc_total()
  → apply_discount() → print_receipt()

好处立竿见影：改折扣只动 apply_discount；测试算钱只调 calc_total；换打印格式只碰 print_receipt。改动被”关”在函数边界内，这就是低耦合。

🧩 六个函数的分工（操作左侧，看谁被"点名"）

void show_menu(void)

只负责展示菜单 ← 正在工作

int add_item(int cart[], int id)

只负责加菜进购物车

int remove_item(int cart[], int id)

只负责撤单

int calc_total(const int cart[])

只负责算钱

int apply_discount(int total)

只负责打折规则

void print_receipt(int pay)

只负责打印小票

💡 模块化的黄金法则：一个函数只做一件事（单一职责）。 好处现在就能体会——想把"满30减5"改成"满50减10"？只动 apply_discount 一个函数， 点菜、算钱、打票的代码一行不碰。main 函数退化成"总调度"，只负责按顺序喊人干活。

VibeCoding 三段迭代提示

  1. 手写基础版：实现 6 个函数版点餐系统。动手前先画”函数分工表”：函数名/输入/输出/职责一句话——写不出一句话职责的函数，说明拆分有问题。
  2. AI 优化进阶版：让 AI 增加”会员9折（与满减不叠加，取更优）“。审查它把新逻辑放进了哪个函数？如果它改了 calc_total，就违反了单一职责——折扣的事归 apply_discount。
  3. 信创加固定稿版：把菜单数据（名称/价格）从代码里分离成 const 数组统一维护；函数间只传必要参数（避免全局变量满天飞）；为 calc_total 写 3 个测试用例（空车/单品/多品）。

素养与思政

一部 C919 大飞机有 600 万个零部件，来自 22 个省市的上千家供应商——机翼归机翼、航电归航电，接口标准定义清楚，各自把各自做到极致。 现代工程的伟力不在个人全能，而在分工协作。模块化编程就是这套文明成果在代码里的映射：函数各司其职、接口清晰承诺，你的 6 个小函数与 600 万个零件遵循的是同一条组织学原理。
