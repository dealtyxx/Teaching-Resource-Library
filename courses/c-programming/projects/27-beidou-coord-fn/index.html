函数封装参数传递复用性

场景导入：同一段逻辑，你已经写过两遍了

第 3 章手写过 NMEA 坐标换算，第 6 章的实训又写了一遍——纬度一份、经度一份，逻辑完全相同。 这就是封装要消灭的”复制粘贴式复用”：

double nmea_to_deg(double raw);   /* 封装一次 */
nmea_to_deg(lat);                 /* 调用 N 次 */
nmea_to_deg(lon);

封装的关键是参数传递的机制——C 语言是值传递（pass by value）：调用时把实参的值拷贝给形参，函数内部操作的是副本。两次调用传入不同的值，同一份代码就产出不同的结果——这就是复用的原理。

coord_fn.c（随输入实时生成）
#include <stdio.h>

/* 一次封装:ddmm.mmmm → 十进制度 */
double nmea_to_deg(double raw) {   /* raw是形参 */
    int    deg = (int)(raw / 100);
    double min = raw - deg * 100;
    return deg + min / 60.0;
}

int main(void) {
    double lat = 3954.4074;
    double lon = 11623.4567;
    /* 两处调用,同一个函数 */
    printf("纬度: %.6f\n", nmea_to_deg(lat));
    printf("经度: %.6f\n", nmea_to_deg(lon));
    return 0;
}
运行结果
纬度: 39.906790
经度: 116.390945

💡 第 3 章你写过一遍换算逻辑，第 6 章又写过——每次都重抄一遍？封装成函数后，逻辑只存在一份： 修 bug 修一处，两处调用同时受益。这就是"复用性"。 注意值传递：形参 raw 是实参的副本，函数里改 raw 不影响 main 的 lat—— 想让函数"改到外面的变量"？那是第 9 章指针的戏份。

VibeCoding 三段迭代提示

  1. 手写基础版：封装 nmea_to_deg 并用它换算一组北京坐标（纬度+经度各调用一次）。体会”逻辑只写一遍”。
  2. AI 优化进阶版：让 AI 增加方向参数 nmea_to_deg(double raw, char dir)（S/W 为负）。审查参数顺序设计：值在前、修饰在后是否更顺手？它的非法 dir 处理返回什么？
  3. 信创加固定稿版：给函数写清”契约注释”（输入范围/输出范围/错误约定），做成可被同学直接调用的 .h + .c 工具对（第 8 章多文件的预演）；对比第 3 章信创版，思考哪些防护应该放进函数、哪些留给调用者。
