野外光伏终端内存优化

进阶选做 信创场景 ★★★★★ 约 120 分钟

学习目标：嵌入式内存优化思维训练

指针传参栈内存节约低功耗

场景导入：荒漠里的终端，死机没人管

戈壁滩上的光伏监测终端：电池供电、4KB 栈空间的国产 MCU、维护人员驱车三小时才能到场。 在这里，第 1 章的内存布局表不再是理论——栈就那么大，溢出即死机。

最容易压垮栈的，是把大结构体按值传参：一条 512 字节的采样记录，每传一层函数就在栈上整份复印一次。调用链 4 层深，就是 2KB 拷贝——半个栈没了。 指针传参一举三得：

  • 省栈：每层只压 4 字节地址，占用与结构体大小脱钩；
  • 省电：不复制就不搬运内存，CPU 更早回到低功耗休眠；
  • 保安全：配上 const 修饰，只读语义由编译器强制。

✅ 栈内安全

💡 做个对照实验：结构体 1024B、深度 4 层——值传递直接爆栈，切到指针传递立降到 5% 以下。 省栈也是省电：不复制就不搬运内存，CPU 更早回到休眠。加 const 则保住只读安全：const PvRecord *r = "看得到、改不了"。

pv_val.c（随参数实时生成）
#include <stdint.h>
#define SAMPLES 64

typedef struct {          /* 光伏采样记录 */
    uint32_t ts;
    float    volt[SAMPLES / 2];
    float    curr[SAMPLES / 2];
} PvRecord;               /* sizeof ≈ 512 字节 */

/* 值传递:每层调用复制整个结构体! */
float calc_power(PvRecord rec) {      /* +512B */
    return rec.volt[0] * rec.curr[0];
}
int check_alarm(PvRecord rec) {       /* +512B */
    return calc_power(rec) > 5000.0f;
}
void log_data(PvRecord rec) {         /* +512B */
    if (check_alarm(rec)) { /*...*/ }
}

int main(void) {
    PvRecord rec = {0};   /* 本体:512B(仅一份) */
    log_data(rec);
    return 0;
}

VibeCoding 三段迭代提示

  1. 手写基础版：定义 512B 采样结构体，分别写值传递/指针传递两版三层调用链，用 sizeof 打印各处开销。
  2. AI 优化进阶版：让 AI 解释”什么时候仍应值传递”（很小的结构体，如 8 字节的坐标对——拷贝比间接访问还便宜）。审查它给出的临界尺寸有没有依据（经验值：小于等于 2 个机器字可考虑值传）。
  3. 信创加固定稿版：查阅你所用国产 MCU 的默认栈大小（链接脚本里的 _Stack_Size）；给项目 30 的递归深度护栏结合本项目重新计算；输出一页”栈预算表”：每个函数最大栈深、总余量。

素养与思政

“双碳”目标下，中国光伏装机容量全球第一，数百万台野外终端在无人处默默工作。它们的电池要撑过阴雨周，它们的固件要十年不重启——绿色能源的底座，是绿色的代码。 少复制一次内存，就少一次功耗尖峰；省下一半栈，就多一分野外无人值守的底气。节约在这里不是美德修辞，是系统能不能活下去的硬指标。 把每个字节当资源敬畏，这是嵌入式工程师与”双碳”时代的握手方式。
