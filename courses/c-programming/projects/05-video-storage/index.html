视频存储容量估算器

综合挑战 生活场景 ★★★ 约 90 分钟

学习目标：综合运用顺序结构解决实际问题

多步运算单位换算综合计算

场景导入：保卫处老师的求助

学校要新装 8 路 1080P 监控，录像保存 30 天。保卫处老师问你：“要买多大的硬盘？” 这是模块一的综合挑战——没有新语法，但要把变量、算术运算、单位换算串成一条更长的流水线：

  1. 每天录像秒数 = 小时 × 3600；
  2. 每路每天比特数 = 码率(Mbps) × 10⁶ × 秒数；
  3. 单位换算：bit ÷ 8 → Byte，÷ 10⁹ → GB；
  4. 总容量 = 每路每天 GB × 天数 × 路数。

四步环环相扣：第③步没除以 8，答案就大 8 倍；第①步忘了 ×3600，答案就小三千多倍。顺序结构的挑战不在单步，而在链条。

四步链式计算（顺序结构的威力）

  1. ① 每天秒数 = 24 × 3600 = 86,400 秒
  2. ② 每天比特 = 4Mbps × 秒数
  3. ③ 换算 GB = ÷8（bit→Byte）÷10⁹ = 43.2 GB/路/天
  4. ④ 总容量 = ×30天 ×8路 = 10368 GB

storage.c
#include <stdio.h>

int main(void) {
    float mbps  = 4.0f;   /* 码率(Mbps) */
    int   hours = 24;      /* 每天录像小时数 */
    int   days  = 30;      /* 保存天数 */
    int   cams  = 8;       /* 摄像头路数 */

    long  sec_per_day = hours * 3600L;                 /* ① */
    float gb_per_day  = mbps * 1e6f * sec_per_day
                        / 8.0f / 1e9f;                 /* ②③ bit→GB */
    float total_gb    = gb_per_day * days * cams;      /* ④ */

    printf("每路每天约 %.1f GB\n", gb_per_day);
    printf("总容量约 %.1f GB (%.2f TB)\n",
           total_gb, total_gb / 1000.0f);
    return 0;
}
运行结果
每路每天约 43.2 GB
总容量约 10368.0 GB (10.37 TB)

💡 审查点：代码里 hours * 3600L 的 L 后缀是什么意思？如果 64 路 4K 摄像头保存 90 天， 用 int 存"总比特数"会发生什么？（提示：21 亿）

VibeCoding 三段迭代提示

  1. 手写基础版：用 scanf 读入码率、时长、天数、路数，输出总 GB 数。先在纸上写好四步公式再敲代码。
  2. AI 优化进阶版：让 AI 增加”输出改为自动选择 GB/TB 单位”与”计算所需 4TB 硬盘块数”（提示：向上取整怎么做？）。审查它是否犯了整数除法截断的错误。
  3. 信创加固定稿版：所有输入加范围校验（码率 1100Mbps、路数 11024）；中间量改用 double 或 uint64_t 彻底消除溢出；单位换算系数全部宏定义。完成后，你就拥有了一个能交付给保卫处的小工具。
