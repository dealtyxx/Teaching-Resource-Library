学习目标：理解后置判断循环的应用场景

do-while循环计数条件终止

场景导入：必须先问一次的循环

登录验证有个微妙的逻辑：判断”密码对不对”之前，必须先让用户输入一次。 while 是”先判断、后执行”——第一圈判断时连输入都还没有，条件从何谈起？这正是 do-while 的主场：

do {
    /* 循环体：先无条件执行一次 */
} while (条件);   /* 再决定要不要下一圈 */

do-while 保证循环体至少执行一次。凡是”先做一次再说”的场景——询问密码、显示菜单、游戏”再来一局”——它都是最贴切的表达。配上计数器 tries 和复合条件 !ok && tries < 3，就是完整的”三次机会”逻辑。

剩余机会：

do-while 轨迹（先执行、后判断）

循环体还未执行——但只要程序运行，至少会询问一次，这正是选 do-while 而非 while 的原因。

login.c
#include <stdio.h>
#include <string.h>
#define MAX_TRIES 3

int main(void) {
    char input[32];
    int tries = 0, ok = 0;
    do {                             /* 先执行:至少要问一次 */
        printf("请输入密码:");
        scanf("%31s", input);        /* %31s 防缓冲区溢出 */
        tries++;
        if (strcmp(input, "BeiDou@2024") == 0) {
            ok = 1;                  /* 密码正确 */
        } else {
            printf("错误!剩余%d次\n", MAX_TRIES - tries);
        }
    } while (!ok && tries < MAX_TRIES); /* 后置判断 */
    if (ok)  printf("登录成功,欢迎回来\n");
    else     printf("已锁定,请联系管理员\n");
    return 0;
}

💡 为什么用 do-while？因为"询问密码"这件事天然要先做一次才能判断—— while 先判断后执行，第一圈判断时连输入都还没有。凡是"至少执行一次"的场景 （菜单显示、重试询问、游戏"再来一局"），do-while 都是更贴切的表达。 顺带注意第 10 行 %31s：给 32 字节数组留 1 字节存 \0——第 2 章的缓冲区防线又出现了。
