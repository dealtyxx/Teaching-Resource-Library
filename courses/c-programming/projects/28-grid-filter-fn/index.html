电网电流滤波函数封装

进阶选做 信创场景 ★★★★ 约 100 分钟

学习目标：电网场景模块化开发思维

函数复用参数设计低耦合

场景导入：一个函数服务全站的采样通道

变电站监测装置要同时处理几十路信号：A/B/C 三相电流、三相电压、零序分量……每路都有毛刺要滤。 给每路写一份滤波代码？维护灾难。正确姿势是一个通用滤波函数 + 参数化设计：

void filter_ma(const float in[], float out[], int n, int w);

这个签名浓缩了三条参数设计原则：

  • 数据用数组传：C 传数组实际传的是首地址——函数能直接读写调用者的数组（与值传递不同！这是第 9 章指针的预告）；
  • 规模用参数传：点数 n、窗口 w 都不写死——同一函数适配任何通道、任何工况；
  • 只读加 const：const float in[] 向调用者承诺”绝不改你的原始数据”。

互动实验：一个滤波函数，喂饱两路信号

函数复用 · 参数设计 · 低耦合

filter_ma(ia, ia_f, 64, w) — A相电流（灰=原始采样，彩=滤波输出，单位 A）

filter_ma(ua, ua_f, 64, w) — A相电压（灰=原始采样，彩=滤波输出，单位 V）

💡 w=1 时输出=输入（不滤波）；w 越大越平滑，但曲线越"迟钝"（相位滞后）——继电保护要在平滑度和响应速度之间做工程权衡。注意两条曲线用的是同一个函数： 量程不同（50A vs 220V）完全不影响它，因为函数只关心"数组进、数组出"，不关心物理含义——这就是低耦合。

grid_filter.c
#include <stdio.h>

/*
 * 滑动平均滤波(通用工具函数)
 * in/out:输入输出数组  n:点数  w:窗口大小
 * 设计要点:窗口作参数传入,不写死 → 低耦合
 */
void filter_ma(const float in[], float out[],
               int n, int w) {
    for (int i = 0; i < n; i++) {
        float sum = 0;
        int   cnt = 0;
        for (int k = i - w + 1; k <= i; k++) {
            if (k < 0) continue;   /* 起始端不足w个 */
            sum += in[k];
            cnt++;
        }
        out[i] = sum / cnt;
    }
}

int main(void) {
    float ia[64], ia_f[64];   /* A相电流 */
    float ua[64], ua_f[64];   /* A相电压 */
    /* ...从采样芯片读入ia/ua... */
    filter_ma(ia, ia_f, 64, 5);  /* 同一函数 */
    filter_ma(ua, ua_f, 64, 5);  /* 复用两路 */
    return 0;
}

🔍 参数设计三问（好函数的自检清单）： ① 窗口 w 为什么是参数而不是 #define？——不同回路要用不同窗口； ② in 为什么加 const？——向调用者承诺"只读不改"（第 2 章的约定回归）； ③ 为什么 out 独立于 in？——项目 22 的双缓冲纪律，原地滤波会污染后续窗口。

VibeCoding 三段迭代提示

  1. 手写基础版：实现 filter_ma 并用它处理一路含毛刺的电流数组。先想清楚：窗口不足 w 个点的起始端怎么办？
  2. AI 优化进阶版：让 AI 增加”限幅滤波”函数（变化超过阈值判为毛刺、用上次值替代），组成两级滤波流水线。审查两个函数的耦合度：限幅函数里是否混进了滑动平均的逻辑？
  3. 信创加固定稿版：函数加防御（n 或 w 非法立即返回错误码）；思考在 200 微秒采样周期内，w=16 的滤波在国产 MCU 上来不来得及（运算量估算）；in/out 指向同一数组时会发生什么——文档里要不要禁止？

素养与思政

电网频率波动超过 ±0.2Hz，继电保护必须在 20 毫秒内动作——留给滤波函数的时间以微秒计。国家电网的信创改造中，这类底层算法函数都要在国产芯片上重新验证时序。 大国重器的可靠性是逐函数验证出来的：每个函数职责单一、接口明确、行为可测，全站几十路信号才能共用一套久经考验的代码。低耦合不是洁癖，是电网安全的工程前提。
