结构体封装异构数据建模业务对象

场景导入：现实怎么说，结构体就怎么长

山东寿光的无人农场：每台农机装着北斗终端，上报”我是谁、在哪、多快、什么状态、剩多少油”。 把这句话直译成 C 类型，就是业务对象建模：

typedef struct { double lat, lon; } GeoPoint;   /* 可复用零件 */
typedef enum { IDLE, WORKING, FAULT } MachineStatus;
typedef struct {
    char          id[8];      /* 我是谁 */
    GeoPoint      pos;        /* 在哪(嵌套!) */
    float         speed_kmh;  /* 多快 */
    MachineStatus status;     /* 什么状态(enum) */
    uint8_t       fuel_pct;   /* 剩多少油 */
} FarmMachine;

三个建模要点：嵌套复用（GeoPoint 农机能用、基站能用、项目 11 的围栏顶点也能用）；enum 管状态（比魔法数字 0/1/2 可读百倍）；链式访问（m.pos.lat——一层一个点号）。

💡 嵌套访问一层一个点号：m.pos.lat——农机的坐标的纬度。 GeoPoint 是可复用的"零件"：农机用它、基站用它、地块边界也用它（项目 11 的围栏顶点！）。好的建模=业务名词直译成类型：现实中怎么说，结构体就怎么长。

farm_machine.c（随选中农机实时生成）
#include <stdint.h>

typedef struct {          /* 嵌套的"零件"结构体 */
    double lat;
    double lon;
} GeoPoint;

typedef enum { IDLE, WORKING, FAULT } MachineStatus;

typedef struct {          /* 业务对象:一台农机 */
    char          id[8];
    GeoPoint      pos;    /* 结构体套结构体 */
    float         speed_kmh;
    uint8_t       fuel_pct;
    MachineStatus status;
} FarmMachine;

int main(void) {
    FarmMachine m = {
        .id = "NJ-001",
        .pos = { 36.8412, 118.0523 },
        .speed_kmh = 5.2f,
        .fuel_pct = 78,
        .status = WORKING
    };
    /* 链式成员访问:一层一个点号 */
    printf("%s @ (%.4f, %.4f)\n",
           m.id, m.pos.lat, m.pos.lon);
    if (m.fuel_pct < 20) printf("低油量告警!\n");
    return 0;
}

VibeCoding 三段迭代提示

  1. 手写基础版：定义 GeoPoint/FarmMachine，创建 2 台农机并打印档案。体会 enum 版 status 与 int 版 0/1/2 的可读性差距。
  2. AI 优化进阶版：让 AI 写 double distance_m(GeoPoint a, GeoPoint b)（简化平面近似即可）计算两台农机间距。审查它对”纬度 1 度≈111km”的换算，及返回单位是否与函数名的 _m 一致（项目 3 的量纲教训）。
  3. 信创加固定稿版：状态切换加合法性检查（FAULT 不能直接跳 WORKING，须先回 IDLE 检修——状态机雏形）；低油量（小于 20%）自动拒绝进入 WORKING；把这些规则封装成 int set_status(FarmMachine *m, MachineStatus s)（指针传参——模块六学以致用）。

素养与思政

北斗农机自动驾驶系统已在全国推广超过 20 万台套：直线播种误差不超过 2.5 厘米，一台无人收割机一天作业 80 亩。新疆的棉田、黑龙江的稻田里，“面朝黄土背朝天”正在被”一部手机管农场”替代。 你建模的 FarmMachine，正是这场变革的数字镜像——把农机变成可计算的对象，把经验变成可执行的规则，这是”藏粮于技”最代码化的注解。
