北斗轨迹离线归档

基础必做 北斗场景 ★★★★★ 约 110 分钟

学习目标：工程轨迹数据的持久化方案

二进制文件数据序列化溯源存储

场景导入：文本太胖，上二进制

远洋渔船的北斗终端每秒记录一个轨迹点，离线归档三个月再回传。用项目 44 的文本格式？一个点约 32 字节；换二进制（fwrite 直接把结构体的内存字节拍进文件）只要 20 字节——窄带卫星信道上，这就是 37% 的流量费。

fwrite(pts, sizeof(TrackPt), n, fp);   /* 写:内存快照落盘 */
fread(pts, sizeof(TrackPt), cap, fp);  /* 读:字节级还原 */

注意模式里的 b（"wb"/"rb"）。二进制的交换条件：人读不懂了，且跨平台要小心（字节序、对齐——项目 37 的填充在这里变成兼容性坑）。溯源场景再加一道保险：校验和，回放前先验字节完整性。

💡 文本存"字符"，二进制存"内存本身"：39.904200 在文本里是 9 个字符 9 字节， 在二进制里就是 double 的 8 个原始字节——fwrite 把结构体的内存快照直接拍进文件。 代价是人读不懂、跨平台要小心（字节序/对齐——项目 37 的填充在这里变成兼容性问题）。 尾部再附一个 XOR 校验和，回放时先验后用——溯源数据的最低保险。

track_archive.c
#include <stdio.h>
#include <stdint.h>

typedef struct {      /* 20字节/点(packed) */
    uint32_t t;       /* Unix时间戳 */
    double   lat;
    double   lon;
} TrackPt;

/* 二进制归档:整块结构体直接落盘 */
int archive(const TrackPt pts[], int n) {
    FILE *fp = fopen("track.bin", "wb");  /* b! */
    if (fp == NULL) return -1;
    /* 一次写n个结构体:fwrite(首址,单块大小,块数,fp) */
    size_t ok = fwrite(pts, sizeof(TrackPt), n, fp);
    fclose(fp);
    return (ok == (size_t)n) ? 0 : -2;
}

/* 回放:二进制读回,字节级还原 */
int replay(TrackPt pts[], int cap) {
    FILE *fp = fopen("track.bin", "rb");
    if (fp == NULL) return 0;
    int n = (int)fread(pts, sizeof(TrackPt), cap, fp);
    fclose(fp);
    return n;
}

VibeCoding 三段迭代提示

  1. 手写基础版：生成 100 个模拟轨迹点，fwrite 归档再 fread 回放，逐点比对验证无损。用 ls -l（或文件属性）核对文件大小 = 100×sizeof(TrackPt)。
  2. AI 优化进阶版：让 AI 设计文件头（魔数 “BDTK” + 版本 + 点数 + XOR 校验和）。审查读取端顺序：先验魔数（防止拿错文件）→ 再验校验和（防止内容损坏）→ 最后才信数据。
  3. 信创加固定稿版：用 #pragma pack 或逐字段读写消除对齐差异（x86 归档、龙芯回放的兼容性）；明确注释字节序假设；损坏文件（截断/翻转一个字节）的注入测试——校验和真的拦住了吗？

素养与思政

全国 6 万余艘海洋渔船装有北斗示位终端：轨迹归档数据既是遇险搜救的生命线（最后一个点位就是搜索起点），也是维权护渔的证据链（谁在哪片海域作业，字节为证）。 溯源数据的三个”不”：不可丢（校验）、不可改（只追加）、不可赖（可回放）。 你设计的 20 字节小结构体，装的是船员的平安和国家的海权——数据完整性从来不是抽象要求。
