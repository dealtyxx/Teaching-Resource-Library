RS485工控数据环形缓存

进阶选做 信创场景 ★★★★ 约 110 分钟

学习目标：工业总线数据缓存设计思维

环形数组防丢包边界控制

场景导入：从”缓存字节”到”缓存帧”，从”能用”到”敢用”

上一个项目的环形缓冲区解决了”存不存得下”；工控场景问的是更狠的问题：丢不丢帧？丢了知不知道？容量选多大才够？

RS485 总线上挂着几十台设备，轮询数据帧持续涌入。工程上有三条铁律：

  1. 丢帧必须可观测：满了丢帧可以接受，静默丢帧不可接受——drop_cnt++ 一行都不能省；
  2. 容量是算出来的：突发积压 ≈（突发速率 − 消费速率）× 突发时长，据此选 N，再留 50% 裕量；
  3. 缓冲只能削峰：若生产速率长期大于消费速率，多大的缓冲都会满——那是架构问题，不是缓存问题。

rs485_ring.c（关键差异：满时的策略）
#define N 16
static uint8_t frame[N][64];   /* 每帧最多64字节 */
static int head = 0, tail = 0, count = 0;
static uint32_t drop_cnt = 0;  /* 丢帧必须可观测! */

int ring_put(const uint8_t *f, int len) {
    if (count == N) {
        drop_cnt++;            /* 策略1:丢新帧并计数 */
        return -1;             /* 策略2(可选):覆盖最旧帧 */
    }
    memcpy(frame[tail], f, len);
    tail = (tail + 1) % N;
    count++;
    return 0;
}

VibeCoding 三段迭代提示

  1. 手写基础版：把项目 20 的字节环形缓冲升级为帧缓冲（二维数组 frame[N][64]），加上 drop_cnt。
  2. AI 优化进阶版：让 AI 增加”高水位告警”：占用超过 75% 时输出预警。审查 75% 的计算——count * 4 >= N * 3 和 count >= N * 0.75 哪个不引入浮点？嵌入式为什么在意这个？
  3. 信创加固定稿版：按实验里的公式为”突发 200 帧/s、持续 2s、消费 100 帧/s”计算最小容量（答案：(200−100)×2=200 帧，取 2 的幂 256）；把策略做成编译期可配置（#define DROP_POLICY）。

素养与思政

国产 PLC、DCS 系统正在电力、石化、轨交领域替代进口——替代的底气不在界面，而在这种看不见的地方：丢帧率、缓存策略、可观测性。进口系统跑了三十年攒下的，正是这些”边界处的严谨”。 信创不是换个 Logo，是把每一个 drop_cnt++ 都做到位。工业软件的护城河，砌在异常路径的处理里。
