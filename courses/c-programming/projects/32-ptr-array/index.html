学习目标：理解指针与数组的内在联系

指针与数组指针偏移

场景导入：下标访问的”真面目”

模块四说”下标本质是偏移量”（项目 18），现在揭开全部真相：

arr[i] 只是 *(arr + i) 的语法糖。

编译器看到 arr[i]，翻译出来的就是”首地址 + i 个元素的偏移，再解引用”。所以：

  • 数组名≈首地址：int *p = arr; 合法（项目 28”数组传参传首地址”的根源）；
  • 指针加减走元素：p + 1 前进的是 sizeof(元素) 个字节，不是 1 个字节；
  • 两种遍历等价：arr[i] 下标法与 *p++ 指针法生成的机器码几乎相同，指针法在老编译器上曾更快，如今更多是嵌入式代码的惯用风格。

此刻的四种等价写法（全都指向同一格）：

p = 0x1000　*p = 305
arr[0] ≡ *(arr + 0) ≡ *(p) ≡ p[0]
地址算术：arr + 0 = 0x1000 + 0×4 = 0x1000

💡 切换类型再走一遍：short 的 p++ 地址加 2，double 加 8——指针加 1 前进的是"一个元素"，不是"一个字节"。 编译器根据指针类型自动换算字节数。这就是为什么指针必须有类型： 没有类型，p++ 都不知道该走多远。

ptr_walk.c（随类型切换实时生成）
#include <stdio.h>

int main(void) {
    int arr[6] = {305, 116, 399, 254, 407, 118};
    int *p = arr;      /* 数组名≈首地址 */
    for (int i = 0; i < 6; i++) {
        printf("%p: ", (void*)p);
        printf("%d\n", *p);
        p++;    /* 走一步 = 前进 sizeof(int) = 4 字节 */
    }
    return 0;
}

素养与思政

arr[i] 和 *(arr+i) 看似两种事物，实为一体两面——学问的进阶，常常是发现”原来它们是同一个东西”。 数学史上，笛卡尔把几何与代数打通（解析几何），麦克斯韦把电与磁打通。你今天打通的是”下标”与”地址算术”——尺度虽小，路径相同：不满足于会用语法，追问语法背后的机器真相。这份追问，正是第 1 章”从会打字到懂机器”的兑现。
