## 场景导入

你在命令行敲下 `pip install requests`，写出人生第一段爬虫代码，满怀期待地打印结果——`resp.status_code` 给你的见面礼却是一个 404。别慌，这正是 HTTP 的说话方式：爬虫每发出一次 GET 请求，服务器都会用一个三位数**状态码**回应你，可能是欢迎（200）、指路（301）、拒绝（403），也可能是求饶（429）。爬虫工程师的第一课不是「抓到数据」，而是**听懂对方在说什么**。

## 动手实验

真实环境里，一次有教养的 GET 请求长这样（浏览器沙箱不发真实网络请求，这段请在本机体验）：

```python
# 本机真实环境：先安装 requests（pip install requests）
import requests

resp = requests.get(
    "https://httpbin.org/get",                # 一个专供练习的测试站点
    headers={"User-Agent": "study-bot/0.1 (contact: you@campus.edu)"},  # 亮明身份
    timeout=5,                                # 最多等 5 秒，不无限期挂着
)
print(resp.status_code)                       # 200 —— 一切顺利
print(resp.headers.get("Content-Type"))       # 响应头：内容类型
print(resp.text[:120])                        # 响应正文前 120 个字符
```

## 思政会客厅

<DimCard dim="职业伦理" title="状态码是对话，不是障碍">
  <ul>
    <li>2xx 放行、3xx 指路、4xx 说「你这边有问题」、5xx 说「我这边出了状况」——把每个状态码当成对方的话来听，而不是当成待绕过的墙，是爬虫工程师的第一层职业操守。</li>
    <li>403 出现时，先自查权限与协议，而不是研究伪装；429 出现时，先降速，而不是换 IP。技术上能绕过，不代表职业上应该绕过。</li>
    <li>在 User-Agent 里亮明身份、附上联系方式，是行业里的老礼节：让站长找得到你，问题才有商量的余地。</li>
  </ul>
</DimCard>

<Callout icon="🫖" tone="gold" title="彩蛋 418 的提醒">
1998 年愚人节，工程师们在 RFC 2324 里一本正经地定义了「超文本咖啡壶控制协议」，418 的意思是「我是茶壶，煮不了咖啡」。这个玩笑保留至今，还常被网站借来婉拒爬虫——它提醒我们：HTTP 从来不是冷冰冰的管道，而是人与人之间的约定，幽默、克制与尊重都写在协议里。
</Callout>
