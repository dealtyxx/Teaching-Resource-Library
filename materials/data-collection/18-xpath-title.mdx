## 场景导入

期末大作业要做一个「高校新闻标题聚合器」，你决定先拿学校官网练手。按下 F12，标题就那么一行 `h1`，却被裹在 `body` → `div` → `h1` 的层层标签里。怎么把它精准地「指」出来？答案是 XPath——一套给网页节点写「门牌号」的语言。这一节我们只做一件事：学会用路径找到标题文本。

## 动手实验

游戏里拼路径，代码里验路径。同一个 `h1` 标题，既能用**绝对路径**从 `/html` 一级级写到底，也能用**相对路径** `//h1` 一步到位。它们真的指向同一个节点吗？跑一下就知道。

<PyPlayground
  client:visible
  title="绝对路径 vs 相对路径"
  note="把 h1 里的文字改一改再运行；或在 div 里再嵌一层 section 包住 h1，看绝对路径为什么断了、相对路径为什么还稳。"
  packages={['lxml']}
  height={320}
  code={`from lxml import etree

# 内联一张最小网页——注意 body / div / h1 的层层嵌套
html = """
<html>
  <body>
    <div class="container">
      <h1>数据采集与预处理</h1>
      <p>模块五 · XPath 库</p>
    </div>
  </body>
</html>
"""

# etree.HTML 把字符串解析成可寻址的元素树
tree = etree.HTML(html)

# 绝对路径：从根 /html 出发，一级一级写到 h1
abs_path = "/html/body/div/h1/text()"
# 相对路径：// 表示任意层级，一步锁定 h1
rel_path = "//h1/text()"

r1 = tree.xpath(abs_path)
r2 = tree.xpath(rel_path)

print("绝对路径：", abs_path, "→", r1)
print("相对路径：", rel_path, "→", r2)
print("命中同一个节点？", r1 == r2)`}
/>

## 思政会客厅

<DimCard dim="创新思维" title="路径即秩序">
  <ul>
    <li>绝对路径像「省市区街道门牌」，精确却脆弱——页面一改结构就失效；相对路径像「找那栋红房子」，灵活却可能撞名。工程里没有最好，只有最合适。</li>
    <li>XPath 的本质是「按规则寻址」：把一张杂乱的网页，看成一棵有秩序的树。先建立秩序感，才谈得上自动化。</li>
    <li>同一个目标常有多条路径，选哪条体现判断力——可维护、抗变化、够精确，是衡量好路径的三把尺子。</li>
  </ul>
</DimCard>

<Callout icon="🧭" tone="gold" title="给节点一个门牌号">
在混乱里建立秩序，是工程师的浪漫。XPath 教我们的第一课不是语法，而是：任何复杂系统，都可以被一套清晰的规则重新组织。
</Callout>
