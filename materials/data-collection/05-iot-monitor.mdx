## 场景导入

你所在的团队接了个「智慧城市」项目：几千个温度、水位、空气传感器铺在城市各处，读数每分钟涌进来。这些数据是新基建的「神经末梢」——调度供暖、预警内涝、监测污染全靠它。可传感器会坏、会漂移、甚至会被伪造，所以采集系统不能只顾着「收」，还得一边收、一边判断「这个读数可信吗」。这一节，我们亲手搭一个最小的监控循环。

## 动手实验

监控系统的内核，是一个「边收边判」的循环：每来一个读数，先看它缺不缺、越不越界，越界就告警、合格才入库，最后算一个质量分。下面这段代码模拟了一批传感器读数被处理的全过程：

<PyPlayground
  client:visible
  title="智慧城市传感器监控循环"
  note="把 HIGH 调低到 30，或往 readings 里再塞几个离谱的值，看质量分怎么往下掉——想想真实城市里，谁在为这条数据「生命线」的质量兜底。"
  code={`# 模拟一批传感器温度读数（℃）；正常区间设为 -10 到 45
readings = [23.5, 24.1, 999.0, 22.8, -50.0, 25.3, 24.7, None, 23.9]
LOW, HIGH = -10.0, 45.0

alarms = 0     # 越界告警数
stored = 0     # 合格入库数
bad = 0        # 坏点数（缺失 + 越界）

for i, v in enumerate(readings):
    if v is None:                     # 缺失值：坏点，不入库
        bad += 1
        print(f"#{i}  缺失读数  → 丢弃")
        continue
    if v < LOW or v > HIGH:           # 越界：告警 + 记坏点
        alarms += 1
        bad += 1
        print(f"#{i}  {v}℃  越界  → 🚨 告警")
        continue
    stored += 1                       # 合格：模拟写入数据库
    print(f"#{i}  {v}℃  正常  → 入库")

total = len(readings)
score = round(stored / total * 100)
print("\\n—— 本轮监控小结 ——")
print(f"总读数 {total} ｜ 入库 {stored} ｜ 告警 {alarms} ｜ 坏点 {bad}")
print(f"数据质量分：{score} / 100")`}
/>

## 思政会客厅

<DimCard dim="社会责任" title="城市生命线，容不得糊弄">
  <ul>
    <li>新基建数据直接连着供暖、排涝、防灾——一个被忽略的异常读数，可能就是一次没能预警的事故。采集质量在这里等同于公共安全。</li>
    <li>「宁可误报，不可漏报」：关键场景下告警逻辑要偏保守，把判断权交给人，而不是让系统悄悄咽下异常。</li>
    <li>系统要可审计：每一次告警、每一条被丢弃的坏点都留痕，出了问题才追得到源头。</li>
  </ul>
</DimCard>

<DimCard dim="数据主权" title="关键基础设施数据要自主可控">
  <ul>
    <li>城市运行数据属于重要数据，《数据安全法》第21条要求按重要程度分类分级、重点保护。</li>
    <li>关键信息基础设施在境内运营中收集、产生的重要数据，应当境内存储（《网络安全法》第37条）——不能一股脑托管到不受控的境外平台。</li>
    <li>从传感器、网关到数据库，核心链路尽量自主可控，才谈得上把城市的「数据命脉」握在自己手里。</li>
  </ul>
</DimCard>

<Callout icon="🛡️" tone="red" title="重要数据，分级而治">
《数据安全法》第21条确立数据分类分级保护制度：关系国计民生的重要数据要重点保护、境内存储、自主可控。智慧城市采集的每一条读数，既是服务市民的资源，也是必须守好的国家数据资产。
</Callout>
