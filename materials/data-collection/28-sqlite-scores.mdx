## 场景导入

教务系统里，一次补考改分背后是什么？绝不只是把 58 改成 60 这么简单——谁改的、什么时候改的、原来多少分，都得留下记录。这一课我们用零配置的 SQLite 亲手搭一个成绩库，走通「建表→增删改查」的完整链路，并给每一次改分都装上「行车记录仪」：**改动可以，但必须留痕**。

## 动手实验

sqlite3 是 Python 自带的数据库，`connect(':memory:')` 直接在内存里开一个库，跑完即焚、最适合练手。下面这段代码建成绩表、录入分数、给一次补考改分，并把「谁在何时把谁的分从多少改到多少」同步写进 audit 留痕表：

<PyPlayground
  client:visible
  title="SQLite 成绩库：改分必留痕"
  note="试着把写 audit 的那行 INSERT 删掉再运行——成绩改了，却查不到是谁改的。体会一下「没有留痕的权限」有多可怕。"
  code={`import sqlite3

# 在内存中开一个数据库（跑完即焚，绝不碰真实磁盘）
conn = sqlite3.connect(":memory:")
cur = conn.cursor()

# 建表：成绩表 + 操作留痕表 audit
cur.execute("CREATE TABLE scores (id INTEGER PRIMARY KEY, name TEXT, course TEXT, score INTEGER)")
cur.execute("CREATE TABLE audit (who TEXT, action TEXT, detail TEXT)")

# INSERT：录入原始成绩（? 占位符防注入）
data = [(1, "张三", "数据采集", 52), (2, "李四", "数据采集", 88)]
cur.executemany("INSERT INTO scores VALUES (?, ?, ?, ?)", data)

# UPDATE：张三补考通过，改分并同步写 audit 留痕
old = cur.execute("SELECT score FROM scores WHERE name='张三'").fetchone()[0]
new = 62
cur.execute("UPDATE scores SET score=? WHERE name='张三'", (new,))
cur.execute("INSERT INTO audit VALUES (?, ?, ?)",
            ("王老师", "补考改分", f"张三 数据采集 {old}->{new}"))

# SELECT：打印最终成绩单
print("=== 成绩单 ===")
for row in cur.execute("SELECT name, course, score FROM scores"):
    print(f"  {row[0]} | {row[1]} | {row[2]} 分")

# 打印留痕：每一次改动都可追溯
print("\\n=== 操作留痕 audit ===")
for w, act, detail in cur.execute("SELECT * FROM audit"):
    print(f"  [{act}] {w}：{detail}")

conn.close()`}
/>

## 思政会客厅

<DimCard dim="创新思维" title="为什么不用 Excel，而用数据库">
  <ul>
    <li>几十条成绩，Excel 够用；几十万条、多人同时读写、还要保证「要么全改成功要么全部回滚」，就非数据库不可。工具随规模升级，是工程思维的体现。</li>
    <li>SQL 用一句话就能表达查、增、改、删，把复杂的数据操作标准化——这正是关系数据库半个世纪不倒的创新内核。</li>
    <li>connect(':memory:') 这种即开即用、跑完即焚的巧思，让你在浏览器里也能练数据库。创新往往就藏在这类降低门槛的设计里。</li>
  </ul>
</DimCard>

<DimCard dim="职业伦理" title="改分必须留痕，权限就是责任">
  <ul>
    <li>数据库给了你 UPDATE 的权限，也给了你如实记录的义务。一条 audit 留痕，区分了「按规程补录」与「暗箱操作」。</li>
    <li>能改数据的人，往往是最需要被约束的人。留痕不是不信任你，而是保护你——出了争议，记录能自证清白。</li>
    <li>教务、财务、病历系统的底线都一样：谁在何时改了什么，必须可查、不可篡改。这是从业者的职业伦理，也是系统的设计红线。</li>
  </ul>
</DimCard>

<Callout icon="🔐" tone="amber" title="权限即责任">
真实的教务、银行、医院系统里，每一次数据改动都会落进不可删除的审计日志。技术上「能改」，制度上「必留痕」——这道护栏保护数据，也保护握着权限的你。
</Callout>
