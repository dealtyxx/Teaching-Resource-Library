## 场景导入

模块 2 的前三个项目给你攒齐了三块积木：听得懂状态码、查得了 robots、控得住节奏。现在把它们拼成一个能复用的框架。真实网络从不温柔：Wi-Fi 抖一下就超时，服务器忙起来回 503，你稍快一点就吃 429。新手的本能是失败立刻重试——结果往往是给本已过载的服务器补上最后一击。工程界的成熟答案叫**指数退避**：每失败一次，等待时间翻倍（1 秒 → 2 秒 → 4 秒），既给对方恢复的时间，也让重试大军自然错峰。而比重试更要紧的，是站在框架大门口的那道**合规闸门**。

## 动手实验

下面这个迷你框架浓缩了本模块的全部要点：一个按剧本「两败一成」回应的模拟服务、一道入口合规闸门、一个带指数退避的 `fetch_with_retry()`。跑一跑，先看第 3 次请求如何柳暗花明，再看不合规的 URL 如何被一票否决：

<PyPlayground
  client:visible
  title="合规爬虫基础框架（指数退避版）"
  note="把 SCRIPT 改成 [503, 429, 503] 再运行，观察「重试用尽、礼貌放弃」的分支；再把 max_retry 调到 5，看看退避时间会翻到多少秒。"
  code={`import time

# ---- 模拟一个不稳定的目标服务：按剧本回应 ----
SCRIPT = [503, 429, 200]           # 前两次故障，第三次成功
state = {"n": 0}

def flaky_get(path):
    """替身版 requests.get：只返回状态码"""
    code = SCRIPT[state["n"] % len(SCRIPT)]
    state["n"] += 1
    return code

# ---- 第一道闸门：合规校验前置（robots 判决沉淀成的白名单） ----
ALLOWED_PREFIX = ("/news/", "/notice/")

def compliance_ok(path):
    return path.startswith(ALLOWED_PREFIX)

# ---- 核心：带指数退避的抓取 ----
def fetch_with_retry(path, max_retry=3):
    if not compliance_ok(path):
        print(f"⛔ 合规校验未通过，拒绝抓取 {path}（一个请求都不发）")
        return None
    delay = 1
    for attempt in range(1, max_retry + 1):
        code = flaky_get(path)
        print(f"第{attempt}次请求 {path} -> 状态码 {code}")
        if code == 200:
            print("✅ 成功！移交解析模块")
            return code
        print(f"   指数退避：等 {delay}s 再试（演示用 sleep 0.05s 代替）")
        time.sleep(0.05)
        delay *= 2                 # 1 -> 2 -> 4
    print("❌ 重试用尽：记录日志，礼貌放弃")
    return None

fetch_with_retry("/news/2026-07-21.html")
print("=" * 46)
fetch_with_retry("/admin/secret")  # 不在白名单：一票否决`}
/>

注意这个框架的骨相：合规校验站在函数第一行，比任何网络代码都靠前；重试只面向 503、429 这类「值得等待」的故障，拿到 200 立刻收手。健壮与守规，在这里是同一套代码。

## 思政会客厅

<DimCard dim="法治意识" title="合规是闸门，不是滤网">
  <ul>
    <li>校验前置：robots 判决、路径白名单、身份声明都要在第一个请求发出之前完成——不合规的 URL，一个字节都不该发。</li>
    <li>分清「值得重试」与「不该重试」：503、429、超时是偶发故障，可以退避再试；403、401 是明确拒绝，反复重试就从容错变成了撞门。</li>
    <li>全程留痕：每次请求、退避、放弃都写日志。可审计，本身就是一种合规能力。</li>
  </ul>
</DimCard>

<DimCard dim="创新思维" title="约束催生好设计">
  <ul>
    <li>指数退避源自以太网时代的冲突避免算法，四十多年后仍是各大云服务重试机制的标配——好的工程思想会跨时代迁移。</li>
    <li>把「不能太快」「不能越界」翻译成默认参数、入口校验与退避策略，约束就从负担变成了框架的竞争力。</li>
    <li>框架设计的最高境界：让做对的事成为最省力的路径，让做错的事必须费很大的劲。</li>
  </ul>
</DimCard>
