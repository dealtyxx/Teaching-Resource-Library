## 场景导入

想象你在做一个「中华典籍数字馆」：《论语》的元数据来自甲机构的 JSON 接口，《诗经》来自乙系统导出的 XML，《史记》又躺在一份 YAML 配置里。三家来源、三种格式、字段名还各不相同（有的叫 name，有的叫 title）。要把它们并进同一份可检索的清单，就得先把「乱」收拾成「序」——这正是数据工程里最常见也最有价值的一步：多源异构整合。这一节，我们让千年典籍在代码里「对齐」。

## 动手实验

整合三步走：**先各自解析**（`json.loads` / `ET.fromstring` / `yaml.safe_load`），**再统一映射**到同一套 schema（`title` / `dynasty` / `category`），**最后合并输出**。字段名不同不要紧，`normalize` 函数就是那把「对齐尺」。全程 `ensure_ascii=False`，让中文清清爽爽：

<PyPlayground
  client:visible
  title="多源典籍元数据整合系统"
  note="试着再加一条来自 JSON 的《周易》元数据，塞进 records，看看统一清单是否自动多出一行。"
  packages={['pyyaml']}
  code={`import json, yaml
import xml.etree.ElementTree as ET

# 三条典籍元数据，来自三种不同「数据源」（现实里可能来自不同机构、不同系统）
src_json = '{"name": "论语", "era": "先秦", "type": "儒家经典"}'
src_xml = '<book><name>诗经</name><era>先秦</era><type>诗歌总集</type></book>'
src_yaml = "name: 史记\\nera: 西汉\\ntype: 纪传体史书"

# 难点：三源「意思相同、写法不同」，目标是统一成同一套 schema
def normalize(name, era, type_):
    return {"title": name, "dynasty": era, "category": type_}

records = []
# 来源①：JSON 字符串
d = json.loads(src_json)
records.append(normalize(d["name"], d["era"], d["type"]))
# 来源②：XML 文档树
r = ET.fromstring(src_xml)
records.append(normalize(r.find("name").text, r.find("era").text, r.find("type").text))
# 来源③：YAML 文本
y = yaml.safe_load(src_yaml)
records.append(normalize(y["name"], y["era"], y["type"]))

# 合并输出——一份规范化的典籍清单
print("中华典籍元数据整合清单")
print("=" * 36)
for i, rec in enumerate(records, 1):
    print(f"{i}. 《{rec['title']}》｜{rec['dynasty']}｜{rec['category']}")

# 导出统一存档 JSON（ensure_ascii=False 保证中文可读）
print("——统一存档（JSON）——")
print(json.dumps(records, ensure_ascii=False, indent=2))`}
