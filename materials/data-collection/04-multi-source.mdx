## 场景导入

实习第一天，导师甩给你三个文件：教务处导出的 CSV、合作方接口返回的 JSON，还有学长手工登记的一份名单（Python 字典列表）。三份数据说的都是学生成绩，可格式各不相同，字段还缺东少西。你的任务：把它们**整合成一张统一的表**，并且老老实实告诉导师——这批数据，到底有多少真能用。

## 动手实验

整合的第一步是「对齐」：不管来源是 CSV、JSON 还是字典，都先读成统一的 `sid / name / score` 结构。第二步是「体检」：逐条检查缺不缺字段、分数能不能转成数字，把结果记进一张质量报告。运行看看六条记录里，最后几条合格：

<PyPlayground
  client:visible
  title="多源数据整合 + 质量校验"
  note="改改三份数据——把某个 name 清空、或把 score 写成一段文字，再运行，看质量报告里的数字怎么跟着变。"
  code={`import json, csv, io

# 来源一：CSV 字符串（教务系统导出）
csv_src = """sid,name,score
2025101,张小葵,88
2025102,李明,not_a_number
2025103,,76"""

# 来源二：JSON 字符串（第三方接口返回）
json_src = '[{"sid": "2025104", "name": "王芳", "score": 91}, {"sid": "2025105", "name": "赵磊"}]'

# 来源三：字典列表（人工登记）
dict_src = [{"sid": "2025106", "name": "陈晨", "score": 82}]

def load_all():
    rows = []                                  # 三个来源统一收进一个列表
    for r in csv.DictReader(io.StringIO(csv_src)):
        rows.append(dict(r))
    rows.extend(json.loads(json_src))
    rows.extend(dict_src)
    return rows

report = {"总数": 0, "缺字段": 0, "类型错误": 0, "合格": 0}
clean = []
for r in load_all():
    report["总数"] += 1
    sid, name, score = r.get("sid"), r.get("name"), r.get("score")
    if not sid or not name or score in (None, ""):     # 缺字段
        report["缺字段"] += 1
        continue
    try:
        score = int(score)                     # 分数必须能转成整数
    except (ValueError, TypeError):
        report["类型错误"] += 1
        continue
    report["合格"] += 1
    clean.append({"sid": sid, "name": name, "score": score})

print("整合后的合格记录：")
for r in clean:
    print("  ", r)
print("\\n质量报告：", report)`}
/>

## 思政会客厅

<DimCard dim="科研诚信" title="质量报告不是摆设">
  <ul>
    <li>整合数据时，「有多少脏数据」必须如实上报——瞒报合格率、偷偷丢弃不合格记录再谎称「数据很干净」，都是学术不端的雏形。</li>
    <li>剔除坏数据要留痕、可复现：谁、为什么、剔了几条，都要说得清，别人才能验证你的结论。</li>
    <li>数据不够好，就说不够好。诚实标注局限，比伪造一份漂亮报表更有价值。</li>
  </ul>
</DimCard>

<DimCard dim="创新思维" title="统一 schema 是整合的地基">
  <ul>
    <li>多源异构的难点不在「读进来」，而在「对齐」——先定义统一 schema，再让每个来源向它靠拢，是应对复杂数据的通用思路。</li>
    <li>校验规则可以不断进化：今天查缺字段与类型，明天就能加上范围校验、去重、交叉验证。</li>
    <li>把「整合 + 质检」抽象成一条可复用的管道，下次换一批数据源也能快速接上——这就是工程化的创新。</li>
  </ul>
</DimCard>

<Callout icon="🔬" tone="blue" title="数据可以不完美，报告必须诚实">
科研与工程里，真正致命的从来不是「有脏数据」，而是「假装没有脏数据」。一张写明总数、缺字段、类型错误的质量报告，就是数据工作者的诚信底线。
</Callout>
