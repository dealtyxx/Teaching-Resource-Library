## 场景导入

保卫处的老师找上数据中心：「这学期想知道哪个门最挤、几点最忙，好排安保。」他甩来一份门禁流水——几万行，每行都是「时间、学号、进的哪个门」。这是最典型的**日志数据源**：一行一条、字段用分隔符隔开、天生带时间戳。今天的活儿听起来轻松——读进来、数一数——可你很快会意识到，每一行都是一位同学真实的脚印。

## 动手实验

真实日志按行存储，Python 用 `splitlines()` 就能把一整块文本切成一行行记录，再用 `split` 按竖线拆出字段。下面这段代码统计各门人流量、找出高峰时段，并且在打印时对学号做了脱敏——数得清人数，认不出个人：

<PyPlayground
  client:visible
  title="门禁日志统计器（含学号脱敏）"
  note="试着把 mask_id 改成只保留后两位，或往 log 里再加几条深夜的记录，看看高峰时段会不会变。"
  code={`# 校园门禁日志：每行「时间|学号|门」，用竖线分隔
log = """07:32|2025101|东门
07:45|2025102|东门
08:03|2025103|北门
08:12|2025101|北门
08:15|2025104|东门
08:20|2025105|东门
12:05|2025102|南门
18:30|2025103|东门"""

def mask_id(sid):
    # 学号脱敏：留前 2 位、后 1 位，中间打码（数得清人，认不出人）
    return sid[:2] + "*" * (len(sid) - 3) + sid[-1]

gate_count = {}   # 各门人流量
hour_count = {}   # 各时段人流量
for line in log.splitlines():
    t, sid, gate = line.split("|")
    hour = t.split(":")[0]
    gate_count[gate] = gate_count.get(gate, 0) + 1
    hour_count[hour] = hour_count.get(hour, 0) + 1
    print(f"{t}  {mask_id(sid)}  进入 {gate}")

print("\\n各门人流量（按人次排序）：")
for gate, n in sorted(gate_count.items(), key=lambda x: -x[1]):
    print(f"  {gate}：{n} 人次")

peak = max(hour_count, key=hour_count.get)
print(f"\\n高峰时段：{peak}:00 前后（{hour_count[peak]} 人次）")`}
/>

## 思政会客厅

<DimCard dim="职业伦理" title="日志分析师的边界感">
  <ul>
    <li>拿到日志的第一反应不该是「能挖出谁几点去了哪」，而是「这次分析到底要不要精确到人」——需求是流量，就只算流量。</li>
    <li>学号、行踪本身就是敏感信息，打印、导出、传阅之前先脱敏，是数据从业者该有的肌肉记忆。</li>
    <li>「技术上能做」不等于「工作里该做」：去反查某个人的作息轨迹，既非任务所需，也越了职业边界。</li>
  </ul>
</DimCard>

<DimCard dim="社会责任" title="做聚合，而不是做监视">
  <ul>
    <li>统计的价值在群体规律——哪个门挤、几点忙，用来优化安保与通行，服务的是全体同学。</li>
    <li>同一份数据，输出「东门早高峰 5 人次」是管理，输出「张三今天几点进出」就滑向监视。技术中立，用途有立场。</li>
    <li>最小必要原则：能用聚合结果解决的问题，就不保留个体明细——数据留得越少，风险也越小。</li>
  </ul>
</DimCard>

<Callout icon="⚠️" tone="amber" title="行踪轨迹属于敏感个人信息">
《个人信息保护法》第28条把行踪轨迹明确列为敏感个人信息，处理需有特定目的与充分必要性。所以门禁统计的正确姿势是：聚合出人流量与高峰时段，而不是拼出某个人的行动地图。
</Callout>
