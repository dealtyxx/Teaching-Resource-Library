## 场景导入

社团想在活动室挂一块「今日校园天气」小屏幕，你去调了一个开放天气接口。请求发出去，返回的不是排好队的表格，而是一长串带大括号的文本——这就是 JSON。它是几乎所有 Web 接口的「通用语」：键值成对、层层嵌套，机器好解析、人也读得懂。今天的任务很实在：把这串文本变成 Python 能操作的数据，再从里面精准挑出「今日概况」和「高温预警」两样东西。

## 动手实验

接口返回的 JSON 就存在 `resp` 这个字符串里。核心其实只有一步——`json.loads()` 把文本解析成字典，之后就像查字典一样用「键」逐层取值。注意最后 `json.dumps()` 里的 `ensure_ascii=False`，它是让中文正常显示、而不是变成一堆转义码的关键：

<PyPlayground
  client:visible
  title="天气接口 JSON 解析"
  note="试着在 alerts 列表里再加一条大风预警，或把 city 改成你的城市，再运行看看输出。"
  code={`import json

# 模拟天气 API 返回的 JSON 字符串（真实接口返回的就是这种文本）
resp = '''
{
  "city": "杭州",
  "date": "2026-07-21",
  "today": {"weather": "晴", "temp_high": 39, "temp_low": 30, "aqi": 62},
  "alerts": [
    {"type": "高温", "level": "橙色", "desc": "最高气温将达39℃以上"},
    {"type": "紫外线", "level": "黄色", "desc": "紫外线照射强，请注意防护"}
  ]
}
'''

# 第一步：把字符串解析成 Python 字典（dict）
data = json.loads(resp)

# 第二步：逐层用「键」取值——像剥洋葱一样一层层往里取
city = data["city"]
today = data["today"]                       # today 本身又是一个字典
overview = f"{today['weather']}，{today['temp_low']}~{today['temp_high']}℃，AQI {today['aqi']}"
print(f"【今日概况】{city} {data['date']}：{overview}")

# 第三步：遍历预警列表，把「高温」预警单独标出来
print("【预警信息】")
for a in data["alerts"]:
    mark = "⚠ 高温" if a["type"] == "高温" else "· 一般"
    print(f"  [{mark}] {a['level']}{a['type']}预警：{a['desc']}")

# 第四步：把提取结果打包回 JSON——ensure_ascii=False 让中文正常显示
has_heat = any(a["type"] == "高温" for a in data["alerts"])
summary = {"城市": city, "高温预警": has_heat}
print("【回传摘要】" + json.dumps(summary, ensure_ascii=False))`}
/>

## 思政会客厅

<DimCard dim="职业伦理" title="调用别人的接口，先守别人的规矩">
  <ul>
    <li>开放接口不是「免费自助餐」：多数平台要求先注册申请 API Key、标注数据来源，并限制调用频次（QPS 与每日上限）。守约调用，是数据工程师的职业底线。</li>
    <li>高德开放平台、和风天气等真实服务都设有配额，恶意高频请求会触发风控限流甚至封禁——尊重规则，也是尊重对方的服务器与其他使用者。</li>
    <li>《数据安全法》第三十二条要求：收集数据应采取合法、正当的方式。按约定用接口，就是「合法正当」最日常的体现。</li>
  </ul>
</DimCard>

<DimCard dim="开源共享" title="站在开放能力的肩膀上">
  <ul>
    <li>气象、地图、翻译这些能力被封装成开放 API 共享出来，小团队也能几行代码就用上——这正是「共享」精神的技术形态。</li>
    <li>享受开放资源的同时，也应回馈约定：注明出处、遵守协议、发现问题反馈给维护方，让这份共享生态可持续。</li>
  </ul>
</DimCard>
