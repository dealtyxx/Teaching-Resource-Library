## 场景导入

你的爬虫辛苦跑了半小时，抓下三千条商品数据，正得意时手一抖关掉了终端——数据全没了。采集只是上半场，把结果稳稳「落盘」保存下来才算真正到手。这一课我们用最通用的 JSON 给采集结果安个家，并立一条规矩：**每次落盘，都回读校验一遍**，确认一条不丢、一字不错。

## 动手实验

下面这个迷你落盘工具把一批书籍数据序列化成 JSON 文本，再原样读回来逐条比对。注意看 `ensure_ascii` 开与关时，中文的两副面孔：

<PyPlayground
  client:visible
  title="JSON 落盘与完整性校验"
  note="把 records 里的中文书名换成你在追的一部剧名，再运行——看 ensure_ascii=False 如何让中文原样落盘。"
  code={`import json

# 模拟采集到的结果：一批书籍条目（dict 列表）
records = [
    {"title": "活着", "author": "余华", "price": 28.0},
    {"title": "三体", "author": "刘慈欣", "price": 59.5},
    {"title": "红楼梦", "author": "曹雪芹", "price": 88.0},
]

# 1) 落盘：dict 列表 -> JSON 文本（Pyodide 里用字符串模拟文件）
#    ensure_ascii=False 让中文原样输出，而非 uXXXX 转义
blob = json.dumps(records, ensure_ascii=False, indent=2)
print("=== 落盘内容（前 40 字）===")
print(blob[:40], "...")

# 对比：默认 ensure_ascii=True 会把中文变成 uXXXX 码
ascii_blob = json.dumps(records, ensure_ascii=True)
print("\\n默认转义：", ascii_blob[:36], "...")

# 2) 回读：JSON 文本 -> dict 列表
loaded = json.loads(blob)

# 3) 完整性校验：条数 + 关键字段逐条比对
ok_count = len(loaded) == len(records)
ok_field = all(a["title"] == b["title"] and a["price"] == b["price"]
               for a, b in zip(records, loaded))

print("\\n=== 完整性校验报告 ===")
print(f"条数：写入 {len(records)} / 读回 {len(loaded)}")
print(f"字段：title 与 price 逐条比对 -> {'一致' if ok_field else '不一致'}")
if ok_count and ok_field:
    print("✅ 完整性校验通过：落盘数据可信")
else:
    print("❌ 校验失败：数据在落盘或回读中丢失")`}
/>

## 思政会客厅

<DimCard dim="科研诚信" title="落盘必校验">
  <ul>
    <li>采集数据是后续分析与论文的原始证据。落盘时少一条、串一行，结论就可能被悄悄改写，而你毫不知情。</li>
    <li>「写完就走」是侥幸，「写完回读」才是专业。多花的零点一秒，换来的是数据可信的底气。</li>
    <li>科研诚信不是空话，它就藏在 len(读回) == len(写入) 这一行断言里：能复现的数据，才是能被信任的数据。</li>
  </ul>
</DimCard>

<Callout icon="🔍" tone="green" title="一个好习惯：写完就读一遍">
把「校验」写进落盘函数的最后一步，就像快递员当面清点包裹。数据科学里最贵的错误，往往不是算法算错了，而是原始数据在某一次保存中悄悄缺了角。
</Callout>
