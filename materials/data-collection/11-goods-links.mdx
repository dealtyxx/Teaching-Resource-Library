## 场景导入

电商课题组要做一份「园艺用品比价表」，数据来自某商城的商品列表页。你要的其实很简单：每件商品的名称、价格和详情页链接。可这些信息都藏在密密麻麻的 a 标签属性里——href 是链接，data-price 是价格。BeautifulSoup 的 Tag 对象，正好能像查字典一样把它们一个个取出来。

## 动手实验

每件商品都是一个带 class 的 a 标签。下面的代码先按 class 筛出「在售」商品，再用两种方式取属性：中括号 `tag['href']` 直接取，`get()` 则在属性缺失时稳稳返回默认值而不报错。

<PyPlayground
  client:visible
  title="商品链接属性提取工具"
  height={360}
  packages={['beautifulsoup4']}
  note="试着把 class_='on-sale' 改成 class_='sold-out'，或删掉某个 a 的 href 属性再运行，体会中括号取值会报错、而 get() 稳稳返回默认值的区别。"
  code={`from bs4 import BeautifulSoup

# 内联的商品列表 HTML：每件商品是一个带 class 的 a 链接
html = """
<ul class="goods">
  <li><a class="item on-sale" href="/p/1001" data-price="9.9">向日葵种子</a></li>
  <li><a class="item on-sale" href="/p/1002" data-price="29.0">园艺手册</a></li>
  <li><a class="item sold-out" href="/p/1003" data-price="59.0">自动浇水壶</a></li>
  <li><a class="item on-sale" href="/p/1004" data-price="15.5">陶土花盆</a></li>
</ul>
"""

soup = BeautifulSoup(html, "html.parser")

# 按 class 精确筛选「在售」商品，sold-out 的会被排除在外
on_sale = soup.find_all("a", class_="on-sale")
print(f"在售商品共 {len(on_sale)} 件：")

for a in on_sale:
    # 中括号取属性：确定存在的属性直接用 a['href']
    link = a["href"]
    # get() 更稳：属性缺失时返回默认值而非报错
    price = a.get("data-price", "面议")
    name = a.get_text(strip=True)
    print(f"  {name}｜￥{price}｜{link}")

# 全程只取页面公开的商品信息，不触碰任何登录后才可见的用户数据`}
/>

## 思政会客厅

<DimCard dim="职业伦理" title="公开信息与用户数据的界线">
  <ul>
    <li>商品的名称、价格、公开链接，是平台主动展示给所有访客的信息，采集它们通常没问题。</li>
    <li>但评价区里的用户昵称、头像、晒单照片属于个人信息——不能顺手一起抓走。</li>
    <li>「能抓」不等于「该抓」：主动给自己的爬虫画一条红线，是数据从业者的职业自觉。</li>
  </ul>
</DimCard>

<DimCard dim="法治意识" title="采集也要合法">
  <ul>
    <li>《个人信息保护法》第十三条规定，处理个人信息需取得个人同意或符合其他法定情形，随意抓取用户数据可能越界。</li>
    <li>判断标准之一：这份数据是「面向公众公开的商品信息」，还是「特定用户的个人信息」？</li>
    <li>合规的采集，从明确「只取什么、不取什么」开始。</li>
  </ul>
</DimCard>

<CaseFileCard name="新浪微博诉脉脉不正当竞争案" year={2016} tag="数据抓取边界" verdict="法院认定脉脉非法抓取、使用微博用户信息构成不正当竞争，判赔约 200 万元。">
脉脉通过合作接口获取了微博用户的教育、职业等信息，并在自己的产品中展示。法院据此确立了广受引用的「三重授权」原则：抓取平台用户数据，需经过『用户授权 + 平台授权 + 用户再授权』。它与商品页面上的公开信息，性质截然不同。
</CaseFileCard>
