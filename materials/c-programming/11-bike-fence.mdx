## 场景导入：还车键按下的那 0.1 秒

你骑共享单车到目的地，按下"还车"——App 在 0.1 秒内完成了一次判定：**这辆车现在停在哪儿？能不能还？**
判定的依据是车载北斗模块报告的经纬度，规则是模块二所有知识点的总和：

- **矩形围栏判定**：`lon >= 西边界 && lon <= 东边界 && lat >= 南边界 && lat <= 北边界`——四个关系运算 + 三个 `&&`（复合条件）；
- **嵌套结构**：先判"在不在运营区"（外层），在运营区内再判"是不是禁停区"（内层）；
- **边界条件**：恰好压在围栏线上算里还是算外？`>=` 与 `>` 的一字之差，决定用户要不要付调度费。

这正是"北斗+生活"的意义：模块一你换算过北斗经纬度，现在这些坐标真正参与业务决策了。

## VibeCoding 三段迭代提示

1. **手写基础版**：写死围栏坐标，读入单车经纬度，输出三种判定之一。先在纸上画出两个矩形和三种区域。
2. **AI 优化进阶版**：让 AI 增加第二个禁停区（图书馆），并输出距离最近可停区边界的粗略方位提示（东/南/西/北）。审查它的嵌套层次：三层 if 还清晰吗？要不要用标志变量拆解？
3. **信创加固定稿版**：所有边界坐标宏定义并注明"压线算内"（`>=`）；增加坐标合法性外层防护（经度 -180~180、纬度 -90~90，第 3 章的范围校验回来了）；思考若北斗信号漂移 ±10 米，边界判定要不要加"缓冲带"？

## 素养与思政

全国共享单车日骑行量超过 4500 万人次。曾经"乱停乱放堆成山"的城市病，如今被电子围栏悄悄治理——不靠人盯，靠的是每辆车里的北斗芯片和你今天写的这几行嵌套判断。
**代码即规则，规则即秩序**：程序员把公共规则写成精确的边界条件，城市就多一分从容。这是"把论文写在祖国大地上"的另一种形态——把代码写进城市的毛细血管里。
