## 场景导入：一个函数服务全站的采样通道

变电站监测装置要同时处理几十路信号：A/B/C 三相电流、三相电压、零序分量……每路都有毛刺要滤。
给每路写一份滤波代码？维护灾难。正确姿势是**一个通用滤波函数 + 参数化设计**：

```c
void filter_ma(const float in[], float out[], int n, int w);
```

这个签名浓缩了三条**参数设计**原则：

- **数据用数组传**：C 传数组实际传的是首地址——函数能直接读写调用者的数组（与值传递不同！这是第 9 章指针的预告）；
- **规模用参数传**：点数 n、窗口 w 都不写死——同一函数适配任何通道、任何工况；
- **只读加 const**：`const float in[]` 向调用者承诺"绝不改你的原始数据"。

## VibeCoding 三段迭代提示

1. **手写基础版**：实现 `filter_ma` 并用它处理一路含毛刺的电流数组。先想清楚：窗口不足 w 个点的起始端怎么办？
2. **AI 优化进阶版**：让 AI 增加"限幅滤波"函数（变化超过阈值判为毛刺、用上次值替代），组成两级滤波流水线。审查两个函数的**耦合度**：限幅函数里是否混进了滑动平均的逻辑？
3. **信创加固定稿版**：函数加防御（n 或 w 非法立即返回错误码）；思考在 200 微秒采样周期内，w=16 的滤波在国产 MCU 上来不来得及（运算量估算）；in/out 指向同一数组时会发生什么——文档里要不要禁止？

## 素养与思政

电网频率波动超过 ±0.2Hz，继电保护必须在 20 毫秒内动作——留给滤波函数的时间以**微秒**计。国家电网的信创改造中，这类底层算法函数都要在国产芯片上重新验证时序。
**大国重器的可靠性是逐函数验证出来的**：每个函数职责单一、接口明确、行为可测，全站几十路信号才能共用一套久经考验的代码。低耦合不是洁癖，是电网安全的工程前提。
