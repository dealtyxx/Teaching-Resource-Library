## 场景导入：必须先问一次的循环

登录验证有个微妙的逻辑：**判断"密码对不对"之前，必须先让用户输入一次**。
while 是"先判断、后执行"——第一圈判断时连输入都还没有，条件从何谈起？这正是 `do-while` 的主场：

```c
do {
    /* 循环体：先无条件执行一次 */
} while (条件);   /* 再决定要不要下一圈 */
```

**do-while 保证循环体至少执行一次**。凡是"先做一次再说"的场景——询问密码、显示菜单、游戏"再来一局"——它都是最贴切的表达。配上计数器 `tries` 和复合条件 `!ok && tries < 3`，就是完整的"三次机会"逻辑。

## VibeCoding 三段迭代提示

1. **手写基础版**：实现 3 次机会登录（密码写死）。对照写一个 while 版本，体会哪里别扭。
2. **AI 优化进阶版**：让 AI 增加"锁定 30 秒后可重试"提示与错误次数持久化思路。审查它的 `scanf("%s")` 有没有宽度限制——没有 `%31s` 就是缓冲区溢出（第 2 章三大 AI 高频错误之一）。
3. **信创加固定稿版**：密码比较改为恒定时间比较的思路讨论（防时序侧信道）；错误提示不要区分"用户名不存在/密码错误"（防枚举）；把 3 次上限设为宏。

## 素养与思政

《网络安全法》第二十一条要求网络运营者"采取防范计算机病毒和网络攻击、网络侵入等危害网络安全行为的技术措施"。登录失败次数限制，是这条法律在代码层面最常见的落点——你写的 `tries < 3`，是暴力破解者面前的第一道闸。
**安全不是产品经理的需求清单，是工程师的法定义务。** 从这个 do-while 开始，把"安全内建"（Security by Design）当成写代码的默认姿势。
