## 场景导入：CRUD——信息系统的四个原子动作

县里的分布式光伏台账：村委屋顶、小学车棚、养殖场大棚……每个站点一条记录。运维每天在做四件事：**增**（新站并网）、**删**（站点注销）、**改**（离线标记）、**查**（按 ID 找站）。

这四个动作合称 **CRUD**，是从学籍系统到 12306 的一切信息系统的骨架。C 语言的最小实现 = **结构体数组 + 计数器**：

```c
Station ledger[CAP];   /* 固定容量的"账本" */
int     count = 0;     /* 当前有效条数 */
```

四个动作各有一个必须想清楚的细节：增要**查满**（count 到顶拒绝）；删要**搬移**（后续记录整体前移补洞）；查要**处理找不到**（返回 -1）；改要**先查后写**（find 到下标再动成员）。

## VibeCoding 三段迭代提示

1. **手写基础版**：实现 add/del/find 三个函数 + main 菜单循环（项目 16 的 do-while 菜单回归）。自检：增满了会怎样？删不存在的下标会怎样？
2. **AI 优化进阶版**：让 AI 增加"按容量排序输出报表"（复用项目 38）与"总装机/在线率统计"（复用项目 14 三大件）。审查它遍历是 `i < count` 还是 `i < CAP`——后者会把残留垃圾统计进去！
3. **信创加固定稿版**：ID 唯一性检查（add 前先 find，重复拒绝）；删除改"软删除"（加 deleted 标志，审计需要——金融/能源行业的合规常识）；对比软硬删除各自的代价。

## 素养与思政

截至 2024 年，全国分布式光伏装机超过 3.7 亿千瓦，其中很大一部分来自农村屋顶——"整县推进"让阳光成了农民的存折。每个县的调度中心里，都有一本这样的台账：谁并网了、谁离线了、今天发了多少度。
**台账的严谨=收益的公正**：漏记一条，就是一户人家的电费损失。CRUD 写得对不对，从来不只是技术问题。
