## 场景导入：数组装不下"一个人"

模块四的数组只能装**同类型**数据：一列学号、或一列成绩。可"一名学生"是学号+姓名+年级+成绩的**异构组合**——四个数组各存一列？下标一乱，张三的成绩就配给了李四。

**结构体**把属于同一实体的数据打包成一个新类型：

```c
struct Student {
    uint32_t id;
    char     name[6];
    uint8_t  grade;
    float    score;
};                       /* 这是"蓝图"，不占内存 */
struct Student s;        /* 这才是"实例"，占内存 */
s.score = 92.5f;         /* 点号访问成员 */
```

**定义是蓝图，变量是实例，点号是钥匙**——三句话记住结构体。

## VibeCoding 三段迭代提示

1. **手写基础版**：定义 Student 结构体，录入并打印 1 名学生。用 `sizeof` 验证你口算的大小——十有八九会被填充"背刺"。
2. **AI 优化进阶版**：让 AI 把成员重排为"从大到小"（float/uint32 在前，uint8 在后）再测 sizeof。审查它对"为什么填充变少了"的解释是否到位。
3. **信创加固定稿版**：用指定初始化器（`.id = ...`）替代按序赋值（防成员顺序调整引发错位）；给 name 录入超长字符串测试截断防护；思考跨平台传输结构体时对齐差异的坑（第 12 章文件存储的伏笔）。

## 素养与思政

一条学生记录，对应一个真实的人：学号是身份、成绩是努力、姓名是尊严。《个人信息保护法》要求处理个人信息"目的明确、最小必要"——建模时多问一句"这个字段真的需要吗"，就是把法律要求落进了 struct 定义。
**数据建模的第一课不是语法，是敬畏**：你定义的每个成员，都是对一个人某个侧面的承诺——存就存准确，用就用正当。
