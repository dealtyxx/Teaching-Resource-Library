## 场景导入：换一种方式写多分支

车速预警要分四档：平稳（0-39）、注意（40-59）、预警（60-79）、制动（≥80）。用 `else if` 链当然能写，但当分档规则是**等宽区间**时，C 语言还有一个更优雅的工具：

```c
int level = speed / 20;   /* 整数除法：55/20 = 2 */
switch (level) { ... }
```

先用**整数除法**把连续的车速"压缩"成离散的档位号（0、1、2、3…），再用 `switch-case` 按档号分发——这是嵌入式状态处理的经典范式。模块一里整数除法是"陷阱"（丢小数），这里又变成了"工具"（天然分档）。

> **switch vs else-if 怎么选**：判据是**离散等值匹配**（档号、命令码、状态码）用 switch，清晰且编译器可优化成跳转表；判据是**区间/复合条件**用 else-if。本项目先用除法把区间变成离散值，正是为了用上 switch。

## VibeCoding 三段迭代提示

1. **手写基础版**：读入车速（int），完成四档判定。故意删掉一个 `break` 编译运行，观察"贯穿"现象——这是最好的反面教材。
2. **AI 优化进阶版**：让 AI 增加负数车速与超范围（>200）的校验，并为每档增加建议时速差值输出。审查它的 default 分支处理了几种情况？"档号 4 和档号 5"都落进 default 合理吗？
3. **信创加固定稿版**：档宽 20、限速 80 全部宏定义；增加"传感器故障"码（速度为 -1 时）优先于一切判定；思考 speed=79 和 80 之间的边界是否与需求文档一致。

## 素养与思政

截至 2024 年，中国城市轨道交通运营里程超过 1.1 万公里，居世界第一；列车自动防护系统（ATP）每 200 毫秒就要完成一次超速判定。
本项目的四色预警只是玩具，但它的骨架——**阈值分级、超限即断、防护优先**——与真实 ATP 的安全逻辑一脉相承。安全不是一句口号，是每一个 `break` 都不缺席的严谨。
