## 场景导入：函数调用自己

模块五的收官挑战：模拟一条"红色信息"在人群网络中的传播——一个人告诉邻居，邻居再告诉邻居的邻居……
这种"同样的动作在下一层重复"的结构，最自然的表达是**递归**——函数调用自己：

```c
void spread(int r, int c, int gen) {
    if (越界 || 已传播) return;   /* 递归出口 */
    map[r][c] = 1;               /* 处理当前节点 */
    spread(r-1, c, gen+1);       /* 向四邻递归 */
    spread(r+1, c, gen+1);
    ...
}
```

递归的两条铁律：**必有出口**（否则无限调用、栈溢出），**规模递减**（每层向出口靠近一步）。
整个程序采用三函数架构：`init_map` 造世界、`spread` 递归传播、`print_stats` 出报告——main 又只当总调度（项目 26 的思想升级重演）。

## VibeCoding 三段迭代提示

1. **手写基础版**：在 8×8 的 char 数组上实现三函数架构（init/spread/stats），从中心点开始 100% 概率传播。先画递归树的前三层。
2. **AI 优化进阶版**：让 AI 把递归版改写为"队列+循环"的迭代版（广度优先），并解释两者遍历顺序的差异（深度优先 vs 逐代扩散）。审查它的队列用数组实现时，容量估算对不对（最坏 W×H）。
3. **信创加固定稿版**：给递归加**深度护栏**（depth 超过 W×H 直接返回并报错——防御栈溢出）；把传播概率、网格尺寸全部参数化；思考 100×100 的网格递归最深可达一万层，MCU 的几 KB 栈够吗？（结论：嵌入式慎用深递归，迭代版才是生产选择。）

## 素养与思政

1930 年，毛泽东在《星星之火，可以燎原》中写道：革命力量虽小，"却是站在历史前进方向上的"，终将燎原。你的模拟给出了同样的数学：**只要网络连通、传播概率为正，一颗火种终将覆盖整个连通域**；而断连率一高，火种就困在角落——组织起来的联结本身就是力量。
同一套模型反过来也是公共卫生的科学：降低接触概率、增加"断连"（隔离），指数曲线就会被摁平。**一个模型，两种读法**——这就是数学模型的普适力量，也是"把论文写在祖国大地上"的另一种方式。
